<h2>Introduction</h2>

<p><a href="https://www.fortinet.com/fortiguard/threat-intelligence/threat-research.html">Fortinet</a> has&nbsp;discovered a new botnet capable of stealing large amounts of user information, as well as remotely manipulating compromised machines. The malware appears to be based on an older botnet known as Grabbot, which was first discovered back in November of 2014. This new variant improves on that existing functionality while adding several dangerous new features. This blog aims to offer a quick insight into how Grabbot functions.</p>
<div id="sblogs">


<h2>Replication</h2>

<p>The bot can be found hosted on a number of compromised websites with a random filename. We currently suspect that Grabbot may arrive on these hosts through Exploit Kits or other malicious campaigns.</p>

<p>The bot may drop several files in the following paths:</p>

<p data-style="margin-left:.5in;">●&quot;%AppData%\{GUID}\{generated filename}.exe&quot;</p>

<p data-style="margin-left:.5in;">●&quot;%AppData%\{GUID}\{generated filename}.bat&quot;</p>

<p data-style="margin-left:.5in;">●&quot;%AppData%\{GUID}\{generated filename}&quot;</p>

<p>Note that each generated filename is different, with the host machine&rsquo;s System Volume Information. Several mutexes are created in the same way. Each drop file also has its file time information set to be the same as &ldquo;cmd.exe&rdquo; in Windows.</p>

<p>The malware creates the following registry entry to survive system reboots:</p>

<p data-style="margin-left:.5in;">●HKEY_CURRENT_USER\Software\Microsoft\ Windows\CurrentVersion\Run</p>

<p data-style="margin-left:1.0in;">○{GUID} = &quot;%AppData%\{GUID}\{generated filename}.exe&quot;</p>

<p>During execution, the bot may inject the main payload into explorer.exe and delete the original file.</p>

<h2>Browser Targeting</h2>

<p>The bot enters a sleep loop and will not perform the rest of its functionality unless one of the following internet browsers is found in the active process list:</p>

<p data-style="margin-left:.5in;">●Internet Explorer (iexplore.exe)</p>

<p data-style="margin-left:.5in;">●Firefox (firefox.exe)</p>

<p data-style="margin-left:.5in;">●Google Chrome (chrome.exe)</p>

<p data-style="margin-left:.5in;">●Opera (opera.exe)</p>

<p>Anti-analysis measures</p>

<p>The bot also scans active processes for the presence of certain system analysis tools, such as Wireshark or Process Explorer. If any is found, the bot may branch into a fake set of behaviours instead of the actual payload.</p>

<p><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/grabbot-is-back-to-nab-your-data-714.png" data-style="width: 855px; height: 350px;"/></p>

<p align="center">Fig.1: Searching for hashes of specific process names</p>

<p align="center"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/grabbot-is-back-to-nab-your-data-715.png" data-style="width: 981px; height: 416px;"/></p>

<p align="center">Fig. 2: Part of the fake behaviour - Random domain name generation and contact</p>

<h2>C&amp;C Connection</h2>

<p>Before the bot attempts to contact the command and control (C&amp;C) server, it first makes a connection to <em>www.microsoft.com</em> to verify internet connectivity. If a connection can be established, the bot will iterate through a list of possible C&amp;C servers and contact each until a response is received. The list of C&amp;Cs observed in this sample are:</p>

<p data-style="margin-left:.5in;">●http://de{REMOVED}is.site</p>

<p data-style="margin-left:.5in;">●http://ge{REMOVED}et.site</p>

<p data-style="margin-left:.5in;">●http://bi{REMOVED}ys.info</p>

<p data-style="margin-left:.5in;">●http://on{REMOVED}nc.site</p>

<p data-style="margin-left:.5in;">●http://de{REMOVED}is.info</p>

<p data-style="margin-left:.5in;">●http://ss{REMOVED}rs.info</p>

<p>When a connection is established, the bot may attempt to download the following data files:</p>

<p data-style="margin-left:.5in;">●/wordpress/ajax/d.dat</p>

<p data-style="margin-left:.5in;">●/wordpress/ajax/e.dat</p>

<p data-style="margin-left:.5in;">●/wordpress/ajax/f.dat</p>

<p data-style="margin-left:.5in;">●/wordpress/ajax/out.dat</p>

<p data-style="margin-left:.5in;">●/wordpress/ajax/g.dat</p>

<p data-style="margin-left:.5in;">●/wordpress/ajax/h.dat</p>

<p>The files are saved on the disk with a generated filename. Notably, the file &ldquo;out.dat&rdquo; is renamed to the executable file in the autorun registry. All communication between the bot and the C&amp;C are encrypted and done through HTTP. In any contact with a C&amp;C, the bot will try twice to establish connection before trying a different C&amp;C.</p>

<p align="center"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/grabbot-is-back-to-nab-your-data-716.png" data-style="width: 760px; height: 485px;"/>Fig.3: C&amp;C communication</p>

<h2>Sending Back Debug Information</h2>

<p>The bot is able to extract current system information, including a list of active processes, detected AV products, and a list of installed applications. The bot may send this information to the C&amp;C on command.</p>

<p align="center"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/grabbot-is-back-to-nab-your-data-717.png" data-style="width: 817px; height: 163px;"/></p>

<p align="center">Fig.4: System debug information</p>

<h2>Banking Backdoor</h2>

<p>The bot is also capable of tracking if specific sites, namely financial institutions and services, are accessed, and may launch a proxy or remote access backdoor to steal information. Some targeted sites from the list are as follows (in the format of *[URL]*;[backdoor cmd][arguments]):</p>

<p data-style="margin-left:.5in;">●*paypal.com*;socks_bc 5.{REMOVED}.250:7777</p>

<p data-style="margin-left:.5in;">●*hxxps://www1.royalbank.com/cgi-bin/rbaccess/*;run_vnc</p>

<p data-style="margin-left:.5in;">●*hxxps://easyweb.td.com/*;run_vnc</p>

<p data-style="margin-left:.5in;">●*hxxps://www1.bmo.com/onlinebanking/cgi-bin/netbnx/NBmain?product=5*;run_vnc</p>

<h2>Crypto-Currency Wallet Stealing</h2>

<p>The bot recursively scans the %AppData% directory looking for files with the name &ldquo;wallet.dat&rdquo;, &ldquo;electrum.dat&rdquo; or &ldquo;wallet&rdquo;. If any match is found, the contents of the file are read and encrypted, then stored into a temporary file for retrieval.</p>

<p align="center"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/grabbot-is-back-to-nab-your-data-718.png" data-style="width: 417px; height: 250px;"/></p>

<p align="center">Fig.5: Wallet data to be retrieved</p>

<h2>Conclusion</h2>

<p>Grabbot was a relatively unknown bot in the past, but from our brief analysis of this new variant it is apparent that Grabbot now has the potential to be very dangerous. Although we are still investigating its current distribution method, Fortinet is able to detect this new variant and we will keep you updated on any further changes.</p>
