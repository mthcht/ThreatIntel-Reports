<div id="sblogs">
<p>Recently, the <a href="https://fortiguard.com/">FortiGuard Labs</a> research team observed that a new variant of <a href="https://www.fortiguard.com/encyclopedia/virus/7470641">Poison Ivy</a> was being spread through a compromised PowerPoint file. We captured a PowerPoint file named Payment_Advice.ppsx, which is in OOXML format. Once the victim opens this file using the MS PowerPoint program, the malicious code contained in the file is executed. It downloads the Poison Ivy malware onto the victim&rsquo;s computer and then launches it. In this <a href="https://www.fortinet.com/fortiguard/threat-intelligence/threat-research.html">blog</a>, I&rsquo;ll show the details of how this happens, what techniques are used by this malware, as well as what it does to the victim&rsquo;s computer.</p>

<h3>The PowerPoint Sample</h3>

<p>Figure 1 shows a screenshot of when the ppsx file is opened.</p>

<p align="center"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-poison-ivy-variant-782.png" data-style="width: 500px; height: 375px;"/></p>

<p align="center"><em>Figure 1. Open Payment_Advice.ppsx</em></p>

<p>As you can see, the ppsx file is played automatically. The &ldquo;ppsx&rdquo; extension stands for &ldquo;PowerPoint Show,&rdquo; which opens the file in presentation mode. This allows the malicious code to be executed automatically. The warning message box alerts the user that it might run an unsafe external program. Usually, the implied content of the document beguiles the user into pressing the Enable button.</p>

<p>Let&rsquo;s take a look at the malicious code embedded inside this PowerPoint file.</p>

<p>OOXML file is a zip format file. By decompressing this file we can see the file/folder structure, shown below.</p>

<p align="center"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-poison-ivy-variant-783.png" data-style="width: 500px; height: 238px;"/></p>

<p align="center"><em>Figure 2. PPSX file structure</em></p>

<p>Going into its .\ppt\slides\ subfolder, slide1.xml is the slide automatically shown in Figure 1. The file &ldquo;.\_rels\slide1.xml.rels&rdquo; is the relationship file where the resources used in slide1.xml are defined. In slide1.xml, I found the xml code:&nbsp;</p>

<p><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-poison-ivy-variant-784.png" data-style="width: 369px; height: 20px;"/><a:hlinkhover action="&lt;strong&gt;ppaction://program&lt;/strong&gt;" r:id="&lt;strong&gt;rId2&lt;/strong&gt;">. </a:hlinkhover></p>

<p><a:hlinkhover action="&lt;strong&gt;ppaction://program&lt;/strong&gt;" r:id="&lt;strong&gt;rId2&lt;/strong&gt;">This means that when the user&#39;s mouse hovers over this element, something named &ldquo;rId2&rdquo; in slide1.xml.rels file is executed.</a:hlinkhover></p>

<p>Figure 3 shows the relationship between them.</p>

<p data-style="text-align: center;"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-poison-ivy-variant-785.png" data-style="width: 500px; height: 203px;"/></p>

<p align="center"><em>Figure 3. The code defined in &ldquo;rId2&rdquo;</em></p>

<h3>Being Added into the Startup Group</h3>

<p>The code defined in &ldquo;rId2&rdquo; uses an echo command of cmd.exe to output vbs codes into the Thumbs.vbs file in the &ldquo;Startup&rdquo; folder of the Start menu. This allows the Thumbs.vbs file to be executed when the victim&rsquo;s system starts. We&rsquo;ll take a look at the content of this Thumb.vbs file below.</p>

<p data-style="text-align: center;"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-poison-ivy-variant-786.png" data-style="width: 500px; height: 427px;"/></p>

<p align="center"><em>Figure 4. Thumb.vbs in the Startup folder and its content</em></p>

<h3>The Downloaded File</h3>

<p>Thumbs.vbs downloads a file from hxxp://203.248.116.182/images/Thumbs.bmp and runs it using msiexec.exe. As you may know, msiexec.exe is the Microsoft Windows Installer program, which is the default handler of .MSI files. Msiexec.exe can be used to install/uninstall/update software on Windows. The MSI file is an Installer Package. It contains a PE file (in a stream) that is executed when it&rsquo;s loaded by msiexec.exe. This PE file could be replaced with malware to bypass any AV software detection. We have also observed that more and more malware authors have started using this method to run their malware. The MSI file is in the Microsoft OLE Compound File format. In Figure 5 we can see the downloaded Thumbs.bmp file content in the DocFile Viewer.</p>

<p data-style="text-align: center;"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-poison-ivy-variant-787.png" data-style="width: 500px; height: 255px;"/></p>

<p align="center"><em>Figure 5. The downloaded Thumb.bmp in DocFile viewer</em></p>

<p>Next, I&rsquo;m going to extract this PE file from the stream into a file (exported_thumbs). By checking with a PE analysis tool, we can see that it&rsquo;s a 64-bit .Net program. This means that this malware only afftects 64bit Windows.</p>

<h3>Analyzing the .Net code and Running It</h3>

<p>After putting this extracted file into dnSpy to be analyzed, we can see the entry function <em>Main()</em>, as shown in Figure 6.</p>

<p data-style="text-align: center;"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-poison-ivy-variant-788.png" data-style="width: 500px; height: 280px;"/></p>

<p align="center"><em>Figure 6. Main function </em></p>

<p>It then calls the <em>rGHDcvkN.Exec()</em> function in Main(), which contains a huge array. Actually, the data in the array is the code that is executed as a thread function by a newly-created thread.</p>

<p>&nbsp;</p>

<p>Figure 7 clearly shows how the code in the array is executed.</p>

<p align="center"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-poison-ivy-variant-789.png" data-style="width: 500px; height: 485px;"/></p>

<p align="center"><em>Figure 7. .Net program runs a thread to execute the code in a huge array</em></p>

<p>If the code is run on a 64-bit platform, IntPtr.Size is 8. So the huge array is passed to array3. It then allocates memory buffer by calling <em>rGHDcvkN.VirtualAlloc()</em> and copies the code from array3 into the new memory by calling <em>Marshal.Copy()</em>. It eventually calls <em>rGHDcvkN.CreateThread()</em> to run the code up.</p>

<p>I started the .Net program in the debugger, and set a breakpoint on CreateThread API to see what the array code would do when it&rsquo;s hit. Per my analysis of the array code, it is a kind of loader. Its main purpose is to dynamically load the main part of the malware code from the memory space into a newly-allocated memory buffer. It then repairs any relocation issues according to the new base address and repairs APIs&rsquo; offset for the main part code. Finally, the main code&rsquo;s entry function is called.</p>

<h3>Anti-Analysis Techniques</h3>

<ol>
	<li>All APIs are hidden. They are restored when being called. The snippet below is the hidden CreateRemoteThread call.</li>
</ol>

<pre>
<code>sub_1B0E6122 proc near      
   mov   rax, 0FFFFFFFF88E23B10h
   neg   rax
   jmp   rax  ;; CreateRemoteThread
sub_1B0E6122 endp
</code></pre>

<ol>
	<li value="2">All strings are encrypted. They are decrypted before using. For example, this is the encrypted &ldquo;ntdll&rdquo; string.</li>
</ol>

<pre>
<code>   unk_1AFD538C  db 54h, 0B2h, 9Bh, 0F1h, 47h, 0Ch  ; ==&gt; "ntdll"</code></pre>

<ol>
	<li value="3">It runs a thread (I named it ThreadFun6) to check if the API has been set as a breakpoint. If yes, it calls TerminateProcess in another thread to exit the process immediately. The thread function checks all APIs in the following modules: &ldquo;ntdll&rdquo;, &ldquo;kernel32&rdquo;, &ldquo;kernelbase&rdquo; and &ldquo;user32&rdquo;. In Figure 8, you can see how this works:</li>
</ol>

<p data-style="margin-left: 0.25in; text-align: center;"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-poison-ivy-variant-790.png" data-style="width: 500px; height: 976px;"/></p>

<p align="center" data-style="margin-left:.25in;"><em>Figure 8. Checking for breakpoints on exported APIs in &ldquo;ntdll&rdquo;</em></p>

<ol>
	<li value="4">It runs a thread to check if any analysis tools are running. It does this by creating specially named pipes that are created by some analysis tools. For example, &ldquo;\\.\Regmon&rdquo; for registry monitor tool RegMon; &ldquo;\\.\FileMon&rdquo; for local file monitor tool FileMon; &ldquo;\\.\NTICE&rdquo; for SoftIce, so on.</li>
</ol>

<p data-style="margin-left:.25in;">If one of the named pipes cannot be created, it means one of the analysis tools is running. It then exits process soon thereafter.</p>

<ol>
	<li value="5">It then goes through all the running program windows to check if any windows class name contains a special string to determine if an analysis tool is running. For example, &ldquo;WinDbgFrameClass&rdquo; is Windbg main window&rsquo;s class name. This check runs in a thread as well (I named it as Threadfun3). Below, Figure 9 shows how this thread function works.</li>
</ol>

<p data-style="margin-left: 0.25in; text-align: center;"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-poison-ivy-variant-791.png" data-style="width: 500px; height: 127px;"/></p>

<p align="center"><em>Figure 9. Check Windows&rsquo; Class Name</em></p>

<ol>
	<li value="6">By checking to see if the &ldquo;Wireshark-is-running-{&hellip;}&rdquo; named mutex object exists (by calling OpenMutex), it could implement&nbsp;anti-WireShark.</li>
	<li value="7">By calling the API &ldquo;IsDebuggerPresent&rdquo;, it can check to see ] if this process is running in a debugger (returns with 1). It&rsquo;s a kind of anti-debugging check. It also checks how much time is spent by calling IsDebuggerPresent. If the time is more than 1000ms, it means that the process runs in a debugger or VM, and it then exits the process.</li>
</ol>

<p>These are all the ways that this malware performs anti-analysis. Most of these checks run in their own threads, and are called every second. It then exits the process if any check is matched.</p>

<p>To continue the analysis of this malware, we have to first skip these checks. We can dynamically modify its code to do so. For example, changing &ldquo;IsDebuggerPresent&rdquo;&rsquo;s return value as 0 allows us to bypass the running-in-debugger detection.</p>

<h3>Generating A Magic String from a Decrypted String</h3>

<p>By decrypting three strings and putting them together, we get the magic string &quot;Poison Ivy C++&quot;, which will be saved in a global variable qword_1B0E4A10. From the code snippet below you can see how it makes this string.</p>

<p data-style="text-align: center;"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-poison-ivy-variant-792.png" data-style="width: 500px; height: 488px;"/></p>

<p align="center"><em>Figure 10. Generating the magic string</em></p>

<h3>Hiding Key-functions in Six Different Modules</h3>

<p>It next loads several modules from its encrypted data. It creates a doubly-linked list, which is used to save and manage these loaded modules. There are many export functions from each of these modules that achieve the malware&rsquo;s main work. In this way, it&rsquo;s also a challenge for dynamic debugging. The variable qword_1AFE45D0 saves the header of that doubly-linked list. Each object in the list has the structure below:</p>

<pre>
<code>+00H  pointer to previous object in the list
+08H  pointer to next object in the list
+18H  for Critical Section object use
+28H  the base address of the module this object is related to
+30H  pointer to export function table
</code></pre>

<p>It then decrypts and decompresses six modules one by one, and adds each of them into the doubly-linked list. Figure 11 shows a code snippet from decrypting these six modules.</p>

<p data-style="text-align: center;"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-poison-ivy-variant-793.png" data-style="width: 500px; height: 294px;"/></p>

<p align="center"><em>Figure 11. Decrypting and decompressing modules</em></p>

<p>Each module has an Initialization function (like DllMain function for Dll files) that is called once the module is completely decrypted and decompressed. Three of these modules have an anti-analysis ability similar to the one I described in the Anti-Analysis section above. So to continue the analysis of this malware, I needed to modify their codes to bypass their detection function.</p>

<p>After that it calls the export functions of those modules. It decrypts the configuration data from the buffer at unk_1AFE3DA0. This configuration data is decrypted many times during the process running, and it tells the malware how to work. I&rsquo;ll talk more about the configuration data in a later section.</p>

<p>The malware then picks a string from the configuration data, which is &ldquo;%windir%\system32\svchost.exe&rdquo;. It later calls CreatProcess to run svchost.exe, and then injects some code and data from malware memory into the newly-created svchost.exe. It finally calls the injected code and exits its current process. The malware&rsquo;s further work is now done in the svchost.exe side.</p>

<h3>Starting over in SVCHOST.exe</h3>

<p>Through my analysis I could see that the injected codes and data represent the entire malware. It all starts over again in the svchost.exe process. Everything I have reviewed about is repeated in svchost.exe. For example, executing the anti-analysis detection code, getting the magic string, creating a doubly-linked list, decrypting six modules and adding them into the doubly-linked list, and so on.</p>

<p>It then goes to different code branch when executing the instruction 01736C2 cmp dword ptr [rdi+0Ch], 1 in module2. [rdi+0ch] is a flag that was passed when the entire code was initialized. When the flag is 0, it takes the code branch to run svchost.exe and inject code in it; when it&rsquo;s 1, it takes the code branch to connect to the C&amp;C server. Before the injected code in svchost.exe is executed, the flag is set to 1. Figure 12 shows the code branches.</p>

<p data-style="text-align: center;"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-poison-ivy-variant-794.png" data-style="width: 500px; height: 276px;"/></p>

<p align="center"><em>Figure 12. Snippet of code branches</em></p>

<h3>Obtaining the C&amp;C Server from PasteBin</h3>

<p>The C&amp;C server&rsquo;s<a href="https://www.fortinet.com/products/security-subscriptions/ipreputation-antibot.html"> IP addresses</a> and ports are encrypted and saved on the PasteBin website. PasteBin is a text code sharing website. A registered user can paste text code on it in order to share the text content to everyone. The malware author created 4 such pages, and put the C&amp;C server IP addresses and ports there. Do you remember when I talked previously about encrypted configuration data? It contains the 4 PasteBin URLs. They are</p>

<pre>
<code>hxxps://pastebin.com/Xhpmhhuy
hxxps://pastebin.com/m3TPwxQs
hxxps://pastebin.com/D8A2azM8
hxxps://pastebin.com/KQAxvdvJ</code></pre>

<p>Figure 13 shows the decrypted configuration data.</p>

<p data-style="text-align: center;"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-poison-ivy-variant-795.png" data-style="width: 500px; height: 501px;"/></p>

<p align="center"><em>Figure 13. Decrypted configuration data</em></p>

<p>If you access any one of these URLs, you will find there are normal Python codes on it. The encrypted server IP address and port are hidden in the normal python code. Let&rsquo;s take a look.</p>

<p>While looking at the main function you will find the code below:</p>

<p><em>win32serviceutil.HandleCommandLine({65YbRI+gEtvlZpo0qw6CrNdWDoev})</em>, the data between &ldquo;{&ldquo; and &ldquo;}&rdquo;, is the encrypted IP address and port. See Figure 14 for more information.</p>

<p data-style="text-align: center;"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-poison-ivy-variant-796.png" data-style="width: 500px; height: 477px;"/></p>

<p align="center"><em>Figure 14. Encrypted C&amp;C IP address and Port on PasteBin</em></p>

<p>Let&rsquo;s see what we can see after decryption in Figure 15.</p>

<p data-style="text-align: center;"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-poison-ivy-variant-797.png" data-style="width: 500px; height: 419px;"/></p>

<p align="center"><em>Figure 15. Decrypted IP address and Port</em></p>

<p>From Figure 15, we can determine that the decrypted C&amp;C server IP address is 172.104.100.53 and the Port is 1BBH i.e. 443. It should be noted that the IP addresses and Ports on the four pages are not the same. The author of this malware can update these IP addresses and Ports by simply updating the python codes on the four PasteBin pages.</p>

<h3>Communicating with the C&amp;C server</h3>

<p>The malware starts connecting and sending data to its C&amp;C server once it gets the IP address and Port. All the packets traveling between the malware and its server are encrypted using a private algorithm. The structure of the packet is like this: (the first 14H bytes is the header part, from 14H on is the data part)</p>

<pre>
<code>+00 4 bytes are a key for encryption or decryption.
+04 4 byte, are the packet command.
+0c 4 bytes is the length in bytes of the data portion of the packet.
+14 4 bytes. From this point on is the real data.</code></pre>

<p>Once the malware has connected to the server, it first sends a &ldquo;30001&rdquo; command, and the server replies with command &ldquo;30003&rdquo;. The command &ldquo;30003&rdquo; requests the client to collect the victim&rsquo;s system information. Once the malware receives this command, it calls tons of APIs to collect the system information.</p>

<ul>
	<li>It gathers the system&#39;s current usage of both physical and virtual memory by calling GlobalmemoryStatusEx.</li>
	<li>It gets the CPU speed from the system registry from &ldquo;HKLM\HARDWARE\DESCRIPTION\SYSTEM\CENTRALPROCESSOR\0\~MHz&quot;.</li>
	<li>It gets the free disk space of all partitions by calling GetDiskFreeSpaceExA.</li>
	<li>It gets the CPU architecture by calling GetNativeSysstemInfo.</li>
	<li>It collects display settings by calling EnumDisplaySetting.</li>
	<li>It collects file information from kernel32.dll.</li>
	<li>It gets the current computer name and user name by calling GetComputerName and GetUserName.</li>
	<li>It also gets the System time by calling GetSystemTime, and the system version by calling GetVersionEx.</li>
	<li>Finally, it copies the svchost.exe&rsquo;s full path and a constant string, &ldquo;PasteBin83&rdquo;, which is from the decrypted configuration data (see Figure 13 again).</li>
</ul>

<p>In Figure 16 you can see the collected system information before encryption. Figure 17 shows the data after encryption as it&rsquo;s about to be sent to the C&amp;C server. The first four bytes are used to encrypt or decrypt the following data.</p>

<p data-style="text-align: center;"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-poison-ivy-variant-798.png" data-style="width: 500px; height: 228px;"/></p>

<p align="center"><em>Figure 16. Collected information from the victim&rsquo;s system</em></p>

<p align="center"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-poison-ivy-variant-799.png" data-style="width: 500px; height: 330px;"/></p>

<p align="center"><em>Figure 17. Encrypted system information from victim&rsquo;s system</em></p>

<p>From my analysis during the malware runtime, I could determine that the malware keeps obtaining the C&amp;C server&rsquo;s IP address from PasteBin and communicating with the C&amp;C server in an infinite loop (by calling Sleep(1000) to suspend the execution).</p>

<p>So far, I only saw that the commands &ldquo;030001&rdquo; and &ldquo;030003&rdquo; are used. I&rsquo;ll continue to monitor and analyze the malware&rsquo;s behavior to see what else it will do.</p>

<h3>Solution</h3>

<p>The FortiGuard Antivirus service has detected the files &quot;Payment_Advice.ppsx&quot; as MSOFFICE/PoisonIvy.A!tr.dldr and &quot;Thumbs.bmp&quot; as MSOFFICE/PoisonIvy.A!tr.</p>
