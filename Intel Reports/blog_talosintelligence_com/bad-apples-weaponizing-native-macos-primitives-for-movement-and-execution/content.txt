    <h1 class="text-center">Bad Apples: Weaponizing native macOS primitives for movement and execution</h1>

    <div class="text-center m-1">
        <div class="post-author">
            <span>By </span>
                <a href="https://blog.talosintelligence.com/author/william/">William Charles Gibson</a>, 
                <a href="https://blog.talosintelligence.com/author/ryan/">Ryan Conry</a>
        </div>

        <br/>
        <time class="post-datetime" datetime="April 21, 2026 06:00">
            Tuesday, April 21, 2026 06:00
        </time>

        <div class="m-3">
        </div>

    <section class="post-content-wrapper mt-5">
        <div class="post-content" id="post-content">
            <ul><li>As macOS adoption grows among developers and DevOps, it has become a high&nbsp;value target; however, native "living-off-the-land" (LOTL) techniques for the platform remain significantly under-documented compared to Windows.&nbsp;</li><li>Adversaries can bypass security controls by repurposing native features like Remote Application Scripting&nbsp;(RAS) for remote execution and abusing Spotlight metadata (Finder comments) to stage payloads in a way that evades static file analysis.&nbsp;</li><li>Attackers can move toolkits and&nbsp;establish&nbsp;persistence using built-in protocols&nbsp;such as SMB,&nbsp;Netcat, Git, TFTP, and SNMP&nbsp;operating&nbsp;entirely outside the visibility of standard SSH-based telemetry.&nbsp;</li><li>Defenders should shift from static file scanning to&nbsp;monitoring&nbsp;process lineage, inter-process communication (IPC) anomalies, and enforcing strict MDM policies to disable unnecessary administrative services.</li></ul><hr><p>As macOS adoption in the enterprise reaches record highs, with over 45 percent of organizations now&nbsp;utilizing&nbsp;the platform, the traditional "security through obscurity" narrative surrounding the&nbsp;OS&nbsp;has been&nbsp;rendered&nbsp;obsolete. Mac endpoints, once relegated to creative departments, are now the primary workstations for developers, DevOps engineers, and system administrators. Consequently, these machines have become high-value targets that serve as gateways to source code repositories, cloud infrastructure, and sensitive production credentials.&nbsp;</p><p>Despite this shift, macOS-native lateral movement and&nbsp;execution&nbsp;tradecraft remain significantly understudied compared to&nbsp;their&nbsp;Windows counterparts. This research was conducted to address this critical knowledge gap. Through a systematic validation of native macOS protocols and system binaries, it is&nbsp;demonstrated&nbsp;how adversaries can&nbsp;“live off the land”&nbsp;(LOTL) by repurposing legitimate administrative tools. By weaponizing native primitives, such as Remote Application Scripting&nbsp;(RAS) and Spotlight metadata, intentional OS security features can be bypassed to transform standard system functions into robust mechanisms for arbitrary code execution and fleet-wide orchestration.</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/04/bad-apples-flow.jpg" class="kg-image" alt="" loading="lazy" width="2000" height="864" srcset="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w600/2026/04/bad-apples-flow.jpg 600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w1000/2026/04/bad-apples-flow.jpg 1000w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w1600/2026/04/bad-apples-flow.jpg 1600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/04/bad-apples-flow.jpg 2310w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 1.&nbsp;macOS&nbsp;living-off-the-land (LOTL)&nbsp;attack&nbsp;flow.</span></figcaption></figure><h2 id="the-macos-enterprise-blind-spot">The macOS&nbsp;enterprise&nbsp;blind&nbsp;spot&nbsp;</h2><p>macOS is no longer a niche operating system. According to the&nbsp;<a href="https://survey.stackoverflow.co/2024/" rel="noreferrer noopener"><u>Stack Overflow 2024 Developer Survey</u></a>, a third of professional developers use macOS as their primary platform. These machines&nbsp;represent&nbsp;high-value pivot points, often holding source code repositories, cloud credentials, and SSH keys to production infrastructure.&nbsp;</p><p>Despite this trend, the MITRE ATT&amp;CK framework documents far fewer techniques for macOS than for Windows, and recent industry reports&nbsp;indicate&nbsp;that macOS environments prevent significantly fewer attacks than their Windows or Linux counterparts. To address this disparity, community-driven resources such as&nbsp;<a href="https://www.loobins.io/" rel="noreferrer noopener"><u>LOOBins</u></a>&nbsp;(living-off-the-orchard&nbsp;binaries) have&nbsp;emerged&nbsp;to catalog native macOS binaries that can be repurposed for malicious activity. This research aims to further close that gap by systematically&nbsp;enumerating&nbsp;the native pathways available for both movement and execution.</p><h2 id="remote-command-execution-weaponizing-native-primitives">Remote&nbsp;command&nbsp;execution: Weaponizing&nbsp;native&nbsp;primitives&nbsp;</h2><p>Establishing a remote shell is the first step in any post-exploitation chain. While SSH is the standard, native macOS features&nbsp;provide&nbsp;several alternatives that can bypass traditional monitoring.&nbsp;</p><h3 id="remote-application-scripting-as-a-software-deployment-tool-t1072">Remote Application&nbsp;Scripting&nbsp;as a&nbsp;Software&nbsp;Deployment&nbsp;Tool (T1072)&nbsp;</h3><p>Remote Application&nbsp;Scripting&nbsp;(formerly known as Remote Apple Events or RAE)&nbsp;was&nbsp;introduced to extend the capabilities of the AppleScript&nbsp;Inter-Process Communication (IPC) framework across a network. By&nbsp;utilizing&nbsp;the Electronic Program-to-Program Communication (“eppc”) protocol, administrative tasks and application automation&nbsp;can be performed&nbsp;on remote&nbsp;macOS systems. This mechanism allows a controller machine to send high-level commands to a target machine, which&nbsp;are&nbsp;then processed by the&nbsp;“AppleEventsD”&nbsp;daemon.&nbsp;</p><p>The Open Scripting Architecture (OSA) is&nbsp;utilized&nbsp;as the standardized framework for&nbsp;this inter-application communication and automation on macOS. Through the exchange of Apple Events, this architecture enables scripts to programmatically interact with the operating system and installed applications, providing the functional foundation for the&nbsp;“osascript”&nbsp;utility.&nbsp;</p><p>Traditionally, RAE is viewed as a lateral movement vector; however, this research&nbsp;demonstrates&nbsp;that it can also be&nbsp;utilized&nbsp;as a standalone&nbsp;<a href="https://attack.mitre.org/techniques/T1072/" rel="noreferrer noopener"><u>Software Deployment Tool for Execution (T1072)</u></a>.&nbsp;</p><p>Adversaries&nbsp;attempting&nbsp;to use RAE for complex payloads often&nbsp;encounter&nbsp;Apple’s intentional security features, specifically the&nbsp;-10016 Handler Error. This restriction prevents the&nbsp;“System Events”&nbsp;application from executing remote shell commands&nbsp;via&nbsp;<code>do&nbsp;shell script</code>,&nbsp;even when RAE is globally enabled.</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/04/Figure-2.png" class="kg-image" alt="" loading="lazy" width="1750" height="676" srcset="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w600/2026/04/Figure-2.png 600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w1000/2026/04/Figure-2.png 1000w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w1600/2026/04/Figure-2.png 1600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/04/Figure-2.png 1750w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 2.&nbsp;The -10016&nbsp;Handler&nbsp;Error in&nbsp;remote&nbsp;application&nbsp;scripting.</span></figcaption></figure><p>To bypass this,&nbsp;a methodology&nbsp;was developed that treats&nbsp;“Terminal.app”&nbsp;as an execution proxy. Unlike&nbsp;“System Events”,&nbsp;“Terminal.app”&nbsp;is designed for shell interaction and accepts&nbsp;remote&nbsp;“do&nbsp;script”&nbsp;commands. To ensure payload integrity and bypass AppleScript parsing limitations (such as the&nbsp;-2741 syntax&nbsp;error),&nbsp;Base64 transport encoding&nbsp;is&nbsp;utilized. This transforms multi-line scripts into flat, alphanumeric strings that are decoded and executed in a two-stage process:&nbsp;</p><ol><li><strong>Deployment:</strong>&nbsp;A single RAE command instructs the remote&nbsp;“Terminal.app”&nbsp;to decode the Base64 string into a temporary path and apply&nbsp;<code>chmod&nbsp;+x</code>.&nbsp;</li><li><strong>Invocation:</strong>&nbsp;A second RAE command explicitly invokes the script via&nbsp;"bash”,&nbsp;ensuring a proper shell context.</li></ol><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/04/Figure-3.png" class="kg-image" alt="" loading="lazy" width="1750" height="596" srcset="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w600/2026/04/Figure-3.png 600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w1000/2026/04/Figure-3.png 1000w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w1600/2026/04/Figure-3.png 1600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/04/Figure-3.png 1750w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 3.&nbsp;Terminal.app&nbsp;as an&nbsp;execution&nbsp;proxy for Base64&nbsp;payloads.</span></figcaption></figure><h3 id="remote-application-scripting-for-lateral-movement-t1021005">Remote Application&nbsp;Scripting&nbsp;for Lateral Movement (T1021.005)&nbsp;</h3><p>While RAE can be weaponized for execution, its primary function&nbsp;remains&nbsp;the facilitation of inter-process communication (IPC) across a network. In a lateral movement context, RAE is&nbsp;utilized&nbsp;to control remote applications by targeting the&nbsp;“eppc://”&nbsp;URI. id="socat-file-transfer">Socat&nbsp;file&nbsp;transfer&nbsp;</h3><p>The&nbsp;<code>socat</code>&nbsp;shell&nbsp;established&nbsp;in&nbsp;the&nbsp;above&nbsp;"socat&nbsp;remote&nbsp;shell” section&nbsp;can also serve as a file transfer channel. Because the listener provides a fully interactive&nbsp;bash session, file&nbsp;contents&nbsp;can be written to the remote host by injecting a heredoc through&nbsp;the connection. This means&nbsp;<code>socat</code>&nbsp;alone handles both remote command execution and tool transfer without requiring any&nbsp;additional&nbsp;services or listeners.&nbsp;</p><p>With the&nbsp;<code>socat</code>&nbsp;listener running on the target, the attacker delivers a file by piping a heredoc-wrapped&nbsp;<code>cat</code>&nbsp;command through a&nbsp;<code>socat</code>&nbsp;connection:</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/04/Figure-33.png" class="kg-image" alt="" loading="lazy" width="1750" height="758" pre-wrap;">Figure 33.&nbsp;File&nbsp;delivery via&nbsp;socat&nbsp;heredoc&nbsp;injection.</span></figcaption></figure><h2 id="detection-and-defensive-considerations">Detection and&nbsp;defensive&nbsp;considerations&nbsp;</h2><p>Defending against&nbsp;LOTL&nbsp;techniques requires a shift from simple network alerts to granular process and metadata analysis.&nbsp;</p><h3 id="network-indicators">Network&nbsp;indicators&nbsp;</h3><p>Inbound TCP traffic on port 3031 (the&nbsp;“eppc”&nbsp;port) and unusual SNMP/TFTP traffic on internal LAN segments should be&nbsp;monitored&nbsp;for potential unauthorized activity.&nbsp;</p><h3 id="endpoint-indicators-evm">Endpoint&nbsp;indicators (EVM)&nbsp;</h3><p>Through mapping to the&nbsp;<a href="https://schema.ocsf.io/" rel="noreferrer noopener"><u>Open Cybersecurity Schema Framework (OCSF)</u></a>, an open-source effort to deliver a simplified and vendor-agnostic taxonomy for security telemetry, high-fidelity signatures for these behaviors were&nbsp;identified:&nbsp;</p><ul><li><strong>Suspicious</strong>&nbsp;<strong>lineage:</strong>&nbsp;Process trees following the pattern&nbsp;<code>launchd</code>&nbsp;-&gt;&nbsp;<code>AppleEventsD</code>&nbsp;-&gt;&nbsp;<code>Terminal</code>&nbsp;-&gt;&nbsp;<code>sh/bash</code>.&nbsp;</li><li><strong>Metadata</strong>&nbsp;<strong>monitoring:</strong>&nbsp;Frequent or unusual calls to&nbsp;<code>mdls</code>&nbsp;or writes to&nbsp;“com.apple.metadata:kMDItemFinderComment”.&nbsp;</li><li><strong>Command</strong>&nbsp;<strong>line</strong>&nbsp;<strong>anomalies:</strong>&nbsp;<code>base64 --decode</code>&nbsp;commands originating from GUI applications or&nbsp;<code>osascript</code>&nbsp;executions&nbsp;containing&nbsp;“of&nbsp;machine "eppc://..."”&nbsp;arguments.&nbsp;</li></ul><h3 id="native-security-controls-and-hardening-recommendations">Native&nbsp;security&nbsp;controls and&nbsp;hardening&nbsp;recommendations&nbsp;</h3><p>Several built-in macOS security mechanisms can be configured to mitigate the risks associated with native primitive abuse:&nbsp;</p><ul><li><strong>Transparency, Consent, and Control (TCC)</strong>&nbsp;<strong>restrictions:</strong>&nbsp;The "Automation" category within TCC is designed to regulate inter-application communication. By enforcing strict TCC policies via Mobile Device Management (MDM), unauthorized Apple Events between applications&nbsp;—&nbsp;such as a script&nbsp;attempting&nbsp;to control&nbsp;“Terminal.app”&nbsp;or&nbsp;“Finder”&nbsp;—&nbsp;can be blocked.&nbsp;</li><li><strong>MDM Policy Enforcement:</strong>&nbsp;RAE&nbsp;and Remote Login (SSH) should be disabled by default across the fleet. These services can be managed and restricted using MDM configuration profiles (e.g., the&nbsp;“com.apple.RemoteAppleEvents”payload) to ensure they are only active on authorized administrative hosts.&nbsp;</li><li><strong>Service</strong>&nbsp;<strong>hardening:</strong>&nbsp;Unnecessary network-facing services, such as&nbsp;<code>tftpd</code>&nbsp;and&nbsp;<code>snmpd</code>,&nbsp;should be explicitly disabled. The removal of these&nbsp;<code>launchd</code>&nbsp;plists&nbsp;from&nbsp;“/System/Library/LaunchDaemons”&nbsp;(where&nbsp;permitted&nbsp;by System Integrity Protection) or the use of&nbsp;<code>launchctl&nbsp;disable</code>&nbsp;commands&nbsp;prevents&nbsp;their use as ad-hoc data transfer channels.&nbsp;</li><li><strong>Application</strong>&nbsp;<strong>firewall</strong>&nbsp;<strong>and Stealth Mode:</strong>&nbsp;The built-in macOS application&nbsp;firewall&nbsp;should be enabled and configured in "Stealth Mode." This configuration ensures the device does not respond to unsolicited ICMP or connection attempts on common ports, reducing the visibility of the endpoint during internal reconnaissance.&nbsp;</li></ul><h2 id="conclusion">Conclusion&nbsp;</h2><p>The research presented in this article underscores&nbsp;a fundamental&nbsp;reality of modern endpoint security. The same primitives designed for administrative convenience and system automation are often the most potent tools in an&nbsp;adversary's arsenal. By moving beyond traditional exploit-based attacks and instead&nbsp;LOTL,&nbsp;attackers can&nbsp;operate&nbsp;within the noise of legitimate system activity.</p><p>From the weaponization of the&nbsp;“eppc”&nbsp;protocol to the creative abuse of Spotlight metadata and SNMP traps, it is clear that the macOS attack surface is both vast and nuanced. These techniques&nbsp;demonstrate&nbsp;that even within a "walled garden" ecosystem, native pathways for movement and execution remain accessible to those who understand the underlying architecture.&nbsp;</p><p>For defenders, the primary takeaway is that visibility&nbsp;remains&nbsp;the most effective deterrent. By shifting focus from static file analysis to the monitoring of process lineage, inter-process communication, and metadata anomalies, these "bad Apples" can be&nbsp;identified&nbsp;and neutralized. As macOS continues its expansion into the enterprise core, the documentation and detection of these native techniques must remain a priority for the security community.&nbsp;</p>
