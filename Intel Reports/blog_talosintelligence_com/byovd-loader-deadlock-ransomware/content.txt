    <h1 class="text-center">New BYOVD loader behind DeadLock ransomware attack</h1>

    <div class="text-center m-1">
        <div class="post-author">
            <span>By </span>
                <a href="https://blog.talosintelligence.com/author/jordyn/">Jordyn Dunk</a>, 
                <a href="https://blog.talosintelligence.com/author/chetan/">Chetan Raghuprasad</a>
        </div>

        <br/>
        <time class="post-datetime" datetime="December 9, 2025 06:00">
            Tuesday, December 9, 2025 06:00
        </time>

        <div class="m-3">
                            <a href="/category/threat-spotlight/" class="category primary-category">
                                Threat Spotlight
                            </a>
                                                    <a href="/category/ransomware/" class="category primary-category">
                                ransomware
                            </a>
                                </div>
    </div>

    <section class="post-content-wrapper mt-5">
        <div class="post-content" id="post-content">
            <ul><li>While tracking ransomware activities, Cisco Talos uncovered new tactics, techniques, and procedures (TTPs) linked to a financially motivated threat actor targeting victims with DeadLock ransomware.&nbsp;</li><li>The actor used the Bring Your Own Vulnerable Driver (BYOVD) technique with a previously unknown loader to exploit the Baidu Antivirus driver vulnerability (<a href="https://nvd.nist.gov/vuln/detail/CVE-2024-51324" rel="noreferrer noopener"><u>CVE-2024-51324</u></a>), enabling the termination of endpoint detection and response (EDR) processes.&nbsp;</li><li>The actor ran a PowerShell script that bypasses User Account Control (UAC), disables Windows Defender, terminates various security, backup, and database services, and deletes all volume shadow copies to prevent system recovery.&nbsp;</li><li>The DeadLock ransomware targets Windows machines with a custom stream cipher encryption algorithm that uses time-based cryptographic keys to encrypt files.&nbsp;</li><li>This custom encryption method allows DeadLock ransomware to effectively encrypt different file types in enterprise environments while preventing system corruption through selective targeting and anti-forensics techniques, which complicate recovery.</li></ul><h2 id="disabling-edr-services-via-byovd-technique">Disabling EDR services via BYOVD technique&nbsp;</h2><p><a href="https://attack.mitre.org/techniques/T1211/" rel="noreferrer noopener"><u>T1211 – Exploitation for defense evasion</u></a>&nbsp;</p><p>Talos observed a threat actor leveraging a BYOVD technique to disable endpoint detection and escalate privileges in an attack that eventually delivered DeadLock ransomware as the payload.&nbsp;</p><p>The attack relied on “BdApiUtil.sys”, a legitimate Baidu Antivirus driver containing an Improper Privilege Management vulnerability with <a href="https://nvd.nist.gov/vuln/detail/CVE-2024-51324" rel="noreferrer noopener"><u>CVE-2024-51324</u></a><strong> </strong>—<strong> </strong>which the actor disguised using the file name “DriverGay.sys”. This Improper Privilege Management vulnerability exposes a critical function in the driver program that allows unprivileged users to terminate any process on the system at the kernel level.&nbsp;</p><p>The attack began when the actor dropped the loader (using the file name “EDRGay.exe”) and the vulnerable driver into the victim's Videos folder and ran the loader. The loader, running in user mode, initializes the driver and establishes a connection via the <code>CreateFile()</code> Windows API. It specifies the driver's real device name (“\\.\BdApiUtil”) to obtain a handle which essentially acts as a "ticket" to authorize future communication between the loader and the driver.&nbsp;</p><p>Once connected, the loader enumerates running system processes to identify the process ID (PID) of the target antivirus or EDR solution. To trigger the exploit, it calls the <code>DeviceIOControl()</code> function, passing the target PID along with the specific I/O Control Code (IOCTL) 0x800024b4.&nbsp;</p><p>This 32-bit IOCTL value is structured to instruct the driver exactly how to operate:&nbsp;</p><ul><li>Device Type: 0x8000&nbsp;</li><li>Access: 0x0 (FILE_ANY_ACCESS)&nbsp;</li><li>Method: 0x0 (METHOD_BUFFERED)&nbsp;</li><li>Function Code: 0x92D&nbsp;</li></ul><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://blog.talosintelligence.com/content/images/2025/12/image10.png" class="kg-image" alt="" loading="lazy" width="2000" height="1342" srcset="https://blog.talosintelligence.com/content/images/size/w600/2025/12/image10.png 600w, https://blog.talosintelligence.com/content/images/size/w1000/2025/12/image10.png 1000w, https://blog.talosintelligence.com/content/images/size/w1600/2025/12/image10.png 1600w, https://blog.talosintelligence.com/content/images/size/w2400/2025/12/image10.png 2400w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 1. Function snippet of the loader, EDRGay, loading the driver and sending the IOCTL command.&nbsp;</span></figcaption></figure><p>Upon receiving the request, the driver decodes the function code 0x92D as a "terminate process" command. Due to the CVE-2024-51324 vulnerability, the driver fails to validate if the user-mode program has the necessary permissions to make this request. Because the driver operates in kernel mode with the highest system privileges, it blindly accepts the command and executes <code>ZwTerminateProcess()</code>, instantly killing the targeted security service.&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://blog.talosintelligence.com/content/images/2025/12/image11.png" class="kg-image" alt="" loading="lazy" width="2000" height="804" srcset="https://blog.talosintelligence.com/content/images/size/w600/2025/12/image11.png 600w, https://blog.talosintelligence.com/content/images/size/w1000/2025/12/image11.png 1000w, https://blog.talosintelligence.com/content/images/size/w1600/2025/12/image11.png 1600w, https://blog.talosintelligence.com/content/images/size/w2400/2025/12/image11.png 2400w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 2. Function snippets of vulnerable drivers for terminating the targeted processes.&nbsp;</span></figcaption></figure><h2 id="powershell-script-for-inhibiting-system-recovery">PowerShell script for inhibiting system recovery&nbsp;</h2><p><a href="https://attack.mitre.org/techniques/T1548/002/" rel="noreferrer noopener"><u>T1548.002 - Bypass User Account Control</u></a>&nbsp;</p><p><a href="https://attack.mitre.org/techniques/T1490/" rel="noreferrer noopener"><u>T1490 – Inhibit system recovery</u></a>&nbsp;&nbsp;</p><p>Talos observed that the threat actor executed a PowerShell script in the victim’s machine before the encryption process. The PowerShell script is a pre-encryption preparation component of the attack that the actor used to bypass the UAC, disable the detection services, and inhibit the system recovery of the victim machine.&nbsp;&nbsp;</p><p>The script implements a<strong> </strong>privilege escalation mechanism through the <code>Test-Admin</code> function that automatically detects current user permissions and re-launches itself with administrative privileges using the Verb <code>RunAs</code> parameter, ensuring it operates with the necessary system-level access required for service manipulation and shadow copy deletion. This elevation technique bypasses UAC prompts through the <code>exec bypass</code> execution policy override, allowing the script to execute without standard PowerShell security restrictions.&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://blog.talosintelligence.com/content/images/2025/12/image.png" class="kg-image" alt="" loading="lazy" width="1764" height="592" srcset="https://blog.talosintelligence.com/content/images/size/w600/2025/12/image.png 600w, https://blog.talosintelligence.com/content/images/size/w1000/2025/12/image.png 1000w, https://blog.talosintelligence.com/content/images/size/w1600/2025/12/image.png 1600w, https://blog.talosintelligence.com/content/images/2025/12/image.png 1764w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 3. Snippet of the PowerShell script escalating the privilege.&nbsp;</span></figcaption></figure><p>The main functionality of the script centers around service termination, designed to disable security software, backup systems, and database applications that could affect the ransomware encryption process. It includes an extensive exclusion list of Windows services that must remain operational to maintain basic functionality of the system for ransom payment discussions and processing, including core networking services (Winrm, Dns, Dhcp), authentication mechanisms (Kdc, Netlogon, Lsm), and essential system components (Rpcss, Plugplay, Eventlog).&nbsp;&nbsp;</p><p>The script targets the running services outside the exclusion list, which not only terminates active services but permanently disables their startup configuration to prevent automatic recovery during system reboots.&nbsp;&nbsp;</p><p>The script executes commands to delete all volume shadow copy snapshots, eliminating the victim’s ability to recover the system. It has a self-deletion mechanism that removes the traces of its existence in the victim machine, hindering the forensic analysis efforts.&nbsp;&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://blog.talosintelligence.com/content/images/2025/12/image-1.png" class="kg-image" alt="" loading="lazy" width="1764" height="1138" srcset="https://blog.talosintelligence.com/content/images/size/w600/2025/12/image-1.png 600w, https://blog.talosintelligence.com/content/images/size/w1000/2025/12/image-1.png 1000w, https://blog.talosintelligence.com/content/images/size/w1600/2025/12/image-1.png 1600w, https://blog.talosintelligence.com/content/images/2025/12/image-1.png 1764w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 4. Snippet of the PowerShell script deleting the shadowcopy.&nbsp;</span></figcaption></figure><p>Talos found that the threat actor disabled several other commands in the script that are designed to eliminate network shares and terminate system process and services through alternative methods. The network share deletion commands target specific Windows file sharing infrastructure through Windows Management Instrumentation (WMI) queries, removing all standard network shares while preserving administrative and domain controller shares, effectively isolating the infected system from network file sharing capabilities that could be used for lateral movement or data exfiltration activities. Subsequently, there are commands that target print-related shares by removing <code>print$</code> and <code>prnproc$</code> administrative shares, disrupting network printing services that could potentially be used as communication channels or recovery mechanisms.&nbsp;&nbsp;</p><p>There are also process termination commands which are designed to directly kill the PIDs associated with the running services that are not on the exclusion list, bypassing standard service shutdown procedures that would trigger alerts before termination.&nbsp;&nbsp;</p><p>Talos spotted a service startup modification command in the script that shows the advanced Windows service management techniques used to permanently alter service startup configurations, ensuring that even after system reboots, targeted services remain disabled.&nbsp;</p><p>We also observed a file-based exclusion technique in the final section of the script where it reads the exclusion service names from an external file “run[.]txt”, indicating the dynamic control of the service exclusion list depending upon the targeted environments.&nbsp;&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://blog.talosintelligence.com/content/images/2025/12/image-4.png" class="kg-image" alt="" loading="lazy" width="1758" height="1446" srcset="https://blog.talosintelligence.com/content/images/size/w600/2025/12/image-4.png 600w, https://blog.talosintelligence.com/content/images/size/w1000/2025/12/image-4.png 1000w, https://blog.talosintelligence.com/content/images/size/w1600/2025/12/image-4.png 1600w, https://blog.talosintelligence.com/content/images/2025/12/image-4.png 1758w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 5. Snippet of PowerShell script with alternative methods of terminating the targeted services.&nbsp;</span></figcaption></figure><h2 id="other-notable-ttps">Other notable TTPs&nbsp;</h2><p>Talos discovered several other notable TTPs of the DeadLock ransomware attacks from the telemetry data. Our assessment revealed that the actor had access to the victim’s network five days prior to the ransomware deployment.&nbsp;&nbsp;&nbsp;</p><h3 id="initial-access-and-system-registry-modification">Initial access and system registry modification&nbsp;&nbsp;</h3><p><a href="https://attack.mitre.org/techniques/T1078/" rel="noreferrer noopener"><u>T1078 – Valid Accounts</u></a>&nbsp;</p><p><a href="https://attack.mitre.org/techniques/T1112/" rel="noreferrer noopener"><u>T1112 – Modify Registry</u></a>&nbsp;</p><p><a href="https://attack.mitre.org/techniques/T1021/001/" rel="noreferrer noopener"><u>T1021.001 - Remote Desktop Protocol</u></a>&nbsp;</p><p><a href="https://attack.mitre.org/techniques/T1562/004/" rel="noreferrer noopener"><u>T1562.004 - Disable or Modify System Firewall</u></a>&nbsp;</p><p><a href="https://attack.mitre.org/techniques/T1569/002/" rel="noreferrer noopener"><u>T1569.002 - Service execution</u></a>&nbsp;</p><p>Talos suspects that the threat actor leverages the compromised valid accounts to gain access to the victim's machine based on telemetry data.&nbsp;</p><p>Upon gaining the system access, we observed that the threat actor attempted to<strong> </strong>enable and expose remote access services on the victim machine by using the <code>reg add</code> command to modify the <code>fDenyTSConnections</code> registry value, which directly enables the machine to accept Remote Desktop Protocol (RDP) connections. Then, the actor executed the <code>netsh advfirewall</code> command to create a new inbound firewall rule, opening TCP port 3389 to ensure RDP traffic isn't blocked. Finally, they used <code>sc config</code> and <code>sc start</code> to change the <code>RemoteRegistry</code> service to <code>on-demand</code> and immediately start it, allowing them to query and modify the system's registry from another machine for further reconnaissance and configuration modifications.&nbsp;</p>
<!--kg-card-begin: html-->
<pre>
reg add HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server /v fDenyTSConnections /t REG_DWORD /d 0 /f 

netsh advfirewall firewall add rule name=allow RemoteDesktop dir=in protocol=TCP localport=3389 action=allow 

sc config RemoteRegistry start= demand 

Sc start RemoteRegistry 
</pre>
<!--kg-card-end: html-->
<h3 id="remote-access-for-persistent-connection">Remote access for persistent connection&nbsp;</h3><p><a href="https://attack.mitre.org/techniques/T1219/002/" rel="noreferrer noopener"><u>T1219.002 - Remote Desktop Software</u></a>&nbsp;</p><p>We assess that the threat actor, operating from a compromised user account, installed a new instance of AnyDesk on a specific host one day prior to an encryption event. This action was likely taken to establish persistent, remote access.&nbsp;</p><p>While other instances of AnyDesk were already present in the environment, this new installation was suspicious. The actor used a specific sequence of commands to silently install the software, configure it to start with Windows, and set up a password for unattended access, while disabling updates that might terminate the actor’s connection to the victim’s machine.&nbsp;</p>
<!--kg-card-begin: html-->
<pre>
C:\AnyDesk.exe --install C:\Program Files (x86)\AnyDesk --start-with-win --silent --update-disabled 

C:\Program Files (x86)\AnyDesk\AnyDesk.exe --start-service 

C:\Program Files (x86)\AnyDesk\AnyDesk.exe --set-password 

C:\Program Files (x86)\AnyDesk\AnyDesk.exe --control 
</pre>

<h3 id="reconnaissance-and-lateral-movement">Reconnaissance and lateral movement&nbsp;&nbsp;</h3><p><a href="https://attack.mitre.org/techniques/T1018/" rel="noreferrer noopener"><u>T1018 - Remote System Discovery</u></a>&nbsp;</p><p><a href="https://attack.mitre.org/techniques/T1069/002/" rel="noreferrer noopener"><u>T1069.002 - Domain discovery</u></a>&nbsp;</p><p><a href="https://attack.mitre.org/techniques/T1033/" rel="noreferrer noopener"><u>T1033 - System owner / user discovery</u></a>&nbsp;</p><p><a href="https://attack.mitre.org/techniques/T1046/" rel="noreferrer noopener"><u>T1046 - Network service discovery</u></a>&nbsp;</p><p><a href="https://attack.mitre.org/techniques/T1218/014/" rel="noreferrer noopener"><u>T1218.014 - System Binary proxy execution: MMC</u></a>&nbsp;</p><p><a href="https://attack.mitre.org/techniques/T1102/" rel="noreferrer noopener"><u>T1102 – Web Service</u></a>&nbsp;</p><p>Talos observed several commands the actor executed for internal reconnaissance and lateral movement within the victim environment following the AnyDesk installation, highlighting their intent to discover and move to high-value targets.&nbsp;&nbsp;</p><p>The actor attempted to discover domain controllers, query the domain structure, and enumerate the privileged groups and their members. They performed a connectivity test using a <code>ping</code> command to see if a target machine was reachable and checked the logged-on user details by executing the <code>Quser</code> command.&nbsp;&nbsp;</p><p>Then, with the discovered internal IP addresses, the actor moved laterally by executing the <code>mstsc</code> command to start the Remote Desktop Protocol (RDP) session. They also executed the <code>mmc.exe compmgmt.msc</code> command, which is an alternative remote computer management command without a full interactive RDP session. Finally, the actor executed <code>iexplore.exe</code>, likely to access an internal web resource.&nbsp;&nbsp;</p>

<h3 id="impair-defenses">Impair defenses&nbsp;</h3><p><a href="https://attack.mitre.org/techniques/T1562/001/" rel="noreferrer noopener"><u>T1562.001 - Disable or Modify tools</u></a>&nbsp;</p><p><a href="https://attack.mitre.org/techniques/T1218/" rel="noreferrer noopener"><u>T1218 – System Binary Proxy Execution</u></a>&nbsp;</p><p>Talos observed that the actor modified the Windows Defender settings using legitimate Windows executable <code>SystemSettingsAdminFlows.exe</code>. By executing the following commands, the actor disabled Real-Time Protection (RTP) in Windows Defender. They subsequently disabled cloud-based protections through the command <code>SpynetReporting 0</code>, which stops the machine from sending threat reports to Microsoft. The command <code>SubmitSamplesConsent 0</code> prevents Windows Defender from automatically submitting suspicious files for analysis.&nbsp;</p>

<h2 id="deadlock-ransomware">DeadLock ransomware&nbsp;</h2><p>Talos observed that the threat actor deployed DeadLock ransomware as the payload in their attack. DeadLock ransomware has been active since as early as July 2025 and, unlike other ransomware actors, this threat actor does not operate a data leak site. Instead, victims are persuaded to contact the threat actor operating the DeadLock ransomware via Session messenger.&nbsp;</p><p>The DeadLock ransomware encryptor is specifically designed to target the Windows environment. The encryptor binary was written in C++ and compiled in July 2025, indicating the start time of the threat actor's operation.&nbsp;</p><p>Upon execution, the DeadLock ransomware immediately drops and executes an embedded batch script (.cmd) in the victim's “ProgramData” folder. This script functions as a loader, first preparing the system by setting up the console code page to UTF-8 by executing the command <code>chcp 65001</code>. This step ensures that the ransom note can be displayed correctly, even with special or non-English characters. After configuring the environment, the script stealthily launches the main ransomware binary and then deletes itself to remove its tracks.&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://blog.talosintelligence.com/content/images/2025/12/data-src-image-f34316b0-9814-4579-9121-5d02d1beedb2.png" class="kg-image" alt="" loading="lazy" width="235" height="103"><figcaption><span style="white-space: pre-wrap;">Figure 6. Malicious batch file that re-runs the ransomware binary.&nbsp;</span></figcaption></figure><p>The ransomware then uses a process hollowing technique to inject itself into the targeted process <code>rundll32.exe</code>, masquerading as a normal system process in the victim machine.&nbsp;</p><h2 id="ransomware-configuration-data">Ransomware configuration data&nbsp;</h2><p>The DeadLock ransomware relies on a massive 8,888-byte configuration block embedded directly within its binary to dictate its entire operational strategy. Upon execution, the ransomware parses this data using pipe (|) delimiters and loads the structure into memory in the following format:&nbsp;</p>
<!--kg-card-begin: html-->
<pre>
[CRYPTO_SEED] | [TIMING] | [PROCESSES] | [SERVICES] | [EXCLUDED_EXTENSIONS] | [EXCLUDED_PATHS] | [CAMPAIGN_ID] | [RANSOM_NOTE] | [HTML_MARKER] | [VISUAL_DATA] 
</pre>
<!--kg-card-end: html-->
<figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://blog.talosintelligence.com/content/images/2025/12/image-5.png" class="kg-image" alt="" loading="lazy" width="1494" height="638" srcset="https://blog.talosintelligence.com/content/images/size/w600/2025/12/image-5.png 600w, https://blog.talosintelligence.com/content/images/size/w1000/2025/12/image-5.png 1000w, https://blog.talosintelligence.com/content/images/2025/12/image-5.png 1494w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 7. DeadLock ransomware configuration data in the system memory.&nbsp;</span></figcaption></figure><p>Talos identified a hardcoded 65-character numeric string within the configuration that serves as the base key for the encryption function:&nbsp;&nbsp;</p><p><code>10581067105910871088211520721049106420921068109010791065111492178193</code></p><p>This key is coupled with specific timing parameters (1000, 0055242988), which are likely used to implement execution delays and initialize pseudo-random number generation seeds.&nbsp;</p><p>The configuration contains a comprehensive "kill list" designed to disable security controls, remote access tools, and file-locking applications.&nbsp;</p><p>The ransomware terminates standard Windows utilities (e.g., Explorer, PowerShell, Task Manager), alongside specific high-value targets:&nbsp;</p><ul><li><strong>Remote access:</strong> AnyDesk, RustDesk, Microsoft Remote Desktop connection (mstsc).&nbsp;</li><li><strong>Cloud storage:</strong> Dropbox, OneDrive.&nbsp;</li><li><strong>Security:</strong> Antimalware Service (msmpeng), SecurityHealthService, SmartScreen.&nbsp;</li></ul><p>The ransomware targets services to release file handles and disable defenses, specifically:&nbsp;</p><ul><li><strong>Databases:</strong> Microsoft SQL Server (including named instances like MSSQL$VEEAMSQL2012), Sybase SQL Anywhere (dbsrv12), and MySQL (FishbowlMySQL).&nbsp;</li><li><strong>Backup and recovery:</strong> Enterprise solutions including Veeam (VeeamTransportSvc), Veritas Backup Exec, Acronis, CA Arcserve, and Carbonite.&nbsp;</li><li><strong>Security suites:</strong> Endpoint protection components from Symantec/Norton (ccEvtMgr, RTVscan), McAfee (MVArmor), and 360 Security defender (zhudongfangyu).&nbsp;</li><li><strong>Business applications:</strong> Intuit QuickBooks, Microsoft Exchange, Apache Tomcat, and VMware tools (vmware-usbarbitator6s4).&nbsp;</li></ul><p>To ensure the OS remains stable enough for the victim to pay the ransom, the configuration enforces strict exclusion lists:&nbsp;</p><ul><li><strong>Critical folders:</strong> $recycle.bin, Program Files, ProgramData, Windows, and System Volume Information.&nbsp;</li><li><strong>File extensions:</strong> A vast list of executables, drivers, and system files, including .exe, .dll, .sys, .msi, .lnk, and .boot.&nbsp;</li><li><strong>Critical files:</strong> Boot loaders and system configuration files, such as bootmgr, ntldr, ntuser.dat, and desktop.ini.&nbsp;</li></ul><p>The configuration block also stores the full plaintext ransom note along with an HTML marker (<code>&lt;!doctype html&gt;</code>) indicates the ransomware is also capable of generating an HTML version of the note. Additionally, Talos observed a unique 64-character, SHA256-like hash value which likely serves as a specific campaign identifier or infection marker.&nbsp;</p><h2 id="deadlock-ransomware-encryption-process">DeadLock ransomware encryption process&nbsp;</h2><p>The Deadlock ransomware encryption operation is a sophisticated approach which includes recursive directory traversal, memory-mapped file I/O, custom stream cipher implementation, and multi-threaded processing to efficiently encrypt entire file systems while avoiding detections through custom cryptographic implementations rather than standard Windows cryptographic APIs.&nbsp;&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://blog.talosintelligence.com/content/images/2025/12/DeadLock_Flow.jpg" class="kg-image" alt="" loading="lazy" width="2000" height="1546" srcset="https://blog.talosintelligence.com/content/images/size/w600/2025/12/DeadLock_Flow.jpg 600w, https://blog.talosintelligence.com/content/images/size/w1000/2025/12/DeadLock_Flow.jpg 1000w, https://blog.talosintelligence.com/content/images/size/w1600/2025/12/DeadLock_Flow.jpg 1600w, https://blog.talosintelligence.com/content/images/size/w2400/2025/12/DeadLock_Flow.jpg 2400w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 8. DeadLock ransomware encryption process flow diagram.&nbsp;</span></figcaption></figure><p>The encryption orchestration function begins its operation with the recursive directory traversal to enumerate all accessible files on the target system while applying the exclusion filters from the parsed configuration data.&nbsp;</p><p>Then the encryption orchestration function executes another key generation function that relies on time-based seeding from system timers through the function <code>GetSystemTimeAsFileTime</code> along with complex mathematical operations producing 8-byte pseudo-random encryption key streams.&nbsp;</p><p>Finally, it executes the core encryption function which first performs a UTF-8 validation check on the file's content and processes file data in 16-byte blocks. For each byte it applies to the stream cipher using the generated pseudo-random key stream, ultimately encrypting the file data in the memory and writing the encrypted result back to the filesystem.&nbsp; Then the ransomware renames the encrypted file by appending the hexadecimal identifier and the file extension <code>“.dlock”</code> to the encrypted files.&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://blog.talosintelligence.com/content/images/2025/12/image-9.png" class="kg-image" alt="" loading="lazy" width="2000" height="1562" srcset="https://blog.talosintelligence.com/content/images/size/w600/2025/12/image-9.png 600w, https://blog.talosintelligence.com/content/images/size/w1000/2025/12/image-9.png 1000w, https://blog.talosintelligence.com/content/images/size/w1600/2025/12/image-9.png 1600w, https://blog.talosintelligence.com/content/images/2025/12/image-9.png 2336w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 9. DeadLock ransomware’s core encryption function applies to a stream cipher algorithm to encrypt the targeted files.&nbsp;</span></figcaption></figure><p>To evade the automated sandbox analysis, the ransomware executes a delay function, which implements a 50-second delay before it initiates the encryption action.&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://blog.talosintelligence.com/content/images/2025/12/Figure10.png" class="kg-image" alt="" loading="lazy" width="2000" height="1447" srcset="https://blog.talosintelligence.com/content/images/size/w600/2025/12/Figure10.png 600w, https://blog.talosintelligence.com/content/images/size/w1000/2025/12/Figure10.png 1000w, https://blog.talosintelligence.com/content/images/size/w1600/2025/12/Figure10.png 1600w, https://blog.talosintelligence.com/content/images/size/w2400/2025/12/Figure10.png 2400w" sizes="(min-width: 720px) 720px"><figcaption><i><em class="italic" style="white-space: pre-wrap;">Figure 10. Execution delay inclusion function of DeadLock ransomware.</em></i></figcaption></figure><p>During its execution, the DeadLock ransomware drops an icon file, Windows batch script, and a bitmap image file in the ProgramData folder of the victim machine.&nbsp;&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://blog.talosintelligence.com/content/images/2025/12/data-src-image-c7324e93-98c1-49e9-a037-31c49ae4989d.png" class="kg-image" alt="" loading="lazy" width="624" height="79" srcset="https://blog.talosintelligence.com/content/images/size/w600/2025/12/data-src-image-c7324e93-98c1-49e9-a037-31c49ae4989d.png 600w, https://blog.talosintelligence.com/content/images/2025/12/data-src-image-c7324e93-98c1-49e9-a037-31c49ae4989d.png 624w"><figcaption><span style="white-space: pre-wrap;">Figure 11. Dropped files of DeadLock ransomware in the ProgramData folder. </span></figcaption></figure><p>Talos observed that the ransomware replaces the icon of encrypted files with a custom icon file by configuring the path of the dropped icon file to the file extension .dlock in the “DefaultIcon” registry key of the victim machine Software registry hive.&nbsp;&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://blog.talosintelligence.com/content/images/2025/12/data-src-image-712f36db-7b18-4c4d-8514-b32483afe6ad.png" class="kg-image" alt="" loading="lazy" width="99" height="100"><figcaption><span style="white-space: pre-wrap;">Figure 12. DeadLock ransomware icon file.&nbsp;</span></figcaption></figure><p>After encryption, the actor also changed the victim machine's desktop wallpaper to a custom wallpaper and disabled the command line utilities in the victim machine.&nbsp;&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://blog.talosintelligence.com/content/images/2025/12/data-src-image-ce8c9d40-32d6-4f6e-bdac-c991a33c2446.png" class="kg-image" alt="" loading="lazy" width="624" height="227" srcset="https://blog.talosintelligence.com/content/images/size/w600/2025/12/data-src-image-ce8c9d40-32d6-4f6e-bdac-c991a33c2446.png 600w, https://blog.talosintelligence.com/content/images/2025/12/data-src-image-ce8c9d40-32d6-4f6e-bdac-c991a33c2446.png 624w"><figcaption><i><em class="italic" style="white-space: pre-wrap;">Figure 13. DeadLock ransomware wallpaper.</em></i></figcaption></figure><p>The ransomware drops the ransom note in each of the folders in the victim machine where the targeted files have been encrypted.&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://blog.talosintelligence.com/content/images/2025/12/data-src-image-0db7b438-76b1-44b6-94ce-c44f74765f34.png" class="kg-image" alt="" loading="lazy" width="624" height="254" srcset="https://blog.talosintelligence.com/content/images/size/w600/2025/12/data-src-image-0db7b438-76b1-44b6-94ce-c44f74765f34.png 600w, https://blog.talosintelligence.com/content/images/2025/12/data-src-image-0db7b438-76b1-44b6-94ce-c44f74765f34.png 624w"><figcaption><span style="white-space: pre-wrap;">Figure 14. DeadLock’s ransom note file.&nbsp;</span></figcaption></figure><p>The DeadLock ransom note displays an alarming claim of “military-grade encryption” followed by a six-step recovery process. The ransom note also describes the acceptance of ransom payment in Bitcoin or Monero and indicates warnings against file renaming or third-party decryption attempts.
