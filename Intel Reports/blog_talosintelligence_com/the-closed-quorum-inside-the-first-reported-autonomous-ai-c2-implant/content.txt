    <h1 class="text-center">The Closed Quorum: Inside the first reported autonomous AI C2 implant</h1>

    <div class="text-center m-1">
        <div class="post-author">
            <span>By </span>
                <a href="https://blog.talosintelligence.com/author/ryan-fetterman/">Ryan Fetterman</a>
        </div>

        <br/>
        <time class="post-datetime" datetime="September 22, 2026 06:00">
            Tuesday, September 22, 2026 06:00
        </time>

        <div class="m-3">
                            <a href="/category/ai/" class="category primary-category">
                                AI
                            </a>
                                                    <a href="/category/threat-spotlight/" class="category primary-category">
                                Threat Spotlight
                            </a>

    <section class="post-content-wrapper mt-5">
        <div class="post-content" id="post-content">
            <ul><li>CLOSEDQUORUM, a malware binary discovered through Cisco Talos’ <a href="https://blog.talosintelligence.com/introducing-cairn-frontier-tracking-for-ai-integrated-malware" rel="noreferrer">CAIRN project</a>, exhibits fully autonomous command and control (C2). While we do not have confirmation of in-the-wild deployment, artifacts from the binary were used to connect the developer to postings on criminal forums related to carding, dating back to 2025.&nbsp;</li><li>This malware is a useful reference example of how attackers can collapse the decision space of a particular attack phase into a constrained set of choices, allowing AI models to provide reasoning and act independently.&nbsp;</li><li>CLOSEDQUORUM represents a shift in effort displacement for attackers, in which expanding portions of the attack chain can be executed without operator involvement.</li></ul><p>AI’s impact on offensive cyber operations has thus far mainly focused on two dimensions: <em>speed </em>and <em>scale</em>. Attackers can generate phishing lures faster and produce more malicious code variants with less effort. These are real effects, visible in the proliferation of AI-generated coding samples and agent-assisted intrusions that have become common in the past few years. But in each case, the human operator remains present: directing the tooling, selecting targets, and guiding the execution. AI makes the operator faster and more productive but does not remove them from the operation.&nbsp;</p><p>A third dimension has received less attention in the malware space: effort displacement. This is not merely augmenting what an operator can accomplish in a session but transferring an entire phase of the attack from the operator to the system. Effort displacement compounds the effects of speed and scale because the human-in-the-loop is no longer the bottleneck. Human operators are bound by attention, working hours, and cognitive load. An AI system capable of executing a phase of the attack chain can continue when the operator is no longer watching. It does not go offline when the attacker sleeps.&nbsp;</p><p>Today Cisco Talos released <a href="https://blog.talosintelligence.com/introducing-cairn-frontier-tracking-for-ai-integrated-malware" rel="noreferrer noopener"><u>CAIRN</u></a>, our <a href="https://github.com/Cisco-Talos/Cognitive-Artifact-Intelligence-Research-Network" rel="noreferrer noopener"><u>open-source research toolkit</u></a> for tracking AI-integrated malware. This is the first in a series of posts sharing what we've found. While the threat class of CAIRN findings may span from experimental proof-of-concept to sophisticated active campaigns, the nature of the threat is aside from the focus: actively studying this frontier provides actionable insights to offset how threat actors are operationalizing AI.</p><h2 id="introducing-closedquorum">Introducing CLOSEDQUORUM&nbsp;</h2><p>CLOSEDQUORUM is, to our knowledge, the first publicly documented Windows implant to apply this model to tactical command and control (C2). After deployment, it delegates the selection of its next action to a panel of commercial large language models (LLMs) and executes the resulting decision, with the intent of harvesting user credentials and crypto wallets. It does not require continued commands from a human operator or tasking from a dedicated, attacker-operated C2 server; the complete dynamic operation is delegated to the AI.&nbsp;</p><p>The name reflects the architecture. A quorum is a decision-making body that requires some minimum of participants to act. CLOSEDQUORUM's quorum is up to four LLM providers: DeepSeek, Qwen, Mistral, and Google Gemini. The session is closed; no humans are admitted. Four models are queried in sequence, their independent verdicts tallied, and the binary acts, based on their judgment.</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/09/Artboard-24-copy-4.jpg" class="kg-image" alt="" loading="lazy" width="1772" height="2648" srcset="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w600/2026/09/Artboard-24-copy-4.jpg 600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w1000/2026/09/Artboard-24-copy-4.jpg 1000w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w1600/2026/09/Artboard-24-copy-4.jpg 1600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/09/Artboard-24-copy-4.jpg 1772w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 1. CLOSEDQUORUM architecture.</span></figcaption></figure><p>The CLOSEDQUORUM C2 architecture supports up to four LLM provider integrations. Each active model votes on the next action, and the action receiving the most votes is selected.&nbsp;</p><p>Our static analysis confirms the full details of the autonomous decision loop, and development builds demonstrate build-time injection of provider credentials. The public distribution build, however, contains placeholder API keys and a dummy webhook, so we did not observe a complete end-to-end execution of the architecture.&nbsp;</p><p>Further details of this post document how CLOSEDQUORUM works, what it can do, and what it means for the future of autonomous offensive AI tooling.</p><h2 id="%E2%80%9Cllm-as-c2-architecture">“LLM-as-C2" architecture&nbsp;</h2><p>CLOSEDQUORUM is a 16.4MB, 64-bit Windows executable compiled in Go. It contains a range of offensive implant functionality, but that isn’t what makes it unique. The foundational design choice in CLOSEDQUORUM is the treatment of LLM providers as the C2 infrastructure.</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/09/importsignificance.png" class="kg-image" alt="" loading="lazy" width="766" height="197" srcset="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w600/2026/09/importsignificance.png 600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/09/importsignificance.png 766w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 2. Ghidra import results summary. </span><code spellcheck="false" style="white-space: pre-wrap;"><span>CGO_ENABLED=1</span></code><span style="white-space: pre-wrap;"> confirms the binary mixes Go and C code, which is how it makes direct Windows system calls. </span></figcaption></figure><p>Traditional C2 architecture requires the attacker to operate server infrastructure: a domain, an IP, a protocol, and a listener. That infrastructure is attributable, blockable, and expensive to rotate. Defenders track C2 domains. Threat intelligence feeds publish C2 IPs. Certificate transparency logs expose new C2 infrastructure before it's used. Instead of a singular, unique C2 server, CLOSEDQUORUM calls up to four commercial LLM provider endpoints used by thousands of legitimate applications daily.&nbsp;&nbsp;</p><p>The providers are queried one-by-one by the <code>ModelOrchestrator</code>. Their responses are aggregated as a <code>[]LLMDecision</code> slice and resolved by <code>interModelDiscussion()</code> into a single action via <em>plurality voting</em>: each provider's <code>Decision</code> field value increments a <code>map[string]int</code> counter, and the highest-count decision wins. The multi-provider design serves both aggregation and resilience, reducing the effect of individual refusals, timeouts, and malformed responses. It increases the likelihood of obtaining a valid decision but does not guarantee one.&nbsp;</p><p>Four providers increase the chance that the quorum reaches a decision even if one or two members are unresponsive, or for example, one model is hitting a guardrail. If all models fail, the fallback decision is <code>consensus</code>: a string with no corresponding capability handler, causing the loop to sleep and retry rather than take a default action.</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/09/decompile.png" class="kg-image" alt="" loading="lazy" width="1261" height="1022" srcset="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w600/2026/09/decompile.png 600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w1000/2026/09/decompile.png 1000w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/09/decompile.png 1261w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 3. </span><code spellcheck="false" style="white-space: pre-wrap;"><span>main.interModelDiscussion</span></code><span style="white-space: pre-wrap;">, Ghidra decompiler view.</span></figcaption></figure><p>The process is described in Figure 3: (1) The four LLM provider keys are initialized as string constants: <code>deepseek</code>, <code>qwen</code>, <code>mistral</code>, <code>gemini</code> (lines 109–116). (2) The four-provider query loop <code>while (uVar16 &lt; 4)</code> iterates across all providers (line 124).&nbsp; (3) <code>main.queryLLM(model, prompt)</code> the live API call that dispatches each provider's structured prompt (line 134). After the loop, responses are aggregated via plurality vote on the <code>Decision</code> field; the winning decision is sent to the operator's Discord webhook before the function returns.&nbsp;</p><h2 id="voting-and-decision-schema">Voting and decision schema&nbsp;</h2><p>The LLM panel is not free to respond in any format. CLOSEDQUORUM constrains it to a typed JSON schema representing a specific attack-decision language. The system prompt, as extracted from the binary, reads “You are an advanced malware strategist. Provide ONLY executable decisions.”</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/09/data-src-image-4a1c6bf0-a022-4031-a5b3-b12e7a3b38ee.png" class="kg-image" alt="" loading="lazy" width="624" height="71" srcset="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w600/2026/09/data-src-image-4a1c6bf0-a022-4031-a5b3-b12e7a3b38ee.png 600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/09/data-src-image-4a1c6bf0-a022-4031-a5b3-b12e7a3b38ee.png 624w"><figcaption><span style="white-space: pre-wrap;">Figure 4. System prompt.</span></figcaption></figure><p>In the per-execution prompt template, <code>TARGET: %s</code> is substituted at runtime:</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/09/systemcontext.png" class="kg-image" alt="" loading="lazy" width="1241" height="345" srcset="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w600/2026/09/systemcontext.png 600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w1000/2026/09/systemcontext.png 1000w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/09/systemcontext.png 1241w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 5. The prompt template enumerates the model’s choices.&nbsp;</span></figcaption></figure><p>The response is deserialized into a Go struct:</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/09/llmdecision.png" class="kg-image" alt="" loading="lazy" width="1242" height="345" srcset="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w600/2026/09/llmdecision.png 600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w1000/2026/09/llmdecision.png 1000w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/09/llmdecision.png 1242w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 6. Structure of the returned model’s decision.&nbsp;</span></figcaption></figure><p>The <code>Decision</code> field routes to capability modules of <code>main.main</code>:&nbsp;</p><ul><li><code>steal</code> simultaneously invokes <code>lsassDump()</code>, <code>dumpBrowserCredentials()</code>, and <code>extractCryptoWallets()</code>; all three run together.&nbsp;&nbsp;</li><li><code>inject</code> calls <code>generateShellcode()</code> then branches: <code>process_hollow</code> exploit type routes to <code>injectProcess()</code> (PEB-walk hollowing); anything else routes to <code>earlyBirdInject()</code> (APC injection).&nbsp;&nbsp;</li><li><code>persist</code> dispatches to <code>establishPersistence()</code>. <code>move</code> has no handler in the distribution build.&nbsp;</li></ul><p>The LLM <em>must </em>emit a valid JSON object matching a known type, and with a decision field that maps to a specific capability, or the response is discarded. This design reduces the model’s output to a constrained set of executable choices.</p><p><code>gatherSystemInfo()</code> is called during initialization to capture the hostname, OS architecture, CPU count, Windows version, and admin status. These variables are stored in the orchestrator as the <code>TARGET:%s</code> context and injected into each LLM prompt. The system info component of the <code>TARGET:%s</code> is static, while <code>target_process</code> refreshes each cycle.&nbsp;</p><p>The <code>Reasoning</code> field preserves the LLM's rationale at execution time. A Discord webhook provides the operator with the output, as well as real-time attack telemetry, including:&nbsp;</p><ul><li>The winning decision (<code>inject</code>/<code>persist</code>/<code>steal</code>/<code>move</code>)&nbsp;</li><li>The reasoning field&nbsp;&nbsp;</li><li><code>target_process</code>, <code>exploit_type</code>, <code>evasion_method</code>, <code>payload_config</code>&nbsp;</li><li>The model and timestamp fields&nbsp;&nbsp;</li></ul><p>The attackers interest is aligned with extracting user credentials, specifically the implant targets:&nbsp;</p><ul><li>LSASS credential dumping — <code>lsassDump()</code> extracts Windows domain/local credentials from memory,&nbsp;</li><li>Browser credential theft — <code>dumpBrowserCredentials()</code> targeting Chrome, Edge, and Firefox saved passwords,&nbsp;</li><li>Crypto wallet extraction — <code>extractCryptoWallets()</code> hitting MetaMask (Chrome extension), Exodus (<code>exodus.wallet</code>), and Ethereum wallets (<code>ethPath</code>).</li></ul><p>Stolen material arrives AES-256-GCM encrypted in the operator's Discord channel as base64 code blocks.&nbsp;</p><h3 id="what-if-there-is-a-tie">What if there is a tie?&nbsp;</h3><p>In any tie, an order of preference kicks in: DeepSeek first, then Qwen, then Mistral, then Gemini.</p><figure pre-wrap;">Figure 7. Vote counting implementation.</span></figcaption></figure><p>DeepSeek holds the deciding vote in any tie: the max-finding loop iterates the decisions slice in submission order and the strict “&lt;” comparison means the first-encountered maximum wins. If DeepSeek failed and isn't in the quorum, Qwen's vote is the deciding vote, and so on down the priority order. The tie behavior is fully deterministic and biased toward DeepSeek.&nbsp;&nbsp;</p><h2 id="the-operating-model">The operating model&nbsp;</h2><p>CLOSEDQUORUM appears to operate as an operator-configured service rather than malware deployed directly by its developer. The publicly observed distribution binary is an inert template: all LLM API credentials initialize to <code>dummy_api_key</code> and the Discord webhook initializes to <code>dummy_webhook_url</code>. The binary is non-functional as distributed.&nbsp;</p><p>Evidence from development builds indicates the developer produces a customized executable for each operator. The inferred distribution model:&nbsp;</p><ul><li>Developer generates a custom binary with the operator's Discord webhook and LLM API keys injected at compile time.&nbsp;</li><li>Operator receives a configured executable and handles delivery independently&nbsp;</li><li>Stolen credentials arrive in the operator's Discord channel, AES-256-GCM encrypted with a daily-rotating key the operator can derive from the message timestamp.&nbsp;</li></ul><p>&nbsp;The encryption uses a symmetric key derived from the current date, not a hardcoded asymmetric key. The developer's infrastructure could theoretically decrypt an operator's exfil if they know the date, which they always do. This is obfuscation, not true confidentiality separation between developer and operator. Each operator nonetheless has a distinct exfil channel and a distinct binary build.&nbsp;</p><p>If operated as assessed, this is a credentials-as-a-service model where the service differentiator is the autonomous LLM orchestration layer. An operator who acquires CLOSEDQUORUM does not need to be online to run their campaign. They deploy the binary, and the LLM panel runs the attack.&nbsp;</p><h2 id="defensive-implications">Defensive implications&nbsp;</h2><p>CLOSEDQUORUM replaces a dedicated C2 endpoint with a chain of correlated behaviors. No single indicator fully identifies the architecture, but the combination is distinct:&nbsp;</p><ul><li>AI-provider API traffic originating from an unexpected Windows executable&nbsp;</li><li>Similar requests potentially sent to several model providers within a short interval&nbsp;</li><li>Structured prompts containing host context or offensive capability language (Note: This would likely only visible through TLS inspection or provider-side telemetry)&nbsp;</li><li>Numerous known malware techniques for process injection, LSASS access, or persistence creation&nbsp;</li><li>Discord webhook communication from the same process or host&nbsp;</li><li>Repeated execution at randomized 5 – 15-minute intervals&nbsp;</li></ul><p>The most useful detection strategy is still to focus on behavioral characteristics, rather than domain blocking. Legitimate applications may contact DeepSeek, OpenRouter, Mistral, Gemini, or Discord independently. Far fewer should contact several of them while also accessing LSASS, injecting into suspended processes, or creating WMI persistence. For the full behavioral characteristics, see the technical appendix and implementation details.&nbsp;</p><h2 id="looking-ahead-the-autonomy-arc">Looking ahead: The autonomy arc&nbsp;</h2><p>CLOSEDQUORUM is best understood not as a sophisticated piece of malware, but as a demonstration that the architectural shift towards attack-chain automation is coming.&nbsp;&nbsp;</p><p>After deployment, tactical choices are delegated to a model-driven decision loop. The models receive host context, choose among implemented capabilities, provide execution parameters, and continue making decisions without human-issued commands or dedicated C2 tasking. This type of scaffolding approach could easily be translated and applied to other adversary objectives.&nbsp;</p><p>The displacement of human attackers also introduces weaknesses. Provider refusals, rate limits, malformed output, predictable tie-breaking, constrained action schemas, and dependence on commercial APIs all create failure modes and defensive opportunities. Autonomy does not make the implant infallible; it exchanges some human limitations for model and infrastructure limitations.&nbsp;</p><p>Even so, CLOSEDQUORUM demonstrates that removing the operator from a bounded phase of an intrusion is achievable with currently available models and ordinary API access. The important precedent is the demonstration of encoding tactical attack logic as model-readable context, converting structured model output directly into execution.&nbsp;&nbsp;</p><p>CLOSEDQUORUM is an early and limited example, but it makes an emerging threat model concrete and gives defenders an outline of the observable signals they can begin addressing today. As effort displacement expands across more phases of an intrusion, its effects will compound with the speed and scale already afforded by modern AI. The advantage for defenders is that this progression is still only beginning. We have an open window to study this transition, with the aim of developing the detections, controls, and response strategies needed before autonomous operations become more capable and widespread.</p>

  function coverageView() {
    const coverageTable = document.getElementById('coverage-block');
    const sidebar = document.getElementById('side-bar');
    const postContent = document.getElementById('post-content');
    const currentWidth = window.innerWidth;  
  
    if (coverageTable && sidebar && postContent) {
      if (currentWidth < 1000) {
        // For viewport less than 1000px, append to post content
        postContent.appendChild(coverageTable);
      } else {
        // For viewport 1000px and wider, check for subscribe button
        const subscribeButton = sidebar.querySelector('.subscribe-button');
        
        if (subscribeButton) {
          // Insert coverage block after the subscribe button
          subscribeButton.insertAdjacentElement('afterend', coverageTable);
        } else {
          // No subscribe button found, prepend to top of sidebar
          sidebar.prepend(coverageTable);
        }
      }
    }
  }
  
  window.addEventListener("resize", coverageView);
  window.addEventListener("load", coverageView);
