    <div class="text-center m-1">
        <div class="post-author">

            <ul><li>Cisco Talos is&nbsp;disclosing&nbsp;a large-scale automated credential harvesting campaign carried out by a threat cluster&nbsp;we&nbsp;are&nbsp;tracking as “UAT-10608.”&nbsp;</li><li>Post-compromise, UAT-10608 leverages automated scripts for extracting and exfiltrating credentials from a variety of applications, that are then posted to its&nbsp;command and control (C2).&nbsp;</li><li>The C2 hosts a&nbsp;web-based&nbsp;graphical&nbsp;user&nbsp;interface (GUI)&nbsp;titled “NEXUS Listener” that can be used&nbsp;to&nbsp;view stolen information and&nbsp;gain&nbsp;analytical&nbsp;insights&nbsp;using precompiled statistics&nbsp;on credentials harvested and hosts compromised.&nbsp;</li></ul><hr><p>Talos is&nbsp;disclosing&nbsp;a&nbsp;large-scale automated credential harvesting&nbsp;campaign&nbsp;carried out by a threat cluster we currently track as UAT-10608. The campaign is primarily&nbsp;leveraging&nbsp;a collection framework dubbed “NEXUS Listener.”&nbsp;The systematic exploitation and exfiltration campaign has resulted in the&nbsp;compromise of at least&nbsp;766 hosts,&nbsp;as of time of writing,&nbsp;across multiple geographic regions and cloud providers.&nbsp;The operation&nbsp;is targeting&nbsp;Next.js applications vulnerable to React2Shell&nbsp;(CVE-2025-55182)&nbsp;to gain initial access,&nbsp;then&nbsp;is deploying&nbsp;a&nbsp;multi-phase credential harvesting tool&nbsp;that harvests credentials, SSH keys, cloud tokens, and environment secrets at scale.&nbsp;</p><p>The breadth of the victim&nbsp;set&nbsp;and the indiscriminate targeting pattern is consistent with automated scanning —&nbsp;likely&nbsp;based&nbsp;on host profile data from services&nbsp;like&nbsp;Shodan,&nbsp;Censys,&nbsp;or custom scanners to&nbsp;enumerate&nbsp;publicly reachable Next.js deployments and probe them for the described React configuration vulnerabilities.&nbsp;</p><p>The core&nbsp;component&nbsp;of the framework is a web application that makes&nbsp;all of&nbsp;the exfiltrated data available to the operator in a&nbsp;graphical interface that includes&nbsp;in-depth&nbsp;statistics and search capabilities to allow them to sift through the compromised data.&nbsp;</p><p>This post details the campaign's&nbsp;methodology,&nbsp;tools,&nbsp;breadth&nbsp;and sensitivity of the exposed data, and the implications for organizations&nbsp;impacted&nbsp;by this activity.&nbsp;</p><p><em>This analysis is based on data collected for security research purposes.&nbsp;Specific credentials and victim identifiers have been withheld from this publication.</em>&nbsp;<em>Talos has informed service providers of exposed and at-risk credentials</em>&nbsp;<em>and is working with industry partners such as GitHub and AWS to quarantine credentials and inform victims.</em>&nbsp;</p>

<h2 id="initial-access">Initial&nbsp;access&nbsp;</h2><p>UAT-10608 targets public-facing web applications using components,&nbsp;predominately Next.js, that are vulnerable to&nbsp;CVE-2025-55182, broadly referred to as “React2Shell.”&nbsp;</p><p>React2Shell&nbsp;is a pre-authentication remote code execution (RCE) vulnerability in React Server Components (RSC). RSCs&nbsp;expose&nbsp;Server Function endpoints that accept serialized data from&nbsp;clients.&nbsp;The affected code deserializes payloads from inbound HTTP requests to these endpoints&nbsp;without&nbsp;adequate validation or&nbsp;sanitization.&nbsp;</p><h3 id="exploitation-steps">Exploitation&nbsp;steps&nbsp;</h3><ol><li>An attacker&nbsp;identifies&nbsp;a publicly accessible application using a vulnerable version of RSCs or a framework built on top of it (e.g., Next.js).&nbsp;</li><li>The attacker crafts a malicious serialized payload designed to abuse the deserialization&nbsp;routine&nbsp;—&nbsp;a technique commonly used to trigger arbitrary object instantiation or&nbsp;method&nbsp;invocation&nbsp;on the server.&nbsp;</li><li>The payload is sent via an HTTP request directly to a Server Function endpoint. No&nbsp;authentication&nbsp;is&nbsp;required.&nbsp;</li><li>The server deserializes the malicious payload, resulting in arbitrary code execution in the&nbsp;server-side Node.js process.&nbsp;</li></ol><p>Once the&nbsp;threat&nbsp;actor&nbsp;identifies&nbsp;a vulnerable endpoint, the automated toolkit takes over.&nbsp;No further manual interaction is&nbsp;required&nbsp;to extract and exfiltrate credentials harvested from the system.&nbsp;</p><h2 id="automated-harvesting-script">Automated&nbsp;harvesting&nbsp;script&nbsp;</h2><p>Data is collected via&nbsp;nohup-executed shell scripts dropped in&nbsp;/tmp&nbsp;with randomized names:</p>
<!--kg-card-begin: html-->
<pre>
/bin/sh -c nohup sh /tmp/.eba9ee1e4.sh >/dev/null 2>&1

tokens&nbsp;&nbsp;</li><li><strong>docker</strong>&nbsp;-&nbsp;Enumerate&nbsp;container configurations&nbsp;&nbsp;</li><li><strong>cmdline</strong>&nbsp;- List all running process command credentials.</em></i></figcaption></figure><p>The observed NEXUS Listener instances display “v3” in the title,&nbsp;indicating&nbsp;the application has gone through various stages of development before reaching the currently deployed version.</p><h2 id="analysis">Analysis&nbsp;</h2><p>Cisco Talos was able to obtain data from an&nbsp;unauthenticated&nbsp;NEXUS Listener instance. The following is an analysis of that data, broken down by&nbsp;credential&nbsp;category.&nbsp;</p><h3 id="credential-categories">Credential Categories&nbsp;</h3><p><strong>Environment</strong>&nbsp;<strong>secrets and API</strong>&nbsp;<strong>keys</strong>&nbsp;</p><p>The&nbsp;“environ.txt”&nbsp;and&nbsp;“jsenv.txt”&nbsp;files&nbsp;contain&nbsp;the runtime environment of each compromised application process, exposing a&nbsp;variety of third-party API credentials:&nbsp;</p><ul><li>AI platform keys: OpenAI, Anthropic, NVIDIA NIM,&nbsp;OpenRouter,&nbsp;Tavily&nbsp;</li><li>Payment processors: Stripe live secret keys (sk_live_*)&nbsp;</li><li>Cloud providers: AWS access key/secret pairs, Azure subscription credentials&nbsp;</li><li>Communication platforms: SendGrid, Brevo/Sendinblue&nbsp;transactional email API keys, Telegram bot tokens and webhook secrets&nbsp;</li><li>Source control: GitHub personal access tokens, GitLab tokens&nbsp;</li><li>Database connection strings: Full&nbsp;DATABASE_URL&nbsp;values including hostnames, ports, usernames, and cleartext passwords&nbsp;</li><li>Custom application secrets: Auth tokens, dashboard passwords, webhook signing secrets — often high-entropy hex or&nbsp;Base64 strings&nbsp;</li></ul><p><strong>SSH</strong>&nbsp;<strong>private</strong>&nbsp;<strong>keys</strong>&nbsp;</p><p>Present&nbsp;in 78% of hosts, the&nbsp;“ssh.txt”&nbsp;files&nbsp;contain&nbsp;complete PEM-encoded private keys (both ED25519 and RSA formats) along with&nbsp;authorized_keys&nbsp;entries. These keys enable lateral movement to any other system that trusts the compromised host's key identity — a particularly severe finding for organizations with shared key infrastructure or bastion-host architectures.&nbsp;</p><p><strong>Cloud</strong>&nbsp;<strong>credential</strong>&nbsp;<strong>harvesting</strong>&nbsp;</p><p>The&nbsp;“aws_full.txt”&nbsp;and&nbsp;“cloud_meta.txt”&nbsp;phases attempt to query the AWS Instance Metadata Service (IMDS), GCP metadata server, and Azure IMDS. For cloud-hosted targets, successful retrieval yields IAM role-associated temporary credentials — credentials that carry whatever permissions were granted to the instance role, which in misconfigured environments can include S3 bucket access, EC2 control plane operations, or secrets manager read access.&nbsp;</p><p><strong>Kubernetes</strong>&nbsp;<strong>service</strong>&nbsp;<strong>account</strong>&nbsp;<strong>tokens</strong>&nbsp;</p><p>The&nbsp;“k8s.txt”&nbsp;phase targets containerized workloads,&nbsp;attempting&nbsp;to read the default service account token mounted at&nbsp;/var/run/secrets/kubernetes.io/serviceaccount/token. A compromised Kubernetes token can allow an attacker to&nbsp;enumerate&nbsp;cluster resources, read secrets from other namespaces, or escalate to cluster-admin depending on RBAC configuration.&nbsp;</p><p><strong>Docker</strong>&nbsp;<strong>container</strong>&nbsp;<strong>intelligence</strong>&nbsp;</p><p>For hosts running Docker (approximately 6% of the dataset), the&nbsp;“docker.txt”&nbsp;phase&nbsp;enumerates&nbsp;all running containers, their images, exposed ports, network configurations, mount points, and environment variables. Notable services&nbsp;observed&nbsp;include phpMyAdmin instances, n8n workflow automation, and internal administrative dashboards — all of which are high-value targets for follow-on access.&nbsp;</p><p><strong>Shell</strong>&nbsp;<strong>command</strong>&nbsp;<strong>history</strong>&nbsp;</p><p>Command history files reveal operator behavior on compromised systems and&nbsp;other information that could be useful for&nbsp;post-compromise&nbsp;activity. Observed patterns include:&nbsp;</p><ul><li>MySQL client invocations with explicit credentials:&nbsp;mysql&nbsp;-u root -p&nbsp;</li><li>Database service management:&nbsp;/etc/init.d/mysqld&nbsp;restart</li></ul><h2 id="implications">Implications&nbsp;</h2><ul><li><strong>Credential</strong>&nbsp;<strong>compromise and</strong>&nbsp;<strong>account</strong>&nbsp;<strong>takeover:</strong>&nbsp;Every credential in this dataset should be considered fully compromised. Live Stripe secret keys enable fraudulent charges and refund manipulation. AWS keys with broad IAM permissions enable cloud infrastructure takeover, data exfiltration from S3, and lateral movement within AWS&nbsp;organizations. Database connection strings with cleartext passwords provide direct access to application data stores&nbsp;containing&nbsp;user&nbsp;personally identifiable information (PII), financial records, or proprietary data.&nbsp;</li><li><strong>Lateral</strong>&nbsp;<strong>movement via SSH:</strong>&nbsp;The large corpus of exposed SSH private keys creates a persistent lateral movement risk that survives the rotation of application credentials. If any of these keys are reused across systems (a common operational practice), the attacker&nbsp;retains&nbsp;access to those systems even after the&nbsp;initial&nbsp;compromise is detected and remediated.&nbsp;</li><li><strong>Supply</strong>&nbsp;<strong>chain</strong>&nbsp;<strong>risk:</strong>&nbsp;Several hosts show evidence of package registry authentication files (“pkgauth.txt”), including&nbsp;npm&nbsp;and pip configuration with registry credentials. Compromised package registry tokens could enable a supply chain attack — publishing malicious versions of packages under a legitimate maintainer's identity.&nbsp;</li><li><strong>Data</strong>&nbsp;<strong>aggregation and</strong>&nbsp;<strong>intelligence</strong>&nbsp;<strong>value:</strong>&nbsp;Beyond the immediate operational value of individual credentials, the aggregate dataset&nbsp;represents&nbsp;a detailed map of the victim organizations' infrastructure: what services they run, how&nbsp;they're&nbsp;configured, what cloud providers they use, and what third-party integrations are in place. This intelligence has significant value for crafting targeted follow-on attacks, social engineering campaigns, or selling access to other threat actors.&nbsp;</li><li><strong>Reputational and</strong>&nbsp;<strong>regulatory</strong>&nbsp;<strong>exposure:</strong>&nbsp;For any&nbsp;organization&nbsp;whose data appears in this set, there are serious compliance implications. Database credentials exposing PII trigger&nbsp;breach&nbsp;notification requirements under GDPR, CCPA, and sector-specific regulations. Organizations that process payments whose Stripe keys are exposed face PCI DSS incident response obligations. The exposure of AI platform API keys can result in significant unauthorized usage charges in addition to the security risk.&nbsp;</li></ul><h2 id="recommendations">Recommendations&nbsp;</h2><ol><li><strong>Audit&nbsp;getServerSideProps&nbsp;and&nbsp;getStaticProps&nbsp;implementations:</strong>&nbsp;Ensure no secrets or server-only environment variables are passed as props to client components.&nbsp;</li><li><strong>Enforce NEXT_PUBLIC_ prefix discipline:</strong>&nbsp;Only variables that are intentionally public should carry this prefix. Audit all variables for misclassification.&nbsp;</li><li><strong>Rotate all credentials&nbsp;immediately</strong>&nbsp;if any overlap with the described victim profile is suspected.&nbsp;</li><li><strong>Implement IMDSv2 enforcement</strong>&nbsp;on all AWS EC2 instances to require session-oriented metadata queries, blocking unauthenticated metadata service abuse.&nbsp;</li><li><strong>Segment SSH keys:</strong>&nbsp;Avoid reusing SSH key pairs across different systems or environments.&nbsp;</li><li><strong>Enable cloud provider secret scanning:</strong>&nbsp;AWS, GitHub, and others offer native secret scanning that can detect and alert on committed or exposed credentials.&nbsp;</li><li><strong>Deploy runtime application self-protection (RASP)</strong>&nbsp;or a WAF rule set tuned for Next.js-specific attack patterns, particularly those targeting SSR data injection points.&nbsp;</li><li><strong>Audit container environments</strong>&nbsp;for least-privilege.&nbsp;Application containers should not have access to the host SSH&nbsp;agent,&nbsp;host filesystem mounts&nbsp;containing&nbsp;sensitive data, or overly permissive IAM instance roles.&nbsp;</li></ol><h2 id="coverage">Coverage&nbsp;</h2><p>SNORT®&nbsp;ID for CVE-2025-55182, aka React2Shell:&nbsp;65554&nbsp;</p><h2 id="indicators-of-compromise-iocs">Indicators of compromise (IOCs)&nbsp;</h2><p>Organizations should investigate for the following artifacts on web application hosts:&nbsp;</p><ul><li>Unexpected processes spawned from /tmp/ with randomized dot-prefixed names (e.g., /tmp/.e40e7da0c.sh)&nbsp;</li><li>nohup&nbsp;invocations in process listings not associated with known application workflows&nbsp;</li><li>Unusual outbound HTTP/S connections from application containers to non-production endpoints&nbsp;</li><li>Evidence of __NEXT_DATA__&nbsp;containing&nbsp;server-side secrets in&nbsp;rendered&nbsp;HTML&nbsp;</li></ul><p>IOCs for this threat also available on our GitHub repository <a href="https://github.com/Cisco-Talos/IOCs/tree/main/2026/04" rel="noreferrer">here</a>.</p>
