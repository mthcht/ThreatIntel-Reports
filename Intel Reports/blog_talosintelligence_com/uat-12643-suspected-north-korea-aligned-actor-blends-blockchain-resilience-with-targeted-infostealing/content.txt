    <h1 class="text-center">UAT-12643: Suspected North Korea-aligned actor blends blockchain resilience with targeted infostealing</h1>

    <div class="text-center m-1">
        <div class="post-author">
            <span>By </span>
                <a href="https://blog.talosintelligence.com/author/chetan/">Chetan Raghuprasad</a>

    <section class="post-content-wrapper mt-5">
        <div class="post-content" id="post-content">
            <ul><li>Cisco Talos discovered malicious infrastructure associated with a financially motivated threat group we are tracking as UAT-12643.&nbsp;</li><li>The actor’s arsenal has several payloads including the Go-based Overlord remote access trojan (RAT), a Python-based infostealer internally labelled “Good Game,” and a multi-cryptocurrency clipboard hijacker.&nbsp;</li><li>The threat actor is likely operating a campaign targeting cryptocurrency holders, gaming platform account owners, and VoIP software users based on the lure file names of the initial vectors and the payloads.&nbsp;</li><li>The Overlord RAT implements a command-and-control (C2) resilience technique in which encrypted server URLs are embedded in Solana blockchain transaction memos.</li></ul><hr><h2 id="victimology">Victimology&nbsp;&nbsp;&nbsp;</h2><p>The threat actor is potentially targeting victims in Europe, according to the payload’s keyword-based file harvesting capability, which specifically targeted documents that had file names in English, French, Spanish, and Portuguese.&nbsp;&nbsp;</p><p>Based on the lure themes and payload file names, the potential victim pool spans across multiple verticals. A lure financial statement decoy PDF — launched when the Good Game stealer is executed — indicates targeting finance and accounting staff. The Viber trojanized installer lure targets messaging platform users, while additional payload variants of files named microsip indicate targeting VoIP softphone operators, consistent with call-center or business telephone environments. Cryptocurrency and gaming users are also targeted by both the clipboard hijacker and the infostealer.&nbsp;&nbsp;</p><h2 id="potential-links-to-north-korea-aligned-actors">Potential links to North Korea-aligned actors&nbsp;</h2><p>Talos assesses with low confidence that UAT-12643 is a North Korea-aligned advanced persistent threat (APT) actor based on overlaps in tactics, techniques, and procedures (TTPs) with those of the other known North Korean APT actors.&nbsp;&nbsp;</p><p>In the current campaign, Talos observed that the actor is using the Overlord RAT as one of their payloads. The threat cluster called UNK_DeadDrop, likely a North Korean threat actor, had employed the Overlord RAT in their earlier campaigns as reported by the security researchers in <a href="https://www.proofpoint.com/us/blog/threat-insight/dont-fear-repo-unkdeaddrop-phishing-campaign-targets-developers-steal" rel="noreferrer noopener"><u>June 2026</u></a>.&nbsp;&nbsp;</p><p>The Overlord RAT variant observed in this campaign implements a blockchain C2 resilience technique with Solana blockchain transactions. This technique was first reported in <a href="https://intel.breakglass.tech/post/lazarus-group-is-using-the-solana-blockchain-as-a-dead-drop-c2-channel-and-nobody-noticed-for-4-months" rel="noreferrer noopener"><u>March 2026</u></a>, employed by the Lazarus APT group. Although the implementation methodology differs (earlier, it was through Node.js), the technique of leveraging Solana transaction memo stayed consistent.&nbsp;&nbsp;</p><p>Talos is aware that Overlord RAT and Solana blockchain hosting technique is also leveraged by other threat actors in their campaigns, as reported by external security researchers in <a href="https://thehackernews.com/2026/10/eight-malicious-npm-packages-downloaded.html" rel="noreferrer noopener"><u>October 2026</u></a>. &nbsp;</p><h2 id="threat-actor-infrastructure">Threat actor infrastructure&nbsp;</h2><p>Talos observed that the actor hosted the malicious files on a server with IP address “41[.]216[.]188[.]11”, running a Flask-based file delivery service on port 8000 with resumable byte-range download support, and serving the payload staging directory. Due to the actor’s operational security failure, the server’s root folder was exposed to the internet, and Talos’ analysis of the exposed folder showed us actor’s tool sets, and the port numbers configured on the C2 server for different services.&nbsp;&nbsp;</p>

Sample malicious MSBuild project XML file.&nbsp;</span></figcaption></figure><h2 id="analysis-of-overlord-rat">Analysis of Overlord RAT&nbsp;</h2><p>The Overlord RAT variant utilized by UAT-12643 in this campaign is a modular Windows RAT compiled from Go source code.&nbsp;</p><p>The defense evasion and anti-analysis techniques implemented include the detection of in-memory execution to suppress forensic artifacts when running in sandboxes and a “kill flag” mechanism that triggers a kernel-level Blue Screen of Death (BSoD), making the process effectively unremovable without triggering a full system crash.&nbsp;&nbsp;</p><p>The RAT first verifies that the current process is running with administrative privilege. It then acquires SeDebugPrivilege for the current process. With that privilege held, it calls a native NT kernel API (NtSetInformationProcess) directly, bypassing the documented Win32 API layer entirely, to set the ProcessBreakOnTermination information class on the current process handle to value 1, which indicates the kernel will handle the process as critical to system operation. With these settings, the operating system treats the process the same way as the core Windows system processes. When a user or a security tool attempt to forcibly terminate the process, the kernel does not allow it to exit cleanly. Instead, it immediately halts the entire operating system and triggers a BSoD with the stop code CRITICAL_PROCESS_DIED.&nbsp;&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/11/BSoD-screen-shot.png" class="kg-image" alt="" loading="lazy" width="2000" height="1359" srcset="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w600/2026/11/BSoD-screen-shot.png 600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w1000/2026/11/BSoD-screen-shot.png 1000w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w1600/2026/11/BSoD-screen-shot.png 1600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/11/BSoD-screen-shot.png 2202w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 6. Snippet of Overlord RAT function that triggers BSoD.</span></figcaption></figure><p>For persistence, the RAT employs two approaches. The primary approach is through a registry autorun entry under the current user's hive, with a randomized value name pointing to the RAT binary located in the Network folder of the local user profile application data folder. The secondary approach is a pre-boot persistence via the Windows Recovery Environment OEM script path. It first removes any previous version of itself and then sets up the OEM environment directly under %TARGETOSDRIVE%\Recovery\OEM\. This folder is the location that the Windows Recovery Environment accesses when performing a "Reset this PC" operation. By placing files here, anything registered in this directory gets executed inside WinRE before the operating system is restored.&nbsp;</p><p>Once the directory is set, the RAT generates a random 20-character file name for its payload file. Each character is picked individually at random from a fixed character set, meaning every installation produces a uniquely named file. With a random name chosen, it writes the RAT's own executable binary into the OEM directory as that payload file.&nbsp;&nbsp;It then constructs the shell command that WinRE will use to launch the payload and wraps it into Windows batch script with the .bat extension.&nbsp;</p>

<p>The use of %TARGETOSDRIVE% is significant, as this environment variable only exists and resolves correctly inside the WinRE pre-boot environment, not in normal Windows. This means the command is specifically crafted to work at recovery time, not during a regular session.&nbsp;&nbsp;</p><p>Before modifying any system configuration, it backs up the existing WinRE reset configuration file. Finally, it modifies the ResetConfig.xml file that governs what WinRE does during a reset. If no config file exists yet, it creates one from scratch; if one already exists, it patches it to append the malicious batch scripts as registered OEM tasks. <p></p><p>The second filter is a keyword allowlist of four languages English, French, Spanish, and Portuguese that must match the file's base name exactly. The keyword list is designed to maximize overlap with the types of sensitive documents that cryptocurrency users, online gamers, and financially active individuals are likely to store on their desktops or in their documents folders. It covers two-factor authentication backup codes, mnemonic seed phrases, cryptocurrency wallet application names, generic password file naming conventions, banking and payment terms, private key and recovery phrase labels, Discord authentication tokens, Telegram session identifiers, and generic high-value labels such as secret, vault, backup, admin, and root.&nbsp;&nbsp;</p><p>Files that satisfy both the extension and keyword filters are written into the archive in the temporary directory, with each file name suffixed by a randomly generated four-digit number before the extension.&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/11/stealer_files.png" class="kg-image" alt="" loading="lazy" width="2000" height="3448" srcset="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w600/2026/11/stealer_files.png 600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w1000/2026/11/stealer_files.png 1000w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w1600/2026/11/stealer_files.png 1600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w2400/2026/11/stealer_files.png 2400w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 11. Targeted files search and exfiltration program for Good Game stealer.&nbsp;</span></figcaption></figure><h3 id="data-exfiltration-mechanism-of-good-game-stealer">Data exfiltration mechanism of Good Game stealer&nbsp;</h3><p>All harvested data is written progressively into a single ZIP file. The ZIP file object is opened with ZIP_DEFLATED compression in the system temporary directory. The archive file name uses the prefix “SK_”, followed by eight randomly generated characters, creating a unique identifier per victim and making the archive harder to identify by name alone.&nbsp;&nbsp;</p><p>The ZIP is structured into named subdirectories such as Screenshot/, Webcam/, Session Files/Wallets/, Session Files/Game Launchers/, Session Files/Apps/Telegram/, and Interesting Files/ alongside flat files in the root for system information and antivirus enumeration results. Browser-derived outputs are labelled with a count suffix such as Passwords (N).txt, where N reflects the number of credentials recovered from that browser, enabling the actor to prioritize.&nbsp;</p><p>Once all stealer modules have been completed, the closed archive is uploaded to <em>hxxps[:]//upload[.]gofile[.]io/uploadFile</em> using an HTTP POST request. The server returns a JSON response containing a direct download link to the uploaded archive.&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/11/upload.png" class="kg-image" alt="" loading="lazy" width="2000" height="638" srcset="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w600/2026/11/upload.png 600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w1000/2026/11/upload.png 1000w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w1600/2026/11/upload.png 1600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/11/upload.png 2114w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 12. Snippet of Good Game stealer exfiltration function.</span></figcaption></figure><p>With the GoFile download URL in hand, the stealer constructs a Discord webhook notification and POSTs it to the hardcoded webhook endpoint. The notification takes the form of a Discord message containing the victim's hostname, username, machine architecture, operating system version, and OS release label providing the operator with an immediate preview of the victim's machine profile without needing to download the archive first. After the webhook POST completes, the stealer calls its cleanup routine to delete the local ZIP archive and all temporary intermediate files including the screenshot PNG and webcam PNG from the temporary directory.&nbsp;</p><figure class="kg-card kg-image-card kg-card-hascaption"><img src="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/11/Webhook.png" class="kg-image" alt="" loading="lazy" width="2000" height="2077" srcset="https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w600/2026/11/Webhook.png 600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w1000/2026/11/Webhook.png 1000w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/size/w1600/2026/11/Webhook.png 1600w, https://storage.ghost.io/c/af/a0/afa04ee3-414f-4481-8d23-7e7c146f192e/content/images/2026/11/Webhook.png 2290w" sizes="(min-width: 720px) 720px"><figcaption><span style="white-space: pre-wrap;">Figure 13. Snippet of Good Game that POSTs reconnaissance data to Discord Webhook.&nbsp;</span></figcaption></figure><h2 id="clipboard-hijacker-targets-multi-cryptocurrency-wallet-addresses">Clipboard hijacker targets multi-cryptocurrency wallet addresses&nbsp;</h2><p>The clipboard hijacker Talos identified in the actor’s toolset is a compact Windows x64 executable written in C++. It has no network component or C2 communication protocol; instead, the actor configuration is compiled directly into the binary as XOR-encrypted wallet addresses in the binary data section.&nbsp;&nbsp;</p><p>Upon execution, the binary dynamically resolves the API function addresses and creates a global mutex “UuuRjinBZPBMIjnc”. Then it retrieves the machine name and searches for the substrings including VBOX, VMWARE, QEMU, and SANDBOX. Persistence is established by copying the binary to %APPDATA%\MsgEdgeUpdate.exe with FILE_ATTRIBUTE_HIDDEN and FILE_ATTRIBUTE_SYSTEM attributes applied, then adding it under user hive’s Run registry key with value named “MsgEdgeUpdate”, spoofing the appearance of a legitimate Microsoft Edge updater process.&nbsp;</p><p>The hijacker polls the Windows clipboard every 500 milliseconds in an infinite loop, applying address-format fingerprinting to detect the copied cryptocurrency. All clipboard APIs are resolved dynamically through user32.dll. On detection, the corresponding attacker wallet address is XOR-decrypted from the data section and overwrites the original wallet address in the victim machine clipboard.&nbsp;&nbsp;</p><h2 id="coverage">Coverage&nbsp;</h2><p>The following ClamAV signatures detect and block this threat:&nbsp;&nbsp;</p><ul><li>Win.Trojan.OverlordRAT-10060615-0&nbsp;</li><li>Ps1.Trojan.LNKBuilder-10060627-0&nbsp;</li><li>Win.Trojan.OverlordRAT2-10060616-0&nbsp;</li><li>Win.Infostealer.GoodGame-10060617-0&nbsp;</li><li>Win.Infostealer.PyStealerDeps-10060618-0&nbsp;</li><li>Py.Infostealer.GoodGame-10060619-0&nbsp;</li><li>Py.Trojan.GoodGameLoader-10060620-0&nbsp;</li><li>Win.Trojan.WalletClipper-10060621-0&nbsp;</li><li>Win.Downloader.LNKMpCmdRun-10060622-0&nbsp;</li><li>Win.Downloader.LNKCertutil-10060623-0&nbsp;</li><li>Win.Trojan.LNKVideosExe-10060624-0&nbsp;</li><li>Html.Downloader.HTAStager-10060656-1&nbsp;</li><li>Xml.Downloader.MSBuildInline2-10060657-0&nbsp;</li></ul><p>The following Snort2 and Snort3 Snort Rules (SIDs) detect and block this threat:&nbsp;</p><ul><li>Snort2: 1:67491, 1:67490&nbsp;</li><li>Snort3: 7:75, 7:74&nbsp;</li></ul><h2 id="indicators-of-compromise-iocs">Indicators of compromise (IOCs)&nbsp;</h2><p>IOCs for this research can be found at our GitHub repository <a href="https://github.com/Cisco-Talos/IOCs/tree/main/2026/11" rel="noreferrer noopener"><u>here</u></a>.&nbsp;</p>
