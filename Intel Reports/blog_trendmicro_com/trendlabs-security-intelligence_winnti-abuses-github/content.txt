	<h1 class="article-details__title">Winnti Abuses GitHub for C&amp;C Communications</h1>
	<p class="article-details__description">The Winnti group, a threat actor with a past of traditional cybercrime — particularly with financial fraud, has been seen abusing GitHub by turning it into a conduit for the C&amp;C communications of their seemingly new backdoor. </p>
	<p class="article-details__author-by">By: Trend Micro
		
			<time class="article-details__date">Mar 22, 2017</time>
		
		
		<span>Read time:&nbsp;</span><span class="eta"></span> (<span class="words"></span> words)

		<div>
			<p><b><i>With additional analysis from Cyber Safety Solutions Team</i></b></p>
<p>Developers constantly need to modify and rework their source codes when releasing new versions of applications or coding projects they create and maintain. This is what makes GitHub—an online repository hosting service that provides version control management—popular. In many ways, it’s like a social networking site for programmers and developers, one that provides a valuable platform for code management, sharing, collaboration, and integration.</p>
<p>GitHub is no stranger to misuse, however. Open-source <a href="https://www.trendmicro.com/en_us/research/16/h/new-open-source-ransomwar-based-on-hidden-tear-and-eda2-may-target-businesses.html">ransomware projects EDA2 and Hidden Tear</a>—supposedly created for educational purposes—were hosted on GitHub, and have since spawned various offshoots that have been found targeting enterprises. Tools that <a href="http://blog.trendmicro.com/trendlabs-security-intelligence/another-challenge-iot-open-backdoors/" target="_blank">exploited vulnerabilities in Internet of Things (IoT) devices</a> were also made available on GitHub. Even the <a href="http://blog.trendmicro.com/trendlabs-security-intelligence/not-limitless-trend-micro-ftr-assists-arrest-limitless-author/" target="_blank">Limitless Keylogger</a>, which was used in targeted attacks, was linked to a GitHub project.</p>
<p>Recently, the Winnti group, a threat actor with a past of traditional cybercrime -particularly with financial fraud, has been seen abusing GitHub by turning it into a conduit for the command and control (C&amp;C) communications of their seemingly new backdoor (detected by Trend Micro as BKDR64_WINNTI.ONM).</p>
<p>Our research also showed that the group still uses some of the infamous PlugX malware variants—a staple in Winnti’s arsenal—to handle targeted attack operations via the GitHub account we identified.</p>
<p><i><b>Malware Analysis</b></i></p>
<p>The malware we analyzed is separated in two files: a loader, and the payload.</p>
<p>The loader, named <i>loadperf.dll</i>, is a modified version of its legitimate, similarly named counterpart—a Microsoft file which helps manipulate the performance registry. An extra component has been added to its sections. It copies itself on <i>%WINDIR%\system32\wbem\</i> and replaces the original DLL. It leverages the WMI performance adapter service (wmiAPSrv), a legitimate file in Windows that collects information related to system performance, to import the loader via <i>services.exe</i>. The system also imports all related DLL files and includes the payload “loadoerf.ini”. The infection chain includes an additional (albeit empty) function imported from <i>loadoerf.ini</i>, <i>gzwrite64</i>, which works as a fake Application Program Interface (API) that serves as the payload’s entry point. Although <i>gzwrite64</i> is imported by <i>loadperf.dll</i>, the payload’s main function is actually located in the <i>DLLMain</i> of “loadoerf.ini”.</p>
<p style="text-align: center;"><a href="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2017/03/winnti-github-1.png"><img src="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2017/03/winnti-github-1.png"/></a><i>Figure 1: Extra section .idata added to the original loadperf.dll</i></p>
<p style="text-align: center;"><a href="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2017/03/winnti-github-2.png"><img src="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2017/03/winnti-github-2.png"/></a><br />
<i style="">Figure 2: Extra imported function gzwrite64</i></p>
<p>The payload is a file named <i>loadoerf.ini</i> that contains decryption, run, and code injection functions. When it is loaded by the system, <i>DLLMain</i> decrypts the payload via <i>CryptUnprotectData</i>. Since the function highly depends on the actual “machine ID”, decryption on another machine that isn’t the original infected host is not viable, making malware analysis more difficult.</p>
<p style="text-align: center;"><a href="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2017/03/winnti-github-3.png"><img src="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2017/03/winnti-github-3.png"/></a><i>Figure 3: Part of the decryption function used in the payload</i></p>
<p>After decryption, partial code is run on the machine, which is then injected to <i>svchost.exe</i> (a key Windows component); payload is then loaded into memory.</p>
<p style="text-align: center;"><a href="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2017/03/winnti-github-4.png"><img src="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2017/03/winnti-github-4.png"/></a><i>Figure 4: Execution/infection flow of loadoerf.ini</i></p>
<p>How is GitHub abused? Upon successful infection, the malware starts communicating with an HTML page from a repository stored in a GitHub project.</p>
<p style="text-align: center;"><a href="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2017/03/winnti-github-5.png"><img src="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2017/03/winnti-github-5.png"/></a><i>Figure 5: GitHub account hosting an HTML page used for C&amp;C communication</i></p>
<p>Any malware threat analyst will immediately recognize Line 3 in the image above as a potential PlugX-encrypted line. The beginning and end markers, DZKS and DZJS, are <a href="https://airbus-cyber-security.com/plugx-some-uncovered-points/" target="_blank">typical</a> in PlugX. A closer look, however, shows that the decryption algorithm is different from PlugX. In this case, decrypting them reveals references to its actual command and control (C&amp;C) server: an IP address and a port number the malware will connect to.</p>
<p>Winnti currently uses different encryption algorithms to store those C&amp;C references in the files they stored on Github. Among them is an algorithm utilized by PlugX. In fact, we found references to PlugX in the C&amp;C strings we analyzed, indicating that the group may also be using the same backdoor in this particular campaign. Although we were unable to find a PlugX sample through that particular GitHub, we surmise some PlugX variants in the wild use this GitHub repository to get their C&amp;C information.</p>
<p>Nearly all the other algorithms used in this GitHub campaign are derived from the original PlugX algorithm:</p>
<ul>
<li><span class="rte-red-bullet">PlugX style + shift string + Base64</span></li>
<li><span class="rte-red-bullet">PlugX style + shift string + Base64 + XOR</span></li>
<li><span class="rte-red-bullet">PlugX style + Base64 + XOR</span></li>
</ul>
<p>One algorithm is also built in mark strings + shift string + Base64 encoding.</p>
<p><i><b>Following Winnti's Trails</b></i></p>
<p>The GitHub account used by the threat actor was created in May 2016. It created one legitimate project/repository (<i>mobile-phone-project</i>) in June 2016, derived from another generic GitHub page.</p>
<p>The repository for Winnti’s C&amp;C communications was created on August 2016. We surmise that the GitHub account was not compromised, and instead created by Winnti. By March 2017, the repository already contained 14 different HTML pages created at various times.</p>
<p><i><b>Timeline of the Campaign</b></i></p>
<p>We mapped Winnti’s activities for this campaign by analyzing the dates exposed in GitHub. For each file, GitHub stores first-and-last commit timestamps; these enabled us to create a timeline of the first use of the group’s many C&amp;C servers.</p>
<p>We monitored the period during which IP addresses were found connecting to Winnti’s C&amp;C servers and found that they started their operations in the afternoon up to late evening. The timetable resembles traditional working hours for cybercriminals, compared to those with less structure who prefer starting their days late, but also working until very late hours. In fact, we only observed one instance of activity during the weekend, where a new HTML file was created.</p>
<p>The earliest activity we tracked on the GitHub account was from August 17, 2016, with the most recent in March 12, 2017.</p>
<p>Here is a timeline of when the C&amp;C server’s IP addresses were first used, based on our monitoring:</p>
<p style="text-align: center;"><a href="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2017/03/winnti-github-6.png"><img src="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2017/03/winnti-github-6.png"/></a><i>Figure 6: Timeline of the C&amp;C server’s IP addresses</i></p>
<p><i><b>C&amp;C Servers</b></i></p>
<p>The GitHub account used by Winnti shows 12 different IP addresses, with various port numbers used for them. All communication to these C&amp;C servers are done on three different port numbers: 53 (DNS), 80 (HTTP), and 443 (HTTPS). These are typical techniques PlugX and Winnti malware variants use to communicate between compromised machines and their C&amp;C servers. Nearly all the C&amp;C servers are hosted in the U.S., while two are located in Japan.</p>

<p><i><b>Conclusion</b></i></p>
<p>Abusing popular platforms like GitHub enables threat actors like Winnti to maintain network persistence between compromised computers and their servers, while staying under the radar. Although Winnti may still be employing traditional malware, its use of a relatively unique tactic to stay ahead of the threat landscape’s curve reflects the <a href="https://www.trendmicro.com/vinfo/tmr/?/us/security/research-and-analysis/predictions/2017">increased sophistication that threat actors are projected to employ</a>.</p>
