		<div>
			<p>We have been detecting a new wave of network attacks since early March, which, for now, are targeting Japan, Korea, China, Taiwan, and Hong Kong. The attacks use Domain Name System (DNS) cache poisoning/DNS spoofing, possibly through <a href="http://blog.trendmicro.co.jp/archives/17181">infringement techniques</a> such as brute-force or dictionary attacks, to distribute and install malicious Android apps. Trend Micro detects these as ANDROIDOS_XLOADER.HRX.</p>
<p>These malware pose as legitimate Facebook or <a href="http://blog.trendmicro.co.jp/archives/17170">Chrome</a> applications. They are distributed from polluted DNS domains that send a notification to an unknowing victim’s device. The malicious apps can steal personally identifiable and financial data and install additional apps. XLoader can also hijack the infected device (i.e., send SMSs) and sports self-protection/persistence mechanisms through device administrator privileges.</p>
<p style="text-align: center;"><a href="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2018/04/xloader-android-dns-spoofing-1.jpg"><img src="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2018/04/xloader-android-dns-spoofing-1.jpg"/></a></p>
<p style="text-align: center;">Figure 1. Screenshot of the fake Facebook and Chrome apps (highlighted) <a href="//blog.trendmicro.com/trendlabs-security-intelligence/files/2018/04/xloader-android-dns-spoofing-2.jpg"><img src="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2018/04/xloader-android-dns-spoofing-2.jpg"/></a> Figure 2. XLoader’s infection chain</p>
<p><b><span class="body-subhead-title">Infection Chain</span></b></p>
<p>As with our <a href="http://blog.trendmicro.co.jp/archives/17170">earlier</a> <a href="http://blog.trendmicro.co.jp/archives/17181">reports</a> in late March, the attack chain involves diverting internet traffic to attacker-specified domains by compromising and overwriting the router’s DNS settings. A fake alert will notify and urge the user to access the malicious domain and download XLoader.</p>
<p style="text-align: center;"><a href="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2018/04/xloader-android-dns-spoofing-3.png"><img src="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2018/04/xloader-android-dns-spoofing-3.png"/></a>Figure 3. Screenshot of the fake notification on a spoofed/poisoned domain</p>
<p><b><span class="body-subhead-title">Technical Analysis</span></b></p>
<p>XLoader first loads the encrypted payload from <i>Assets/db</i> as <i>test.dex</i> to drop the necessary modules then requests for device administrator privileges. Once granted permission, it hides its icon from the launcher application list then starts a service that it keeps running in the background. The background service uses the <a href="https://blog.trendmicro.com/trendlabs-security-intelligence/mobile-ransomware-protect/">reflection</a> technique (a <a href="http://www.oracle.com/technetwork/articles/java/javareflection-1536171.html">feature</a> that allows the inspection and modification of Java-based programs’ internal properties) to invoke the method <i>com.Loader.start</i> in the payload.</p>
<p style="text-align: center;"><a href="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2018/04/xloader-android-dns-spoofing-4.png"><img src="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2018/04/xloader-android-dns-spoofing-4.png"/></a>Figure 4. Code snippet showing the main malicious module invoked via the reflection technique</p>
<p><b><span class="body-subhead-title">Monitoring Broadcast Events</span></b></p>
<p>XLoader registers many broadcast receivers in the payload dynamically (to monitor <a href="https://developer.android.com/guide/components/broadcasts.html">broadcast events</a> sent between system and applications). Registering broadcast receivers enable XLoader to trigger its malicious routines. Here is a list of broadcast actions:</p>
<ul>
<li><span class="rte-red-bullet">android.provider.Telephony.SMS_RECEIVED</span></li>
<li><span class="rte-red-bullet">android.net.conn.CONNECTIVITY_CHANGE</span></li>
<li><span class="rte-red-bullet">android.intent.action.BATTERY_CHANGED</span></li>
<li><span class="rte-red-bullet">android.intent.action.USER_PRESENT</span></li>
<li><span class="rte-red-bullet">android.intent.action.PHONE_STATE</span></li>
<li><span class="rte-red-bullet">android.net.wifi.SCAN_RESULTS</span></li>
<li><span class="rte-red-bullet">android.intent.action.PACKAGE_ADDED</span></li>
<li><span class="rte-red-bullet">android.intent.action.PACKAGE_REMOVED</span></li>
<li><span class="rte-red-bullet">android.intent.action.SCREEN_OFF</span></li>
<li><span class="rte-red-bullet">android.intent.action.SCREEN_ON</span></li>
<li><span class="rte-red-bullet">android.media.RINGER_MODE_CHANGED</span></li>
<li><span class="rte-red-bullet">android.sms.msg.action.SMS_SEND</span></li>
<li><span class="rte-red-bullet">android.sms.msg.action.SMS_DELIVERED</span></li>
</ul>
<p> </p>
<p><b><span class="body-subhead-title">Creating a Web Server to Phish</span></b></p>
<p>XLoader creates a provisional web server to receive the broadcast events. It can also create a simple HTTP server on the infected device to deceive victims. It shows a web <a href="https://www.trendmicro.com/vinfo/us/security/news/cybercrime-and-digital-threats/best-practices-identifying-and-mitigating-phishing-attacks">phishing</a> page whenever the affected device receives a broadcast event (i.e., if a new package is installed or if the device’s screen is on) to steal personal data, such as those keyed in for banking apps. The phishing page is translated in Korean, Japanese, Chinese, and English, which are hardcoded in the payload. It will appear differently to users depending on the language set on the device.</p>
<p style="text-align: center;"><a href="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2018/04/xloader-android-dns-spoofing-5.png"><img src="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2018/04/xloader-android-dns-spoofing-5.png"/></a>Figure 5. Screenshot of the phishing page (in Japanese)</p>
<p><b><span class="body-subhead-title">XLoader as Spyware and Banking Trojan</span></b></p>
<p>XLoader can also collect information related to usage of apps installed in the device. Its data-stealing capabilities include collecting SMSs after receiving an SMS-related broadcast event and covertly recording phone calls. XLoader can also hijack accounts linked to financial or game-related apps installed on the affected device.</p>
<p style="text-align: center;"><a href="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2018/04/xloader-android-dns-spoofing-6.png"><img src="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2018/04/xloader-android-dns-spoofing-6.png"/></a>Figure 6. Code Snippet showing how XLoader records phone calls</p>
<p>XLoader can also start other attacker-specified packages. A possible attack scenario involves replacing legitimate apps with repackaged or malicious versions. By monitoring the package installation broadcast event, XLoader can start their packages. This enables it to launch malicious apps without the user’s awareness and explicit consent.</p>
<p>We reverse engineered XLoader and found that it appears to target South Korea-based banks and <a href="https://blog.trendmicro.com/trendlabs-security-intelligence/selling-online-gaming-currency-makes-way-attacks-enterprises/">game development companies</a>. XLoader also prevents victims from accessing the device’s settings or using a known antivirus (AV) app in the country.</p>
<p>XLoader can also load multiple malicious modules to receive and execute commands from its remote command-and-control (C&amp;C) server, as shown below:</p>
<p style="text-align: center;"><a href="//blog.trendmicro.com/trendlabs-security-intelligence/files/2018/04/xloader-android-dns-spoofing-7.png"><img src="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2018/04/xloader-android-dns-spoofing-7.png"/></a></p>
<p style="text-align: center;">Figure 7. Screenshot showing XLoader’s malicious modules</p>
<p>Here’s a list of the modules and their functions:</p>
<ul>
<li><span class="rte-red-bullet"><i>sendSms </i>— send SMS/MMS to a specified address</span></li>
<li><span class="rte-red-bullet"><i>setWifi </i>— enable or disable Wi-Fi connection</span></li>
<li><span class="rte-red-bullet"><i>gcont </i>— collect all the device’s contacts</span></li>
<li><span class="rte-red-bullet"><i>lock </i>— currently just an input lock status in the settings (<i>pref</i>) file, but may be used as a screenlocking ransomware</span></li>
<li><span class="rte-red-bullet"><i>bc </i>— collect all contacts from the Android device and SIM card</span></li>
<li><span class="rte-red-bullet"><i>setForward </i>— currently not implemented, but can be used to hijack the infected device</span></li>
<li><span class="rte-red-bullet"><i>getForward </i>— currently not implemented, but can be used to hijack the infected device</span></li>
<li><span class="rte-red-bullet"><i>hasPkg </i>— check the device whether a specified app is installed or not</span></li>
<li><span class="rte-red-bullet"><i>setRingerMode </i>— set the device’s ringer mode</span></li>
<li><span class="rte-red-bullet"><i>setRecEnable </i>— set the device’s ringer mode as silent</span></li>
<li><span class="rte-red-bullet"><i>reqState </i>— get a detailed phone connection status, which includes activated network and Wi-Fi (with or without password)</span></li>
<li><span class="rte-red-bullet"><i>showHome </i>— force the device’s back to the home screen</span></li>
<li><span class="rte-red-bullet"><i>getnpki</i>: get files/content from the folder named NPKI (contains certificates related to financial transactions)</span></li>
<li><span class="rte-red-bullet"><i>http </i>— access a specified network using <a href="https://developer.android.com/reference/java/net/HttpURLConnection.html"><i>HttpURLConnection</i></a></span></li>
<li><span class="rte-red-bullet"><i>onRecordAction </i>— simulate a number-dialed tone</span></li>
<li><span class="rte-red-bullet"><i>call </i>— call a specified number</span></li>
<li><span class="rte-red-bullet"><i>get_apps </i>— get all the apps installed on the device</span></li>
<li><span class="rte-red-bullet"><i>show_fs_float_window </i>— show a full-screen window for phishing</span></li>
</ul>
<p> </p>
<p>Of note is XLoader’s abuse of the <a href="https://tools.ietf.org/html/rfc6455">WebSocket protocol</a> (supported in many browsers and web applications) via <i>ws(WebSockets)</i> or <i>wss(WebSockets over SSL/TLS)</i> to communicate with its C&amp;C servers. The URLs  — abused as part of XLoader’s C&amp;C — are hidden in three webpages, and the C&amp;C server that  XLoader connects to differ per region.</p>
<p>The abuse of the WebSocket protocol provides XLoader with a persistent connection between clients and servers where data can be transported any time. XLoader abuses the MessagePack (a data interchange format) to package the stolen data and exfiltrate it via the WebSocket protocol for faster and more efficient transmission.</p>
<p style="text-align: center;"><a href="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2018/04/xloader-android-dns-spoofing-8.png"><img src="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2018/04/xloader-android-dns-spoofing-8.png"/></a>Figure 8. Screenshot showing one of the web pages with hidden C&amp;C-related URL</p>
<p style="text-align: center;"><a href="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2018/04/xloader-android-dns-spoofing-9.png"><img src="/content/dam/trendmicro/global/en/migrated/security-intelligence-migration-spreadsheet/trendlabs-security-intelligence/2018/04/xloader-android-dns-spoofing-9.png"/></a>Figure 9. Code snippet showing how XLoader parses the C&amp;C URL</p>
<p><b><span class="body-subhead-title">Mitigations</span></b></p>
<p>XLoader will not download malicious apps if the Android device uses a mobile data connection. Nevertheless, users should practice proper <a href="https://www.trendmicro.com/vinfo/us/security/news/internet-of-things/securing-routers-against-mirai-home-network-attacks">security hygiene</a> to mitigate threats that may take advantage of a home or business router’s security gaps. Employ stronger credentials, for instance, to make them less susceptible to unauthorized access. Regularly update and patch the router’s software and firmware to prevent exploits, and enable its built-in firewall.</p>
<p>For system administrators and information security professionals, configuring the router to be more resistant to attacks like <a href="https://www.trendmicro.com/vinfo/us/security/news/cybercrime-and-digital-threats/infosec-guide-defending-against-man-in-the-middle-attacks">DNS cache poisoning</a> can help mitigate similar threats. Everyday users can do the same by <a href="http://sitesafety.trendmicro.com/">checking</a> the router’s DNS settings if they’ve been modified. Even threats like DNS cache poisoning employ social engineering, so users should also be more <a href="https://www.trendmicro.com/vinfo/us/security/news/mobile-safety/best-practices-securing-your-mobile-device">prudent</a> against suspicious or unknown messages that have telltale signs of malware.</p>
<p>We have worked with Google and they ensure that <a href="https://www.android.com/play-protect/">Google Play Protect</a> proactively catches apps of this nature. No instances of these apps were found in Google Play.</p>
