── SUMMARY ──────────────────────────────────────────────────

Shai-Hulud is a self-propagating supply chain worm targeting developer
workstations and CI/CD runners. Operated by TeamPCP (Carnage APT), the
worm steals NPM tokens, GitHub PATs, AWS credentials across 17 regions,
Kubernetes service account tokens, and cloud provider secrets. Stolen
data is exfiltrated via dynamically created attacker-controlled GitHub
repositories. The worm poisons the NPM supply chain by publishing
malicious tarballs with forged Sigstore provenance using stolen tokens.

A destructive persistence mechanism (deadman switch) wipes the victim
host if a stolen GitHub token is revoked during incident response.

── INITIAL DISCOVERY ────────────────────────────────────────

Worm sample received 2026-05-13 04:20 UTC. Persistence mechanism
identified at 04:45 UTC. Full campaign reversal complete 10:35 UTC.
Total active analysis window: 6 hours 15 minutes.

The campaign predates this disclosure — Shai-Hulud Wave 1 was first
identified September 2025. Wave 2 emerged November 2025. The May 2026
wave (Mini Shai-Hulud) expanded to 172 npm and PyPI packages including
TanStack, Mistral AI, UiPath, OpenSearch, and Guardrails AI ecosystems.

── PROPAGATION METHOD ───────────────────────────────────────

Three dropper variants (bash, Python, Node/config.mjs) download and
install the Bun JavaScript runtime from oven-sh/bun or the attacker
C2 domain git-tanstack.com. Entry points: ai_init.js, router_runtime.js,
setup.mjs, config.mjs.

The worm installs via npm preinstall hooks in poisoned packages. In CI/CD
environments, the May 2026 wave used a pull_request_target workflow
misconfiguration to poison GitHub Actions cache, then extracted OIDC
tokens directly from runner process memory (/proc/<pid>/mem) to publish
malicious package versions without stealing npm credentials directly.

Sigstore provenance bundles are forged (application/vnd.dev.sigstore.bundle.v0.3+json)
to make malicious releases appear to have valid SLSA provenance.

Stolen data is committed to attacker-created GitHub repositories using
the beacon string IfYouRevokeThisTokenItWillWipeTheComputerOfTheOwner
embedded in file contents, enabling the attacker to locate their own
exfiltration repos via GitHub code search.

── PERSISTENCE MECHANISM ────────────────────────────────────

The worm installs a background daemon named gh-token-monitor on both
macOS and Linux.

Files dropped:
  ~/.local/bin/gh-token-monitor.sh
  ~/.config/gh-token-monitor/token    (stolen GitHub PAT)
  ~/.config/gh-token-monitor/handler  (destructive payload)

macOS persistence:
  ~/Library/LaunchAgents/com.user.gh-token-monitor.plist

Linux persistence:
  ~/.config/systemd/user/gh-token-monitor.service

VSCode persistence:
  .vscode/tasks.json with runOn: folderOpen triggers setup.mjs

Claude Code persistence (distinct finding):
  .claude/settings.json SessionStart hook executes setup.mjs
  on every AI agent session start. This is separate from
  ~/.claude.json token scraping documented in other reports.

── DEADMAN SWITCH ───────────────────────────────────────────

gh-token-monitor polls https://api.github.com/user every 60 seconds
using the stolen GitHub PAT. If the token is revoked (HTTP 4xx response),
the daemon executes the handler payload: rm -rf ~/

This destroys the victim home directory if standard incident response
(immediate token rotation) is performed before the persistence mechanism
is defused. This is a deliberate counter-IR measure, not a bug.

Trigger conditions: 401 Unauthorized, 403 Forbidden, 404 Not Found

CRITICAL REMEDIATION ORDER: Defuse persistence before revoking tokens.
Vaccine script: https://github.com/breakingcircuits1337/Shai-Hulud-Carnage-APT-Report/blob/main/shaihuld-remediate.sh
