    <h1 id="regretlocker">RegretLocker</h1>

<h2 id="summary">Summary</h2>

<p><strong><em>RegretLocker</em></strong> is a new ransomware that has been found in the wild in the last month that does not only encrypt normal files on disk like other ransomwares. When running, it will particularly search for <strong><em>VHD</em></strong> files, mount them using <strong><em>Windows Virtual Storage API</em></strong>, and then encrypt all the files it finds inside of those <strong><em>VHD</em></strong> files.</p>

<p>Typically, <strong><em>VHD</em></strong> files are huge in size with a max size of nearly 2TB because it’s mainly ussed to store the contents of a hard disk of a VM which includes disk particitions and file systems. This makes it unrealistic for ransomware to waste time encrypting simply because it’s too big.</p>

<p>However, through mounting these virtual disks as physical disks, <strong><em>RegretLocker</em></strong> can go through and encrypt the individual files inside, which significantly increases encryption speed overall.</p>

<p>For encryption, <strong><em>RegretLocker</em></strong> reaches out to the C&amp;C server for a <strong><em>RSA</em></strong> key in order to encrypt and produce a unique <strong><em>AES</em></strong> key. This <strong><em>AES</em></strong> key will be used to encrypt all of the files on the disks. However, if the machine is offline or it can’t reach C&amp;C, it will just uses the hard-coded <strong><em>RSA</em></strong> key in memory, which makes it simple to write a decryption tool for!</p>

<p>All of the encrypted files have the extension <strong><em>.mouse</em></strong>.</p>

<p>Huge shout-outs to <a href="https://twitter.com/VK_Intel">Vitali Kremez</a> and <a href="https://twitter.com/malwrhunterteam">MalwareHunterTeam</a> for bringing this ransomware to my attention!</p>

<p><img src="/uploads/RegretLocker.png" alt="alt text"></p>

<h2 id="iocs">IOCS</h2>

<p><strong><em>RegretLocker</em></strong> comes in the form of a 32-bit PE file.</p>

<p><strong><em>MD5</em></strong>: 3265b2b0afc6d2ad0bdd55af8edb9b37</p>

<p><strong><em>SHA256</em></strong>: a188e147ba147455ce5e3a6eb8ac1a46bdd58588de7af53d4ad542c6986491f4</p>

<p><img src="/uploads/VT_result.PNG" alt="alt text"></p>

<h2 id="dependencies">Dependencies</h2>

<p><strong><em>Advapi32.dll and Crypt32.dll</em></strong>: Main crypto functionalities such as RSA and AES encryption</p>

<p><strong><em>VirtDisk.dll</em></strong>: Mounting virtual disk functionalities</p>

<p><strong><em>tor-lib.dll</em></strong>: DLL dropped by <strong><em>RegretLocker</em></strong> that is used to contact C&amp;C through Tor</p>

<h2 id="networking">Networking</h2>

<p><strong><em>RegretLocker</em></strong> contacts the C&amp;C server at <strong><em>http://regretzjibibtcgb.onion/input</em></strong> through Tor 3 times:</p>

<div class="language-plaintext highlighter-rouge"><div class="highlight"><pre class="highlight"><code>- Retrieve RSA key from server
- Sending information such as the computer's IP, name, volume of the disks,..
- Signalling when it finishes encrypting
</code></pre></div></div>

<p>Before contacting C&amp;C, it sends a GET request to <strong><em>http://api.ipify.org/</em></strong> to retrieve the PC’s public IP address. If this fails, the malware can assume that it’s running offline and will use the hard-coded RSA key.</p>

<h2 id="ransom-note">Ransom Note</h2>

<p><strong><em>RegretLocker</em></strong> drops a ransom note in every folder that it encrypts. This is the content if you run the malware with Internet connection. The hash is used to identify which RSA key is used to generate the AES key on your machine.</p>

<p><img src="/uploads/RegretLockerRansomnote.PNG" alt="alt text"></p>

<p>You can find malware log <a href="/uploads/locker.log">here</a> on my Github</p>

<h2 id="code-analysis">Code Analysis</h2>

<h3 id="only-one-process-running">Only One Process Running</h3>

<p><strong><em>RegretLocker</em></strong> first check if there is only one version of itself running by looping through all of the running processes using <strong><em>CreateToolhelp32Snapshot, Process32First, and Process32Next</em></strong>.</p>

<p>For each of the running processes, it compares the name against its own name to make sure that there is no process with the same name.</p>

<p>If there is one with the same name, the ransomware exits immediately.</p>

<p><img src="/uploads/RegretLocker1.png" alt="alt text"></p>

<h3 id="dropping-tor-libdll">Dropping tor-lib.dll</h3>

<p>The malware extracts the path to the current directory it is located in through <strong><em>GetModuleFileNameA</em></strong> and concats <strong><em>”\tor-lib.dll”</em></strong> to it, which means that it drops this dll in the same directory of the malware.</p>

<p><img src="/uploads/RegretLocker2.png" alt="alt text"></p>

<p>It then calls a function to extract the dll from its resource section through <strong><em>FindResourceA, LoadResource, and LockResource</em></strong>. As we can see in <strong><em>Resource Hacker</em></strong>, the dll is stored unencrypted in the resource section. After extracting the dll, it calls <strong><em>LoadLibrary</em></strong> to get a handle to the dll. This handle will be used for the malware to contact C&amp;C.</p>

<p><img src="/uploads/RegretLocker3.png" alt="alt text"></p>

<h3 id="development-check">Development Check</h3>

<p>The malware writter has 2 weird checks to check for a particular user name and PC name(<strong><em>WIN-295748OMAKG</em></strong>). If the user name or the PC name matches, the malware will exit immediately.</p>

<p>This is potentially just a check against the development PC to make sure that the ransomware does not try to encrypt the machine during development.</p>

<p>As a developer myself, I’m disappointed by this unprofessionalism <img class="emoji" title=":disappointed:" alt=":disappointed:" src="https://github.githubassets.com/images/icons/emoji/unicode/1f61e.png" height="20" width="20">. Clean up your damn code please!</p>

<p><img src="/uploads/RegretLocker4.png" alt="alt text"></p>

<h3 id="persistence">Persistence</h3>

<p>For persistence, the malware set the registry <strong><em>SOFTWARE\Microsoft\Windows\CurrentVersion\Run</em></strong> to the path of the malware. This ensures that the malware is automatically run every time the user logs into the machine.</p>

<p><img src="/uploads/RegretLocker5.png" alt="alt text"></p>

<p>Next, it also schedules the malware as a task every minite using this <strong><em>Schtasks.exe</em></strong> command, which is run from <strong><em>cmd.exe</em></strong> using <strong><em>ShellExecuteA</em></strong>.</p>

<div class="language-plaintext highlighter-rouge"><div class="highlight"><pre class="highlight"><code>  schtasks /Create /SC MINUTE /TN "Mouse Application" /TR "RegretLocker_path" /f
</code></pre></div></div>

<p><img src="/uploads/RegretLocker6.png" alt="alt text"></p>

<h3 id="encryption-setup">Encryption Setup</h3>

<p>The malware builds and executes this command from <strong><em>cmd.exe</em></strong>.</p>

<div class="language-plaintext highlighter-rouge"><div class="highlight"><pre class="highlight"><code>  cmd.exe /C wmic SHADOWCOPY DELETE &amp; wbadmin DELETE SYSTEMSTATEBACKUP &amp; bcdedit.exe / set{ default } bootstatuspolicy ignoreallfailures &amp; bcdedit.exe / set{ default } recoveryenabled No
</code></pre></div></div>

<ul>
  <li>
<strong><em>wmic SHADOWCOPY DELETE</em></strong>: This will delete all of the shadow copies of the files on the system, preventing the encrypted files to be reverted to their previous state.</li>
  <li>
<strong><em>wbadmin DELETE SYSTEMSTATEBACKUP</em></strong>: Delete system backup. Preventing the system to go back to a previous snapshot</li>
  <li>
<strong><em>bcdedit.exe / set{ default } bootstatuspolicy ignoreallfailures</em></strong>: Set the boot status policy to ignore errors during a failed boot. Make sure the PC does not fail over to Windows recovery or reboot.</li>
  <li>
<strong><em>bcdedit.exe / set{ default } recoveryenabled No</em></strong>: Make sure the system can’t be recovered.</li>
</ul>

<p>Next, it loops through all the drives and add the name of those with the drive type <strong><em>DRIVE_FIXED, DRIVE_REMOVABLE, or DRIVE_REMOTE</em></strong>.</p>

<p><img src="/uploads/RegretLocker7.png" alt="alt text"></p>

<p>These names are mounted to the C drive using <strong><em>GetVolumePathNamesForVolumeNameA, SetVolumeMountPointA, FindFirstVolumeA, and FindNextVolumeA</em></strong>. Since this function name is labeled as <em>show_hided_drives()</em>, this function just probably mounts all the valid drives so it won’t miss any hidden drive.</p>

<p><img src="/uploads/RegretLocker8.png" alt="alt text"></p>

<h3 id="retrieving-rsa-key">Retrieving RSA key</h3>

<p>As discussed above, the malware will first reach out to C&amp;C at <strong><em>http://regretzjibibtcgb.onion/input</em></strong> with <strong><em>get_key</em></strong> in the query to request the RSA key.</p>

<p><img src="/uploads/RegretLocker9.png" alt="alt text"></p>

<p>The global variable <strong><em>RSA_KEY</em></strong> will be written accordingly with the RSA key depending on if it can reach the C&amp;C or not. If it can’t, it will use this hard-coded RSA key.</p>

<div class="language-plaintext highlighter-rouge"><div class="highlight"><pre class="highlight"><code>-----BEGIN PUBLIC KEY-----
MIGfMA0GCSqGSIb3DQEBAQUAA4GNADCBiQKBgQC1ZQInrnhxXCtAN/LsOX2GmgbvBxMsO49lc1/qodshkUvRQLazWv61UbMLKx2gaRQrCYuVrR1Cgd7LxY4ueGo50TqZioAJbCcfzdiXlEkJqLlz4RTU9RFZ/wFjWxChek2NsU6vLLSowPPTw+JhwTooI+QPAIYeoxCf4xz7Kvu9CQIDAQAB
-----END PUBLIC KEY-----
</code></pre></div></div>

<h3 id="generating-aes-key">Generating AES key</h3>

<p>Using the RSA key, it will call <strong><em>CryptAcquireContextA, CryptDecodeObjectEx, CryptImportPublicKeyInfo, and CryptEncrypt</em></strong> to encrypt the “AES” buffer in memory, generating a new AES key</p>

<p><img src="/uploads/RegretLocker14.png" alt="alt text"></p>

<p>With this method, the malware can generate a different AES key as long as it’s receiving a different RSA key from C&amp;C. However, this AES key is constant after this encryption if the malware is run offline, so it should be straightforward to produce a decrypting tool if either C&amp;C is down or the PC is not connected to the Internet.</p>

<h3 id="encryption---usb-drives">Encryption - USB Drives</h3>

<p>The first encryption happens to USB drives, if there are any. This function is called to retrieve the name of all the USB drives by checking for any drive with <strong><em>DRIVE_REMOVABLE</em></strong> type.
This function was pretty similar of the one previously used in <em>show_hided_drives()</em>.</p>

<p><img src="/uploads/RegretLocker10.png" alt="alt text"></p>

<p>Next, it loops through all of these USB drives and call a function to encrypt its content. I label this as <em>small_encrypt()</em> because it is used to encrypt USB drives and small files only.</p>

<p><img src="/uploads/RegretLocker11.png" alt="alt text"></p>

<p>I will dive into these encryption functions later because there are a few different version to cover.</p>

<h3 id="encryption---smb-scanner">Encryption - SMB Scanner</h3>

<p>The malware is written in C++, and there is a class called <strong><em>smb_scanner</em></strong>. The SMB function tries SMB scanning to find</p>
<ul>
  <li>Adapter names and address ranges on the adapter</li>
  <li>NetServers’s IP addresses and machine names on the server using <strong><em>NetServerEnum</em></strong>.</li>
</ul>

<p><img src="/uploads/RegretLocker12.png" alt="alt text"></p>

<p>The result value is a buffer of all the SMB folders in string form.</p>

<p>Then, it goes through a while loop calling a function to encrypt these SMB folders, so I label this encryption function as <em>smb_encrypt()</em>. I actually have not set up SMB on my virtual machine, so when I ran this, I did not know if it could actually encrypt SMB folders or not…</p>

<p><img src="/uploads/RegretLocker13.png" alt="alt text"></p>

<h3 id="encryption---large-files">Encryption - Large Files</h3>

<p>The malware has a specific method of looking for large files and then begins to encrypt them right after the SMB encryption.</p>

<p><img src="/uploads/RegretLocker15.png" alt="alt text"></p>

<p>The malware author called this encryting function <em>encrypt_large_file()</em>, so I just went along with it. Seems like it’s the same as most of the other encrypting functions except that it has extra stuff to account for the file size. The core of this function still boils down to an AES encryption.</p>

<p><img src="/uploads/RegretLocker16.png" alt="alt text"></p>

<p>After the encryption, it will rename the encrypted file to the same name but with the extension <strong><em>.mouse</em></strong> and overwrite the file buffer with this newly encrypted buffer.</p>

<h3 id="encryption---everything-else">Encryption - Everything Else</h3>

<p>After the large file encryption, <strong><em>RegretLocker</em></strong> goes into a while loop to encrypt everything else with <em>small_encrypt()</em>.</p>

<p><img src="/uploads/RegretLocker17.PNG" alt="alt text"></p>

<p><em>small_encrypt()</em> calls a wrapper function to navigate around directories and files before encrypting them. It specifically looks out for these to avoid encrypting them.</p>

<ul>
  <li><strong><em>RegretLocker file</em></strong></li>
  <li><strong><em>.log</em></strong></li>
  <li><strong><em>HOW TO RESTORE FILES.TXT</em></strong></li>
  <li><strong><em>Windows folder</em></strong></li>
  <li><strong><em>ProgramData</em></strong></li>
  <li><strong><em>Microsoft</em></strong></li>
  <li><strong><em>System</em></strong></li>
</ul>

<p>Next, it checks the file type. If the file type is FILE_ATTRIBUTE_DIRECTORY, it will calls a recursive encrypting function to recursively go through every layer inside the folder. If the file type is not a folder, it will simply call the main encrypting function to encrypt it.</p>

<p><img src="/uploads/RegretLocker18.png" alt="alt text"></p>

<p>Inside of the recursive encrypting function, <strong><em>RegretLocker</em></strong> specifically looks for these file names to avoid encrypting them.</p>

<ul>
  <li><strong><em>Cheat</em></strong></li>
  <li><strong><em>Notepad</em></strong></li>
  <li><strong><em>x96dbg</em></strong></li>
  <li><strong><em>Hex Editor</em></strong></li>
  <li><strong><em>tor-lib.dll</em></strong></li>
  <li><strong><em>.mouse</em></strong></li>
</ul>

<p>Since the drives are mounted, <strong><em>RegretLocker</em></strong> checks the file extension for <strong><em>“.vhd”</em></strong> in order to detect any virtual drive. If found, it will call a function to open the virtual drive to start encrypting everything inside by recursively calling back to the recursive function. The ransomware uses a series of calls to <strong><em>OpenVirtualDisk, AttachVirtualDisk, GetVirtualDiskPhysicalPath, FindFirstVolumeW, CreateFileW, DeviceIoControl, GetVolumePathNamesForVolumeNameW, and FindNextVolumeW</em></strong> to retrieve a list of file and folder names inside.</p>

<p><img src="/uploads/RegretLocker19.png" alt="alt text"></p>

<p>If the file is not a folder, it will just call the main encrypting function to encrypt it.</p>

<p>This function is divided into 2 condition blocks. If the file size is greater than 104857600 bytes or around 105MB, the file is counted as a large file and will be encrypted with the <em>encrypt_large_file()</em> function. If it’s not, then <strong><em>RegretLocker</em></strong> proceeds to encrypt it using AES.</p>

<p><img src="/uploads/RegretLocker20.PNG" alt="alt text"></p>

<p>There is a catch here. If the encryption fails, it means the file is running or used by some process. For that case, <strong><em>RegretLocker</em></strong> will find the process that is currently using this file and attempt to terminate it. It’s accomplishing this through the use of <strong><em>Restart Manager</em></strong> with these API calls.</p>

<ul>
  <li>
<strong><em>RmStartSession</em></strong>: Start a new session for <strong><em>Restart Manager</em></strong>
</li>
  <li>
<strong><em>RmRegisterResources</em></strong>: Registering the file to be encrypted as a resource</li>
  <li>
<strong><em>RmGetList</em></strong>: Get the list of application of services/processes that are using this resource</li>
  <li>
<strong><em>CreateToolhelp32Snapshot, Process32FirstW, and Process32NextW</em></strong>: Check all running processes for their ID, comparing with the processes above</li>
</ul>

<p><img src="/uploads/RegretLocker21.PNG" alt="alt text"></p>

<p>After getting the processes that are using the file, it checks for the name. If they match any of these, they will not be added to the list and closed later.</p>

<ul>
  <li><strong><em>vnc</em></strong></li>
  <li><strong><em>ssh</em></strong></li>
  <li><strong><em>mstsc</em></strong></li>
  <li><strong><em>System</em></strong></li>
  <li><strong><em>svchost.exe</em></strong></li>
</ul>

<p><img src="/uploads/RegretLocker22.png" alt="alt text"></p>

<p><strong><em>RegretLocker</em></strong> then builds the command string <code class="language-plaintext highlighter-rouge">taskkill /F /IM \process_name</code> and runs it with <strong><em>cmd.exe</em></strong>. This command basically just filters out the process with the given process name and terminates it.</p>

<p>The ransomware will continuously loop until it successfully closes the process. Then it will attempt the encryption again.</p>

<h3 id="encryption---aes">Encryption - AES</h3>

<p>The core of the encrypting functions above are this one AES encrypting function. It basically just uses the generated AES key to encrypt the file with a series of calls to <strong><em>CryptAcquireContextA, CryptImportKey, CryptSetKeyParam, and CryptEncrypt</em></strong>, which is fairly standard.</p>

<p>After the encryption, it will write this encrypted buffer back into the file with the new file extension <strong><em>.mouse</em></strong>. It will also check the folder path to see if it has created the file <strong><em>HOW TO RESTORE FILES.TXT</em></strong> already and created one if it has not.</p>

<p><img src="/uploads/RegretLocker23.PNG" alt="alt text"></p>
