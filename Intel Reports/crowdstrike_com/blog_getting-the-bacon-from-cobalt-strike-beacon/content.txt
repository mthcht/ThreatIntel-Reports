">nation-state adversaries</span></a><span style="	font-weight: 400;
"> to conduct their operations following the initial access to victims’ environments.<p> </p></span>

<span style="	font-weight: 400;
">Cobalt Strike is a commercially available post-exploitation framework developed for adversary simulations and </span><a href="/en-us/epp-101/red-team-vs-blue-team/"><span style="	font-weight: 400;
">red team operations</span></a><span style="	font-weight: 400;
"> and features an easy-to-use interface. Although the vendor uses processes and technology measures in an effort to limit distribution of Cobalt Strike to security professionals, adversaries have also been observed using Cobalt Strike. In the <a href="/en-us/resources/reports/threat-hunting-report-2020/">CrowdStrike 2020 Threat Hunting Report</a></span><span style="	font-weight: 400;
">, The Falcon OverWatch team reported Cobalt Strike as the #2 most common </span><a href="/en-us/epp-101/penetration-testing/"><span style="	font-weight: 400;
">penetration testing</span></a><span style="	font-weight: 400;
"> tool observed in the first half of 2020.</span>

<span style="	font-weight: 400;
">A common feature used by adversaries is the Cobalt Strike framework client agent, known as Beacon. The Beacon client agent is executed in the memory space of a compromised system, typically leaving minimal on-disk footprints. This blog discusses CrowdStrike’s research and testing of Cobalt Strike’s Beacon in an isolated Active Directory domain to identify host-based indicators generated from the use of this tool.</span>

<span style="	font-weight: 400;
">This blog also enumerates and provides an explanation of host-based artifacts generated as a result of executing specific built-in Beacon commands. The artifacts can be used to create detection and prevention signatures in Windows environments, aiding in the positive identification of remnants of Beacon execution.</span>
<h2><span style="	font-weight: 400;
">Beacon Behavior Summary</span></h2>
<span style="	font-weight: 400;
">Adversaries often execute a variety of Beacon commands once they establish a foothold within an environment. Beacon commands can be used to spawn other Beacons on additional systems accessible to the initial Beacon, effectively furthering persistence in the target environment. Beacons can also be leveraged for remote access and execution.<p> </p></span>
<ul><li style="	font-weight: 400;
"><span style="	font-weight: 400;
">The execution of the commands highlighted in this blog will generate a variety of Windows security events depending on the context of the command: The Beacon commands </span><code><span style="	font-weight: 400;
">jump psexec</span></code><span style="	font-weight: 400;
"> and </span><code><span style="	font-weight: 400;
">jump psexec_psh</span></code><span style="	font-weight: 400;
"> will generate an EID 7045 (Service Installation) from </span><code><span style="	font-weight: 400;
">System.evtx</span></code><span style="	font-weight: 400;
">.</span></li><li style="	font-weight: 400;
"><span style="	font-weight: 400;
">The additional commands will generate an EID 400 event log<p> </p> (PowerShell Engine Startup) from </span><span style="	font-weight: 400;
">Windows <code>PowerShell.evtx</code></span><span style="	font-weight: 400;
">.</span></li></ul>
<span style="	font-weight: 400;
">The majority of PowerShell Engine Startup events generated by Cobalt Strike will have the </span><code><span style="	font-weight: 400;
">HostApplication</span></code><span style="	font-weight: 400;
"> field begin with a command prefix. With the default configuration that command prefix is </span><code><span style="	font-weight: 400;
">powershell -nop -exec -bypass -EncodedCommand</span></code><span style="	font-weight: 400;
">. Although this prefix is configurable, CrowdStrike has observed adversaries leverage the default configuration in multiple incident response (IR) engagements.</span>
<h2><span style="	font-weight: 400;
">Beacon Commands</span></h2>
<span style="	font-weight: 400;
">As part of our research, CrowdStrike Services evaluated the following Beacon commands, which are encountered frequently in incident response engagements:</span>
<ul><li style="	font-weight: 400;
"><span style="	font-weight: 400;
">powershell and powershell-import</span></li><li style="	font-weight: 400;
"><span style="	font-weight: 400;
">powerpick</span></li><li style="	font-weight: 400;
"><span style="	font-weight: 400;

">remote-exec wmi</span></li><li style="	font-weight: 400;
"><span style="	font-weight: 400;
">remote-exec powershell</span></li></ul>
<span style="	font-weight: 400;
">In the following sections we’ll review the purpose behind each of these commands, and the artifacts generated that may be useful for security analysts and threat hunters.</span>
<h3><span style="	font-weight: 400;
">The </span><code><span style="	font-weight: 400;
">powershell</span></code><span style="	font-weight: 400;

">powershell-import</span></code> <span style="	font-weight: 400;

<span style="	font-weight: 400;

The </span><code><span style="	font-weight: 400;
">powershell-import</span></code><span style="	font-weight: 400;

">HostApplication</span></code><span style="	font-weight: 400;
"> field. The generated event is not affected by the usage of any of the PowerShell-related Beacon commands.</span><span style="	font-weight: 400;
"><p> </p></span>
<h4><span style="	font-weight: 400;
">Observations of </span><code><span style="	font-weight: 400;
">jump winrm</span></code><span style="	font-weight: 400;
"> on the compromised system:</span></h4>
<ul><li style="	font-weight: 400;
"><span style="	font-weight: 400;
">The </span><code><span style="	font-weight: 400;
">HostApplication</span></code><span style="	font-weight: 400;
"> field is set to </span><code><span style="	font-weight: 400;
">powershell -nop -exec -bypass -EncodedCommand &lt;base64-encoded-command&gt;</span></code></li><li style="	font-weight: 400;
">The base64 encoded command decodes to <code>IEX (New-Object Net.Webclient).DownloadString(‘http://127.0.0.1:&lt;ephemeral-port-number&gt;/’)</code></li></ul>
<div class="wp-caption" id="attachment_26952"><a href="/content/dam/crowdstrike/www/en-us/wp/2020/09/Figure-7a.png" target="_blank" rel="noopener noreferrer"><img class="size-full wp-image-26952" src="/content/dam/crowdstrike/www/en-us/wp/2020/09/Figure-7a-1.png" alt="" width="1114" height="740"/></a> Figure 7. Artifact generated by the <code>jump winrm</code> Beacon command when executed, on the compromised system (click image to enlarge)</div>

<span style="	font-weight: 400;
">An example of the observed artifact as shown in Figure 7:</span>
<div class="blog-post-code-wrapper">

<code><span style="	font-weight: 400;
">HostApplication&#61;powershell -nop -exec bypass -EncodedCommand SQBFAFgAIAAoAE4AZQB3AC0ATwBiAGoAZQBjAHQAIABOAGUAdAAuAFcAZQBiAGMAbABpAGUAbgB0ACkALgBEAG8AdwBuAGwAbwBhAGQAUwB0AHIAaQBuAGcAKAAnAGgAdAB0AHAAOgAvAC8AMQAyADcALgAwAC4AMAAuADEAOgAyADgAMwA0ADUALwAnACkA</span></code><code><span style="	font-weight: 400;
">Decoded Base64 Command: IEX (New-Object Net.Webclient).DownloadString(&#39;http://127.0.0.1:28345/&#39;)</span></code>

</div>
<span style="	font-weight: 400;
">If a WinRM listener is not present on the remote system when the </span><code><span style="	font-weight: 400;
">jump winrm</span></code><span style="	font-weight: 400;
"> command is executed, Cobalt Strike will create an EID 400 event log on the remote system, as shown in Figure 7.</span>
<h4><span style="	font-weight: 400;
">Observations of an event created by </span><code><span style="	font-weight: 400;
">jump winrm</span></code><span style="	font-weight: 400;
"> on the remote system:</span></h4>
<ul><li style="	font-weight: 400;
"><span style="	font-weight: 400;
">The </span><code><span style="	font-weight: 400;
">HostApplication</span></code><span style="	font-weight: 400;
"> field is set to </span><code><span style="	font-weight: 400;
">&lt;path-to-PS-executable&gt; -Version &lt;PS-Version&gt; -s -NoLogo -NoProfile</span></code></li></ul>
<div class="wp-caption" id="attachment_26953"><a href="/content/dam/crowdstrike/www/en-us/wp/2020/09/Figure-8a.png" target="_blank" rel="noopener noreferrer"><img class="size-full wp-image-26953" src="/content/dam/crowdstrike/www/en-us/wp/2020/09/Figure-8a-1.png" alt="" width="1210" height="687"/></a> Figure 8. Artifact generated by the <code>jump winrm</code> Beacon command when executed on the remote system (click image to enlarge)</div>

<span style="	font-weight: 400;
"><p> </p>An example of the observed artifact as shown in Figure 8:</span>
<div class="blog-post-code-wrapper">

<code><span style="	font-weight: 400;
">HostApplication&#61;c:\windows\syswow64\windowspowershell\v1.0\powershell.exe -Version 5.1 -s -NoLogo -NoProfile</span></code>

</div>
<h3><span style="	font-weight: 400;
">The </span><code><span style="	font-weight: 400;
">remote-exec wmi</span></code><span style="	font-weight: 400;
"> Command</span><span style="	font-weight: 400;
"><p> </p></span></h3>
<span style="	font-weight: 400;
">The </span><code><span style="	font-weight: 400;
">remote-exec wmi</span></code><span style="	font-weight: 400;
"> Beacon command executes a command on a remote system via WMI. When the </span><span style="	font-weight: 400;
"><code>remote-exec wmi</code> </span><span style="	font-weight: 400;
">command is executed, the filesystem will generate an EID 400 event log (PowerShell Engine Startup) on the compromised system with the standard Cobalt Strike PowerShell command prefix in the </span><code><span style="	font-weight: 400;
">HostApplication</span></code><span style="	font-weight: 400;
"> field.</span>
<h4><span style="	font-weight: 400;
">Observations of </span><code><span style="	font-weight: 400;
">remote-exec wmi</span></code><span style="	font-weight: 400;
">:</span></h4>
<ul><li style="	font-weight: 400;
"><span style="	font-weight: 400;
">The </span><code><span style="	font-weight: 400;
">HostApplication</span></code><span style="	font-weight: 400;
"> field is set to </span><code><span style="	font-weight: 400;
">powershell -nop -exec Bypass -EncodedCommand &lt;base64-encoded-command&gt;</span></code></li><li style="	font-weight: 400;
"><span style="	font-weight: 400;
">The base64 encoded command decodes to </span><code><span style="	font-weight: 400;
">Invoke-WMIMethod win32_process -name create -argumentlist &#39;&lt;command&gt;&#39; -ComputerName &lt;target&gt;</span></code></li></ul>
<div class="wp-caption" id="attachment_26955"><a href="/content/dam/crowdstrike/www/en-us/wp/2020/09/Figure-9a.png" target="_blank" rel="noopener noreferrer"><img class="size-full wp-image-26955" src="/content/dam/crowdstrike/www/en-us/wp/2020/09/Figure-9a-1.png" alt="" width="1252" height="713"/></a> Figure 9. Artifact generated by the <code>remote-exec wmi</code> Beacon command when executed on the compromised system (click image to enlarge)</div>

<span style="	font-weight: 400;
"><p> </p>An example of the observed artifact as shown in Figure 9:</span>
<div class="blog-post-code-wrapper">

<code><span style="	font-weight: 400;
">HostApplication&#61;powershell -nop -exec Bypass -EncodedCommand SQBuAHYAbwBrAGUALQBXAE0ASQBNAGUAdABoAG8AZAAgAHcAaQBuADMAMgBfAHAAcgBvAGMAZQBzAHMAIAAtAG4AYQBtAGUAIABjAHIAZQBhAHQAZQAgAC0AYQByAGcAdQBtAGUAbgB0AGwAaQBzAHQAIAAnAHcAaABvAGEAbQBpACcAIAAtAEMAbwBtAHAAdQB0AGUAcgBOAGEAbQBlACAAVwBJAE4AMQAwAA</span></code><code><span style="	font-weight: 400;
">Decoded Base64 Command: Invoke-WMIMethod win32_process -name create -argumentlist &#39;whoami&#39; -ComputerName WIN10</span></code>

</div>
<h3><span style="	font-weight: 400;
">The </span><code><span style="	font-weight: 400;
">remote-exec powershell</span></code><span style="	font-weight: 400;
"> Command</span></h3>
<span style="	font-weight: 400;
">The </span><code><span style="	font-weight: 400;
">remote-exec powershell</span></code><span style="	font-weight: 400;
"> Beacon command executes a command on a remote system via PowerShell remoting from a compromised system. When the </span><code><span style="	font-weight: 400;
">remote-exec powershell</span></code><span style="	font-weight: 400;
"> command is executed, the filesystem will generate an EID 400 event log (PowerShell Engine Startup) on the compromised system. The event created will contain the standard Cobalt Strike PowerShell command prefix in the </span><code><span style="	font-weight: 400;
">HostApplication</span></code><span style="	font-weight: 400;
"> field.</span>
<h4><span style="	font-weight: 400;
">Observations of </span><code><span style="	font-weight: 400;
">remote-exec powershell</span></code><span style="	font-weight: 400;
">:</span></h4>
<ul><li style="	font-weight: 400;
"><span style="	font-weight: 400;
">The </span><code><span style="	font-weight: 400;
">HostApplication</span></code><span style="	font-weight: 400;
"> field is set to </span><code><span style="	font-weight: 400;
">powershell -nop -exec Bypass -EncodedCommand &lt;base64-encoded-command&gt;</span></code></li><li style="	font-weight: 400;
"><span style="	font-weight: 400;
">The Base64 encoded command decodes to </span><code><span style="	font-weight: 400;
">Invoke-Command -ComputerName &lt;target&gt; -ScriptBlock { &lt;command&gt; }</span></code></li></ul>
<div class="wp-caption" id="attachment_26956"><a href="/content/dam/crowdstrike/www/en-us/wp/2020/09/Figure-10a.png" target="_blank" rel="noopener noreferrer"><img class="size-full wp-image-26956" src="/content/dam/crowdstrike/www/en-us/wp/2020/09/Figure-10a-1.png" alt="" width="1113" height="742"/></a> Figure 10. Artifact generated by the <code>remote-exec powershell</code> Beacon command when executed on the compromised system (click image to enlarge)</div>

<span style="	font-weight: 400;
">An example of the observed artifact as shown in Figure 10:</span>
<div class="blog-post-code-wrapper">

<code><span style="	font-weight: 400;
">HostApplication&#61;powershell -nop -exec Bypass -EncodedCommand SQBuAHYAbwBrAGUALQBDAG8AbQBtAGEAbgBkACAALQBDAG8AbQBwAHUAdABlAHIATgBhAG0AZQAgADEAMAAuADAALgAwAC4AMQAwACAALQBTAGMAcgBpAHAAdABCAGwAbwBjAGsAIAB7ACAAdwBoAG8AYQBtAGkAIAB9AA</span></code><code><span style="	font-weight: 400;
">Decoded Base64 Command: Invoke-Command -ComputerName 10.0.0.10 -ScriptBlock { whoami }</span></code>

</div>
<h2><span style="	font-weight: 400;
">Conclusions</span></h2>
<span style="	font-weight: 400;
">Although Cobalt Strike provides the operator a degree of freedom to configure some of the previously mentioned commands, those features are not always leveraged by adversaries. Due to the high prevalence of Cobalt Strike in contemporary intrusions, CrowdStrike recommends collecting EID 400 (PowerShell Engine Startup) and EID 7045 event logs (Service Installation) for monitoring and alerting in a centralized </span><a href="/en-us/epp-101/what-is-siem-in-cybersecurity/"><span style="	font-weight: 400;
">security information and event management (SIEM) platform</span></a><span style="	font-weight: 400;
">.<p> </p></span>

<span style="	font-weight: 400;
">CrowdStrike also recommends upgrading to the most recent version of PowerShell and disabling previous versions, as PowerShell is backward compatible. While these additional security measures do not provide full visibility into Cobalt Strike activity, they can aid in its detection.</span>
