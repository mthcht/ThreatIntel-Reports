        <h1>Herpaderping: Security Risk or Unintended Behavior?</h1>
        
        <div class="publish_info">
            <p>January 21, 2021</p>
            <span>•</span>
            <a href="/en-us/blog/author.johnny-shaw/" title="Posts by Johnny Shaw" rel="author">
                Johnny Shaw</a>
            <span>•</span>
                
            <a href="/en-us/blog/category.engineering-and-technology/" title="Engineering &amp; Tech">Engineering &amp; Tech</a>
        </div>
        <div class="post_image">
            <img width="1060" height="698" src="https://assets.crowdstrike.com/is/image/crowdstrikeinc/Blog_1060x698-38-2" class="attachment-post-thumbnail size-post-thumbnail wp-post-image" alt="" decoding="async" fetchpriority="high" srcset="/content/dam/crowdstrike/www/en-us/wp/2021/01/Blog_1060x698-38-2.jpg 1060w,https://assets.crowdstrike.com/is/image/crowdstrikeinc/Blog_1060x698-38-2-768x506 768w,https://assets.crowdstrike.com/is/image/crowdstrikeinc/Blog_1060x698-38-2-1024x674 1024w,https://assets.crowdstrike.com/is/image/crowdstrikeinc/Blog_1060x698-38-2-300x198 300w" sizes="(max-width: 1060px) 100vw, 1060px"/>

<div class="text text--blog-content aem-GridColumn aem-GridColumn--default--12">



<div class="cmp-text" id="text-468284244f" data-cmp-name="cmp-text-" data-cmp-is="text" data-target-location="false">
    
       <span><span style="	font-weight: 400;
"><p> </p></span><span style="	font-weight: 400;
">The answer to that question often depends on who you ask.</span>

<span style="	font-weight: 400;
">By definition, </span><strong>process herpaderping</strong><span style="	font-weight: 400;
"> is a hacking technique in which digital adversaries modify on-disk content after the image has been mapped in order to obscure the process. This obscurity can confuse security products or the operating system itself, sometimes allowing malicious code to be executed. For more information on process herpaderping, please read my earlier explainer post </span><a href="https://github.com/jxy-s/herpaderping"><span style="	font-weight: 400;
">here</span></a>.
<div class="blog-post-code-wrapper">
<h3><strong>At a Glance: How Process Herpaderping Occurs</strong></h3>
<ol><li><span style="	font-weight: 400;
"> Write target binary to disk, keeping the handle open. This is what will execute in memory.</span></li><li><span style="	font-weight: 400;
"> Map the file as an image section (</span><a href="https://docs.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-zwcreatesection"><span style="	font-weight: 400;
">NtCreateSection</span></a><span style="	font-weight: 400;
">, </span><a href="https://docs.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-createfilemappinga"><span style="	font-weight: 400;
">SEC_IMAGE</span></a><span style="	font-weight: 400;
">).</span></li><li><span style="	font-weight: 400;
"> Create the process object using the section handle (NtCreateProcessEx).</span></li><li><span style="	font-weight: 400;
"> Using the same target file handle, obscure the file on disk.</span></li><li><span style="	font-weight: 400;
"> Create the initial thread in the process (NtCreateThreadEx). At this point the process creation callback in the kernel will fire. The contents on disk do not match what was mapped. Inspection of the file at this point will result in incorrect attribution.</span></li><li>Close the handle. <a href="https://docs.microsoft.com/en-us/windows-hardware/drivers/kernel/irp-mj-cleanup">IRP_MJ_CLEANUP</a> will occur here. Since we&#39;ve hidden the contents of what is executing, inspection at this point will result in incorrect attribution.</li></ol>
</div>
<span style="	font-weight: 400;
">From an OS’s perspective, herpaderp attacks are often categorized as unintentional activity. But from a developer’s point of view, it’s a clear security threat—and a potent one at that.</span><span style="	font-weight: 400;
"><p> </p></span>

<span style="	font-weight: 400;
">To illustrate this principle, let’s take a look at a recent example. Over the summer, it may have appeared that Google distributed a signed copy of Mimikatz. Sounds strange? It should because Google did </span><span style="	font-weight: 400;
">not</span><span style="	font-weight: 400;
"> distribute a signed copy of Mimikatz. Rather, if you saw this, you were witnessing a case of process herpaderping, an exploit technique that obscures the intentions of a process by modifying the content on disk after the image has been mapped.</span>

<img class="alignnone size-full wp-image-28139" src="/content/dam/crowdstrike/www/en-us/wp/2021/01/mimikatz-for-windows-1.png" alt="" width="274" height="119"/>

<span style="	font-weight: 400;
">My team disclosed this process herpaderping attack to the Microsoft Security Response Center (MSRC) in mid-July. A case was opened a few days later. MSRC concluded their investigation near the end of August and determined the findings of the MSRC investigation were valid but did not require immediate servicing.</span>

<span style="	font-weight: 400;
">And with that, the case was closed—without a real resolution or timeline for future review, despite our reiterated belief to MSRC that this bug is severe.</span>

<strong><a href="https://github.com/jxy-s/herpaderping/blob/main/res/SurivDemo.gif">Review the details here.</a></strong>
<h2>What Does Herpaderping Mean for Developers?</h2>
<span style="	font-weight: 400;
">The consensus from the cybersecurity community and researchers sees the situation quite differently. The POC shows this is exploitable and as a &#34;defense evasion&#34; or &#34;masquerading&#34; technique.<p> </p><p> </p></span>

<span style="	font-weight: 400;
">When an attack of this nature is miscategorized by an OS as unintentional activity it has major cybersecurity implications for any and all developers, not just security vendors. For example, where a Microsoft OS categorizes this attack as unintentional, Microsoft Defender Antivirus scans completed on the image backing the process may not prevent execution by a known malicious binary. Once the file is copied to the desktop, Microsoft Defender will likely realize there is a problem, but by then, the damage is done.<p> </p></span>

<span style="	font-weight: 400;
">Many antivirus vendors are thought to be vulnerable to this type of attack, which means that many organizations are at risk of experiencing a herpaderping attack. </span>
<h2><b>Herpaderping: How It’s Done</b></h2>
<span style="	font-weight: 400;
">When the OS characterizes herpaderping as unintentional activity, it fails to address such exploits, and thus the burden of the solution falls on developers, both cybersecurity vendors and general app developers. But in order to defend against such attacks, we must first understand how they work.</span>

<span style="	font-weight: 400;
">Generally, a security product takes action on process creation by registering a callback in the OS kernel (</span><a href="https://docs.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddk/nf-ntddk-pssetcreateprocessnotifyroutineex"><span style="	font-weight: 400;
">PsSetCreateProcessNotifyRoutineEx</span></a><span style="	font-weight: 400;
">). At this point, a security product may inspect the file that was used to map the executable and determine if this process should be allowed to execute. However, the kernel callback is invoked when the initial thread is inserted, not when the process object is created.</span>

<span style="	font-weight: 400;
">Because of this disconnect, an actor can create and map a process, modify the content of the file, then create the initial thread. A product that does inspection at the creation callback would then see the modified content.</span>

<div class="wp-caption" id="attachment_28142"><a href="/content/dam/crowdstrike/www/en-us/wp/2021/01/Herpaderping-Figure-1-rev.png" target="_blank" rel="noopener noreferrer"><img class="wp-image-28142 size-full" src="/content/dam/crowdstrike/www/en-us/wp/2021/01/Herpaderping-Figure-1-rev-1.png" alt="" width="900" height="1672"/></a> Click image to enlarge</div>

<span style="	font-weight: 400;
">In addition, some products use an on-write scanning approach that consists of monitoring for file writes. A familiar optimization is recording the file as written and deferring the actual inspection until </span><a href="https://docs.microsoft.com/en-us/windows-hardware/drivers/kernel/irp-mj-cleanup"><span style="	font-weight: 400;
">IRP_MJ_CLEANUP</span></a><span style="	font-weight: 400;
"> occurs (e.g. the file handle is closed). Thus, an actor using a write -&gt; map -&gt; modify -&gt; execute -&gt; close workflow will subvert on-write scanning that solely relies on inspection at </span><a href="https://docs.microsoft.com/en-us/windows-hardware/drivers/kernel/irp-mj-cleanup"><span style="	font-weight: 400;
">IRP_MJ_CLEANUP</span></a><span style="	font-weight: 400;
">.</span>

<span style="	font-weight: 400;
">To abuse this convention, adversaries first write a binary to a target file on disk. Then, they map an image of the target file and provide it to the OS to use for process creation. The OS then maps the original binary. Using the existing file handle, and before creating the initial thread, the adversary then modifies the target file content to obscure or fake the file backing the image. Later, the initial thread is created in order to begin execution of the original binary. Finally, the target file handle can be closed.</span>

<strong><a href="https://github.com/jxy-s/herpaderping/blob/main/res/ProcessHerpaderp.gif">Let’s look at an example of herpaderping in action.</a></strong>

<span style="	font-weight: 400;
">As you can see in the demo linked above, Cmd.exe is used as the execution target. The first run overwrites the bytes on disk with a pattern. The second run overwrites .exe with ProcessHacker.exe.</span>

<span style="	font-weight: 400;
">The herpaderping tool then fixes the binary to look as close to ProcessHacker.exe as possible, even retaining the original signature. Note the multiple executions of the same binary and how the process looks to the user compared to what is in the file on disk.</span>

<span style="	font-weight: 400;
">Looking at this flow from Process Monitor, we observe the source file being written and the OS mapping the image at the section creation. Using the same handle, the exploit overwrites the source binary with whatever it likes before creating the initial thread. By the time the process creation notification fires in the kernel the file backing the image is not what was mapped:</span>

<div class="wp-caption"><a href="/content/dam/crowdstrike/www/en-us/wp/2021/01/Herpaderping-Figure-2b.png" target="_blank" rel="noopener noreferrer"><img class="wp-image-28145 size-full" src="/content/dam/crowdstrike/www/en-us/wp/2021/01/Herpaderping-Figure-2b-1.png" alt="" width="1249" height="1290"/></a> Click image to enlarge</div>

<span style="	font-weight: 400;
">The </span><a href="https://docs.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ns-wdm-_section_object_pointers"><span style="	font-weight: 400;
">SECTION_OBJECT_POINTERS</span></a><span style="	font-weight: 400;
"> of the </span><a href="https://docs.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ns-wdm-_file_object"><span style="	font-weight: 400;
">FILE_OBJECT</span></a><span style="	font-weight: 400;
"> play a key role here. The OS will cache the initial image mapping and re-use the already mapped section, even if there is active write access to the</span><a href="https://docs.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ns-wdm-_file_object"> <span style="	font-weight: 400;
">FILE_OBJECT</span></a><span style="	font-weight: 400;
">. This also means that a user can open the original file with exclusive access. While this won’t necessarily create an issue for the kernel callback, it does affect downstream logic in that it assumes that when the user opens the file with read access it will be broken. However, such logic does not apply, given that the file content has been overwritten. Further, the kernel callback is hopeless too, since reading directly from the file using that </span><a href="https://docs.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ns-wdm-_file_object"><span style="	font-weight: 400;
">FILE_OBJECT</span></a><span style="	font-weight: 400;
"> will read the wrong data.</span>

<span style="	font-weight: 400;
">This also means if a user tries to execute that process again it will result in a sharing violation. From user mode, without access to that original target file handle, no one may conventionally execute the process.</span>
<h2>Resolving This Issue: A Short-term Fix and Long-term Solution</h2>
<span style="	font-weight: 400;
">Unfortunately, there is not a clear fix for herpaderping attacks. It seems reasonable that preventing an image section from being mapped/cached when there is write access to the file should close the hole. However, that may or may not be a practical solution.</span>

<span style="	font-weight: 400;
">There is a frustration among the development community about the incoherency between what is on disc and what it is going to execute, which is a common issue with all major operating systems. As such, that is something that should be considered when designing a security product.</span>

<span style="	font-weight: 400;
">While there isn&#39;t a clear mechanism to guarantee that coherency, there are ways that security vendors, as well as security engineers and analysts, can foresee this issue and minimize the risk.</span>

<span style="	font-weight: 400;
">One way to detect this type of exploit is to look for write access to the related file object when the process is created. </span><span style="	font-weight: 400;
">The exploit seems achievable through a higher-level API call. That said, the API juggling involved usually requires a native-call, which allows the attacker to tightly control the process creation flow.<p> </p></span>

<span style="	font-weight: 400;
">Another way to detect this type of exploit is checking for coherency between the file on disk and the mapped process. Viewing the image coherency between the file on disk and the mapped process may be seen in an addition I&#39;ve made to Process Hacker, and also shows the spoofed display of “Google” as the “signer” due to the exploit.<p> </p></span>

<div class="wp-caption"><a href="/content/dam/crowdstrike/www/en-us/wp/2021/01/Herpaderp-Figure-3.png" target="_blank" rel="noopener noreferrer"><img class="size-full wp-image-28147" src="/content/dam/crowdstrike/www/en-us/wp/2021/01/Herpaderp-Figure-3-1.png" alt="" width="811" height="876"/></a> Click image to enlarge</div>

<span style="	font-weight: 400;
">Here is a link to the enhancement proposal I&#39;ve made to Process Hacker: </span><a href="https://github.com/processhacker/processhacker/issues/744"><span style="	font-weight: 400;
">https://github.com/processhacker/processhacker/issues/744</span></a><span style="	font-weight: 400;
"><p> </p></span>

<span style="	font-weight: 400;
">Process Tampering may also be seen through a recent addition to SysMon by Mark Russinovich, CTO of Microsoft Azure, reproduced below and in </span><a href="https://twitter.com/markrussinovich/status/1328769178233237504?s&#61;20"><span style="	font-weight: 400;
">this tweet</span></a><span style="	font-weight: 400;
">.<p> </p></span>

<div class="wp-caption" id="attachment_28148"><a href="/content/dam/crowdstrike/www/en-us/wp/2021/01/Herpaderp-Figure-4.png" target="_blank" rel="noopener noreferrer"><img class="size-full wp-image-28148" src="/content/dam/crowdstrike/www/en-us/wp/2021/01/Herpaderp-Figure-4-1.png" alt="" width="930" height="403"/></a> Click image to enlarge</div>

<div class="wp-caption" id="attachment_28149"><a href="/content/dam/crowdstrike/www/en-us/wp/2021/01/Herpaderp-Figure-5.png" target="_blank" rel="noopener noreferrer"><img class="wp-image-28149 size-full" src="/content/dam/crowdstrike/www/en-us/wp/2021/01/Herpaderp-Figure-5-1.png" alt="" width="930" height="533"/></a> Click image to enlarge</div>

<span style="	font-weight: 400;
">As for a long-term solution, that would require working with the OS to agree on a joint approach.<p> </p> We&#39;re hopeful that as the technique gains broader awareness, the OS vendors will work with the cybersecurity community to adopt more stringent countermeasures directly in the OS.</span>
