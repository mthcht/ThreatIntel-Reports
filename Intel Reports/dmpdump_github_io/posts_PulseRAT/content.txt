data-bs-placement="bottom" title="1053 words" > <em>5 min</em> read</span></div></div></div></header><div class="content"><p>On May 19, 2026, I came across an interesting ISO <a href="https://x.com/G60930953/status/2056919558967943187?s=20">uploaded from UAE</a>. The ISO is named <code class="language-plaintext highlighter-rouge">UAE-India_Strategic_Partnership_Week.iso</code>, and it is likely related to the defense partnership between India and UAE <a href="https://web.archive.org/web/20260515161227/https://www.middleeasteye.net/news/india-and-uae-sign-defence-and-energy-deals-during-modi-state-visit">announced in May 2026</a>. The ISO contains payload that leads to a RAT which I had not seen before. I will temporarily call this RAT <code class="language-plaintext highlighter-rouge">'PulseRAT'</code>, but if the reader recognizes it as a known or previously reported malware family, I will be happy to update the name and reference previous research.</p><p>The ISO contains 2 files:</p><ul><li><code class="language-plaintext highlighter-rouge">Document_11052026-03578240540350-93.exe</code><li><code class="language-plaintext highlighter-rouge">UAE-India_Strategic_Partnership-Week.lnk</code></ul><p><a href="/assets/images/pulserat/isofiles.png" class="popup img-link shimmer"><img src="/assets/images/pulserat/isofiles.png" alt="sshot" loading="lazy"></a></p><p>The LNK file does just one thing: it runs the accompanying executable file:</p><div class="language-plaintext highlighter-rouge"><div class="code-header"> <span data-label-text="Plaintext"><i class="fas fa-code fa-fw small"></i></span> <button aria-label="copy" data-title-succeed="Copied!"><i class="far fa-clipboard"></i></button></div><div class="highlight"><code><table class="rouge-table"><tbody><tr><td class="rouge-gutter gl"><pre class="lineno">1

</pre></table></code></div></div><p><code class="language-plaintext highlighter-rouge">Document_11052026-03578240540350-93.exe</code> is a .NET executable. Its original file name is <code class="language-plaintext highlighter-rouge">FinalTool.exe</code> and it was compiled on May 11, 2026, 8 days before I found it. This executable is a simple dropper for a RAT. When executed, it checks if the directory <code class="language-plaintext highlighter-rouge">%LOCALAPPDATA%\Microsoft\Vault</code> exists. If not, it creates it. Then, it extracts 2 embedded resources:</p><ul><li><code class="language-plaintext highlighter-rouge">InternalExe</code> is the final payload. This executable is saved as <code class="language-plaintext highlighter-rouge">%LOCALAPPDATA%\Microsoft\Vault\vaultsvc.exe</code> and is executed with a Scheduled Task that has 2 triggers.<li><code class="language-plaintext highlighter-rouge">InternalBait</code> is saved to disk and opened. This “decoy PDF” is a 0 byte resource, so it does not render as a PDF.</ul><p><a href="/assets/images/pulserat/droppermain.png" class="popup img-link shimmer"><img src="/assets/images/pulserat/droppermain.png" alt="sshot" loading="lazy"></a></p><p>The Scheduled Task is implemented via the <code class="language-plaintext highlighter-rouge">CreatePersistence</code> method using the Windows Task Scheduler COM interface. The Task created for initial execution and persistence is called <code class="language-plaintext highlighter-rouge">WindowsVaultSyncService</code> and has the following description: <code class="language-plaintext highlighter-rouge">Windows Edge Core Update Task Machine Discord Update</code>. Two triggers are set for the execution of <code class="language-plaintext highlighter-rouge">vaultsvc.exe</code>: 3 minutes after the Scheduled Task creation and when the current user logs on.</p><p><a href="/assets/images/pulserat/dropperpersistence.png" class="popup img-link shimmer"><img src="/assets/images/pulserat/dropperpersistence.png" alt="sshot" loading="lazy"></a></p><p>After setting up the Scheduled Task, the dropper runs the <code class="language-plaintext highlighter-rouge">Melt</code> method to:</p><ul><li>Implement a 2 second delay via <code class="language-plaintext highlighter-rouge">choice.exe</code>.<li>Self-delete.<li>Move the <code class="language-plaintext highlighter-rouge">InternalBait</code> “PDF” to the dropper’s directory.</ul><p><a href="/assets/images/pulserat/melt.png" class="popup img-link shimmer"><img src="/assets/images/pulserat/melt.png" alt="sshot" loading="lazy"></a></p><h1 id="pulserat---google-sheets-based-rat">PulseRAT - Google Sheets-based RAT</h1><p>The final payload in this infection chain is the .NET RAT dropped by <code class="language-plaintext highlighter-rouge">Document_11052026-03578240540350-93.exe</code> as <code class="language-plaintext highlighter-rouge">vaultsvc.exe</code>. This RAT uses Google Sheets as a C2 channel. The RAT has the following metadata:</p><ul><li>Original File Name: <code class="language-plaintext highlighter-rouge">Syn.exe</code><li>Compilation date: <code class="language-plaintext highlighter-rouge">May 8, 2026</code><li>Description: <code class="language-plaintext highlighter-rouge">Windows System Synchronization Service</code></ul><p>The first thing the RAT does is generate a UID for each victim. The UID is generated by computing a SHA-256 hash of the concatenated username + machine name:</p><p><a href="/assets/images/pulserat/guid.png" class="popup img-link shimmer"><img src="/assets/images/pulserat/guid.png" alt="sshot" loading="lazy"></a></p><p>The UID is subsequently used to generate and check the presence of the following mutex: <code class="language-plaintext highlighter-rouge">Global\\WinSync_ + UID</code>. If the mutex does not exist, it continues execution and:</p><ul><li>Hides the console.<li>Sets connection properties via the ServicePointManager class.<li>Calls the <code class="language-plaintext highlighter-rouge">Pulse</code> method. This method implements the RAT functionality.</ul><p><a href="/assets/images/pulserat/mainrat.png" class="popup img-link shimmer"><img src="/assets/images/pulserat/mainrat.png" alt="sshot" loading="lazy"></a></p><p>The <code class="language-plaintext highlighter-rouge">Pulse</code> method uses a string decoding/decryption method named <code class="language-plaintext highlighter-rouge">JIT</code> to base64-decode and XOR decrypt the strings for the Spreadsheet ID and the Service Account used by the RAT. The XOR key passed to the decryption function is <code class="language-plaintext highlighter-rouge">discrete</code>.</p><p><a href="/assets/images/pulserat/jitcall.png" class="popup img-link shimmer"><img src="/assets/images/pulserat/jitcall.png" alt="sshot" loading="lazy"></a></p><p><a href="/assets/images/pulserat/jit.png" class="popup img-link shimmer"><img src="/assets/images/pulserat/jit.png" alt="sshot" loading="lazy"></a></p><p>The decoded/decrypted Spreadsheet ID is: <code class="language-plaintext highlighter-rouge">1Lb5BEIsehbCGe8p1jkfWf5Mw1dBAcw5RHWFdga5gFq8</code>.</p><p>After decoding the Spreadsheet ID, the RAT authenticates to Google Spreadsheets via the <code class="language-plaintext highlighter-rouge">RefreshAuth</code> function. The Service Account for authentication is decoded/decrypted with the <code class="language-plaintext highlighter-rouge">JIT</code> function (using the same <code class="language-plaintext highlighter-rouge">discrete</code> key).</p><p>The decoded/decrypted Service Account is: <code class="language-plaintext highlighter-rouge">sheet5@sheet5-495707.iam.gserviceaccount.com</code>.</p><p><code class="language-plaintext highlighter-rouge">RefreshAuth</code> creates a JWT, signs it with an embedded RSA private key, and exchanges it with Google’s OAuth2 token endpoint to obtain an access token for the Google Sheets API.</p><p><a href="/assets/images/pulserat/refreshauth.png" class="popup img-link shimmer"><img src="/assets/images/pulserat/refreshauth.png" alt="sshot" loading="lazy"></a></p><p>When the RAT connects to the attacker-controlled Google Spreadsheet, it checks if a sheet exists for the previously generated victim UID. If it does not exist, it creates a new sheet for the victim UID.</p><p><a href="/assets/images/pulserat/pulse1.png" class="popup img-link shimmer"><img src="/assets/images/pulserat/pulse1.png" alt="sshot" loading="lazy"></a></p><p>The RAT then writes the following to the spreadsheet cells:</p><div class="table-wrapper"><table><thead><tr><th>Cell<th>Content<th>Purpose<tbody><tr><td>A1<td><code class="language-plaintext highlighter-rouge">First: &lt;timestamp&gt;</code><td>Timestamp of first connection<tr><td>B1:C1<td><code class="language-plaintext highlighter-rouge">Pulse: &lt;timestamp&gt;</code><td>Heartbeat, updated with every beacon<tr><td>A2:C2<td><code class="language-plaintext highlighter-rouge">I | O | T </code><td>Input / Output / Timestamp for command execution logging<tr><td>A3:C3<td><code class="language-plaintext highlighter-rouge">c3lzdGVtaW5mbw== | &lt;systeminfo output&gt; | &lt;timestamp&gt; </code><td>System Info Data</table></div><p>The <code class="language-plaintext highlighter-rouge">systeminfo</code> command is run once via an in-process PowerShell execution. The output of the command is logged to the attacker-controlled spreadsheet. The attacker can also write base64-encoded PowerShell commands starting on cell A4. The RAT will read the commands from cell A4 onwards, it will base64-decode them, execute them, and will base64-encode the output that is written back to the spreadsheet. This includes a timestamp logging time of command execution. For this, it uses the <code class="language-plaintext highlighter-rouge">I(nput)</code>, <code class="language-plaintext highlighter-rouge">O(utput)</code>, and <code class="language-plaintext highlighter-rouge">T(imestamp)</code> sections created before.</p><p><a href="/assets/images/pulserat/pulse2.png" class="popup img-link shimmer"><img src="/assets/images/pulserat/pulse2.png" alt="sshot" loading="lazy"></a></p><p>In my attempts to connect to the Google Spreadsheet using the authentication material embedded to the RAT, I noticed that the account may have been deleted. However, based on the way that the RAT interacts with the spreadsheet, we may reconstruct what a sheet may look like:</p><p><a href="/assets/images/pulserat/samplesheet.png" class="popup img-link shimmer"><img src="/assets/images/pulserat/samplesheet.png" alt="sshot" loading="lazy"></a></p><p>The base64 decoding of commands, in-process PowerShell execution, and base64 encoding of outputs is implemented in the <code class="language-plaintext highlighter-rouge">RunPS</code> method. This method creates a PowerShell runspace to avoid spawning a PowerShell process, which is typically suspicious.</p><p><a href="/assets/images/pulserat/runps.png" class="popup img-link shimmer"><img src="/assets/images/pulserat/runps.png" alt="sshot" loading="lazy"></a></p><h1 id="possible-connection-with-an-xls">Possible Connection with an XLS</h1><p>While hunting for additional artifacts associated with the host used to create the LNK file (<code class="language-plaintext highlighter-rouge">desktop-526nitv</code>), I came across a benign Excel file uploaded on April 1, 2026 from Afghanistan: <code class="language-plaintext highlighter-rouge">Compliance_Checklist.xlsx</code> (9c713a33fd9a3f6327faa3eae256732dedf7e19399d55a2ca8d395263f26c2d7). This XLS was originally created by user <code class="language-plaintext highlighter-rouge">atra.gov.af</code> (associated with the Afghanistan Telecom Regulatory Authority), but it was modified by a ‘Default User’ using a machine named <code class="language-plaintext highlighter-rouge">desktop-526nitv</code>, the same machine name that we saw in the LNK. The associated path is <code class="language-plaintext highlighter-rouge">Desktop\CAMP\31-03</code>, potentially referencing a campaign date.</p><p><a href="/assets/images/pulserat/compliancechecklist.png" class="popup img-link shimmer"><img src="/assets/images/pulserat/compliancechecklist.png" alt="sshot" loading="lazy"></a></p><p><a href="/assets/images/pulserat/excelauthor.png" class="popup img-link shimmer"><img src="/assets/images/pulserat/excelauthor.png" alt="sshot" loading="lazy"></a></p><p><a href="/assets/images/pulserat/excelmodified.png" class="popup img-link shimmer"><img src="/assets/images/pulserat/excelmodified.png" alt="sshot" loading="lazy"></a></p><p>The link between the XLSX and the LNK is relatively weak, and I could not find any specific threats associated with the Excel file. However, given the time proximity and the overlap between machine names, I continue looking for artifacts that may prove or refute a meaningful link between the artifacts.</p><h1
