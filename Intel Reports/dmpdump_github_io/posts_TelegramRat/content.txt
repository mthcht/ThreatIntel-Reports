The main logic in the DLL starts with an exported function named <code class="language-plaintext highlighter-rouge">Run</code>. The first thing the DLL does is search for a file named <code class="language-plaintext highlighter-rouge">Word Document - 2026 BBBC.docx</code> in its current working directory. Most of the relevant strings in the DLL are encrypted with simple XOR encryption using key <code class="language-plaintext highlighter-rouge">0xD6C7DCF9EAC9A3E5</code>.</p><p><a href="/assets/images/telegramrat/searchdoc.png" class="popup img-link shimmer"><img src="/assets/images/telegramrat/searchdoc.png" alt="sshot" loading="lazy"></a></p><p><code class="language-plaintext highlighter-rouge">Word Document - 2026 BBBC.docx</code> is not a real Word document. A simple inspection reveals that it is a blob of encrypted data.</p><p><a href="/assets/images/telegramrat/encrypteddoc.png" class="popup img-link shimmer"><img src="/assets/images/telegramrat/encrypteddoc.png" alt="sshot" loading="lazy"></a></p><p>The DLL takes a 2-layer XOR decryption approach to obtain the next stages of the infection.</p><ul><li>First, the complete <code class="language-plaintext highlighter-rouge">Word Document - 2026 BBBC.docx</code> is XOR-decrypted with the same key that is used to decrypt strings (<code class="language-plaintext highlighter-rouge">0xD6C7DCF9EAC9A3E5</code>).<li>Then, the string <code class="language-plaintext highlighter-rouge">5737851</code> is decrypted with the same XOR key. This string is subsequently converted to an integer and used to calculate the ‘tail’ of the document.<li>The first part of the decrypted data (total decrypted file size - last 5737851 bytes) is used as a decoy/corrupted Word document.
