<h2>Background</h2>

<p>This is the second part of FortiGuard Labs’ deep analysis of the new Emotet variant. In <a href="https://blog.fortinet.com/2017/05/03/deep-analysis-of-new-emotet-variant-part-1">the first part</a> of the analysis we demonstrated that by bypassing the server-side<strong> Anti-Debug</strong> or <strong>Anti-Analysis </strong>technique we could download three or four modules (.dll files) from the C&C server. In that first blog we only analyzed one module (I named it ‘module2’). In this blog, we’ll review how the other modules work. Here we go.</p>

<h2>Stealing email addresses from MS Outlook PST files</h2>

<p>As I detailed in Part 1 of this blog, the first module we’re looking at here (I’ve named it ‘module1’) is loaded in a ThreadFunction, whose main function is to go through all Outlook accounts by reading the PST files. A PST file is a personal folder file in Microsoft Outlook that stores your email messages, calendar, tasks, and other items. PST files are usually located in the “Documents\Outlook Files” folder on your computer. See Figure 1.</p>

<p><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-emotet-variant-part-2-2431.png" data-style="width: 75%;"/></p>

<p align="center">Figure 1. PST files</p>

<p>Microsoft has provided a group of APIs called MAPI (Microsoft Outlook Messaging API), which is the messaging architecture for Microsoft Outlook. Using the MAPIs you can operate PST files.  The MAPIs are used in the module1 file.</p>

<p>Once module1 file is executed it creates a temporary file that is used to store the stolen Outlook version information and email addresses that have been collected.  Loading MAPI functions is the next step. Figure 2 shows how, along with what it loads.</p>

<p align="center"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-emotet-variant-part-2-2432.png" data-style="width: 75%;"/></p>

<p align="center">Figure 2. Loading MAPI functions</p>

<p>It then starts reading all PST files according to the Outlook accounts on the computer, going through all email messages with an unread status in every folder (Inbox, Deleted Items, Junk E-mail, Sent Items, etc.) under one email account. It steals the sender name and the email address from each unread email. Figure 3 shows a sample unread email about a Facebook notification that was sent to me.</p>

<p align="center"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-emotet-variant-part-2-2433.png" data-style="width: 75%;"/></p>

<p align="center">Figure 3. Sample unread email message</p>

<p>Figure 4 shows what module1 has stolen from the unread email message shown in Figure 3. “Facebook” is the sender name, and “notification+kr4yxeragnmn@facebookmail.com” is the sender’s email address.</p>

<p align="center"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-emotet-variant-part-2-2434.png" data-style="width: 75%;"/></p>

<p align="center">Figure 4. The stolen email information in the memory buffer</p>

<p>As I mentioned before, the stolen data is saved in a temporary file. In this case, it’s “AE74.tmp.” It will be read when module1 prepares to encrypt and send the stolen information to its C&C server. Figure 5 shows the data before encryption, which is read from “AE74.tmp.”</p>

<p align="center"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-emotet-variant-part-2-2435.png" data-style="width: 75%;"/></p>

<p align="center">Figure 5. Data before encryption</p>

<p>As you can see, it contains the Outlook version and stolen email information. Once encrypted, the data will be sent to the C&C server through a “POST” request. Figure 6 is the packet screenshot from WireShark.</p>

<p align="center"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-emotet-variant-part-2-2436.png" data-style="width: 75%;"/></p>

<p align="center">Figure 6. Sending the encrypted data to the C&C server</p>

<h2>Sending spam using the C&C server template</h2>

<p>This is the largest Emotet module (I have named it ‘module4’) of the malware’s four modules. Its main function is to send spam to the email addresses which were stolen and sent to the C&C server. When it is executed in a thread it generates a GUID by calling the CoCreateGuid function. It then base64-encodes the GUID and sends it as a cookie to the C&C server. The response provides the encrypted spam message, as well as the  email addresses that the spam will be sent to. The two figures below show the packet from the C&C server, as well as the content after decryption.</p>

<p><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-emotet-variant-part-2-2437.png" data-style="width: 70%;"/></p>

<p align="center">Figure 7. Sent GUID and response from the C&C server</p>

<pre>
<img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-emotet-variant-part-2-2438.png" data-style="width: 70%;"/>
</pre>

<p align="center">Figure 8. Decrypted spam template and email addresses</p>

<p>Once module4 receives the decrypted data, it reads out the spam template and the email addresses the spam message is being sent to. In module4, it supports SMTP protocol over both port 25 (regular) and port 587 (SSL). The figures below show how it uses the SMTP protocol to spread this spam, and what the spam looks like in an email client.</p>

<p><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-emotet-variant-part-2-2439.png" data-style="width: 75%;"/></p>

<p align="center">Figure 9. Related code and data generating SMTP packets</p>

<pre>
<img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-emotet-variant-part-2-2440.png" data-style="width: 70%;"/>
</pre>

<p align="center">Figure 10. Spam shown in Wireshark</p>

<p align="center"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-emotet-variant-part-2-2441.png" data-style="width: 75%;"/></p>

<p align="center">Figure 11. Spam shown in email client</p>

<p>As you can see in Figure 11, the spam attempts to trick the email recipients into opening a URL, that points to a malicious Word file. Figure 12 shows its Antivirus detection rating on VirusTotal.</p>

<pre>
<img alt="" src="/content/dam/fortinet-blog/new-images/uploads/deep-analysis-of-new-emotet-variant-part-2-2442.png" data-style="width: 75%;"/>
</pre>

<p align="center">Figure 12. Antivirus detection rate on VirusTotal</p>

<h2>Conclusion</h2>

<p>From this deep analysis of the new Emotet variant we can see that it focuses on stealing email-related data from a victim’s device, and then uses that device and the email addresses it has collected from it to send spam that can spread other malware.</p>

<p>NOTE: at the end of my analysis, I noticed that the Anti-Debug technique on the server side sometimes worked, and sometimes didn’t.</p>

<p>The URL attached to the spam generated by this malware has been detected as <strong>Malicious Websites </strong>by the FortiGuard Webfilter service, and the downloaded Word file has been detected as <strong>WM/Agent.DEA!tr.dldr</strong> by the FortiGuard Antivirus service.</p>

<h2>Summary of the four Received Modules</h2>

<p>Module1 (size 1c000H): steals email addresses and the recipients’ names from Outlook PST files.</p>

<p>Module2 (size 32000h): steals credentials from installed Office Outlook, IncrediMail, Group Mail, MSN Messenger, Mozilla ThunderBird, etc. The analysis of this module was provided in the first blog.</p>

<p>Module3 (size 70000h): steals saved information in browsers. Since it’s simple, I chose to not provide any analysis.</p>

<p>Module4 (size 0F0000h): sends spams to spread other malware.</p>
