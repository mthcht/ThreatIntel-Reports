<div class="cmp cmp-text aem-GridColumn aem-GridColumn--default--12">
  <p>FortiGuard Labs<span> has encountered version 3.0 of what is now dubbed IceXLoader, a new malware loader being advertised in malware hacking forums.</span></p>
<p>IceXLoader is a commercial malware used to download and deploy additional malware on infected machines. The latest version is written in <a href="https://nim-lang.org/">Nim</a>, a relatively new language utilized by threat actors the past two years, most notably by the NimzaLoader variant of BazarLoader used by the TrickBot group.</p>
<p>This article discusses the technical details of how IceXLoader behaves and the potential malware that it can deliver in an infected system.</p>
<p style="	margin-left: 40.0px;
"><b>Affected Platforms:</b> Windows<br />
<b>Impacted Parties:</b> Windows users<br />
<b>Impact: </b>Potential to deploy additional malware for <a href="https://www.fortinet.com/resources/cyberglossary/malware?utm_source&#61;blog&amp;utm_medium&#61;blog&amp;utm_campaign&#61;blog-malware">malicious purposes</a><br />
<b>Severity Level: </b>Medium</p>
<h2>The ICE X Project</h2>
<p>While hunting for new malware families written in the Nim programming language, <a href="https://www.fortinet.com/fortiguard/labs?utm_source&#61;blog&amp;utm_campaign&#61;fortiguardlabs">FortiGuard Labs</a> discovered a loader malware with the strings “ICE_X” and “v3.0”.<b></b></p>
<p>A loader is a type of malware that is intended for downloading and executing additional payloads provided by a threat actor to further their malicious objectives.</p>
<p>Collected samples had some incomplete features, for example the code for using a mutex for running only a single instance of the malware is only comprised of dummy code. When coupled with the “v3.0” string (implying the presence of earlier versions of a similar malware), we suspected that this was a work-in-progress port of an existing malware to Nim.</p>
<p>To validate our hypothesis, we dug deeper and found links to underground forums where the developers sell the loader as ICE X at $118 for a lifetime license (Figure 1).</p>

  <p>The developers market their loader as FUD (Fully UnDetected), a common term used within malware hacking forums to denote malware that can bypass antivirus products. They also claim that they will continuously update it as security products eventually detect such malware.</p>
<p>This need to evade security products could be a reason the developers chose to transition from AutoIt to Nim for IceXLoader version 3. Since Nim is a relatively uncommon language for applications to be written in, threat actors take advantage of the lack of focus on this area in terms of analysis and detection.</p>
<p>The following technical analysis will focus primarily on IceXLoader version 3. However, comparisons to old versions are mentioned where necessary.</p>
<h2>Technical Details</h2>
<p>The IceXLoader builder generates a standalone executable EXE file with the chosen configuration values hardcoded into each file that a threat actor can distribute to potential victims.</p>
<p>Once this file is executed on a victim machine, it initializes itself based on the configured settings.</p>
<h4><span style="	font-weight: normal;
">Persistence</span></h4>
<p>If configured, IceXLoader utilizes Windows startup features commonly abused by malware to survive system reboots. It copies itself to %AppData%\Microsoft\Windows\Start Menu\Programs\Startup\<i> </i>with a configurable filename.</p>
<p>At the same time, it adds a registry entry in Software\Microsoft\Windows\CurrentVersion\Run with the value set to a second copy previously dropped in %AppData%.</p>
<p>As the mutex implementation is incomplete in the version 3 samples, multiple instances of IceXLoader will run when Windows restarts.</p>
<h4><span style="	font-weight: normal;
">Evasion</span></h4>
<p>IceXLoader performs a known method of in-memory patching of “AmsiScanBuffer” in AMSI.DLL. It does this to bypass the Microsoft Windows Antimalware Scan Interface used by security products to scan and detect malicious content. This reduces the chance of IceXLoader and its subsequent malware payloads being detected.</p>
<p>It then writes some PowerShell commands to %TEMP%\file.bat (Figure 6) and executes them to disable Windows Defender’s real-time scan. Moreover, it adds exclusions to Windows Defender to prevent it from scanning the directory where IceXLoader is located.</p>


</div>

<div class="cmp cmp-text aem-GridColumn aem-GridColumn--default--12">
  <p>Once the malware has completed initialization, it proceeds to communicate with the C2 to carry out further actions in the victim system.</p>
<h4><span style="	font-weight: normal;
">Client-Server Communication Protocol</span></h4>
<p>IceXLoader communicates with a hardcoded list of C2 servers via HTTP/HTTPS POST requests. The User-Agent HTTP header is set to the Windows machine GUID, which uniquely identifies each infected machine. This could be referred to as a victim ID. Communication between the loader and C2 is in plaintext and is not encoded or encrypted.</p>
<p>Figure 7 demonstrates the communication flow between IceXLoader and its C2 server. The “info” command is used as an example below, but other commands use a similar flow:</p>

<div class="cmp cmp-text aem-GridColumn aem-GridColumn--default--12">
  <p>An initial beaconing POST request with “SetOn&#61;On” is sent by IceXLoader to notify the C2 that it is ready to receive commands.</p>
<p>The C2 server usually responds with an “info” command to register the loader as a valid client in the server panel. The client acknowledges the command by responding with “Done&#61;<i>&lt;command&gt;</i>&lt;|&gt;” i.e., “Done&#61;info&lt;|&gt;”. After that, the client executes the command.</p>
<p> For the “info” command, IceXLoader collects the following information and sends it to the C2 server</p>
<ul><li>Nickname (set by malware operator and hardcoded in binary sample, “ICE X” by default)</li><li>Victim ID</li><li>Username and machine name and whether user has administrative privileges</li><li>Windows OS version</li><li>Installed antivirus products</li><li>Presence of .NET Framework v2.0 and/or v4.0</li><li>Loader version (hardcoded in binary sample)</li><li>Total amount of installed memory</li><li>Processor name</li><li>Graphics card name<br />
</li></ul>
<p>Figure 8 shows an HTTP POST request with all the information gathered from the victim system.</p>

<div class="cmp cmp-text aem-GridColumn aem-GridColumn--default--12">
  <h2>Commands</h2>
<p>Once the system info is sent to the C2 server, IceXLoader regularly repeats the beaconing request to poll for additional commands.</p>
<p>The list of all the commands supported by IceXLoader can be found below. The pipe “|” character is used to separate options for the commands. Words in <i>italics</i> refer to values supplied by the threat actor.</p>
<ul><li><b>close: </b>Stop execution</li><li><b>info:</b> Collect system info and send it to C2</li><li><b>msg|<i>MESSAGE:</i></b> Display a dialog box with specified message</li><li><b>restart: </b>Restart the loader</li><li><b>runFile|<i>URL</i>|<i>TEMP_FILE_NAME</i>:</b> Send a GET request to download a file from URL to %TEMP% as TEMP_FILE_NAME and then open it with “cmd /c”. The advantage of using “cmd /c” is the ability to open any file type registered on the system, e.g., .txt files or Office documents. It is not limited to just executable files</li><li><b>runFile|<i>URL</i>|mem|True: </b>Send a GET request to download an executable file from URL and run it from memory</li><li><b>runFile|<i>URL</i>|mem|False:</b> Not fully implemented in version 3. This command loads and executes a .NET assembly in version 1</li><li><b>Sleep|<i>INTERVAL</i></b>: Change the C2 server beaconing interval to the new value specified by INTERVAL (in milliseconds)</li><li><b>Update: </b>Current implementation in version 3 is identical to the “runFile” command, but original implementation in version 1 was designed for updating IceXLoader itself</li><li><b>uninstall:</b> Remove all copies of itself from disk and stop running<br />
</li></ul>
<p>As the main function of IceXLoader, the malware operator can interactively send “runFile” commands to the loader to download and execute additional malware on disk or filelessly in memory.</p>

<h2>Conclusion</h2>
<p>In this article, we highlighted how threat actors continually evolve to evade and deter detection of their malware to the extent of porting existing code to a different and uncommon language. While simple and limited in functionality, loaders like IceXLoader pose a threat to users due to the possibility of threat actors deploying more full-featured malware upon infection.</p>
<p>FortiGuard Labs will continue to monitor IceXLoader and emerging trends in the loader threat landscape.</p>
