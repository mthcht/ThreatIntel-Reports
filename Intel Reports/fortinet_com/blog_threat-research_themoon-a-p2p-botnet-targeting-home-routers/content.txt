        <p>The vulnerable ASUS router will &nbsp;download and execute the binary file .nttpd from the attacker controlled website. &nbsp;The following figure shows its MD5 hash and file attributes:</p>

        <p><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/themoon-a-p2p-botnet-targeting-home-routers-2970.png" data-style="width: 723px; height: 105px;"/></p>

        <p align="center">Figure 2 md5sum and file attributes</p>

        <p>A simple search shows that this bot was analyzed <a href="https://vms.drweb-av.pl/virus/?i=7936862&amp;lng=en">here</a>. &nbsp;However, that analysis was based on sample MD5: c44f2d8ad37c18ea84a99db584d6992d, and some parts are misleading, so we want to share our updated findings in this post.</p>

        <p>This bot belongs to the TheMoon family of malware, which shares the following program structure.</p>

        <p align="center"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/themoon-a-p2p-botnet-targeting-home-routers-2971.png" data-style="width: 300px; height: 338px;"/></p>

        <p align="center">Figure 3 Program structure of <em>TheMoon</em> family</p>

        <p>The differences between the family members are mainly located in functions os_init and run_modules.</p>

        <p>This bot inserts the following eight iptables rules in function os_init.</p>

        <p><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/themoon-a-p2p-botnet-targeting-home-routers-2972.png" data-style="width: 571px; height: 134px;"/></p>

        <p align="center">Figure 3 iptables rules</p>

        <p>The first rule stops other attackers from exploiting the ASUS vulnerability CVE-2014-9583, while the second one stops other attackers from exploiting the <a href="https://fortiguard.com/encyclopedia/ips/38026">Linksys Unauthenticated Remote Code Execution vulnerability.</a></p>

        <p>All the rest ensure that the attacker has access to this router. We will talk about hard-coded peers later in this post.</p>

        <p>In the function run_modules, this bot launches three modules: &ldquo;clk,&rdquo; &ldquo;net&rdquo; and &ldquo;dwl.&rdquo; Let&rsquo;s analyze them one by one.</p>

        <h3>Clk Module</h3>

        <p>This module launchs two threads.&nbsp; The first one calculates the running time while the second one maintains the time. This bot queries public NTP servers for the UTC time, as shown in the following figure.</p>

        <p><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/themoon-a-p2p-botnet-targeting-home-routers-2973.png" data-style="width: 653px; height: 108px;"/></p>

        <p align="center">Figure 4 Hard-coded NTP servers</p>

        <p>The following figure shows an NTP request sent by this bot, and the response from the public NTP server.</p>

        <p><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/themoon-a-p2p-botnet-targeting-home-routers-2974.png" data-style="width: 804px; height: 266px;"/></p>

        <p align="center">Figure 5 NTP request and response</p>

        <p>We don&rsquo;t believe that these hard-coded IP addresses are C&amp;C servers, as was claimed<a href="https://vms.drweb-av.pl/virus/?i=7936862&amp;lng=en"> here</a>.</p>

        <p>If the NTP query fails, the bot will instead use the local time.</p>

        <h3>Net Module</h3>

        <p>This module adds an iptables rule to open UDP port 5143, and then creates a thread which is responsible for P2P communication. &nbsp;It is worth mentioning that the supported message types are variant-specific, and usually different port numbers are used for communication.</p>

        <p>This bot supports following three types of message.</p>

        <ol>
            <li>Register message</li>
            <li>RegisterTo&nbsp; message</li>
            <li>FetchCommand message</li>
        </ol>

        <p>Every message contains a header and a body. All these messages share the following header structure:</p>

        <blockquote>
            <p>Offset &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;Size &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;Description</p>

            <p>0 &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;&nbsp;1 &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;Body length</p>

            <p>1 &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;&nbsp;&nbsp; &nbsp;1 &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;Message Type</p>

            <p>2 &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;&nbsp; &nbsp;&nbsp;1 &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;TTL</p>

            <p>3 &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;&nbsp; &nbsp; &nbsp;&nbsp;1 &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;0x8F (variant specific)</p>

            <p>For every received message, the bot decreases the TTL by one, and forwards the message to its peers if the result is not zero. The following figure demonstrates this behavior.</p>
        </blockquote>

        <p><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/themoon-a-p2p-botnet-targeting-home-routers-2975.png" data-style="width: 565px; height: 477px;"/></p>

        <p align="center">Figure 6 Forwarded message to its peers</p>

        <ol>
            <li><strong>Register message</strong></li>
        </ol>

        <p data-style="margin-left:.25in;">The type value of this message is 0. The bot sends this message to hard-coded peers after launching three modules successfully.</p>

        <p data-style="margin-left:.25in;"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/themoon-a-p2p-botnet-targeting-home-routers-2976.png" data-style="width: 489px; height: 163px;"/></p>

        <p data-style="margin-left:.25in;"><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/themoon-a-p2p-botnet-targeting-home-routers-2977.png" data-style="width: 974px; height: 546px;"/></p>

        <p align="center">Figure 7 register to hard-coded peers</p>

        <p>As you may remember, iptables rules are installed to allow access to these hard-coded peers. The following figure shows the traffic sent to hard-coded peers:</p>

        <p><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/themoon-a-p2p-botnet-targeting-home-routers-2978.png" data-style="width: 630px; height: 225px;"/></p>

        <p align="center">Figure 8 Register message</p>

        <p>The message body is comprised of two double words: The first one is 0x6d6163f4 (variant specific) and the second is the property value of this peer. The bot adds the sender as its peer after receiving this message. &nbsp;This bot supports 0x64 peers at maximum.</p>

        <ol>
            <li value="2"><strong>RegistertTo</strong></li>
        </ol>

        <p>The type value of this message is zero as well, but the message body is 12 bytes long. If the third double word is not zero, this bot sends a register message to a specified IP. Otherwise, it sends the register message to the sender. The following figure shows a RegisterTo message received by the bot.</p>

        <p><strong><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/themoon-a-p2p-botnet-targeting-home-routers-2979.png" data-style="width: 669px; height: 255px;"/> </strong></p>

        <p align="center">Figure 9 RegisterTo message</p>

        <ol>
            <li value="3"><strong>FetchCommand</strong></li>
        </ol>

        <p>The type value of this message is one. The following is the structure of the message body.</p>

        <blockquote>
            <p>Offset &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;Size &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;Description</p>

            <p>0&nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;&nbsp;4&nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;&nbsp;Peer IP address</p>

            <p>4&nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;4&nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;Command id</p>

            <p>8&nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;4 &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;&nbsp;Command size (Maximum 0x19001)</p>

            <p>12&nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;n&nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp; &nbsp;file name(n&lt;=8)</p>
        </blockquote>

        <p>The following figure shows a FetchCommand message received by this bot.</p>

        <p><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/themoon-a-p2p-botnet-targeting-home-routers-2980.png" data-style="width: 667px; height: 247px;"/></p>

        <p align="center">Figure 10 FetchCommand message</p>

        <p>If the sender is its peer, the bot stores the message in the following structure for the dwl module:</p>

        <blockquote>
            <p>Struct PendingCommand</p>

            <p>{</p>

            <p>DWORD ip;</p>

            <p>DWORD cmd_id;</p>

            <p>DWORD cmd_size;</p>

            <p>CHAR filename[8];</p>

            <p>};</p>
        </blockquote>

        <h3>Dwl Module</h3>

        <p>This module creates a thread which is responsible for handling the PendingCommand information created by the net module. This bot connects to TCP port 4543 of the designated IP and sends it the required file name and command id. The following figure shows the traffic captured through Wireshark:</p>

        <p><img alt="" src="/content/dam/fortinet-blog/new-images/uploads/themoon-a-p2p-botnet-targeting-home-routers-2981.png" data-style="width: 663px; height: 353px;"/></p>

        <p align="center">Figure 11 Command request</p>

        <p>The designed IP is supposed to return the requested file. The bot stores the response in the specified file and executes it. The following figure shows a sequence of calls that create and execute the file received:</p>

        <p><<img alt="" src="/content/dam/fortinet-blog/new-images/uploads/themoon-a-p2p-botnet-targeting-home-routers-2982.png" data-style="width: 561px; height: 625px;" /></p>

        <p align="center">Figure 12 download and execute command</p>

        <p>While we were unable to download a command file for analysis at the time of this post, based on the file name and size we monitor, they should be the TheMoon family members.</p>

        <h3>Conclusion</h3>

        <p>The TheMoon family was first discovered by <a href="https://isc.sans.edu/forums/diary/Linksys+Worm+TheMoon+Summary+What+we+know+so+far/17633/">SANS ISC</a> in 2014. This family targets routers and installs malware by exploiting their vulnerabilities. This bot is used on ASUS and Linksys routers based on their hard-coded iptables rules.</p>

        <p>We also discovered that its P2P communication is not as mature as its peers on PCs. For example, instead of using digital signing, the botmaster uses iptables to ensure only he can command the bots. Unfortunately, or fortunately, these rules can be bypassed. In addition, the communication is not encrypted, which leads to easier analysis and detection.</p>

        <p>Fortinet released following detections for this bot:</p>

        <p>AV: Linux/Agent.B!tr.bdr</p>

        <p>AppCtrl: TheMoon.Botnet</p>
