    <p><em>Note: we are updating as the investigation continues. Revision history listed at the bottom.</em></p>

</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>This post contains technical details about the methods of the actor we believe was involved in <a href="https://blogs.microsoft.com/on-the-issues/2020/12/13/customers-protect-nation-state-cyberattacks/" target="_blank" data-bi-compnm="null" rel="noopener noreferrer">Recent Nation-State Cyber Attacks</a>, with the goal to enable the broader security community to hunt for activity in their networks and contribute to a shared defense against this sophisticated threat actor. <strong>Please see the Microsoft Product Protections and Resources section for additional investigative updates, guidance, and released protections.</strong></p>

</div>

    

</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>As we wrote in that blog, while these elements aren’t present in every attack, this is a summary of techniques that are part of the toolkit of this actor.</p>

</div>

    

</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <ul><li>An intrusion through malicious code in the SolarWinds Orion product. This results in the attacker gaining a foothold in the network, which the attacker can use to gain elevated credentials. Microsoft Defender now has detections for these files. Also, see <a href="https://www.solarwinds.com/securityadvisory" target="_blank" data-bi-compnm="null" rel="noopener noreferrer">SolarWinds Security Advisory</a>.</li><li>Once in the network, the intruder then uses the administrative permissions acquired through the on-premises compromise to gain access to the organization’s global administrator account and/or trusted SAML token signing certificate. This enables the actor to forge SAML tokens that impersonate any of the organization’s existing users and accounts, including highly privileged accounts.</li><li>Anomalous logins using the SAML tokens created by the compromised token signing certificate can then be made against any on-premises resources (regardless of identity system or vendor) as well as to any cloud environment (regardless of vendor) because they have been configured to trust the certificate. Because the SAML tokens are signed with their own trusted certificate, the anomalies might be missed by the organization.</li><li>Using the global administrator account and/or the trusted certificate to impersonate highly privileged accounts, the actor may add their own credentials to existing applications or service principals, enabling them to call APIs with the permission assigned to that application.</li></ul>

</div>

    

</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>Due to the critical nature of this activity, Microsoft is sharing the following information to help detect, protect, and respond to this threat.</p>

</div>

    

</div>
<div class="heading aem-GridColumn aem-GridColumn--default--12" data-component-id="6b880e252846ae03b532f40bd58c2fae">

<h2 class="h2 mb-2 " data-automation-test-id="Heading-">Activity Description</h2>



</div>
<div class="heading aem-GridColumn aem-GridColumn--default--12" data-component-id="6b880e252846ae03b532f40bd58c2fae">

<h3 class="h3 mb-2 " data-automation-test-id="Heading-">Initial Access</h3>



</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>Although we do not know how the backdoor code made it into the library, from the recent campaigns, research indicates that the attackers might have compromised internal build or distribution systems of SolarWinds, embedding backdoor code into a legitimate SolarWinds library with the file name <code>SolarWinds.Orion.Core.BusinessLayer.dll</code>. This backdoor can be distributed via automatic update platforms or systems in target networks. Microsoft security researchers currently have limited information about how the attackers compromised these platforms.</p>

</div>

    

</div>
<div class="heading aem-GridColumn aem-GridColumn--default--12" data-component-id="6b880e252846ae03b532f40bd58c2fae">

<h3 class="h3 mb-2 " data-automation-test-id="Heading-">Execution</h3>



</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>While updating the SolarWinds application, the embedded backdoor code loads before the legitimate code executes. Organizations are misled into believing that no malicious activity has occurred and that the program or application dependent on the libraries is behaving as expected.</p>

</div>

    

</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>The attackers have compromised signed libraries that used the target companies’ own digital certificates, attempting to evade application control technologies. Microsoft already removed these certificates from its trusted list. The certificate details with the signer hash are shown below:</p>

</div>

    

</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>

  
    <img src="https://cdn-dynmedia-1.microsoft.com/is/image/microsoftcorp/2020__12__86f33cb1?scl&#61;1" class="mx-auto d-block img-fluid max-height-600"/>
  

</p>

</div>

    

</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>The DLL then loads from the installation folder of the SolarWinds application. Afterwards, the main implant installs as a Windows service and as a DLL file in the following path using afolder with different names:</p>

</div>

    

</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">

<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>Microsoft security researchers observed malicious code from the attacker activated only when running under <code>SolarWinds.BusinessLayerHost.exe</code> process context for the DLL samples currently analyzed.</p>

</div>

    

</div>
<div class="heading aem-GridColumn aem-GridColumn--default--12" data-component-id="6b880e252846ae03b532f40bd58c2fae">

<h3 class="h3 mb-2 " data-automation-test-id="Heading-">Command-and-control (C2)</h3>



</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>The malicious DLL calls out to a remote network infrastructure using the domains <em>avsvmcloud.com</em>. to prepare possible second-stage payloads, move laterally in the organization, and compromise or exfiltrate data.</p>

</div>

    

</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>Microsoft detects the main implant and its other components as Solorigate.</p>

</div>

    

</div>
<div class="heading aem-GridColumn aem-GridColumn--default--12" data-component-id="6b880e252846ae03b532f40bd58c2fae">

<h3 class="h3 mb-2 " data-automation-test-id="Heading-">Actions on Objectives</h3>



</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>In actions observed at the Microsoft cloud, attackers have either gained administrative access using compromised privileged account credentials (e.g. stolen passwords) or by forging SAML tokens using compromised SAML token signing certificates.</p>

</div>

    

</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>In cases where we see SAML token signing certificate compromise, there are cases where the specific mechanism by which the actor gains access to the certificate has not been determined. In the cases we have determined that the SAML token signing certificate was compromised, common tools were used to access the database that supports the SAML federation server using administrative access and remote execution capabilities.</p>

</div>

    

</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>In other cases, service account credentials had been granted administrative privileges; and in others, administrative accounts may have been compromised by unrelated mechanisms. Typically, the certificate is stored on the server that provides the SAML federation capabilities; this makes it accessible to anyone with administrative rights on that server, either from storage or by reading memory.</p>

</div>

    

</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>Once the certificate has been acquired, the actor can forge SAML tokens with whatever claims and lifetime they choose, then sign it with the certificate that has been acquired. By doing this, they can access any resources configured to trust tokens signed with that SAML token signing certificate. This includes forging a token which claims to represent a highly privileged account in Azure AD.</p>

</div>

    

</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>As with on premises accounts, the actor may also gain administrative Azure AD privileges with compromised credentials. This is particularly likely if the account in question is not protected by multi-factor authentication.</p>

</div>

    

</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>Regardless of whether the actor minted SAML tokens or gained access to Azure AD through other means, specific malicious activities have been observed using these administrative privileges to include long term access and data access as described below.</p>

</div>

    

</div>
<div class="heading aem-GridColumn aem-GridColumn--default--12" data-component-id="6b880e252846ae03b532f40bd58c2fae">

<h3 class="h3 mb-2 " data-automation-test-id="Heading-">Long Term Access</h3>



</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>Having gained a significant foothold in the on premises environment, the actor has made modifications to Azure Active Directory settings to facilitate long term access.</p>

</div>

    

</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <ol><li>
<p>Federation Trusts</p>
<ul><li>Microsoft has observed the actor <a href="https://docs.microsoft.com/office365/troubleshoot/active-directory/update-federated-domain-office-365" target="_blank" data-bi-compnm="null" rel="noopener noreferrer">adding new federation trusts</a> to an existing tenant or modifying the properties of an existing federation trust to accept tokens signed with actor-owned certificates.</li></ul>
</li><li>
<p>OAuth Application &amp; Service Principal Credentials</p>
<ul><li>The actor has been observed adding credentials (x509 keys or password credentials) to one or more legitimate OAuth Applications or Service Principals, usually with existing <em>Mail.Read</em> or _Mail.ReadWrite _permissions, which grants the ability to read mail content from Exchange Online via Microsoft Graph or Outlook REST. Examples include mail archiving applications. Permissions are usually, but not always, AppOnly.</li><li>The actor may use their administrator privileges to grant additional permissions to the target Application or Service Principal (e.g. <em>Mail.Read</em>, <em>Mail.ReadWrite</em>).</li></ul>
</li></ol>

</div>

    

</div>
<div class="heading aem-GridColumn aem-GridColumn--default--12" data-component-id="6b880e252846ae03b532f40bd58c2fae">

<h3 class="h3 mb-2 " data-automation-test-id="Heading-">Data Access</h3>



</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>Data access has relied on leveraging minted SAML tokens to access user files/email or impersonating the Applications or Service Principals by authenticating and obtaining Access Tokens using credentials that were added in 2a. Above. The actor periodically connects from a server at a VPS provider to access specific users’ emails using the permissions granted to the impersonated Application or Service Principal. In many cases, the targeted users are key IT and security personnel. By impersonating existing applications that use permissions like <em>Mail.Read</em> to call the same APIs leveraged by the actor, the access is hidden amongst normal traffic. For this reason, if you suspect you are impacted you should assume your communications are accessible to the actor.</p>

</div>

    

</div>
<div class="heading aem-GridColumn aem-GridColumn--default--12" data-component-id="6b880e252846ae03b532f40bd58c2fae">

<h2 class="h2 mb-2 " data-automation-test-id="Heading-">Recommended Defenses</h2>



</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <p>If your organization has not been attacked or compromised by this actor, Microsoft recommends you consider the following actions to protect against the techniques described above as part of your overall response. This is not an exhaustive list, and Microsoft may choose to update this list as new mitigations are determined:</p>

</div>

    

</div>
<div class="richtext aem-GridColumn aem-GridColumn--default--12" data-component-id="aca330e78c05fd9ffbcf8222be356f7b">
<div class="cmp-text text-break" data-automation-test-id="RichTextV1Div-">
    
    <ol><li>Run up to date antivirus or EDR products that detect compromised SolarWinds libraries and potentially anomalous process behaviour by these binaries. Consider disabling SolarWinds in your environment entirely until you are confident that you have a trustworthy build free of injected code. For more details consult <a href="https://www.solarwinds.com/securityadvisory" target="_blank" data-bi-compnm="null" rel="noopener noreferrer">SolarWinds’ Security Advisory</a>.</li><li>Block known C2 endpoints listed below in IOCs using your network infrastructure.</li><li>Follow the best practices of your identity federation technology provider in securing your SAML token signing keys. Consider hardware security for your SAML token signing certificates if your identity federation technology provider supports it. Consult your identity federation technology provider for specifics. For Active Directory Federation Services, review Microsoft’s recommendations here: <a href="https://docs.microsoft.com/en-us/windows-server/identity/ad-fs/deployment/best-practices-securing-ad-fs" target="_blank" data-bi-compnm="null" rel="noopener noreferrer">Best Practices for Securing ADFS</a></li><li>Ensure that user accounts with administrative rights follow best practices, including use of privileged access workstations, JIT/JEA, and strong authentication. Reduce the number of users that are members of highly privileged Directory Roles, like Global Administrator, Application Administrator, and Cloud Application Administrator.</li><li>Ensure that service accounts and service principals with administrative rights use high entropy secrets, like certificates, stored securely. Monitor for changes to secrets used for service accounts and service principals as part of your security monitoring program. Monitor for anomalous use of service accounts. <a href="https://docs.microsoft.com/en-us/azure/active-directory/reports-monitoring/concept-all-sign-ins" target="_blank" data-bi-compnm="null" rel="noopener noreferrer">Monitor your sign ins</a> . Microsoft Azure AD indicates session anomalies, as does Microsoft Cloud App Security if in use.</li><li>Reduce surface area by removing/disabling unused or unnecessary applications and service principals. Reduce permissions on active applications and service principals, especially application (AppOnly) permissions.</li><li>See <a href="https://docs.microsoft.com/azure/security/fundamentals/steps-secure-identity" target="_blank" data-bi-compnm="null" rel="noopener noreferrer">Secure your Azure AD identity infrastructure</a> for more recommendations.</li></ol>

</div>

    

</div>
