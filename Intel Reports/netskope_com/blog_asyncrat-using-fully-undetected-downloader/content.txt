  (function () {
    let pagefind;
    let debounceTimer;

    async function loadPagefind() {
      if (pagefind) return pagefind;
      try {
        pagefind = await import('/pagefind/pagefind.js');
        await pagefind.init();
      } catch {
        pagefind = null;
      }
      return pagefind;
    }

    function initSearch() {
      const overlay = document.getElementById('search-overlay');
      const openBtn = document.getElementById('search-open');
      const closeBtn = document.getElementById('search-close');
      const input = document.getElementById('search-input');
      const results = document.getElementById('search-results');

      function openModal() {
        overlay?.classList.remove('hidden');
        overlay?.classList.add('flex');
        input?.focus();
        loadPagefind();
      }

      function closeModal() {
        overlay?.classList.add('hidden');
        overlay?.classList.remove('flex');
        if (input) input.value = '';
        if (results) results.innerHTML = '';
      }

      openBtn?.addEventListener('click', openModal);
      closeBtn?.addEventListener('click', closeModal);
      overlay?.addEventListener('click', (e) => {
        if (e.target === overlay) closeModal();
      });
      document.addEventListener('keydown', (e) => {
        if (e.key === 'Escape') closeModal();
        if ((e.metaKey || e.ctrlKey) && e.key === 'k') {
          e.preventDefault();
          openModal();
        }
      });

      input?.addEventListener('input', () => {
        clearTimeout(debounceTimer);
        debounceTimer = setTimeout(runSearch, 200);
      });

      async function runSearch() {
        const query = input?.value.trim() ?? '';
        if (!results) return;
        if (!query) {
          results.innerHTML = '';
          return;
        }

        const pf = await loadPagefind();
        if (!pf) {
          results.innerHTML = `<p class="p-4 text-sm text-(--text-secondary)">Search is unavailable in development. It runs against the built site.</p>`;
          return;
        }

        const search = await pf.search(query);
        if (search.results.length === 0) {
          results.innerHTML = `<p class="p-4 text-sm text-(--text-secondary)">No results for "${query}".</p>`;
          return;
        }

        const items = await Promise.all(search.results.slice(0, 8).map((r) => r.data()));
        results.innerHTML = items
          .map(
            (item) => `
            <a href="${item.url}" class="block px-4 py-3 border-b border-(--border-subtle) last:border-0 hover:bg-(--bg-tertiary) transition-colors">
              <p class="font-medium text-(--text-primary) text-sm mb-1">${item.meta?.title ?? item.url}</p>
              <p class="text-xs text-(--text-secondary) line-clamp-2">${item.excerpt}</p>
            </a>
          `,
          )
          .join('');
      }
    }

    // Initialize on page load and after Astro view transitions
    document.addEventListener('astro:page-load', initSearch);
  })();

lg:px-8 py-12 bg-(--bg-primary)"><div class="prose max-w-none"><h2 id="summary">Summary</h2>
<p><a href="https://malpedia.caad.fkie.fraunhofer.de/details/win.asyncrat">AsyncRAT</a> is an open-source remote administration tool <a href="https://github.com/NYAN-x-CAT/AsyncRAT-C-Sharp">released on GitHub</a> in January 2019. It’s designed to remotely control computers via encrypted connection, providing complete control via functionalities such as:</p>
<ul>
<li>View and record screen</li>
<li><a href="/library/malware/keylogger" class="threat-link">Keylogger</a></li>
<li>Upload, download and execute files</li>
<li>Chat communication</li>
<li>Persistence mechanisms</li>
<li>Disable Windows Defender</li>
<li><a href="/library/malware/shutdown" class="threat-link">Shutdown</a> / Restart the machine</li>
<li>DOS attack</li>
</ul>
<p>Although the official GitHub repository contains a legal disclaimer, <a href="/library/malware/asyncrat" class="threat-link">AsyncRAT</a> is popularly used by attackers and even some <a href="https://www.trendmicro.com/it_it/research/22/d/new-apt-group-earth-berberoka-targets-gambling-websites-with-old.html">APT groups</a>. Netskope Threat Labs recently came across a <a href="https://twitter.com/malwrhunterteam/status/1559881926688784385">FUD (Fully Undetected) Batch script</a> which is downloading AsyncRAT from an Amazon S3 Bucket. At the time of our analysis, the Batch script wasn’t being detected by any of the antivirus engines on VirusTotal. The attacker used some simple techniques to make the script fly under the radar, as we will describe later in this analysis.</p>
<p>The downloaded file (second stage) is a PowerShell script that creates and uses multiple files to execute AsyncRAT, which is injected into a legitimate process.</p>
<p><img src="/_astro/asyncrat-1-1024x575.CJtTbs-0_Z26CUm6.webp" alt="AsyncRAT Attack Flow Summary" loading="lazy" decoding="async" width="1024" height="575"></p>
<p>In this blog post, we will analyze the complete infection flow of AsyncRAT, from the FUD BAT downloader spotted by the <a href="https://twitter.com/malwrhunterteam">MalwareHunterTeam</a> to the last payload.</p>
<h2 id="stage-01---fud-downloader">Stage 01 - FUD Downloader</h2>
<p>The first stage is a batch script that contains <a href="https://www.virustotal.com/gui/file/16b4a6fec76b452f77a6832871ff2e906d673e557a0e6c2673fc952181d1319b">zero detections</a> on VirusTotal.</p>
<p><img src="/_astro/asyncrat-2.Dh7wZO7F_Z2fiYEw.webp" alt="Screenshot of FUD AsyncRAT downloader." loading="lazy" decoding="async" width="680" height="222"></p>
<p>FUD AsyncRAT downloader.</p>
<p>Although no AV vendor is detecting the file, it contains many detections via <a href="/library/malware/sigma" class="threat-link">Sigma</a> and IDS rules, as well as by sandboxes used by VirusTotal.</p>
<p><img src="/_astro/asyncrat-3.B7z13yrk_ZCt2tL.webp" alt="Screenshot of Sigma rules detecting malicious behavior." loading="lazy" decoding="async" width="883" height="449"></p>
<p>Sigma rules detecting malicious behavior.</p>
<p>The file not being detected is likely due to a long string added in the file multiple times (more than 100) by the attacker.</p>
<p><img src="/_astro/asyncrat-4-1024x553.aENmyjpV_Zg9dE2.webp" alt="Screenshot of commented strings added to the file." loading="lazy" decoding="async" width="1024" height="553"></p>
<p>Commented strings added to the file.</p>
<p>The string is always the same and is in Japanese. Doing a rough translation, this string seems to be nonsense words added by the attacker.</p>
<p><img src="/_astro/asyncrat-5.B4445EQv_1iY6tz.webp" alt="Screenshot of the rough translation from the string found multiple times in the file." loading="lazy" decoding="async" width="575" height="184"></p>
<p>Rough translation from the string found multiple times in the file.</p>
<p>The malicious command is quite simple and it can be found within the nonsense strings. It’s slightly obfuscated, which probably contributes to the absence of detection.</p>
<p><img src="/_astro/asyncrat-6.CrgVZZ6I_Zyxtso.webp" alt="Example of command executed by the batch file." loading="lazy" decoding="async" width="920" height="362"></p>
<p>Command executed by the batch file.</p>
<p>The command downloads and executes the second stage via PowerShell from an Amazon S3 bucket.</p>
<h2 id="stage-02---powershell">Stage 02 - PowerShell</h2>
<p>The file downloaded from the Amazon S3 bucket is a PowerShell script. As we demonstrated in the diagram in the summary section, this script creates multiple files to execute the last stage.</p>
<p>First, it creates a folder named “Not” in “C:\ProgramData”.</p>
<p><img src="/_astro/asyncrat-7.DhfE90C2_Eyqfo.webp" alt="Example of second stage creating a directory." loading="lazy" decoding="async" width="330" height="64"></p>
<p>Second stage creating a directory.</p>
<p>Then, it creates five files in this directory. The primary goal of this stage is to run another PowerShell script in a chained execution, described below:</p>
<ol>
<li>File “xx.vbs” is executed by the second stage;</li>
<li>File “xx.vbs” executes file “xx.bat”;</li>
<li>File “xx.bat” executes file “Bin.vbs” via scheduled task;</li>
<li>File “Bin.vbs” executes file “Bin.bat”;</li>
<li>And finally, “Bin.bat” executes “Bin.ps1” via PowerShell.</li>
</ol>
<p><img src="/_astro/asyncrat-8.Csi0wP9v_Z2vCmBy.webp" alt="Example of chained execution to run “Bin.ps1”." loading="lazy" decoding="async" width="714" height="430"></p>
<p>Chained execution to run “Bin.ps1”.</p>
<p>There are two PE files within the last PowerShell script.</p>
<p><img src="/_astro/asyncrat-9.BHpNlyO4_146m5I.webp" alt="Example of two PE files within the last PowerShell script." loading="lazy" decoding="async" width="620" height="356"></p>
<p>Two PE files within the last PowerShell script.</p>
<p>The first file is known as “RunPE” and it’s used to inject AsyncRAT into a legitimate process, which is the second PE file in the script.</p>
<p><img src="/_astro/asyncrat-10.BRONSr2e_ZS60s3.webp" alt="Example of PowerShell running RunPE." loading="lazy" decoding="async" width="637" height="132"></p>
<p>PowerShell running RunPE.</p>
<p>The PowerShell script loads RunPE directly into memory, so none of the PE files are written into disk.</p>
<h2 id="stage-03---runpe">Stage 03 - RunPE</h2>
<p>This file is responsible for injecting AsyncRAT into another process using <a href="https://attack.mitre.org/techniques/T1055/012/">Process Hollowing</a>. It’s developed in .NET and protected with Confuser.</p>
<p><img src="/_astro/asyncrat-11.BPKkWWSV_9JGsI.webp" alt="Screenshot of RunPE details." loading="lazy" decoding="async" width="632" height="271"></p>
<p>RunPE details.</p>
<p>The PowerShell script in the second stage loads RunPE in memory and calls a method named “Execute” from “GIT.local”. The method receives the path of the targeted executable (“C:\Windows\Microsoft.NET\Framework\v4.0.30319\aspnet_compiler.exe”) and the AsyncRAT bytes in the arguments.</p>
<p><img src="/_astro/asyncrat-12.DTtw00e7_sIB62.webp" alt="Example of the method executed by the PowerShell." loading="lazy" decoding="async" width="418" height="378"></p>
<p>Method executed by the PowerShell.</p>
<p>After removing part of the obfuscation, we can confirm that AsyncRAT is being injected via Process Hollowing.</p>
<p><img src="/_astro/asyncrat-13.BdEtfpC8_2t8rGl.webp" alt="Screenshot of some of the API calls used for Process Hollowing." loading="lazy" decoding="async" width="796" height="336"></p>
<p>Some of the API calls used for Process Hollowing.</p>
<h2 id="stage-04---asyncrat">Stage 04 - AsyncRAT</h2>
<p>As previously mentioned, AsyncRAT is an open-source remote administration tool developed in .NET, and it’s often abused by attackers. The specific sample analyzed in this blog post was likely compiled on July 22, 2022.</p>
<p><img src="/_astro/asyncrat-14.BhfZ0gbw_8gR8H.webp" alt="Screenshot of AsyncRAT sample delivered by the FUD Batch script." loading="lazy" decoding="async" width="629" height="272"></p>
<p>AsyncRAT sample delivered by the FUD Batch script.</p>
<p>This sample doesn’t contain any obfuscation or protection, so it’s not difficult to understand the code once decompiled.</p>
<p><img src="/_astro/asyncrat-15.DtUTK3bt_Z4ANm1.webp" alt="Screenshot of decompiled AsyncRAT sample." loading="lazy" decoding="async" width="288" height="250"></p>
<p>Decompiled AsyncRAT sample.</p>
<p>We can summarize AsyncRAT’s main execution flow in six-steps:</p>
<ol>
<li>Initialize its configuration (decrypts the strings);</li>
<li>Verifies and creates a Mutex (to avoid running duplicated instances);</li>
<li>If enabled in the settings, exits if a virtualized or analysis environment is detected;</li>
<li>If enabled in the settings, establishes persistence;</li>
<li>If enabled in the settings, sets its own process as critical;</li>
<li>Starts the communication with the server.</li>
</ol>
<p><img src="/_astro/asyncrat-16.CiaBQizx_Z1U2cG.webp" alt="Example of the AsyncRAT main method." loading="lazy" decoding="async" width="515" height="520"></p>
<p>AsyncRAT main method.</p>
<p>AsyncRAT’s configuration is decrypted within the “InitializeSettings” method.</p>
<p><img src="/_astro/asyncrat-17.BxRn7_ep_ZtY4Ry.webp" alt="Screenshot of AsyncRAT method that initializes the configuration." loading="lazy" decoding="async" width="945" height="352"></p>
<p>AsyncRAT method that initializes the configuration.</p>
<p>AsyncRAT uses AES-256 in CBC mode to decrypt the strings.</p>
<p><img src="/_astro/asyncrat-18-1024x608.CzHrzwsZ_Z2tHo16.webp" alt="Example of AsyncRAT method that decrypts data using AES." loading="lazy" decoding="async" width="1024" height="608"></p>
<p>AsyncRAT method that decrypts data using AES.</p>
<p>This function reads a base64 encoded string, where the first 32 bytes represents the HMAC, the following 16 bytes the decryption IV, and the remaining bytes are the encrypted data.</p>
<p><img src="/_astro/asyncrat-19.GicyfD74_ZcqiUW.webp" alt="Example of AsyncRAT variables storing encrypted data." loading="lazy" decoding="async" width="1001" height="179"></p>
<p>AsyncRAT variables storing encrypted data.</p>
<p>We created a <a href="https://github.com/netskopeoss/NetskopeThreatLabsIOCs/tree/main/AsyncRAT/script">Python script</a> that can be used to decrypt AsyncRAT strings using the same algorithm.</p>
<p><img src="/_astro/asyncrat-20.FBKDYXXT_1cmkzL.webp" alt="Example of decrypting AsyncRAT configuration." loading="lazy" decoding="async" width="825" height="744"></p>
<p>Decrypting AsyncRAT configuration.</p>
<p>The anti-analysis feature of this sample is disabled, but AsyncRAT provides the option to detect virtualized and analysis environments via simple techniques, such as checking the disk size, checking the OS manufacturer and model, etc.</p>
<p><img src="/_astro/asyncrat-21.Cnda-KSo_ZdD3Dy.webp" alt="Example of AsyncRAT anti-analysis method." loading="lazy" decoding="async" width="668" height="176"></p>
<p>AsyncRAT anti-analysis method.</p>
<p>It’s also able to establish persistence via registry or a scheduled task.</p>
<p><img src="/_astro/asyncrat-22-1024x391.CQazeq_5_CoD79.webp" alt="Screenshot of AsyncRAT persistence mechanisms." loading="lazy" decoding="async" width="1024" height="391"></p>
<p>AsyncRAT persistence mechanisms.</p>
<p>Furthermore, AsyncRAT stores the C2 address and port within its configuration. However, it also provides the option to download this information from Pastebin.</p>
<p><img src="/_astro/asyncrat-23.DZqpqXYd_ZkBSWg.webp" alt="Example of method to download C2 address and port from Pastebin." loading="lazy" decoding="async" width="606" height="191"></p>
<p>Method to download C2 address and port from Pastebin.</p>
<p>After all the steps executed by the main function, which we summarized earlier, AsyncRAT starts an encrypted communication with the C2 server. Once connected, the attacker has full control over the device through GUI, as shown in the example below.</p>
<p><img src="/_astro/asyncrat-24.BJseRrNW_Z2cR1ge.webp" alt="Example of AsyncRAT controller." loading="lazy" decoding="async" width="888" height="404"></p>
<p>Example of AsyncRAT controller.</p>
<h2 id="conclusions">Conclusions</h2>
<p>In this blog post, we analyzed the complete attack flow of AsyncRAT, from the downloader to the last payload. In this scenario, the attacker used simple techniques to make the downloader fly under the radar, being detected by none of the engines on VirusTotal. Furthermore, since AsyncRAT is open-source, one could easily change its code to add or remove functionalities as needed.</p>
<p>Batch scripts like this are commonly used by attackers as an initial foothold. We expect an increase in the use of this file type and others (such as LNK and VBS) after Microsoft released a <a href="/blog/2022/02/microsoft-office-vba-blocked-by-default-in-files-from-the-internet">protection</a> against malicious Microsoft Office macros, which are also popularly abused to deliver malware. Netskope Threat Labs always recommends users avoid opening files of unknown origin, especially those received by email. For organizations, we strongly recommend security training for employees and to use a secure web gateway with advanced threat protection, being able to scan and detect malicious files in real-time.</p>
