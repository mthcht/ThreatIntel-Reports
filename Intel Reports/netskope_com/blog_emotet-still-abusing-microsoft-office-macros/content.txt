  (function () {
    let pagefind;
    let debounceTimer;

    async function loadPagefind() {
      if (pagefind) return pagefind;
      try {
        pagefind = await import('/pagefind/pagefind.js');
        await pagefind.init();
      } catch {
        pagefind = null;
      }
      return pagefind;
    }

    function initSearch() {
      const overlay = document.getElementById('search-overlay');
      const openBtn = document.getElementById('search-open');
      const closeBtn = document.getElementById('search-close');
      const input = document.getElementById('search-input');
      const results = document.getElementById('search-results');

      function openModal() {
        overlay?.classList.remove('hidden');
        overlay?.classList.add('flex');
        input?.focus();
        loadPagefind();
      }

      function closeModal() {
        overlay?.classList.add('hidden');
        overlay?.classList.remove('flex');
        if (input) input.value = '';
        if (results) results.innerHTML = '';
      }

      openBtn?.addEventListener('click', openModal);
      closeBtn?.addEventListener('click', closeModal);
      overlay?.addEventListener('click', (e) => {
        if (e.target === overlay) closeModal();
      });
      document.addEventListener('keydown', (e) => {
        if (e.key === 'Escape') closeModal();
        if ((e.metaKey || e.ctrlKey) && e.key === 'k') {
          e.preventDefault();
          openModal();
        }
      });

      input?.addEventListener('input', () => {
        clearTimeout(debounceTimer);
        debounceTimer = setTimeout(runSearch, 200);
      });

      async function runSearch() {
        const query = input?.value.trim() ?? '';
        if (!results) return;
        if (!query) {
          results.innerHTML = '';
          return;
        }

        const pf = await loadPagefind();
        if (!pf) {
          results.innerHTML = `<p class="p-4 text-sm text-(--text-secondary)">Search is unavailable in development. It runs against the built site.</p>`;
          return;
        }

        const search = await pf.search(query);
        if (search.results.length === 0) {
          results.innerHTML = `<p class="p-4 text-sm text-(--text-secondary)">No results for "${query}".</p>`;
          return;
        }

        const items = await Promise.all(search.results.slice(0, 8).map((r) => r.data()));
        results.innerHTML = items
          .map(
            (item) => `
            <a href="${item.url}" class="block px-4 py-3 border-b border-(--border-subtle) last:border-0 hover:bg-(--bg-tertiary) transition-colors">
              <p class="font-medium text-(--text-primary) text-sm mb-1">${item.meta?.title ?? item.url}</p>
              <p class="text-xs text-(--text-secondary) line-clamp-2">${item.excerpt}</p>
            </a>
          `,
          )
          .join('');
      }
    }

    // Initialize on page load and after Astro view transitions
    document.addEventListener('astro:page-load', initSearch);
  })();

<p>In April 2022, Netskope Threat Labs analyzed an <a href="/library/malware/emotet" class="threat-link">Emotet</a> campaign that was <a href="/blog/2022/05/emotet-new-delivery-mechanism-to-bypass-vba-protection">using LNK files</a> instead of Microsoft Office documents, likely as a response to the <a href="/blog/2022/02/microsoft-office-vba-blocked-by-default-in-files-from-the-internet">protections launched by Microsoft</a> in 2022 to mitigate attacks via Excel 4.0 (XLM) and VBA macros.</p>
<p>However, we recently came across hundreds of malicious Office documents that are being used to download and execute Emotet, indicating that some attackers are still using old delivery methods in the wild. Despite the protection Microsoft released in 2022 to <a href="https://techcommunity.microsoft.com/t5/excel-blog/excel-4-0-xlm-macros-now-restricted-by-default-for-customer/ba-p/3057905">prevent the execution of Excel 4.0 (XLM) macros</a>, this attack is still feasible against users who are using outdated versions of Office. It is also feasible against users who have changed the default setting to explicitly enable macros. The fact that attackers are still using Excel 4.0 Macros indicates that outdated Office versions and users who have this protection disabled are still common.</p>

Most of the files share the same URLs and some metadata. We <a href="https://github.com/netskopeoss/NetskopeThreatLabsIOCs/blob/main/Emotet/2022-06-24/script/extract_xls_urls.py">extracted 18 URLs</a> out of the 776 samples, four of which were online and delivering Emotet.</p>

<h2 id="stage-01---malicious-spreadsheets">Stage 01 - Malicious Spreadsheets</h2>
<p>The first stage is a malicious spreadsheet that abuses Excel 4.0 (XLM) macros to download and execute Emotet. These files are being delivered as email attachments.</p>
<p><img src="/_astro/emotet-still-abusing-macros-3.CFIPXE38_ZdIpLT.webp" alt="Examples of phishing emails with malicious spreadsheets attached." loading="lazy" decoding="async" width="888" height="578"></p>
<p>Phishing emails with malicious spreadsheets attached.</p>
<p>There are also cases where the spreadsheet is <a href="https://twitter.com/Slvlombardo/status/1539332657712087040">attached within a password-protected ZIP file</a>.</p>
<p>The spreadsheet contains a message to lure the user to remove the protected view by clicking the “Enable Editing” button.</p>
<p><img src="/_astro/emotet-still-abusing-macros-4.0t_JLRJ9_1YpWQb.webp" alt="Example of spreadsheet message asking to click “Enable Editing”." loading="lazy" decoding="async" width="969" height="258"></p>
<p>Spreadsheet message asking to click “Enable Editing”.</p>
<p>The malicious code is obfuscated and spread across hidden spreadsheets and cells.</p>
<p><img src="/_astro/emotet-still-abusing-macros-5-1024x264.C3PrGno3_1b4bc6.webp" alt="Screenshot of part of the Excel 4.0 Macros." loading="lazy" decoding="async" width="1024" height="264"></p>
<p>Part of the Excel 4.0 Macros.</p>
<p>The code downloads the payload from an external URL via “<a href="https://docs.microsoft.com/en-us/previous-versions/windows/internet-explorer/ie-developer/platform-apis/ms775123(v=vs.85)">URLDownloadToFileA</a>” API and executes it with “<a href="https://lolbas-project.github.io/lolbas/Binaries/Regsvr32/">regsvr32.exe</a>”, which is a commonly used binary for the <a href="/blog/2021/11/malicious-office-documents-multiple-ways-to-deliver-payloads">Living-off-the-Land</a> technique.</p>
<p><img src="/_astro/emotet-still-abusing-macros-6-1024x149.BMG797Cg_ZiNFMC.webp" alt="Screenshot of deobfuscated code from the spreadsheet." loading="lazy" decoding="async" width="1024" height="149"></p>
<p>Deobfuscated code from the spreadsheet.</p>
<p>Furthermore, most of the files we analyzed were authored by “<em>Dream</em>” and last saved either by “<em>RHRSDJTJDGHT</em>” or “<em>TYHRETH</em>”, indicating the files likely share an author.</p>
<p><img src="/_astro/emotet-still-abusing-macros-7.5WpPlFFs_1YWJBs.webp" alt="Screenshot of common metadata across the spreadsheets." loading="lazy" decoding="async" width="849" height="273"></p>
<p>Common metadata across the spreadsheets.</p>
<h2 id="stage-02---packed-emotet">Stage 02 - <a href="/library/malware/packed" class="threat-link">Packed</a> Emotet</h2>
<p>We were able to download samples from four different URLs out of the 18 extracted from the spreadsheets. Two of the downloaded files were unpacking the same Emotet payload.</p>
<p><img src="/_astro/emotet-still-abusing-macros-8-1024x438.QcGaurRo_2fEhA2.webp" alt="Example of four payloads downloaded from the spreadsheet URLs." loading="lazy" decoding="async" width="1024" height="438"></p>
<p>Four payloads downloaded from the spreadsheet URLs.</p>
<p>Emotet’s main payload is encrypted and stored in the PE resources of the loader, which is the same case as other Emotet packed samples <a href="/blog/2022/05/emotet-new-delivery-mechanism-to-bypass-vba-protection">we analyzed</a> earlier in 2022.</p>
<p><img src="/_astro/emotet-still-abusing-macros-9.3BffQQoF_1xw6M6.webp" alt="Screenshot of Emotet’s main payload stored in the PE resources." loading="lazy" decoding="async" width="760" height="424"></p>
<p>Emotet’s main payload stored in the PE resources.</p>
<p>The unpacking/decryption process is also very similar to the samples we analyzed earlier in 2022, where a key is used in a simple rolling XOR algorithm.</p>
<p><img src="/_astro/emotet-still-abusing-macros-10-1024x486.ihcytUMz_2hLynQ.webp" alt="Example of Emotet decryption process." loading="lazy" decoding="async" width="1024" height="486"></p>
<p>Emotet decryption process.</p>
<h2 id="stage-03---emotet-payload">Stage 03 - Emotet Payload</h2>
<p>We extracted three different payloads (64-bit DLLs) from the samples we downloaded from the URLs.</p>
<p><img src="/_astro/emotet-still-abusing-macros-11.2kY-NTJh_Z1U0Xwe.webp" alt="Screenshot of main Emotet payloads" loading="lazy" decoding="async" width="381" height="104"></p>
<p>Main Emotet payloads.</p>
<p>We can find some similarities by comparing these payloads with the ones <a href="/blog/2022/05/emotet-new-delivery-mechanism-to-bypass-vba-protection">we analyzed in April 2022</a>, like the pattern used in the DLL name.</p>
<p><img src="/_astro/emotet-still-abusing-macros-12.COEs9i3w_1KKxig.webp" alt="Screenshot of real name for all three samples is “E.dll”." loading="lazy" decoding="async" width="333" height="111"></p>
<p>Real name for all three samples is “E.dll”.</p>
<p>And also the persistence mechanism via Windows service that executes the payload via <strong>regsvr32.exe.</strong></p>
<p><img src="/_astro/emotet-still-abusing-macros-13.Dcb1htKM_Z1EqqSI.webp" alt="Screenshot of Emotet persistence mechanism." loading="lazy" decoding="async" width="766" height="183"></p>
<p>Emotet persistence mechanism.</p>
<p>However, there are some differences between these payloads and the ones we analyzed in April 2022. The first one is where and how Emotet decrypts its strings. In previous payloads, Emotet was storing its strings in the PE .text section.</p>
<p>In these latest payloads, Emotet uses functions to retrieve decrypted strings. Simply put, the attacker is using the concept of stack strings, which are passed via parameter to the function that performs the decryption process.</p>
<p><img src="/_astro/emotet-still-abusing-macros-14.BZX5zbMv_1gESG9.webp" alt="Screenshot of Emotet function to return a decrypted string." loading="lazy" decoding="async" width="739" height="193"></p>
<p>Emotet function to return a decrypted string.</p>
<p>The decrypted strings can be easily retrieved by placing breakpoints in the return of these functions. Also, it’s possible to use a <a href="https://research.openanalysis.net/emotet/emulation/config/dumpulator/malware/2022/05/19/emotet_x64_emulation.html">Python script</a> to automatically extract this data using <a href="https://github.com/mrexodia/dumpulator">Dumpulator</a> or any other emulation framework.</p>
<p><img src="/_astro/emotet-still-abusing-macros-15.BJCd2_eW_ZoA1GK.webp" alt="Screenshot of Emotet decrypted strings." loading="lazy" decoding="async" width="376" height="515"></p>
<p>Emotet decrypted strings.</p>
<p>The C2 addresses are also retrieved in a different way on these payloads. Instead of storing this data in the PE .data section, Emotet parses the C2 addresses via functions as well.</p>
<p><img src="/_astro/emotet-still-abusing-macros-16.FWuOeNdu_1xuLSk.webp" alt="Example of Emotet parsing the C2 server addresses." loading="lazy" decoding="async" width="810" height="391"></p>
<p>Emotet parsing the C2 server addresses.</p>
<p>And it’s also possible to extract this information statically using an emulation script, similar to the one used for the strings.</p>
<p><img src="/_astro/emotet-still-abusing-macros-17.eQeJwnr4_Z1PMutw.webp" alt="Screenshot of part of Emotet C2 server addresses." loading="lazy" decoding="async" width="174" height="279"></p>
<p>Part of Emotet C2 server addresses.</p>
<h2 id="conclusions">Conclusions</h2>
<p>In April 2022 we analyzed an Emotet campaign that was <a href="/blog/2022/05/emotet-new-delivery-mechanism-to-bypass-vba-protection">not using Microsoft Office</a> files to spread, as a possible response to <a href="/blog/2022/02/microsoft-office-vba-blocked-by-default-in-files-from-the-internet">Microsoft protections</a>. However, we still see some attackers abusing Microsoft Office files to download and execute Emotet. We strongly recommend users to update Microsoft Office to its latest versions. Also, IT administrators may also completely block Excel 4.0 (XLM) Macros <a href="https://techcommunity.microsoft.com/t5/excel-blog/excel-4-0-xlm-macros-now-restricted-by-default-for-customer/ba-p/3057905">via Group Policy</a>.</p>
