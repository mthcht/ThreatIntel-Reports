  (function () {
    let pagefind;
    let debounceTimer;

    async function loadPagefind() {
      if (pagefind) return pagefind;
      try {
        pagefind = await import('/pagefind/pagefind.js');
        await pagefind.init();
      } catch {
        pagefind = null;
      }
      return pagefind;
    }

    function initSearch() {
      const overlay = document.getElementById('search-overlay');
      const openBtn = document.getElementById('search-open');
      const closeBtn = document.getElementById('search-close');
      const input = document.getElementById('search-input');
      const results = document.getElementById('search-results');

      function openModal() {
        overlay?.classList.remove('hidden');
        overlay?.classList.add('flex');
        input?.focus();
        loadPagefind();
      }

      function closeModal() {
        overlay?.classList.add('hidden');
        overlay?.classList.remove('flex');
        if (input) input.value = '';
        if (results) results.innerHTML = '';
      }

      openBtn?.addEventListener('click', openModal);
      closeBtn?.addEventListener('click', closeModal);
      overlay?.addEventListener('click', (e) => {
        if (e.target === overlay) closeModal();
      });
      document.addEventListener('keydown', (e) => {
        if (e.key === 'Escape') closeModal();
        if ((e.metaKey || e.ctrlKey) && e.key === 'k') {
          e.preventDefault();
          openModal();
        }
      });

      input?.addEventListener('input', () => {
        clearTimeout(debounceTimer);
        debounceTimer = setTimeout(runSearch, 200);
      });

      async function runSearch() {
        const query = input?.value.trim() ?? '';
        if (!results) return;
        if (!query) {
          results.innerHTML = '';
          return;
        }

        const pf = await loadPagefind();
        if (!pf) {
          results.innerHTML = `<p class="p-4 text-sm text-(--text-secondary)">Search is unavailable in development. It runs against the built site.</p>`;
          return;
        }

        const search = await pf.search(query);
        if (search.results.length === 0) {
          results.innerHTML = `<p class="p-4 text-sm text-(--text-secondary)">No results for "${query}".</p>`;
          return;
        }

        const items = await Promise.all(search.results.slice(0, 8).map((r) => r.data()));
        results.innerHTML = items
          .map(
            (item) => `
            <a href="${item.url}" class="block px-4 py-3 border-b border-(--border-subtle) last:border-0 hover:bg-(--bg-tertiary) transition-colors">
              <p class="font-medium text-(--text-primary) text-sm mb-1">${item.meta?.title ?? item.url}</p>
              <p class="text-xs text-(--text-secondary) line-clamp-2">${item.excerpt}</p>
            </a>
          `,
          )
          .join('');
      }
    }

    // Initialize on page load and after Astro view transitions
    document.addEventListener('astro:page-load', initSearch);
  })();

bg-(--bg-primary)"><div class="prose max-w-none"><h2 id="summary">Summary</h2>
<p><a href="https://malpedia.caad.fkie.fraunhofer.de/details/win.lockbit">LockBit Ransomware (a.k.a. ABCD)</a> is yet another ransomware group operating in the RaaS (Ransomware-as-a-Service) model, following the same architecture as other major threat groups, <a href="/blog/2021/07/netskope-threat-coverage-revil">like REvil</a>. This threat emerged in September 2019 and is still being improved by its creators. In June 2021, the <a href="/library/malware/lockbit" class="threat-link">LockBit</a> group <a href="https://twitter.com/Intel_by_KELA/status/1406905385580118017/photo/1">announced the release of LockBit 2.0</a>, which included a new website hosted on the deep web, as well as a new feature to <a href="https://www.bleepingcomputer.com/news/security/lockbit-ransomware-now-encrypts-windows-domains-using-group-policies/">encrypt Windows domains</a> using group policy.</p>
<p>On August 11, 2021, the LockBit ransomware group announced in their deep web forum that they have infected the global IT consultancy company Accenture.</p>
<p><img src="/_astro/lockbit-coverage-1-1024x602.B6sx6uyT_Ltz9L.webp" alt="Screenshot of LockBit official website showing the Accenture information." loading="lazy" decoding="async" width="1024" height="602"></p>
<p><em>LockBit official website, hosted on the deep web, showing the Accenture information.</em></p>
<p><a href="https://twitter.com/AuCyble/status/1425422006690881541">According to the company Cyble</a>, the attackers have allegedly stolen about 6TB of data, and are demanding $50M (USD) as ransom. Also, Cyble mentioned that this attack was supposedly carried out by an insider, however, that has not been verified yet. The IT giant Accenture has <a href="https://www.bleepingcomputer.com/news/security/accenture-confirms-hack-after-lockbit-ransomware-data-leak-threats/">confirmed the attack</a> and also affirmed that the breach had no impact on their operations or systems.</p>
<p>The period established for Accenture to pay the ransom was August 11, 2021, which has now passed.</p>
<p><img src="/_astro/lockbit-coverage-2.C8rFKR92_ZIraox.webp" alt="Screenshot showing the original deadline for the ransom’s payment has passed, according to LockBit’s website." loading="lazy" decoding="async" width="807" height="379"></p>
<p><em>The original deadline for the ransom’s payment has passed, according to LockBit’s website.</em></p>
<p>However, as I am writing this blog post, the period to pay the ransom was changed to August 12, 2021, at the end of the day.</p>
<p><img src="/_astro/lockbit-coverage-3.CLS32zMQ_Cv2mQ.webp" alt="Screenshot showing new deadline established by the attackers for Accenture’s ransom" loading="lazy" decoding="async" width="835" height="511"></p>
<p><em>New deadline established by the attackers for Accenture’s ransom</em></p>
<p>At this point, it’s unclear how the attack was carried out, or if LockBit really stole sensitive data from the company. In this threat coverage report, we will briefly show how LockBit works, describing some features used for anti-analysis.</p>
<h2 id="threat">Threat</h2>
<p>LockBit ransomware is developed in both C and Assembly and uses AES + ECC to encrypt the files. The group operates in the RaaS model, and on their official website hosted on the deep web, we can find an advertisement trying to attract more affiliates into the scheme.</p>
<p><img src="/_astro/lockbit-coverage-4.oLogVP0P_Z1RU7eD.webp" alt loading="lazy" decoding="async" width="824" height="491"></p>
<p><em>LockBit “advertisement” posted on their website.</em></p>
<p>According to the page, the group is using a custom stealer named “StealBIT” to exfiltrate data from companies. They have even included a comparison between their service and other services, like MEGA and pCloud.</p>
<p><img src="/_astro/lockbit-coverage-5-1024x456.CK_kVMNd_Z1WXUjz.webp" alt="Screenshot of LockBit “advertisement” showing how fast they are when it comes to data exfiltration." loading="lazy" decoding="async" width="1024" height="456"></p>
<p><em>LockBit “advertisement” showing how fast they are when it comes to data exfiltration.</em></p>
<p>The website also includes an encryption speed comparative between LockBit and other ransomware families, such as <a href="/library/malware/ragnar" class="threat-link">Ragnar</a>, <a href="/library/malware/revil" class="threat-link">REvil</a>, <a href="/library/malware/conti" class="threat-link">Conti</a>, and others.</p>
<p><img src="/_astro/lockbit-coverage-6-1024x750.C9vjVnKf_ZayYse.webp" alt="Screenshot of LockBit “advertisement” showing an encryption speed comparison between ransomware families." loading="lazy" decoding="async" width="1024" height="750"></p>
<p><em>LockBit “advertisement” showing an encryption speed comparison between ransomware families.</em></p>
<p>Once the sample is executed, the code implements a very simple technique to detect if the process is being debugged, by checking the NtGlobalFlag value in the <a href="https://docs.microsoft.com/en-us/windows/win32/api/winternl/ns-winternl-peb">Process Environment Block</a> (PEB) structure. This is usually done to avoid direct calls to the function <code>​​CheckRemoteDebuggerPresent</code> or <code>IsDebuggerPresent</code>.</p>
<p><img src="/_astro/lockbit-coverage-7.BnUkR6dR_2brUqO.webp" alt="Screenshot of basic anti-debug technique." loading="lazy" decoding="async" width="539" height="308"></p>
<p><em>Basic anti-debug technique.</em></p>
<p>Also, LockBit verifies if the process is running with Administrator privileges by checking the return of the API <code>OpenSCManagerA</code>. If it’s not a privileged process, the function will fail, consequently reaching the <code>ExitProcess</code> call.</p>
<p><img src="/_astro/lockbit-coverage-8.DXJJZgMv_2wy3aI.webp" alt="Screenshot of LockBit checking if the process is privileged." loading="lazy" decoding="async" width="485" height="318"></p>
<p><em>LockBit checking if the process is privileged.</em></p>
<p>The sample also uses a Mutex to verify if there is another instance of LockBit running at the same time.</p>
<p><img src="/_astro/lockbit-coverage-9.CfzCCDlv_2t0v1.webp" alt="Screenshot of LockBit creating a Mutex object." loading="lazy" decoding="async" width="827" height="108"></p>
<p><em>LockBit creating a Mutex object.</em></p>
<p>Looking at the PE .rdata section, we can see that LockBit attempts to protect some relevant information by encrypting the strings, which is just a basic protection against detection or quick analyses.</p>
<p>Furthermore, we can observe that LockBit is using Intel 128-bit XMM registers in the operations, probably to increase the performance of the code.</p>
<p><img src="/_astro/lockbit-coverage-10.VaqvMH7e_Z2e6j6q.webp" alt="Screenshot of LockBit encrypted strings." loading="lazy" decoding="async" width="821" height="414"></p>
<p><em>LockBit encrypted strings.</em></p>
<p>The algorithm is straightforward — it decrypts the string by doing a single byte XOR operation, using the first byte of the string as a key.</p>
<p><img src="/_astro/lockbit-coverage-11.pTJjBTMr_13sG0C.webp" alt="Screenshot of LockBit string decryption algorithm." loading="lazy" decoding="async" width="885" height="310"></p>
<p><em>LockBit string decryption algorithm.</em></p>
<p>It should be possible to decrypt LockBit strings applying the same logic.</p>
<p><img src="/_astro/lockbit-coverage-12.Dm7zWvOA_1HdumC.webp" alt="Screenshot showing decrypting of LockBit’s strings using Python." loading="lazy" decoding="async" width="924" height="132"></p>
<p><em>Decrypting LockBit’s strings using Python.</em></p>
<p>In addition, LockBit also executes a series of commands using the API <code>ShellExecuteA</code> to avoid any restoration of the files in the machine by disabling the system’s recovery mode and the Windows Shadow Copies.</p>
<p><img src="/_astro/lockbit-coverage-13.DR3PWCnx_16vSJh.webp" alt="Screenshot of some of the commands executed by LockBit" loading="lazy" decoding="async" width="552" height="213"></p>
<p><em>Some of the commands executed by LockBit.</em></p>
<p>After the files are encrypted, LockBit creates the ransom note in every single directory where there are encrypted files.</p>
<p><img src="/_astro/lockbit-coverage-14.Dq4tRD6G_2kocAu.webp" alt="Screenshot of LockBit ransom note" loading="lazy" decoding="async" width="900" height="485"></p>
<p><em>LockBit ransom note</em></p>
<p>Lastly, the computer’s wallpaper is also changed by the malware, in case encrypting the files wasn’t enough to catch the victim’s attention.</p>
<p><img src="/_astro/lockbit-coverage-15-1024x217.D7ds4kXj_Z1ljBH7.webp" alt="Screenshot of LockBit wallpaper." loading="lazy" decoding="async" width="1024" height="217"></p>
<p><em>LockBit wallpaper.</em></p>
