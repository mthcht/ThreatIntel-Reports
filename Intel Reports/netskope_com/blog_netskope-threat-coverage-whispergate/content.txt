  (function () {
    let pagefind;
    let debounceTimer;

    async function loadPagefind() {
      if (pagefind) return pagefind;
      try {
        pagefind = await import('/pagefind/pagefind.js');
        await pagefind.init();
      } catch {
        pagefind = null;
      }
      return pagefind;
    }

    function initSearch() {
      const overlay = document.getElementById('search-overlay');
      const openBtn = document.getElementById('search-open');
      const closeBtn = document.getElementById('search-close');
      const input = document.getElementById('search-input');
      const results = document.getElementById('search-results');

      function openModal() {
        overlay?.classList.remove('hidden');
        overlay?.classList.add('flex');
        input?.focus();
        loadPagefind();
      }

      function closeModal() {
        overlay?.classList.add('hidden');
        overlay?.classList.remove('flex');
        if (input) input.value = '';
        if (results) results.innerHTML = '';
      }

      openBtn?.addEventListener('click', openModal);
      closeBtn?.addEventListener('click', closeModal);
      overlay?.addEventListener('click', (e) => {
        if (e.target === overlay) closeModal();
      });
      document.addEventListener('keydown', (e) => {
        if (e.key === 'Escape') closeModal();
        if ((e.metaKey || e.ctrlKey) && e.key === 'k') {
          e.preventDefault();
          openModal();
        }
      });

      input?.addEventListener('input', () => {
        clearTimeout(debounceTimer);
        debounceTimer = setTimeout(runSearch, 200);
      });

      async function runSearch() {
        const query = input?.value.trim() ?? '';
        if (!results) return;
        if (!query) {
          results.innerHTML = '';
          return;
        }

        const pf = await loadPagefind();
        if (!pf) {
          results.innerHTML = `<p class="p-4 text-sm text-(--text-secondary)">Search is unavailable in development. It runs against the built site.</p>`;
          return;
        }

        const search = await pf.search(query);
        if (search.results.length === 0) {
          results.innerHTML = `<p class="p-4 text-sm text-(--text-secondary)">No results for "${query}".</p>`;
          return;
        }

        const items = await Promise.all(search.results.slice(0, 8).map((r) => r.data()));
        results.innerHTML = items
          .map(
            (item) => `
            <a href="${item.url}" class="block px-4 py-3 border-b border-(--border-subtle) last:border-0 hover:bg-(--bg-tertiary) transition-colors">
              <p class="font-medium text-(--text-primary) text-sm mb-1">${item.meta?.title ?? item.url}</p>
              <p class="text-xs text-(--text-secondary) line-clamp-2">${item.excerpt}</p>
            </a>
          `,
          )
          .join('');
      }
    }

    // Initialize on page load and after Astro view transitions
    document.addEventListener('astro:page-load', initSearch);
  })();

<p>A new destructive malware called <a href="https://malpedia.caad.fkie.fraunhofer.de/details/win.whispergate">WhisperGate</a> <a href="https://www.microsoft.com/security/blog/2022/01/15/destructive-malware-targeting-ukrainian-organizations/">was discovered</a> in mid-January 2022 targeting Ukrainian organizations. This threat emerged during <a href="https://thehackernews.com/2022/01/ukrainian-government-officially-accuses.html">geopolitical conflicts</a> in Ukraine, masquerading as ransomware. However, this malware has a more destructive nature: wiping files and corrupting disks to prevent the OS from loading. Ukraine has suffered other cyberattacks that seem to be connected to <a href="/library/malware/whispergate" class="threat-link">WhisperGate</a>, such as the <a href="https://www.washingtonpost.com/national-security/ukraine-russia-cyberattacks/2022/01/18/79590750-78a1-11ec-bf97-6eac6f77fba2_story.html">defacement of many websites</a> connected to their governments.</p>
<p>This is a multi-stage malware, where one of the payloads is hosted on a Discord server. The preference of attackers to use cloud services for malicious purposes is increasingly common, as pointed out in an analysis of a threat campaign that uses <a href="/blog/2022/01/infected-powerpoint-files-using-cloud-services-to-deliver-multiple-malware">multiple cloud services throughout the attack</a>. The threat group behind WhisperGate is being tracked as <a href="https://bazaar.abuse.ch/browse/tag/DEV-0586/">DEV-0586</a>, and so far there isn’t any association between this attack to known APT groups. In this threat coverage, we analyzed all four stages of WhisperGate to demonstrate how it works.</p>
<h2 id="analysis">Analysis</h2>
<h3 id="stage-01">Stage 01</h3>
<p>WhisperGate’s first stage is a small executable compiled with MinGW, responsible for corrupting the disk by writing code into the <a href="https://www.ntfs.com/mbr.htm">Master Boot Record</a> (MBR), which is a small section on disk that contains the Partition Table and an executable code related to the boot loader.</p>
<p><img src="/_astro/whispergate-blog-1.C6EtOx8p_Z2hXLsV.webp" alt="Screenshot of Binary information about WhisperGate’s first stage" loading="lazy" decoding="async" width="633" height="242"></p>
<p>Binary information about WhisperGate’s first stage</p>
<p>Corrupting the MBR is a <a href="https://www.ntfs.com/mbr-virus.htm">simple technique</a> to prevent any Operating System from loading, as the assembly code is executed before the OS.</p>
<p>The entire code for the first stage of WhisperGate can fit in a single screenshot, where the malware loads the MBR data that will be written to disk, opens a handle to the physical drive with <strong>CreateFileW</strong>, and uses <strong>WriteFile</strong> to writes the 512 bytes to MBR, which is located in the first sector of the disk.</p>
<p><img src="/_astro/whispergate-blog-2.D7GLUTt-_mvIMp.webp" alt="Screenshot of Disassembled code of WhisperGate’s first stage." loading="lazy" decoding="async" width="599" height="595"></p>
<p>Disassembled code of WhisperGate’s first stage.</p>
<p>The MBR stub written to disk includes a 16-bit assembly code and a message.</p>
<p><img src="/_astro/whispergate-blog-3.VxGR6nCG_ZpJCuo.webp" alt="Screenshot of Data written on disk by WhisperGate" loading="lazy" decoding="async" width="840" height="738"></p>
<p>Data written on disk by WhisperGate</p>
<p>If we load this data into the disassembler, we can analyze the 16-bit assembly that will be executed once the computer is rebooted, which doesn’t do anything but display a message.</p>
<p><img src="/_astro/whispergate-blog-4.D4iu0U4-_Z102zL3.webp" alt="Example of code that is executed once the computer is infected with WhisperGate." loading="lazy" decoding="async" width="1007" height="287"></p>
<p>Code that is executed once the computer is infected with WhisperGate.</p>
<p>Once the computer is infected, as soon as it restarts, the message is displayed and the OS is prevented from loading. The message says the hard drive was corrupted and demands a payment of $10,000 via Bitcoin to a specific walled address.</p>
<p><img src="/_astro/whispergate-blog-5-1024x474.DG2avm89_Z1xA0xl.webp" alt="Example of computer infected with the first stage of WhisperGate." loading="lazy" decoding="async" width="1024" height="474"></p>
<p>Computer infected with the first stage of WhisperGate.</p>
<p>This is the only action performed by the first stage of WhisperGate. The following stages were created probably to add a certain resilience to the attack in case the first stage fails, as systems may use <a href="https://www.ntfs.com/guid-part-table.htm">GUID Partition Table</a> (GPD), which is MBR’s successor.</p>
<h3 id="stage-02">Stage 02</h3>
<p>In this stage, we have a simple .NET downloader for stage 03. The binary contains an expired signature from Microsoft, and although it is not shown by identification tools, the file is obfuscated with NetReactor, as pointed out by <a href="https://github.com/OALabs/Lab-Notes/blob/main/WhisperGate/WhisperGate.ipynb">OALabs</a>.</p>
<p><img src="/_astro/whispergate-blog-6.C-_pUnbq_2aYrdf.webp" alt="Screenshot of binary information about WhisperGate’s second stage." loading="lazy" decoding="async" width="630" height="250"></p>
<p>Binary information about WhisperGate’s second stage.</p>
<p>Once running, it downloads the third stage from a Discord server, named “<strong>Tbopbh.jpg</strong>”.</p>
<p><img src="/_astro/whispergate-blog-7.COnI08ko_QmsxB.webp" alt="Example of WhisperGate’s .NET downloader." loading="lazy" decoding="async" width="751" height="362"></p>
<p>WhisperGate’s .NET downloader.</p>
<p>After the download, the malware loads the binary as a .NET assembly and executes the method named “<strong>Ylfwdwgmpilzyaph</strong>”.</p>
<p><img src="/_astro/whispergate-blog-8.Cos2sBpn_Z1VmTXi.webp" alt="Example of malware executing the third stage of WhisperGate" loading="lazy" decoding="async" width="514" height="310"></p>
<p>Malware executing the third stage of WhisperGate</p>
<h3 id="stage-03">Stage 03</h3>
<p>Here we have a 32-bit DLL, also developed in .NET. Since this file is directly loaded by the second stage as a .NET assembly, the DLL doesn’t have an entry point, which requires some adjustments to make dynamic analysis feasible.</p>
<p><img src="/_astro/whispergate-blog-9.zGTtGFHZ_ZW4Q7K.webp" alt="Screenshot of binary information about WhisperGate’s third stage." loading="lazy" decoding="async" width="632" height="268"></p>
<p>Binary information about WhisperGate’s third stage.</p>
<p>As shown in the image above, the file is protected with Eazfuscator, likely to hinder researchers’ analysis. Searching throughout the decompiled code, we can find the same method that is executed by the second stage.</p>
<p><img src="/_astro/whispergate-blog-10.DnjnTORP_14nYBJ.webp" alt="Screenshot of main function from the third stage of WhisperGate." loading="lazy" decoding="async" width="866" height="273"></p>
<p>Main function from the third stage of WhisperGate.</p>
<p>Once running, it checks if the process is running as an Administrator. If it’s not the case, it launches itself with elevated permissions and exits the process.</p>
<p><img src="/_astro/whispergate-blog-11.DwMotpcI_1fj0s0.webp" alt="Example of Malware checking for administrative permissions." loading="lazy" decoding="async" width="808" height="123"></p>
<p>Malware checking for administrative permissions.</p>
<p>Then, it drops a VBS named “<strong>Nmddfrqqrbyjeygggda.vbs</strong>” into the Windows temporary folder, containing a simple PowerShell code that adds the path “C:\” to Windows Defender’s exclusion list.</p>
<p><img src="/_astro/whispergate-blog-12.CaJyDVGV_22cSR6.webp" alt="Example of simple VBS / PowerShell to bypass Windows Defender." loading="lazy" decoding="async" width="961" height="147"></p>
<p>Simple VBS / PowerShell to bypass Windows Defender.</p>
<p>It also drops an executable named “<strong>AdvancedRun.exe</strong>” to the same directory, which is a <a href="https://www.nirsoft.net/utils/advanced_run.html">tool from NirSoft</a> to execute programs with different settings. WhisperGate uses this tool to execute commands in the “TrustedInstaller” group context.</p>
<p><img src="/_astro/whispergate-blog-13.eVeEFq_F_1NEe6l.webp" alt="Example of usage of AvancedRun tool, by NirSoft." loading="lazy" decoding="async" width="755" height="147"></p>
<p>Usage of AvancedRun tool, by <a href="/library/malware/nirsoft" class="threat-link">NirSoft</a>.</p>
<p>It executes two commands with this tool, both as an attempt to disable Windows Defender. The first one tries to stop Defender’s service, and the second tries to delete its respective folder.</p>
<p><img src="/_astro/whispergate-blog-14.DBau35cW_ATN9I.webp" alt="Example of commands executed with AdvancedRun." loading="lazy" decoding="async" width="835" height="132"></p>
<p>Commands executed with AdvancedRun.</p>
<p>Then, WhisperGate copies “InstallUtil.exe” to Windows temporary folder, which is a <a href="https://docs.microsoft.com/en-us/dotnet/framework/tools/installutil-exe-installer-tool">binary from .NET Framework</a>.</p>
<p><img src="/_astro/whispergate-blog-15.Csbux_dT_288eLf.webp" alt="Example of copying InstallUtil executable to Windows temporary folder." loading="lazy" decoding="async" width="801" height="167"></p>
<p>Copying InstallUtil executable to Windows temporary folder.</p>
<p>And finally, WhisperGate’s last stage is injected into an instance of the InstallUtil’s process. The payload is stored within an encrypted resource, where all the bytes are reversed and compressed with <a href="https://www.gnu.org/software/gzip/">Gzip</a>.</p>
<p><img src="/_astro/whispergate-blog-16.dK26JOZd_1qMS2U.webp" alt="Example of malware loading WhisperGate’s last stage." loading="lazy" decoding="async" width="729" height="346"></p>
<p>Malware loading WhisperGate’s last stage.</p>
<h3 id="stage-04">Stage 04</h3>
<p>The binary used in this stage is quite similar to the first one in terms of compiler and linker.</p>
<p><img src="/_astro/whispergate-blog-17.BQFw6km5_ZtJufy.webp" alt="Screenshot of WhisperGate’s last stage." loading="lazy" decoding="async" width="629" height="245"></p>
<p>WhisperGate’s last stage.</p>
<p>Looking at the main function of the malware, we have two functions being called prior to the end of the execution.</p>
<p><img src="/_astro/whispergate-blog-18.VWT_KFP0_Z1hnhW4.webp" alt="Screenshot of WhisperGate’s main function." loading="lazy" decoding="async" width="370" height="481"></p>
<p><em>WhisperGate’s main function.</em></p>
<p>At the function we named “<strong>mw_main_routine</strong>”, the malware starts by listing the drives with the help of <a href="https://docs.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getlogicaldrives">GetLogicalDrives</a> API.</p>
<p><img src="/_astro/whispergate-blog-19.Df1J6Azl_Z1F5hm2.webp" alt="Screenshot of malware listing OS drives." loading="lazy" decoding="async" width="303" height="289"></p>
<p>Malware listing OS drives.</p>
<p>Then, it uses <a href="https://docs.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdrivetypew">GetDriveTypeW</a> to check if the drive is either fixed or remote. If that’s the case, it starts the function that will wipe the files.</p>
<p><img src="/_astro/whispergate-blog-20.C-fYTLvG_Z2aJJYu.webp" alt="Example of malware checking the drive type." loading="lazy" decoding="async" width="470" height="587"></p>
<p>Malware checking the drive type.</p>
<p>Within the function we named “<strong>mw_wipe_files</strong>”, it starts by listing all the files in the root path of the drive with <a href="https://docs.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-findfirstfilew">FindFirstFileW</a>.</p>
<p><img src="/_astro/whispergate-blog-21.BH5HQ3_x_Z1iNexQ.webp" alt="Screenshot of malware listing all the files in the current directory." loading="lazy" decoding="async" width="467" height="302"></p>
<p>Malware listing all the files in the current directory.</p>
<p>If the current object is a directory, the “<strong>mw_wipe_files</strong>” function is called recursively with the identified directory as a parameter. This is verified by calling the “<strong>_wstat</strong>” function and checking the <a href="https://docs.microsoft.com/en-us/previous-versions/visualstudio/visual-studio-2013/14h5k7ff(v=vs.120)">st_mode</a> bits.</p>
<p><img src="/_astro/whispergate-blog-22-1024x441.Cgf--YQk_Z2wKLvy.webp" alt="Screenshot of malware checking if the current object is a directory." loading="lazy" decoding="async" width="1024" height="441"></p>
<p>Malware checking if the current object is a directory.</p>
<p>WhisperGate does not wipe files in the Windows directory.</p>
<p><img src="/_astro/whispergate-blog-23.d7pKOxAt_MRlfW.webp" alt="Screenshot of WhisperGate skipping Windows folder." loading="lazy" decoding="async" width="512" height="290"></p>
<p>WhisperGate skipping Windows folder.</p>
<p>The last verification is related to the file’s extension, where the malware iterates over a list of targeted extensions and, if the file name matches, a function we named “<strong>mw_write_bytes_to_file”</strong> is called.</p>
<p><img src="/_astro/whispergate-blog-24.BoSkfylT_21V2uC.webp" alt="Example of WhisperGate checking for targeted extensions" loading="lazy" decoding="async" width="625" height="594"></p>
<p>WhisperGate checking for targeted extensions.</p>
<p>WhisperGate targets many files with extensions related to websites, such as “.html”, “.php”, “.asp”, “.jsp”, as well as common documents like “.doc”, “.xls”, “.ppt”, etc. A complete list of targeted extensions can be found in our <a href="https://github.com/netskopeoss/NetskopeThreatLabsIOCs/tree/main/WhisperGate/IOCs">GitHub repository</a>.</p>
<p><img src="/_astro/whispergate-blog-25.BauQ-uw6_qbq2I.webp" alt="Screenshot of WhisperGate’s targeted extensions." loading="lazy" decoding="async" width="290" height="343"></p>
<p>WhisperGate’s targeted extensions.</p>
<p>And finally, if the file matches the criteria, WhisperGate wipes the file by replacing its content with a sequence of <strong>0x100000</strong> bytes of <strong>0xCC.</strong></p>
<p><img src="/_astro/whispergate-blog-26.BcAGPnT8_1BOxjl.webp" alt="Screenshot of WhisperGate wiping system’s files." loading="lazy" decoding="async" width="417" height="451"></p>
<p>WhisperGate wiping system’s files.</p>
<p>Also, a random extension is appended to the file’s name.</p>
<p><img src="/_astro/whispergate-blog-27.uctf_0p9_2gXtRi.webp" alt="Screenshot of files wiped by WhisperGate." loading="lazy" decoding="async" width="914" height="336"></p>
<p>Files wiped by WhisperGate.</p>
<p>Once it’s over, WhisperGate deletes itself through a simple command line, where “%s” is the file path obtained with <a href="https://docs.microsoft.com/en-us/windows/win32/api/libloaderapi/nf-libloaderapi-getmodulefilenamea">GetModuleFileNameA</a>.</p>
<p><img src="/_astro/whispergate-blog-28.CObzqLTS_Z279xMT.webp" alt loading="lazy" decoding="async" width="702" height="76"></p>
<p>This is the only behavior of WhisperGate’s last stage. Paying the ransom demanded would be fruitless because the MBR and files were simply overwritten, not encrypted like they would be by ransomware.</p>
<h2 id="conclusions">Conclusions</h2>
<p>WhisperGate is a multi-stage destructive malware that has emerged in the midst of the geopolitical conflict that <a href="https://www.washingtonpost.com/politics/2022/01/04/fears-mount-about-russian-cyberattacks-ukraine/">is still unfolding</a> in Ukraine.
