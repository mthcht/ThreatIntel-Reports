    <div class="rt post-rt post-article__body"><p>Emotet first appeared in 2014 as a banking trojan built to steal sensitive information and financial credentials. Over time it evolved into a large, modular botnet that functions like Infrastructure as a Service for cybercrime. Instead of focusing only on theft, Emotet now delivers additional payloads for partner crews, including other banking trojans, credential stealers, spam modules, and ransomware loaders. This shift turned Emotet into a distribution hub that fuels many different intrusions across industries.</p>
<p data-start="598" data-end="1246">Operators rely on high volume email campaigns, thread hijacking, and malicious attachments or links to seed new infections. Once a system is compromised, Emotet deploys modules for persistence, lateral movement, and credential harvesting. It is known for frequent code updates, polymorphic payloads, and fast changing command and control infrastructure to evade detection. Obfuscation techniques include packed binaries, encrypted configurations, and randomized filenames and services. Emotet has survived takedowns and reemerged with refreshed loaders and new delivery partners, which keeps it relevant as a first stage tool in many attack chains.</p>
<p data-start="1248" data-end="1868" data-is-last-node="" data-is-only-node="">Defenders can reduce risk by blocking macro enabled documents from the internet, enforcing multifactor authentication, and restricting script interpreters where possible. Collect process creation and command line telemetry, monitor email for thread hijacking indicators, and alert on unusual outbound connections and sudden spikes in SMB or SMTP traffic. Maintain tested backups and segment critical systems to limit lateral movement. Finally, validate controls against real Emotet behaviors so you can confirm that detections fire, response playbooks work, and access is contained before additional malware is deployed.</p>
<p>We revealed obfuscated Visual Basic codes in <a href="/blog/emotet-technical-analysis-part-1-reveal-the-evil-code" rel="noopener"> the first part of the Emotet Technical Analysis series </a> . In this second part, we analyze the PowerShell codes in the Emotet malware document ( <code>PowerShell,</code> <code> <a href="https://attack.mitre.org/techniques/T1086/" target="_blank" rel="noopener" style="background-color: #fafafa;"> MITRE ATT&amp;CK T1086 </a> </code> ).</p>

<p>Syntax:</p>
<pre><code>uint32 Create(

</ul>
<ul>
<li>The second variable is the <code>CurrentDirectory</code> . If this parameter is <code>NULL</code> , the new process will have the same path as the calling process.</li>
</ul>
<ul>
<li>The third variable is <code>ProcessStartupInformation</code> , like <code>winmgmtS:win32_ProcessStartuP</code> in this example.</li>

This directory stores personal data of the user and a typical path is <code>C:\Users\Username</code> .</p>
</td>
</tr>
</tbody>
</table></div>
</div>
<ul>
<li>The third line, an <code>If</code> condition, returns <code>true</code> if the length of the downloaded file <code>937.exe</code> is greater than or equal to 29936 bytes by using <code>-ge 29936</code> comparison operator ( <code>ge: greater than or equal</code> ). If it returns true, <code>Diagnostics.Process.Start</code> method executes the <code>937.exe</code> , then exits the loop. The exact file size of <code>937.exe</code> is <a href="https://www.virustotal.com/gui/file/cb463bc2cfbe95d234afc0d3708babb85c7e29089d3691ab0ba6695eeeccb60f/details" target="_blank" rel="noopener"> 905472 bytes </a> . What could be the reason for comparing the file size? The answer is simple; adversaries are trying to figure out whether the file is actually downloaded.<br><br>
<div data-hs-responsive-table="true" style="overflow-x: auto; max-width: 100%; width: 100%; margin-left: auto; margin-right: auto;">
<div class="post-table"><table class="post-code">
<tbody>
<tr>
<td class="post-code__cell"><code>💡Diagnostics.Process.Start(string fileName)</code> : The <a href="https://docs.microsoft.com/en-us/dotnet/api/system.diagnostics.process.start?view=netframework-4.8" target="_blank" rel="noopener"> <code>Process.Start</code> </a> method of <code>System.Diagnostics</code> namespace starts a process resource by specifying the name of a document or application file and associates the resource with a new Process component.</td>
</tr>
</tbody>
</table></div>
</div>
</li>
</ul>
<p>Adversaries used the <code>Invoke-Item</code> cmdlet to execute the downloaded file in <a href="/blog/the-christmas-card-you-never-wanted-a-new-wave-of-emotet-is-back-to-wreak-havoc" rel="noopener"> our previous Emotet analysis </a> . Now, they are using the <a href="https://docs.microsoft.com/en-us/dotnet/api/system.diagnostics.process.start?view=netframework-4.8" target="_blank" rel="noopener"> <code>Process.Start</code> </a> method instead of <code>Invoke-Item</code> to decrease the detection rate.</p>
<p>In our analysis, the PowerShell coded downloaded <code>937.exe</code> from the first URL. The other URLs are also active.</p>
<pre><code>MD5: 032a5220e159fcf2f33cc9799f11ade6
SHA-1: 9768eb95d1ac398425fc5eced31b5f83025c6faf
SHA-256: cb463bc2cfbe95d234afc0d3708babb85c7e29089d3691ab0ba6695eeeccb60f

VirusTotal detection rate: <strong><a href="https://www.virustotal.com/gui/file/cb463bc2cfbe95d234afc0d3708babb85c7e29089d3691ab0ba6695eeeccb60f/detection" target="_blank" rel="noopener">6/73</a></strong><strong> as of January 21, 2020</strong>, 49/73 as of February 6, 2020
Names: 937.exe, 565.exe</code></pre>
<h2>Summary</h2>
<p>The purpose of this second part of the Emotet Technical Analysis Series is analyzing the PowerShell code included in the heavily obfuscated Visual Basic macros revealed in <a href="/blog/emotet-technical-analysis-part-1-reveal-the-evil-code" rel="noopener"> the first article </a> . <strong> Briefly, this PowerShell code downloads a file from a list of URLs, then executes the file as a process. </strong></p>
<p>Adversaries used the following techniques in the PowerShell code for obfuscation and evasion:</p>
<ol start="1">
<li>
<p><code>WMI</code> was used to create a process instead of <code>cmd</code> . If WMI activity is not monitored, it is hard to detect the creation of the malicious process.</p>
</li>
</ol>
<ol start="2">
<li>
<p>Substrings of parameters were used instead of the complete version of the parameters. PowerShell completes the incomplete version of a parameter. <code>-w</code> was used for <code>-WindowStyle</code> and <code>-en</code> was used for the <code>-EncodedCommand</code> .</p>
</li>
</ol>
<ol start="3">
<li>
<p>The <code>-WindowStyle</code> parameter was used with the <code>Hidden</code> value to hide the PowerShell command window.</p>
</li>
</ol>
<ol start="4">
<li>
<p>The Base64-encoded version of the PowerShell command was used with <a href="https://docs.microsoft.com/en-us/powershell/module/Microsoft.PowerShell.Core/About/about_PowerShell_exe?view=powershell-5.1" target="_blank" rel="noopener"> <code>-EncodedCommand</code> </a> parameter.</p>
</li>
</ol>
<ol start="5">
<li>
<p>Garbage variable assignments were used to obfuscate the code.</p>
</li>
</ol>
<ol start="6">
<li>
<p>The <code>` (backtick</code> character was used to obfuscate strings. For example, <code>Dow`Nloadfi`LE</code> was used instead of <code>DowNloadfiLE</code> .</p>
</li>
</ol>
<ol start="7">
<li>
<p><code>+</code> operator was used to concatenate fragmented strings. As an example, <code>'new-o'+'bj'+'ect'</code> was used instead of <code>newobject</code> to evade weak security controls.</p>
</li>
</ol>
<ol start="8">
<li>
<p>URLs were joined with <code>* (asterisk)</code> character to evade weak URL regexes of security controls. Then, the <code>Split()</code> method was used to separate URLs.</p>
</li>
</ol>
<ol start="9">
<li>
<p>The <code>[char]</code> conversion function was used to obfuscate. For example, <code>[char]42</code> was used for the <code>* (asterisk)</code> character.</p>
</li>
</ol>
<ol start="10">
<li>
<p>Randomized case (e.g., <code>NeT.WeBCLiEnT</code> ) was used to bypass weak security controls.</p>
</li>
</ol>
<ol start="11">
<li>
<p>The <a href="https://docs.microsoft.com/en-us/dotnet/api/system.diagnostics.process.start?view=netframework-4.8" target="_blank" rel="noopener"> <code>Process.Start</code> </a> method was used to execute the downloaded file instead of the more common execution method like the <code>Invoke-Item</code> cmdlet.</p>
</li>
</ol>
