<h1 class="blog-banner__heading">
      This isn't Optimus Prime's Bumblebee but it's Still Transforming
  </h1>

    </div>
  </div>

  <div class="blog-content">
    <div class="blog-content__sharethis sharethis_toolbox sharethis_32x32_style">

        <div class="blog-content__metadata blog-content__metadata-author">
      <span class="blog-content__date">  <time datetime="2022-04-28T15:53:51Z">April 28, 2022</time>

</span>
        <span class="blog-content__author">
                Kelsey Merriman and Pim Trouerbach
  
        </span>
    </div>
    <div class="node-full__body blog-content__body">  <h2>Key Findings</h2>

<ul>
	<li>Proofpoint has tracked a new malware loader called Bumblebee used by multiple crimeware threat actors previously observed delivering BazaLoader and IcedID.</li>
	<li>Several threat actors that typically use BazaLoader in malware campaigns have transitioned to Bumblebee. BazaLoader has not been seen in Proofpoint data since February 2022.</li>
	<li>Bumblebee is in active development and wields elaborate evasion techniques to include complex anti-virtualization.</li>
	<li>Unlike most other malware that uses process hollowing or DLL injection, this loader utilizes an asynchronous procedure call (APC) injection to start the shellcode from the commands received from the command and control (C2).</li>
	<li>Proofpoint observed Bumblebee dropping Cobalt Strike, shellcode, Sliver, and Meterpreter.</li>
	<li>Threat actors using Bumblebee are associated with malware payloads that have been linked to follow-on ransomware campaigns.</li>
</ul>

<h2>Overview</h2>

<p>Starting in March 2022, Proofpoint observed campaigns delivering a new downloader called Bumblebee. At least three clusters of activity including known threat actors currently distribute Bumblebee. Campaigns identified by Proofpoint overlap with activity <a href="https://blog.google/threat-analysis-group/exposing-initial-access-broker-ties-conti" target="_blank">detailed</a> in the Google Threat Analysis Group blog as leading to Conti and Diavol ransomware.</p>

<p>Bumblebee is a sophisticated downloader containing anti-virtualization checks and a unique implementation of common downloader capabilities, despite it being so early in the malware's development. Bumblebee's objective is to download and execute additional payloads. Proofpoint researchers observed Bumblebee dropping Cobalt Strike, shellcode, Sliver and Meterpreter. The malware name comes from the unique User-Agent "bumblebee" used in early campaigns.</p>

<p>The increase of Bumblebee in the threat landscape coincides with BazaLoader a popular payload that facilitates follow-on compromises–disappearing recently from Proofpoint threat data.</p>

<h2>Campaign Details</h2>

<p>Proofpoint researchers have observed Bumblebee being distributed in email campaigns by at least three tracked threat actors. The threat actors have used multiple techniques to deliver Bumblebee. While lures, delivery techniques, and file names are typically customized to the different threat actors distributing the campaigns, Proofpoint observed several commonalities across campaigns, such as the use of ISO files containing shortcut files and DLLs and a common DLL entry point used by multiple actors within the same week.</p>

<h3>URLs and HTML Attachments Leading to Bumblebee</h3>

<p>In March 2022, Proofpoint observed a DocuSign-branded email campaign with two alternate paths designed to lead the recipient to the download of a malicious ISO file. The first path began with the recipient clicking on the "REVIEW THE DOCUMENT" hyperlink in the body of the email. Once clicked, this would link the user to the download of a zipped ISO file, hosted on OneDrive.</p>

<p><img alt="image-20220427171512-1" data-entity-type="file" data-entity-uuid="25c1a7d6-931d-4251-8201-f6d3ea60e3a0" height="667" src="/sites/default/files/inline-images/image-20220427171512-1.png" width="1099" loading="lazy"><br>
<em>Figure 1: Email delivered March 2022 containing a URL and an HTML attachment</em></p>

<p>Alternatively, the same email also contained an HTML attachment. The appearance of the opened HTML file masqueraded to look like an email containing a link to an unpaid invoice. The embedded URL in the HTML attachment used a redirect service which Proofpoint refers to as Cookie Reloaded, a URL redirect service which uses Prometheus TDS to filter downloads based on the time zone and cookies of the potential victim. The redirector in turn directed the user to a zipped ISO file, also hosted on OneDrive.</p>

<p><img alt="image-20220427171512-2" data-entity-type="file" data-entity-uuid="242f5c5e-ba1a-433d-881a-2eed8ce7f94e" height="533" src="/sites/default/files/inline-images/image-20220427171512-2.png" width="1101" loading="lazy"><br>
<em>Figure 2: HTML Attachment Containing Link to Cookie Reloaded URL Redirect</em></p>

<p>The ISO file contained files named "ATTACHME.LNK" and "Attachments.dat". If ran, the shortcut file "ATTACHME.LNK" executed "Attachments.dat" with the correct parameters to run the downloader, Bumblebee.</p>

<p><img alt="image-20220427171512-3" data-entity-type="file" data-entity-uuid="4b675e69-2f71-48b2-9205-2943d938e23a" height="429" src="/sites/default/files/inline-images/image-20220427171512-3.png" width="1100" loading="lazy"><br>
<em>Figure 3: Contents of the archive viewed in WinRAR</em></p>

<p><img alt="image-20220427171512-4" data-entity-type="file" data-entity-uuid="3fdb153e-ad74-4ddb-b50f-830560bb37c6" height="454" src="/sites/default/files/inline-images/image-20220427171512-4.png" width="1338" loading="lazy"><br>
<em>Figure 4: Contents of ISO viewed in WinRAR</em></p>

<p>Process tree from the shortcut file:</p>

<p><em>cmd.exe /c start /wait "" "C:\Users\[removed]\AppData\Local\Temp\ATTACHME.LNK"<br>
rundll32.exe "C:\Windows\System32\rundll32.exe"<br>
Attachments.dat,IternalJob</em></p>

<p><img alt="image-20220427171512-5" data-entity-type="file" data-entity-uuid="bb56d587-e5a5-43bd-a84b-bf12ca7a5321" height="561" src="/sites/default/files/inline-images/image-20220427171512-5.png" width="1421" loading="lazy"><br>
<em>Figure 5: TA579 attack chain leading to Bumblebee</em></p>

<p>Proofpoint researchers attributed this campaign with high confidence to the cybercriminal group TA579. Proofpoint has tracked TA579 since August 2021. This actor frequently delivered BazaLoader and IcedID in past campaigns.</p>

<h3>Thread Hijacked, Zipped ISO Attachments Leading to Bumblebee</h3>

<p>In April 2022, Proofpoint observed a thread-hijacking campaign delivering emails that appeared to be replies to existing benign email conversations with malicious zipped ISO attachments. All the attachment names in this campaign used the pattern "doc_invoice_[number].zip".</p>

<p><img alt="image-20220427171513-6" data-entity-type="file" data-entity-uuid="cc68ba66-9411-45cb-be29-8ee2b7cc84b8" height="578" src="/sites/default/files/inline-images/image-20220427171513-6.png" width="1042" loading="lazy"><br>
<em>Figure 6: Email sample of a hijacked thread containing a malicious zipped ISO attachment</em></p>

<p>The zipped ISO was password-protected and contained "DOCUMENT.LNK" and "tar.dll". The password was shared in the body of the email. The shortcut file "DOCUMENT.LNK", if ran, executed "tar.dll" with the correct parameters to start the Bumblebee downloader.</p>

<p><img alt="image-20220427171513-7" data-entity-type="file" data-entity-uuid="8ebd153d-d9b8-486a-bd07-0e439681df69" height="151" src="/sites/default/files/inline-images/image-20220427171513-7.png" width="1101" loading="lazy"><br>
<em>Figure 7: Process Tree from the shortcut file</em></p>

<p><img alt="image-20220427171513-8" data-entity-type="file" data-entity-uuid="d5ea1fd4-17ec-473c-8a11-71cd4d6696e1" height="314" src="/sites/default/files/inline-images/image-20220427171513-8.png" width="1216" loading="lazy"><br>
<em>Figure 8: Thread hijacking attack chain leading to Bumblebee</em></p>

<h3>Contact Forms "Stolen Images" Leading to Bumblebee</h3>

<p>In March 2022, Proofpoint observed a campaign delivering emails generated by submitting a message to a contact form on the target's website. Additionally, depending on how the website's "contact us" section was configured, the submission also left public comments regarding this topic on the target's site. The emails purported to be claims that stolen images existed on the website.</p>

<p><img alt="image-20220427171513-9" data-entity-type="file" data-entity-uuid="704e0ef1-324c-4ebc-bbdd-9423601a9c54" height="736" src="/sites/default/files/inline-images/image-20220427171513-9.png" width="1272" loading="lazy"><br>
<em>Figure 9: Email sample containing a link to a landing page</em></p>

<p>The "complaint" contained a link to a landing page which directed the user to the download of an ISO file containing "DOCUMENT_STOLENIMAGES.LNK" and "neqw.dll").</p>

<p><img alt="image-20220427171513-10" data-entity-type="file" data-entity-uuid="3c1d47fc-9000-4e7b-aa24-6aa7abc7b549" height="622" src="/sites/default/files/inline-images/image-20220427171513-10.png" width="1099" loading="lazy"><br>
<em>Figure 10: Example Landing page</em></p>

<p>The shortcut file, if ran, executed "neqw.dll" with the correct parameters to start the Bumblebee downloader.</p>

<p><img alt="image-20220427171513-11" data-entity-type="file" data-entity-uuid="79078881-5928-48a4-804e-ae8b90d6534f" height="256" src="/sites/default/files/inline-images/image-20220427171513-11.png" width="1543" loading="lazy"><br>
<em>Figure 11: "Contact Form" attack chain leading to Bumblebee</em></p>

<p>Proofpoint attributed this campaign to TA578, a threat actor that Proofpoint researchers have been tracking since May of 2020. TA578 has previously been observed in email-based campaigns delivering Ursnif, IcedID, KPOT Stealer, Buer Loader, BazaLoader, and Cobalt Strike.</p>

<h2>Relationship to Other Malware</h2>

<p>The use of Bumblebee by multiple threat actors, the timing of its introduction in the landscape, and behaviors described in this report can be considered a notable shift in the cybercriminal threat landscape. Additionally, Proofpoint assesses with moderate confidence the actors using Bumblebee may be considered initial access facilitators, that is, independent cybercriminal groups that infiltrate major targets and then sell access to follow-on ransomware actors.</p>

<p>At least three tracked threat actors that typically distribute BazaLoader malware have transitioned to Bumblebee payloads, with BazaLoader last appearing in Proofpoint data in February 2022.</p>

<p>BazaLoader is a first stage downloader first identified in 2020 that has been associated with follow-on ransomware campaigns <a href="https://thedfirreport.com/2021/10/04/bazarloader-and-the-conti-leaks/" target="_blank">including Conti</a>. Proofpoint researchers initially observed BazaLoader being distributed in high volume by a threat actor that was primarily known to distribute the Trick banking trojan.</p>

<p><img alt="image-20220428121656-1" data-entity-type="file" data-entity-uuid="0d5a07e6-a414-4142-884a-c8e70f4df35b" height="625" src="/sites/default/files/inline-images/image-20220428121656-1.png" width="1174" loading="lazy"><br>
<em>Figure 12: Timeline of select campaigns from BazaLoader and Bumblebee</em></p>

<p>BazaLoader's apparent disappearance from the cybercrime threat landscape coincides with the timing of Conti Leaks, when, at the end of February 2022, a Ukrainian researcher with access to Conti's internal operations began <a href="https://therecord.media/conti-leaks-the-panama-papers-of-ransomware/" target="_blank">leaking</a> data from the cybercriminal organization. Infrastructure associated with BazaLoader was identified in the leaked files.</p>

<p>Proofpoint assesses with high confidence based on malware artifacts all the tracked threat actors using Bumblebee are receiving it from the same source.</p>

<h2>Malware Analysis</h2>

<p>Bumblebee is a downloader written in C++. The initial Bumblebee DLL sample analyzed contains two exports. One directly starts the thread for the Bumblebee main function. The other eventually leads to the same main function, but adds checks to see if hooks have been placed within key dynamic link libraries (DLLs). The LNK loading this DLL skips the default DllMain function and instead calls the export that checks for function hooks.</p>

<p><img alt="image-20220427171513-13" data-entity-type="file" data-entity-uuid="9b9f8ac2-b977-4ff0-93b9-5af933e720cf" height="806" src="/sites/default/files/inline-images/image-20220427171513-13.png" width="989" loading="lazy"><br>
<em>Figure 13: Screenshot of Bumblebee hook check</em></p>

<p>The majority of the Bumblebee loader is condensed into a single function unlike most malware where initialization, request sending, and response handling are broken out into different functions. The loader starts with copying over the group ID which is effectively used as botnet identifier. Unlike most other malware, Bumblebee currently has its configuration stored in plaintext, but Proofpoint suspects that obfuscation may be added in the future. With the group ID copied, the loader resolves addresses for various NTDLL functions that allow it to properly perform injection later in the loading process.</p>

<p><img alt="image-20220427171513-14" data-entity-type="file" data-entity-uuid="037f581d-6826-4116-b1a9-d244571b6a68" height="497" src="/sites/default/files/inline-images/image-20220427171513-14.png" width="843" loading="lazy"><br>
<em>Figure 14: Group ID copied and set</em></p>

<p>Once the functions are resolved a unique event is created that serves as a mutex to ensure only a single instance of the loader is running.</p>

<p><img alt="image-20220427171513-15" data-entity-type="file" data-entity-uuid="0a4101c5-a0bd-40fd-b1c5-4a3db469b868" height="269" src="/sites/default/files/inline-images/image-20220427171513-15.png" width="768" loading="lazy"><br>
<em>Figure 15: Event creation</em></p>

<p>At this point, a single instance of Bumblebee is confirmed to be running, and the malware begins gathering system information. The following WMI queries are executed via a COM object to gather details needed for communication:</p>

<ul>
	<li><em>SELECT * FROM Win32_ComputerSystem</em></li>
	<li><em>SELECT * FROM Win32_ComputerSystemProduct</em></li>
</ul>

<p>The hostname and UUID of the system are gathered and concatenated based on the query output. An MD5 hash of this value is then generated and turned into a hex digest. The result becomes the unique client ID of the bot.</p>

<p><img alt="image-20220427171513-16" data-entity-type="file" data-entity-uuid="b2a41f42-fea0-469b-867e-11664b4bfac8" height="758" src="/sites/default/files/inline-images/image-20220427171513-16.png" width="659" loading="lazy"><br>
<em>Figure 16: Client ID creation</em></p>

<p>After the client ID has been generated, the loader creates the system version string which includes the caption of a WMI query, the host's username, and the domain of the host if applicable.</p>

<p>With all this information gathered, the loader can start communication with the C2. The loader checks into the C2 every 25 seconds to retrieve commands. Unlike most malware that has a set of modules or payloads that are immediately returned to the bot, it appears the actors behind this malware manually deploy payloads to Bumblebee as it can take multiple hours before it receives any jobs to execute. Each server response contains a variation of the data shown in the figure below. If valid tasks are returned, the "tasks" value will be a list of dictionaries that contain all the task information.</p>

<p><img alt="image-20220427171513-17" data-entity-type="file" data-entity-uuid="ee11b018-6e5d-4319-b1ed-5eb3623ceae5" height="167" src="/sites/default/files/inline-images/image-20220427171513-17.png" width="470" loading="lazy"><br>
<em>Figure 17: Bumblebee response</em></p>

<p>Bumblebee loader supports the following commands:</p>

<ul>
	<li>Shi: shellcode injection</li>
	<li>Dij: DLL injection</li>
	<li>Dex: Download executable</li>
	<li>Sdl: uninstall loader</li>
	<li>Ins: enable persistence on the bot</li>
</ul>

<h3>Ins Command</h3>

<p>The Ins command enables persistence by copying the Bumblebee DLL to a subdirectory of %APPDATA% folder and creating a Visual Basic Script that will load the DLL. A scheduled task is created that invokes the Visual Basic Script via wscript.exe.</p>

<p><img alt="image-20220427171513-18" data-entity-type="file" data-entity-uuid="3e312880-b708-4f4a-a933-3a1b5aaa11fc" height="97" src="/sites/default/files/inline-images/image-20220427171513-18.png" width="651" loading="lazy"><br>
<em>Figure 18: VBS script loading the DLL</em></p>

<p><img alt="image-20220427171513-19" data-entity-type="file" data-entity-uuid="105f08bf-cf26-4ca7-8c9b-f573d2188eb8" height="326" src="/sites/default/files/inline-images/image-20220427171513-19.png" width="912" loading="lazy"><br>
<em>Figure 19: Scheduled task created with the VBS file</em></p>

<h3>Dex Command</h3>

<p>The Dex command is the most rudimentary of the supported commands. It takes the base64 decoded content from the server response, writes it to disk at a hardcoded path and executes it via a COM object</p>

<p><img alt="image-20220427171513-20" data-entity-type="file" data-entity-uuid="b2151e1b-9f5e-4aaa-9612-1b7c8a770beb" height="370" src="/sites/default/files/inline-images/image-20220427171513-20.png" width="861" loading="lazy"> <em>Figure 20: Dex command output</em></p>

<h3>Dij Command</h3>

<p>The Dij command adds the ability to inject DLLs into the memory of other processes. For injection targets, the malware picks one of three hardcoded options to inject the DLL into (ImagingDevices.exe, wab.exe, or wabmig.exe).</p>

<p><img alt="image-20220427171513-21" data-entity-type="file" data-entity-uuid="471f3dd3-4e0b-4570-9201-174bad6663b4" height="165" src="/sites/default/files/inline-images/image-20220427171513-21.png" width="884" loading="lazy"><br>
<em>Figure 21: Identifying executable files as injection targets</em></p>

<p>With a random executable picked, the loader starts the process in a suspended state (also via a COM object). This allows the malware to easily manipulate the process without causing issues. Next, it prepares the process for injection by enabling debug privileges so it can inject the shellcode necessary for execution.</p>

<p><img alt="image-20220427171513-22" data-entity-type="file" data-entity-uuid="922ee550-8ac7-494d-9cdb-bedc9155e962" height="532" src="/sites/default/files/inline-images/image-20220427171513-22.png" width="631" loading="lazy"><br>
<em>Figure 22: New process creation and enabling debug privileges</em></p>

<p>With proper permissions set, data can be manipulated, and the loader writes shellcode to the suspended process, overriding the initial entry point with a new one. This implementation writes 32 bytes of shellcode and replaces a placeholder of with the resolved address of <em>SleepEx</em>.</p>

<p><img alt="image-20220427171513-23" data-entity-type="file" data-entity-uuid="797de427-251e-488a-9feb-feb531b0f95a" height="430" src="/sites/default/files/inline-images/image-20220427171513-23.png" width="876" loading="lazy"><br>
<em>Figure 23: SleepEx replacing the placeholder value</em></p>

<p><img alt="image-20220427171513-24" data-entity-type="file" data-entity-uuid="135db1fb-99e4-44c0-b15d-940af40b5549" height="168" src="/sites/default/files/inline-images/image-20220427171513-24.png" width="597" loading="lazy"><br>
<em>Figure 24: Disassembled shellcode</em></p>

<p>The "call RAX" instruction in the shellcode assembly shown in above figure gets replaced with the address of the SleepEx as seen in the previous figure and the shellcode calls SleepEx with a value of 1000 milliseconds. With the shellcode now injected into the process, the process can be resumed and the loader can inject the malicious payload into the executable via an APC routine.</p>

<p><img alt="image-20220427171513-25" data-entity-type="file" data-entity-uuid="3a1f6723-424d-4608-835b-fd771254fce6" height="196" src="/sites/default/files/inline-images/image-20220427171513-25.png" width="743" loading="lazy"></p>

<p><em>Figure 25: Process injection via APC</em></p>

<p>To properly inject, the loader creates two new sections within the injection target and copies the buffer from <q>dij</q> into the new section then invokes the copied contents in the target executable via a dynamically resolved <em>NtQueueApcThread</em>.</p>

<p><img alt="image-20220427171513-26" data-entity-type="file" data-entity-uuid="c5eaba7c-890d-4ea6-8b1f-15bf167a611f" height="460" src="/sites/default/files/inline-images/image-20220427171513-26.png" width="1090" loading="lazy"><br>
<em>Figure 26: Creation of two new sections</em></p>

<p><img alt="image-20220427171513-27" data-entity-type="file" data-entity-uuid="5ec27304-02af-4087-a676-7127d20ffd2a" height="163" src="/sites/default/files/inline-images/image-20220427171513-27.png" width="674" loading="lazy"><br>
<em>Figure 27: Calling the dynamically resolved NtQueueApcThread</em></p>

<h3>Malware Development</h3>

<p>Proofpoint researchers noticed that within a month of campaigns, Bumblebee developers added new features to the malware. Specifically, the inclusion of anti-VM and anti-sandbox checks. Below is the earlier sample:</p>

<p><img alt="image-20220427171513-28" data-entity-type="file" data-entity-uuid="51cb7add-9f00-49e7-9516-aa46db903f00" height="332" src="/sites/default/files/inline-images/image-20220427171513-28.png" width="702" loading="lazy"><br>
<em>Figure 28: Old Bumblebee sample</em></p>

<p>And the more recent sample:</p>

<p><img alt="image-20220427171513-29" data-entity-type="file" data-entity-uuid="00194bc2-21cb-4077-8077-b3b8267a054c" height="411" src="/sites/default/files/inline-images/image-20220427171513-29.png" width="854" loading="lazy"><br>
<em>Figure 29: Updated Bumblebee sample with addition of check_bad_artifacts</em></p>

<p>Researching the new functionality revealed a neat surprise:</p>

<p><img alt="image-20220427171513-30" data-entity-type="file" data-entity-uuid="15f422b7-79f6-4795-86f9-3f7cb9535890" height="524" src="/sites/default/files/inline-images/image-20220427171513-30.png" width="601" loading="lazy"><br>
<em>Figure 30: Decompilation of the malware's firmware check</em></p>

<p><img alt="image-20220427171513-31" data-entity-type="file" data-entity-uuid="449d2f82-3fab-44a1-bd60-a556f589df34" height="484" src="/sites/default/files/inline-images/image-20220427171513-31.png" width="704" loading="lazy"><br>
<em>Figure 31: Open source code from Al Khaser showing the exact same check</em></p>

<p>The above figures are part of the <a href="https://github.com/LordNoteworthy/al-khaser/blob/06d4a89e9ecc3e49e4d2df67fe0b2d6faf04166e/al-khaser/Shared/Utils.cpp#L950" style="color:#0563c1; text-decoration:underline">Al Khaser</a> suite which is a common tool used to check for VM artifacts. It appears that the developers of the Bumblebee loader rely on open-source tooling, just like standard developers.</p>

<h2>Significant Update</h2>

<p>Proofpoint noted significant changes to Bumblebee functionality in the latest version of Bumblebee observed on April 19, 2022. Support for multiple C2s via a comma delimited list is now supported.</p>

<p><img alt="image-20220427171513-32" data-entity-type="file" data-entity-uuid="84d0b175-e75a-4cdf-92f7-5f340a5ec1d8" height="75" src="/sites/default/files/inline-images/image-20220427171513-32.png" width="580" loading="lazy"><br>
<em>Figure 32: Multiple embedded C2s</em></p>

<p>The sleep interval in the older versions was previously hardcoded at 25 seconds but now that has been replaced with a randomized value.</p>

<p><img alt="image-20220427171513-33" data-entity-type="file" data-entity-uuid="88de0620-5035-49d8-b041-32efb7e22c40" height="167" src="/sites/default/files/inline-images/image-20220427171513-33.png" width="571" loading="lazy"><br>
<em>Figure 33: Addition of random sleep values</em></p>

<p>The most significant change to the malware has been the addition of an encryption layer to the network communications. The developers added RC4 via a hardcoded key to the sample which is used to encrypt the requests and decrypt the responses.</p>

<p><img alt="image-20220427171513-34" data-entity-type="file" data-entity-uuid="ae8b5c75-e9f9-4aeb-9e53-609ccfdcd4fa" height="247" src="/sites/default/files/inline-images/image-20220427171513-34.png" width="703" loading="lazy"><br>
<em>Figure 34: encryption of the request</em></p>

<p><img alt="image-20220427171513-35" data-entity-type="file" data-entity-uuid="5503c501-60b0-4f5e-b343-da42b1bcae68" height="183" src="/sites/default/files/inline-images/image-20220427171513-35.png" width="363" loading="lazy"><br>
<em>Figure 35: decryption of the response</em></p>

<p style="margin-bottom:16px"><span style="font-size:12pt"><span style="line-height:107%"><span style="font-family:&quot;Avenir Next LT Pro&quot;,sans-serif"><span style="color:black">As another marker of this group demonstrating their fast development velocity, on April 22 <sup>&nbsp;</sup>Proofpoint observed this group adding a new thread to Bumblebee that checks current running processes against a hardcoded list of common tools used by malware analysts. This thread gets created at the beginning of the Bumblebee process. </span></span></span></span></p>

<p><img alt="image-20220427171513-36" data-entity-type="file" data-entity-uuid="0c57dfd2-4f39-4bf6-92ec-c6e2a36c73a1" height="433" src="/sites/default/files/inline-images/image-20220427171513-36.png" width="762" loading="lazy"><br>
<em>Figure 36: The Bumblebee main function showing the start of the new thread.</em></p>

<p><img alt="image-20220427171513-37" data-entity-type="file" data-entity-uuid="97e7e4e1-b9d1-47ae-8418-871f80a53f27" height="734" src="/sites/default/files/inline-images/image-20220427171513-37.png" width="440" loading="lazy"><br>
<em>Figure 37: The list of tools Bumblebee checks for.</em></p>

<p>If any of these processes are found, the function returns 1 which triggers the main Bumblebee thread to be terminated.</p>

<h2>Conclusion</h2>

<p>Bumblebee is a sophisticated malware loader that demonstrates evidence of ongoing development. It is used by multiple cybercrime threat actors. Proofpoint assesses with high confidence Bumblebee loader can be used as an initial access facilitator to deliver follow-on payloads such as ransomware. Based on the timing of its appearance in the threat landscape and use by multiple cybercriminal groups, it is likely Bumblebee is, if not a direct replacement for BazaLoader, then a new, multifunctional tool used by actors that historically favored other malware.</p>
