<h1 class="blog-banner__heading">
      DTPacker – a .NET Packer with a Curious Password 
  </h1>

    </div>
  </div>

  <div class="blog-content">
    <div class="blog-content__sharethis sharethis_toolbox sharethis_32x32_style">
      <div class="blog-content__sharethis_label sharethis__label">Share with your network!</div>

        <div class="blog-content__metadata blog-content__metadata-author">
      <span class="blog-content__date">  <time datetime="2022-01-24T13:09:18Z">January 24, 2022</time>

    <div class="node-full__body blog-content__body">  <p><meta charset="utf-8"></p>

<h3>Key Findings&nbsp;</h3>

<ul>
	<li>Proofpoint identified a malware packer which researchers have dubbed DTPacker.&nbsp;</li>
	<li>The payload decoding uses a fixed password containing former U.S. president Donald Trump’s name.&nbsp;&nbsp;</li>
	<li>For several weeks the downloader variant used Liverpool Football Club themed download locations.&nbsp;</li>
	<li>The malware is typically used to pack remote access trojans that can be used to steal information and load follow-on payloads such as ransomware.&nbsp;&nbsp;</li>
</ul>

<h3>Overview&nbsp;</h3>

<p>In a previous blog&nbsp;<a href="https://www.proofpoint.com/us/blog/threat-insight/commodity-net-packers-use-embedded-images-hide-payloads" target="_blank">Commodity .NET Packers use Embedded Images to Hide Payloads</a>, we described the "CyaX" and "Hectobmp" families of .NET packers.&nbsp;</p>

<p>In this blog, we describe a two-stage commodity .NET packer or downloader which although seeing considerable variety in the first stage, uses a second stage with a fixed password as part of the decoding. The main difference between a packer and a downloader is the location of the payload data which is embedded in the former and downloaded in the latter. DTPacker uses both forms. It is unusual for a piece of malware to be both a packer and downloader.&nbsp;&nbsp;&nbsp;&nbsp;</p>

<p>Proofpoint has observed DTPacker distributing multiple remote access trojans (RATs) and information stealers including Agent Tesla, Ave Maria, AsyncRAT, and FormBook. The malware uses multiple obfuscation techniques to evade antivirus, sandboxing, and analysis. It is likely distributed on underground forums. Proofpoint has observed DTPacker associated with dozens of campaigns and multiple threat actors including TA2536 and TA2715 since 2020. Proofpoint has observed DTPacker used by both advanced persistent threat (APT) and cybercrime threat actors. Identified campaigns included thousands of messages and impacted hundreds of customers in multiple industries.&nbsp;</p>

<h3>Attack Path Example&nbsp;</h3>

<p>In many observed campaigns, email is used as an initial infection vector. The attachment is typically a malicious document or compressed executable that, when interacted with by a user, downloads the packer executable. The malware decodes an embedded or downloaded resource to a DLL which contains the malware payload, and then executes the malware.&nbsp;&nbsp;</p>

<p><img alt="Figure 1" data-entity-type="file" data-entity-uuid="b040cdb8-63d7-4c5e-a094-dbf0185a1a42" src="/sites/default/files/inline-images/Figure%201%20.png" width="1407" height="389" loading="lazy"></p>

<p>Figure 1: DTPacker attack path example.&nbsp;</p>

<h3>Custom XOR Decoding&nbsp;</h3>

<p>Proofpoint observed multiple decoding methods and two Donald Trump-themed fixed keys, thus the name “DT”Packer. Many packers and loaders are built in two stages of functionality. Earlier versions of DTPacker used a custom XOR routine to decode the malicious content in both stages. The first stage of DTPacker decodes an embedded or downloaded resource to an intermediate stage (usually a DLL), then the second stage extracts and executes the payload from that DLL.&nbsp;</p>

<p>The custom XOR routine, in addition to XORing with the key, subtracts the next data value and is implemented in this Python script (on Github)&nbsp;<a href="https://raw.githubusercontent.com/EmergingThreats/threatresearch/master/dtpacker/decoder-xor-sub.py" target="_blank">decoder-xor-sub.py.</a>&nbsp;</p>

<p>For a Windows Portable Executable, there are significant sequences of null bytes, and consequently, XORing the ciphertext with itself shifted by 1 byte reveals the key at locations corresponding to those null bytes.&nbsp;</p>

<p>For example, in this sample (SHA256</p>

<p>512b2f1f4b659930900abcc8f51d175e88c81b0641b7450a6618b77848fa3b40):&nbsp;</p>

<p>The intermediate stage is stored in a .NET resource encoded with the custom XOR routine and key "P" (in ASCII not Unicode UTF-16 this time).&nbsp;</p>

<p><img alt="DTPacker 2" data-entity-type="file" data-entity-uuid="70dbf380-f5f9-4d06-96b4-fcf224540643" src="/sites/default/files/inline-images/2.png" width="1372" height="353" loading="lazy"></p>

<p>The .NET resource XORed with itself shifted by one byte reveals the password "P":&nbsp;</p>

<p><img alt="DTPacker 3" data-entity-type="file" data-entity-uuid="8768348d-8332-4bd0-8de9-6658ebaf020a" src="/sites/default/files/inline-images/3.png" width="1361" height="360" loading="lazy"></p>

<p>Decoding with key "P" gives the second stage executable:&nbsp;</p>

<p><img alt="DTPacker 4" data-entity-type="file" data-entity-uuid="36f073da-4410-4325-bcb5-2930ef84bca8" src="/sites/default/files/inline-images/4.png" width="1362" height="359" loading="lazy"></p>

<p>The second stage contains a .NET resource (named "00112266"):&nbsp;</p>

<p><img alt="DTPacker 5" data-entity-type="file" data-entity-uuid="83872e82-2da3-4ee2-8ea8-ac54e42e1016" src="/sites/default/files/inline-images/5.png" width="1366" height="356" loading="lazy"></p>

<p>XORed with itself shifted by one byte gives:&nbsp;</p>

<p><img alt="DTPacker 6" data-entity-type="file" data-entity-uuid="ce9e2813-02cf-4a27-a6e1-3ca37d6dd07d" src="/sites/default/files/inline-images/6.png" width="1357" height="355" loading="lazy"></p>

<p>which gives a key of "trump2020" in Unicode UTF-16. The threat actors used this key consistently for a year and is the reason for the packer’s name.&nbsp;</p>

<p>Decoding with the “trump2020” key gives the final payload:&nbsp;</p>

<p><img alt="DTPacker 7" data-entity-type="file" data-entity-uuid="c65a06eb-99ea-4482-818f-018990c1f00b" src="/sites/default/files/inline-images/7.png" width="1364" height="359" loading="lazy"></p>

<p>In this case, the payload was Agent Tesla, a common information stealer.&nbsp;</p>

<h3>Varied First Stage Encoding&nbsp;</h3>

<p>In this downloader sample (SHA256</p>

<p>9d713d2254e529286ed3ac471e134169d2c7279b0eaf82eb9923cd46954d5d27) the Download URLs are stored as strings obfuscated with junk Unicode characters&nbsp;</p>

<p>In this case, the decompiled code looks like:&nbsp;</p>

<p><img alt="DTPacker 8" data-entity-type="file" data-entity-uuid="3ac10d49-bdeb-410e-97ee-277180c46eed" src="/sites/default/files/inline-images/8.png" width="1330" height="473" loading="lazy"></p>

<p>and removing the Unicode characters gives:&nbsp;</p>

<p><img alt="DTPacker XX" data-entity-type="file" data-entity-uuid="eff678f6-cd51-4ce8-9844-8eb3b49aa580" src="/sites/default/files/inline-images/XX.png" width="1053" height="35" loading="lazy"></p>

<p>The downloads are glued together and contain base64-encoded strings:&nbsp;</p>

<p><img alt="DTPacker 9" data-entity-type="file" data-entity-uuid="a83c071c-0238-4bc0-904e-a16c4cde5597" src="/sites/default/files/inline-images/9.png" width="1345" height="132" loading="lazy"></p>

<p>These decode to:&nbsp;</p>

<p><img alt="DTPacker 10" data-entity-type="file" data-entity-uuid="e0c71aa6-1bd0-4ec7-b054-6f378235e558" src="/sites/default/files/inline-images/10.png" width="1327" height="346" loading="lazy"></p>

<p>which after XORing with byte 0x02 gives:&nbsp;</p>

<p><img alt="DTPacker 11" data-entity-type="file" data-entity-uuid="d008684d-d039-4130-9f2f-a62a5b592b50" src="/sites/default/files/inline-images/11.png" width="1317" height="341" loading="lazy"></p>

<p>This is a second stage executable containing a "00112266" resource encoded with the "trump2020" key as before, which then decodes to Agent Tesla.&nbsp;</p>

<h3>Decimal Character Codes&nbsp;</h3>

<p>One recurrent theme in this family of packers is the use of decimal character codes with digits substituted with other characters.&nbsp;</p>

<p>For example, this sample (SHA256</p>

<p>285f4e79ae946ef179e45319caf11bf0c1cdaa376924b83bfbf82ed39361911b) is a packer with the second stage embedded in the .NET Strings table:&nbsp;</p>

<p><img alt="DTPacker 12" data-entity-type="file" data-entity-uuid="b15dadbc-f567-4f62-97eb-93aa4196cf0b" src="/sites/default/files/inline-images/Figure%2012%20.png" width="1393" height="88" loading="lazy"></p>

<p>which are comma-separated decimal ASCII character codes with digits 0-9 replaced by "!@#$%[X]&amp;*()" where "[X]" represents Unicode character 0x8ac2; reversing this gives us:&nbsp;</p>

<p><img alt="DTPacker 13" data-entity-type="file" data-entity-uuid="7e65c618-c6d3-4a54-bc7b-9ad99e94c3b9" src="/sites/default/files/inline-images/figure%2013.png" width="1393" height="67" loading="lazy"></p>

<p>This decodes to an intermediate PE containing the "00112266" resource with key "trump2020" which decodes to Ave Maria, also known as Warzone RAT.&nbsp;&nbsp;</p>

<p>This sample (SHA256</p>

<p>1312912d725d45bcd1b63922ec9a84abca7a8c9c669c13efbd03472c764be056 is similar to the above, but with the second stage stored in the User Strings table:&nbsp;</p>

<p><img alt="DTPacker 14" data-entity-type="file" data-entity-uuid="b0ffc7bb-141c-4974-bd7b-d6a193ddf614" src="/sites/default/files/inline-images/Figure%2014.png" width="1385" height="58" loading="lazy"></p>

<p>with digits 0-9 replaced by "zxcasdwqru" (partially matching the first three letters on rows of a QWERTY keyboard). This decodes to AsyncRAT.&nbsp;</p>

<p>Another sample (SHA256</p>

<p>ba0f9be7cf006404bcfab6b6adbad0cef7281c3792490903632a4010d8a74f42) is a loader with download string obfuscated in a similar way to Sample 1, which deobfuscates to (defanged):&nbsp;</p>

<p>hxxps://ahgwqrq[.]xyz/getrandombase64.php?get=E2E813E9694BE43CAD964C0453632F91@@@hxxps://ahgwqrq[.]xyz/getrandombase64.php?get=63DC49E5D8F5F50F8838551347009928@@@hxxps://ahgwqrq[.]xyz/getrandombase64.php?get=D13B96F0619AC39B44A32D3E0A260C89@@@hxxps://ahgwqrq[.]xyz/getrandombase64.php?get=85530E49BB23CD9DBD8461A2FC5D18A2&nbsp;</p>

<p>The downloads are obfuscated in a similar in the above samples, with digits 0-9 replaced by the letters A-J:&nbsp;</p>

<p><img alt="DTPacker 15" data-entity-type="file" data-entity-uuid="c137e88b-cb90-4a5d-a4d3-246a7ab11b3b" src="/sites/default/files/inline-images/Figure%2015.png" width="1398" height="152" loading="lazy"></p>

<p>The download decodes to the usual second stage which in turn decodes to Agent Tesla.&nbsp;</p>

<h3>String Obfuscation using Large Character Code Offsets&nbsp;</h3>

<p>This sample (SHA256 5d555eddfc23183dd821432fd2a4a04a543c8c1907b636440eb6e7d21829576c) is a loader with strings obfuscated as Unicode strings followed by an integer to subtract from their character codes, e.g.&nbsp;</p>

<p><img alt="DTPacker 16" data-entity-type="file" data-entity-uuid="9a33d184-3997-4e21-aa57-740eefca9a57" src="/sites/default/files/inline-images/16.png" width="1342" height="379" loading="lazy"></p>

<p>which decodes to:</p>

<p><img alt="DTPacker 17" data-entity-type="file" data-entity-uuid="99c11516-16e9-4a84-88d9-8912808ffdcd" src="/sites/default/files/inline-images/17.png" width="1222" height="219" loading="lazy"></p>

<p>The downloads are again ASCII character codes with digits 0-9 replaced by the letters "PxfnVCKsAi".&nbsp;</p>

<p>This time, however, there is no intermediate step with the custom XOR routine and "trump2020" key, and the payload is Agent Tesla.&nbsp;</p>

<p>From March 2021, Proofpoint observed samples using websites for soccer clubs and their fans being used as download locations. These websites appear to have been decoys, with the actual payload locations embedded in the list.&nbsp;</p>

<p>For example, in this sample (SHA256 b53558a85b8bb10ce70cb0592a81e540683d459b9d8666b7927c105f1141a189), decompiled code looks like:&nbsp;</p>

<p><img alt="DTPacker 20" data-entity-type="file" data-entity-uuid="35b00e79-eabb-4969-b356-274b26a5379b" src="/sites/default/files/inline-images/20.png" width="1308" height="380" loading="lazy"></p>

<p><img alt="DTPacker 21" data-entity-type="file" data-entity-uuid="08420880-5716-4f1d-a5b7-e646968097d7" src="/sites/default/files/inline-images/21.png" width="1296" height="257" loading="lazy"></p>

<h3>String Obfuscation using Obfuscated Character Code Arrays&nbsp;</h3>

<p>This sample (SHA256 281cdbf590c22cd684700dcde609d6be48ddf3e4d988d48e65d9c688ce76f7af) uses obfuscated .NET code to store important strings as arrays of ASCII character codes:&nbsp;&nbsp;&nbsp;</p>

<p>[0] : qHWXhtvYuc&nbsp;</p>

<p>[1] : Append&nbsp;</p>

<h3>CyaX Packer using Same Modified XOR Routine&nbsp;</h3>

<p>From November 2021, Proofpoint&nbsp;<a href="https://www.proofpoint.com/us/blog/threat-insight/commodity-net-packers-use-embedded-images-hide-payloads" target="_blank">observed CyaX-packer</a>&nbsp;using a very similar second stage to that of DTPacker with the "trump2020" key.&nbsp;</p>

<p>This time, however, the keys are randomly generated, ASCII, mixed case alphabetic, and 8-14 characters long, rather than UTF-16-encoded "trump2020".&nbsp;</p>

<p>In this sample (SHA2564053206d66d627d145d9da8d8e208d08c85755036a5393ccc6e8afd6117df864), the intermediate stage contains a .NET resource file "18Ocjj4dc4" starting:&nbsp;</p>

<p><img alt="DTPacker 32" data-entity-type="file" data-entity-uuid="0ef18d19-16a0-4d88-bf28-a6cb4ae3f643" src="/sites/default/files/inline-images/32.png" width="1226" height="317" loading="lazy"></p>

<p><img alt="DTPacker 33" data-entity-type="file" data-entity-uuid="19de6773-9b7d-484f-af34-4a17e86c3f7b" src="/sites/default/files/inline-images/33.png" width="1233" height="325" loading="lazy"></p>

<p>which, after fixing the first byte, is Agent Tesla.&nbsp;</p>

<p>This would suggest a common source for the second stage of both the "trump2020" version of DTPacker and the latest second stage of CyaX. It is possible there is a resource overlap between DTPacker and CyaX, such as both authors paying for the same DLL encoder, but Proofpoint cannot confirm this.&nbsp;</p>

<h3>Conclusion&nbsp;</h3>

<p>DTPacker’s use as both a packer and downloader and its variation in delivery and obfuscation whilst keeping two such unique keys as part of its decoding is very unusual.&nbsp;</p>

<p>It is unknown why the malware author specifically referred to Donald Trump in the malware’s fixed passwords, as it is not used to specifically target politicians or political organizations and would not be seen by the intended victims. Proofpoint assesses this malware will continue to be used by multiple threat actors.&nbsp;&nbsp;</p>
