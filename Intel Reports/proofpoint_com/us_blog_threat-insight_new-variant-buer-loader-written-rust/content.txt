<h1 class="blog-banner__heading">
      New Variant of Buer Loader Written in Rust  
  </h1>

    </div>
  </div>

  <div class="blog-content">
    <div class="blog-content__sharethis sharethis_toolbox sharethis_32x32_style">
      <div class="blog-content__sharethis_label sharethis__label">Share with your network!</div>
      <div class="blog-content__sharethis_buttons sharethis_buttons">
        <div class="sharethis-inline-share-buttons"></div>
      </div>
    </div>
        <div class="blog-content__metadata blog-content__metadata-author">
      <span class="blog-content__date">  <time datetime="2021-05-03T19:53:18Z">May 03, 2021</time>

</span>
        <span class="blog-content__author">
                Kelsey Merriman, Bryan Campbell, Selena Larson, and the Proofpoint Threat Research Team
  
        </span>
    </div>
    <div class="node-full__body blog-content__body">  <style type="text/css">.node-blog-full .blog-content img {
border: 1px solid #000 !important;
}
</style>
<p><strong>Overview</strong></p>

<p>Proofpoint researchers identified a new variant of the Buer malware loader distributed via emails masquerading as shipping notices in early April. <a href="https://malpedia.caad.fkie.fraunhofer.de/details/win.buer">Buer</a> is a downloader sold on underground marketplaces that is used as a foothold in compromised networks to distribute other malware, <a href="https://www.cert.ssi.gouv.fr/uploads/CERTFR-2021-CTI-006.pdf">including ransomware</a>. Proofpoint first <a href="https://www.proofpoint.com/us/threat-insight/post/buer-new-loader-emerges-underground-marketplace">observed Buer in 2019</a>.</p>

<p>In the associated campaigns, the emails purported to be from DHL Support. They contained a link to a malicious Microsoft Word or Excel document download that used macros to drop the new malware variant. Proofpoint is calling this new variant RustyBuer. The emails impacted over 200 organizations across more than 50 verticals. The new strain is completely rewritten in a coding language called Rust, a departure from the previous C programming language. It is unusual to see common malware written in a completely different way.</p>

<p><strong>Key Findings</strong></p>

<ul>
	<li>The new Buer variant is written in Rust, an efficient and easy-to-use programming language that is becoming increasingly popular. Proofpoint is calling this variant RustyBuer.</li>
	<li>Rewriting the malware in Rust enables the threat actor to better evade existing Buer detection capabilities.</li>
	<li>Proofpoint observed RustyBuer campaigns delivering Cobalt Strike Beacon as a second-stage payload in some campaigns.</li>
	<li>Researchers assess some threat actors may be establishing a foothold with the Buer loader to then sell access to other threat actors. This is known as “access-as-a-service.”</li>
</ul>

<p><strong>Campaign Details</strong></p>

<p>Proofpoint analysts observed a series of malicious campaigns that delivered the Buer malware loader. The campaigns generally used DHL-themed phishing emails to distribute malicious Word or Excel documents. While sharing similar email lure themes, the campaigns distributed two distinct variants of the Buer malware: one was written in C while the other was rewritten in the Rust programming language. Proofpoint dubbed this variant RustyBuer. The campaigns also used different lure techniques, with RustyBuer attachments containing more detailed content to better engage the recipient.</p>

<p>The rewritten malware, and the use of newer lures attempting to appear more legitimate, suggest threat actors leveraging RustyBuer are evolving techniques in multiple ways to both evade detection and attempt to increase successful click rates.</p>

<p><img alt="Rusty_1" data-entity-type="file" data-entity-uuid="a8616fea-4ad1-401e-83a5-19262199d1ee" height="877" src="/sites/default/files/inline-images/Rusty_1.png" width="801" loading="lazy"></p>

<p>Figure 1: Emails masquerading as DHL shipping themes used to distribute RustyBuer and Buer loaders.</p>

<p><img alt="Rusty_2" data-entity-type="file" data-entity-uuid="61db7a19-e138-440b-ba8a-ae36e374ae7c" height="502" src="/sites/default/files/inline-images/Rusty_2.png" width="869" loading="lazy"></p>

<p>Figure 2: Malicious Excel attachment distributing RustyBuer containing multiple security software brand logos in an attempt to add legitimacy to the document.</p>

<p>RustyBuer was embedded directly into the document macro and required user interaction to initiate the infection. This macro leveraged an Application Bypass (Windows Shell DLL via <a href="https://lolbas-project.github.io/lolbas/Libraries/Shell32/">LOLBAS</a>) to evade detection from endpoint security mechanisms.</p>

<p><strong>Example Script execution:</strong></p>

<p>rundll32.exe shell32.dll,ShellExec_RunDLL C:\ProgramData\OfficeSignCheck.exe</p>

<p>Once RustyBuer is dropped, it establishes persistence by using a shortcut (.LNK) file which runs at startup.</p>

<p>All the identified campaigns used consistent naming conventions following the inclusion of “Office” in the dropped executable. Both the Rust and C versions of the malware followed this same pattern including:</p>

<ol>
	<li>OfficeVerifySign.exe (<strong>3abed86f46c8be754239f8c878f035efaae91c33b8eb8818c5bbed98c4d9a3ac</strong>)</li>
	<li>Office_WorkForWestBank.exe (<strong>423790a4a722f3549d1dfc1026fa627d829c6dd8c26546d45f2ca4b6d6626acb</strong>)</li>
	<li>OfficeReleaseFix.exe (<strong>b3d510ef04275ca8e698e5b3cbb0ece3949ef9252f0cdc839e9ee347409a2209</strong>)</li>
	<li>OfficeConsultPlugin.exe (sha256:<strong>b3d510ef04275ca8e698e5b3cbb0ece3949ef9252f0cdc839e9ee347409a2209</strong>)</li>
</ol>

<p>Proofpoint researchers observed RustyBuer distributing Cobalt Strike Beacon as a second-stage payload in some instances, like previous Buer campaigns. Cobalt Strike is a legitimate security tool used by penetration testers to emulate adversary activity in a network that is becoming increasingly popular as a tool for threat actors.</p>

<p>However, not all identified campaigns contained a second-stage payload. Researchers assess this may be due to threat actors in some specific instances operating as access-as-a-service providers. These threat actors may be attempting to establish initial access in victim environments to then sell their access to other threat actors in underground marketplaces. Other security firms have <a href="https://news.sophos.com/en-us/2020/10/28/hacks-for-sale-inside-the-buer-loader-malware-as-a-service/">documented this behavior</a> from threat actors using Buer loader previously.</p>

<p><strong>Malware Analysis</strong></p>

<p>Proofpoint classified the new variant of Buer (RustyBuer) as a rewritten version in Rust based on present anti-analysis features, strings, and encoding and format of the command and control (C2) requests.</p>

<p>It is unclear why the threat actors took the time and effort to rewrite the malware in a new programming language, however Proofpoint researchers identify two likely reasons:</p>

<ol>
	<li>Rust is an increasingly popular programming language that is more efficient and has a broader feature set than C. (Microsoft, for example, is <a href="https://www.zdnet.com/article/microsoft-why-we-used-programming-language-rust-over-go-for-webassembly-on-kubernetes-app/">increasingly</a> using it in its products and <a href="https://cloudblogs.microsoft.com/opensource/2021/02/08/microsoft-joins-rust-foundation/">joined</a> the Rust Foundation in February 2021.)</li>
	<li>Rewriting the malware in Rust can enable the threat actor to evade existing Buer detections that are based on features of the malware written in C. The malware authors have programmed it in a way that it should maintain compatibility with existing Buer backend C2 servers and panels.</li>
</ol>

<p><img alt="Rusty_3" data-entity-type="file" data-entity-uuid="a402452e-55fa-4dae-a600-36fc2425a621" height="374" src="/sites/default/files/inline-images/Rusty_3.png" width="737" loading="lazy"></p>

<p>Figure 3: Example of select Rust dependencies</p>

<p>The following is a detailed analysis of the new variant.</p>

<p>Anti-analysis features</p>

<ul>
	<li>Checks for virtual machines (Figure 7)</li>
	<li>Checks locale to make sure the malware is not running in specific countries (Figure 8). These countries appear to be a part of the Commonwealth of Independent States (CIS).</li>
</ul>

<p><img alt="Rusty_4" data-entity-type="file" data-entity-uuid="cc6ddf30-4444-453e-b981-d1a908d0c538" src="/sites/default/files/inline-images/Rusty_4.png" width="768" height="579" loading="lazy"></p>

<p>Figure 4: Virtual machine checks</p>

<p><img alt="Rusty_5" data-entity-type="file" data-entity-uuid="690d6cf6-580f-46cf-907d-c5cc04ea30a2" src="/sites/default/files/inline-images/Rusty_5.png" width="431" height="169" loading="lazy"></p>

<p>Figure 5: Locale check</p>

<p><strong>Command and Control</strong></p>

<p>The C2 requests are nearly identical to the requests used in the latest version of Buer. The C2 functions are handled via HTTP(S) POST requests. The initial POST request will be sent with POST data delimitated by the "&amp;" and "=" characters. The POST request contains both pseudorandom characters and encrypted information about the compromised system. An example command beacon can be seen in Figure 6:</p>

<p><img alt="Rusty_6" data-entity-type="file" data-entity-uuid="e85e295b-69c1-42b3-a087-cb832dde2d21" height="450" src="/sites/default/files/inline-images/Rusty_6.png" width="924" loading="lazy"></p>

<p>Figure 6: RustyBuer initial POST request</p>

<p><img alt="Rusty_7" data-entity-type="file" data-entity-uuid="0a817c4c-6485-48c2-be36-9eddd2367752" src="/sites/default/files/inline-images/Rusty_7.png" width="852" height="1030" loading="lazy"></p>

<p>Figure 7: Buer Loader initial POST request</p>

<p>An example of the plaintext parameter from Figure 8 with the pseudorandom characters removed is:</p>

<p>Yv3FHY+KQgL5YKs58+uRvGVZT8IS82xY+eij8SW/OhZd5Kk70Oryj8G4C5NB341+u9Xk8FFWvgdHoxrX68ZwZdrWO18fPzUeMJZvDfXcWKo0WaSad2RooXIPzbjPTqooMCxES4LVt/a812bqP8iJnuvZb1JIHa4m/eLC6hOGQBMSG8yY561aXdv+iLB3vhv8kww/1vhyIsmvxHzgcAzY9NWDSm/oZ3BfjAnfVCsgwQ6MebuHvEUXjyJBe6NsjRS+bYiLLrjO9HU=JbSYHpjfúÆ</p>

<p>These request parameters are encrypted. They can be decrypted by:</p>

<ol>
	<li>Base64 decoding</li>
	<li>Hex decoding</li>
	<li>RC4 decryption (the key used in the analyzed samples was “kpM5WOtfo”)</li>
</ol>

<p>The decrypted plaintext parameter from Figure 6 is:</p>

<p>299bc0beffe830d0871f8f6d7cadb40117208ea59f59cadd08b220b903f4e31c|e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855|Windows 7 Ultimate|x64|4|Admin|[Computer Name]|133/238|[AD Domain]|[User Name]|1</p>

<p>It contains pipe-delimited data consisting of:</p>

<ul>
	<li>Bot ID (SHA-256 hex digest of various system parameters such as hardware profile GUID and name, computer name, volume serial number, and CPUID)</li>
	<li>An SHA-256 hash of its own executable image</li>
	<li>Windows version</li>
	<li>Architecture type</li>
	<li>Number of processors</li>
	<li>User privileges</li>
	<li>Computer name</li>
	<li>Space used / total (suspected)</li>
	<li>AD Domain</li>
	<li>User name</li>
</ul>

<p>The response beacon can be decrypted similarly to the request parameter above, except that the hex-encoded bytes are separated by dash characters. As with Buer, the JSON object returned in the beacon response contains various options on how to download and execute a payload:</p>

<ul>
	<li>type - there are two types:</li>
	<li>options - specifies options for the payload to download:
	<ul>
		<li>Hash - only applicable to “update” type to determine whether a new update is available</li>
		<li>x64 - whether the payload is 64-bit</li>
		<li>FileType - not used in analyzed samples</li>
		<li>AssemblyType - not used in analyzed samples</li>
		<li>AccessToken - used to download the payload</li>
		<li>External - indicates whether the payload is downloaded from the C&amp;C or an external URL</li>
	</ul>
	</li>
	<li>method - method of execution</li>
	<li>parameters - parameters to pass on the command line</li>
	<li>pathToDrop - not used in analyzed samples</li>
	<li>autorun - indicates whether to setup Registry RunOnce persistence for the payload</li>
	<li>modules</li>
	<li>timeout - not used in analyzed samples</li>
</ul>

<p><strong>Conclusion</strong></p>

<p>Despite existing since 2019, the new variant of Buer loader malware suggests threat actors continue to modify their payloads in a likely attempt to evade detection. When paired with the attempts by threat actors leveraging RustyBuer to further legitimize their lures, it is possible the attack chain may be more effective in obtaining access and persistence. RustyBuer and the original Buer loader have been observed as a first-stage loader for additional payloads including Cobalt Strike and multiple ransomware strains, as well as possibly providing victim access to other threat actors in the underground marketplace. Proofpoint anticipates this activity will continue. Based on the frequency of RustyBuer campaigns observed by Proofpoint, researchers anticipate we will continue to see the new variant in the future.</p>
