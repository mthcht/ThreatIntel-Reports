												<div class="c-wysiwyg">
													<p>In February 2017, we published <a href="https://securelist.com/fileless-attacks-against-enterprise-networks/77403/">research</a> on fileless attacks against enterprise networks. We described the data collected during incident response in several financial institutions around the world, exploring how attackers moved through enterprise networks leaving no traces on the hard drives. The goal of these attackers was money, and the best way to cash out and leave no record of transactions is through the remote administration of ATMs. This second paper is about the methods and techniques that were used by the attackers in the second stage of their attacks against financial organizations – basically enabling remote administration of ATMs.</p>
<p>In June 2016, Kaspersky Lab received a report from a Russian bank that had been the victim of a targeted attack. During the heist, the criminals were able to gain control of the ATMs and upload malware to them. After cashing out, the malware was removed. The bank&#8217;s forensics specialists were unable to recover the malicious executables because of the fragmentation of a hard drive after the attack, but they were able to restore the malware&#8217;s logs and some file names.</p>
<p>The bank&#8217;s forensic team were able, after careful forensic analysis of the ATM&#8217;s hard drive, to recover the following files containing logs:</p>
<ul>
<li><i>C:\Windows\Temp\kl.txt</i></li>
<li><i>C:\logfile.txt</i></li>
</ul>
<p>In addition, they were able to find the names of two deleted executables. Unfortunately, they were not able to recover any of the contents:</p>
<ul>
<li><i>C:\ATM\!A.EXE</i></li>
<li><i>C:\ATM\IJ.EXE</i></li>
</ul>
<p>Within the log files, the following pieces of plain text were found:</p>
<p><i>[Date &#8211; Time]</i><br />
<i>[%d %m %Y &#8211; %H : %M : %S] &gt; Entering process dispense.</i><br />
<i>[%d %m %Y &#8211; %H : %M : %S] &gt; Items from parameters converted successfully. 4 40</i><br />
<i>[%d %m %Y &#8211; %H : %M : %S] &gt; Unlocking dispenser, result is 0</i><br />
<i>[%d %m %Y &#8211; %H : %M : %S] &gt; Catch some money, bitch! 4000000</i><br />
<i>[%d %m %Y &#8211; %H : %M : %S] &gt; Dispense success, code is 0</i></p>
<p>As mentioned in the previous paper, based on the information from the log file we created a YARA rule to find a sample, in this case: MD5 cef6c2aa78ff69d894903e41a3308452. And we&#8217;ve found one. This sample was uploaded twice (from Kazakhstan and Russia) as &#8220;tv.dll&#8221;.</p>
<p>The malware, which we have dubbed ATMitch, is fairly straightforward. Once remotely installed and executed via Remote Desktop Connection (RDP) access to the ATM from within the bank, the malware looks for the &#8220;command.txt&#8221; file that should be located in the same directory as the malware and created by the attacker. If found, the malware reads the one character content from the file and executes the respective command:</p>
<ul>
<li><i>&#8216;O&#8217;</i> &#8211; Open dispenser</li>
<li><i>&#8216;D&#8217;</i> &#8211; Dispense</li>
<li><i>&#8216;I&#8217;</i> &#8211; Init XFS</li>
<li><i>&#8216;U&#8217;</i> &#8211; Unlock XFS</li>
<li><i>&#8216;S&#8217;</i> &#8211; Setup</li>
<li><i>&#8216;E&#8217;</i> &#8211; Exit</li>
<li><i>&#8216;G&#8217;</i> &#8211; Get Dispenser id</li>
<li><i>&#8216;L&#8217;</i> &#8211; Set Dispenser id</li>
<li><i>&#8216;C&#8217;</i> &#8211; Cancel</li>
</ul>
<p>After execution, ATMitch writes the results of this command to the log file and removes &#8220;command.txt&#8221; from the ATM&#8217;s hard drive.</p>
<p>The sample &#8220;tv.dll&#8221; successfully retrieved in this case does not try to conceal itself within the system.</p>
<p><a href="https://media.kasperskycontenthub.com/wp-content/uploads/sites/43/2017/04/07180257/atmitch_eng_2.png" class="magnificImage"><img loading="lazy" decoding="async" class="aligncenter size-full wp-image-77922" src="https://media.kasperskycontenthub.com/wp-content/uploads/sites/43/2017/04/07180257/atmitch_eng_2.png" alt="ATMitch: remote administration of ATMs" width="936" height="968" srcset="https://media.kasperskycontenthub.com/wp-content/uploads/sites/43/2017/04/07180257/atmitch_eng_2.png 936w, https://media.kasperskycontenthub.com/wp-content/uploads/sites/43/2017/04/07180257/atmitch_eng_2-290x300.png 290w, https://media.kasperskycontenthub.com/wp-content/uploads/sites/43/2017/04/07180257/atmitch_eng_2-768x794.png 768w, https://media.kasperskycontenthub.com/wp-content/uploads/sites/43/2017/04/07180257/atmitch_eng_2-32x32.png 32w" sizes="auto, (max-width: 936px) 100vw, 936px" /></a></p>
<p style="text-align: center; font-weight: bold;"><i>The malware&#8217;s command parser</i></p>
<p>The malware uses the standard XFS library to control the ATM. It should be noted that it works on every ATM that supports the XFS library (which is the vast majority).</p>
<p>Unfortunately, we were unable to retrieve the executables (!A.exe and IJ.exe, located in C:\ATM) from the ATM; only the file names were found as artefacts during the forensic analysis. We assume that these are the installer and uninstaller of the malware. It should also be noted that &#8220;tv.dll&#8221; contained one Russian-language resource.</p>
<p>Kaspersky Lab continues to monitor and track these kinds of threats and reiterates the need for allowlisting in ATMs as well as the use of <a href="https://www.kaspersky.com/advert/enterprise-security/anti-targeted-attacks?redef=1&amp;THRU&amp;reseller=gl_slpost_pro_ona_smm__onl_b2b_securelist_lnk____kata___">anti-APT solutions</a> in banking networks.</p>
<p><a href="https://sas.kaspersky.com/?utm_medium=blg&amp;utm_source=sl_banner_170206&amp;utm_campaign=ww_saslp"><img decoding="async" src="https://media.kasperskycontenthub.com/wp-content/uploads/sites/43/2017/02/07181524/hor.png" /></a></p>
