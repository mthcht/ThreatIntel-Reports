			<p>A threat actor named Emotet Trojan has been in the wild for more than 5 years, and now it is back after a 5 months break. It has spread globally, infecting new as well as old targets. It is re-launched with multiple Malspam Campaigns to distribute in all sectors.</p>
<p>We observed through our detection telemetry that Emotet campaigns have targeted a variety of sectors. It is spread through SpamMail with hot topics like Covid-19, Vaccine for Covid-19 and few other generic keywords like Health Insurance, Payment, Invoice, Job Update/Opening, <a href="https://www.seqrite.com/blog/5-cyber-attacks-that-shook-the-world/" data-wpel-link="internal" target="_self" rel="follow">Cyberattack</a>, Shipping and many more.</p>
<h2>Infection chain</h2>
<figure id="attachment_4510" aria-describedby="caption-attachment-4510" style="width: 1246px" class="wp-caption aligncenter"><img decoding="async" class="size-full wp-image-4510" src="https://www.seqrite.com/blog/wp-content/uploads/2020/09/Fig-1-Infection-chain.jpg" alt="Fig 1: Infection chain" width="1246" height="484" srcset="https://www.seqrite.com/blog/wp-content/uploads/2020/09/Fig-1-Infection-chain.jpg 1246w, https://www.seqrite.com/blog/wp-content/uploads/2020/09/Fig-1-Infection-chain-300x117.jpg 300w, https://www.seqrite.com/blog/wp-content/uploads/2020/09/Fig-1-Infection-chain-768x298.jpg 768w, https://www.seqrite.com/blog/wp-content/uploads/2020/09/Fig-1-Infection-chain-1024x398.jpg 1024w" sizes="(max-width: 1246px) 100vw, 1246px" /><figcaption id="caption-attachment-4510" class="wp-caption-text">Fig 1: Infection chain</figcaption></figure>
<p>The infection chain starts by sending crafted emails to the target organization or person. The attacker uses the Hijacking email method for sending the crafted mails with an attachment. The attachment may contain a word document a macro file or a PDF. Sometimes the email body contains URLs too. As mailbox is hijacked, attachment is sent replying to old email threads or forwarding to an existing mail list, due to which the victim easily opens the attachment as the mail comes from a trusted mail id.</p>

<p>which translates into <strong>winmgmts:win32_process. O</strong>nce we removed the chunked data we got a readable code with functions and reference variables.</p>

<h2><strong>Payload Analysis</strong></h2>
<p>The payload downloaded from the above file has a customized packer. The unpacking is done at runtime. Emotet’s packer code is polymorphic which makes it difficult for signature-based detection tools to detect it based on the packer code.</p>
<p>Its resource (.rsrc) section has significant data which seems to be an indication that the malware might be packed. In the below Fig. we can see that RCData has an encrypted code.</p>
<figure id="attachment_4527" aria-describedby="caption-attachment-4527" style="width: 533px" class="wp-caption aligncenter"><img loading="lazy" decoding="async" class="size-full wp-image-4527" src="https://www.seqrite.com/blog/wp-content/uploads/2020/09/Fig-7.-File-having-encrypted-data-in-resource.png" alt="Fig 7: File having encrypted data in resource" width="533" height="189" srcset="https://www.seqrite.com/blog/wp-content/uploads/2020/09/Fig-7.-File-having-encrypted-data-in-resource.png 533w, https://www.seqrite.com/blog/wp-content/uploads/2020/09/Fig-7.-File-having-encrypted-data-in-resource-300x106.png 300w" sizes="auto, (max-width: 533px) 100vw, 533px" /><figcaption id="caption-attachment-4527" class="wp-caption-text">Fig 7: File having encrypted data in resource</figcaption></figure>
<p>While debugging the file, we observed that the data will be decrypted using a slightly modified version of RC4. Key for RC4 is hardcoded in the file. After decryption, the control goes to the decrypted shellcode.</p>
<figure id="attachment_4528" aria-describedby="caption-attachment-4528" style="width: 535px" class="wp-caption aligncenter"><img loading="lazy" decoding="async" class="size-full wp-image-4528" src="https://www.seqrite.com/blog/wp-content/uploads/2020/09/Fig-8.-RC4-used-for-decryption.png" alt="Fig 8: RC4 used for decryption" width="535" height="144" srcset="https://www.seqrite.com/blog/wp-content/uploads/2020/09/Fig-8.-RC4-used-for-decryption.png 535w, https://www.seqrite.com/blog/wp-content/uploads/2020/09/Fig-8.-RC4-used-for-decryption-300x81.png 300w" sizes="auto, (max-width: 535px) 100vw, 535px" /><figcaption id="caption-attachment-4528" class="wp-caption-text">Fig 8: RC4 used for decryption</figcaption></figure>
<p>In some files, we have seen the use of <em>VirtualAllocExNuma </em>to allocate new memory. This is used for fast processing. The beginning of an obfuscated shellcode is copied to the new address after being decrypted using the modified RC4 algorithm. In addition to the relatively short shellcode, an additional PE can be seen in the memory.</p>
<figure id="attachment_4529" aria-describedby="caption-attachment-4529" style="width: 480px" class="wp-caption aligncenter"><img loading="lazy" decoding="async" class="size-full wp-image-4529" src="https://www.seqrite.com/blog/wp-content/uploads/2020/09/Fig-9.-Decrypted-shellcode-and-PE-File.png" alt="Fig 9: Decrypted shellcode and PE File" width="480" height="293" srcset="https://www.seqrite.com/blog/wp-content/uploads/2020/09/Fig-9.-Decrypted-shellcode-and-PE-File.png 480w, https://www.seqrite.com/blog/wp-content/uploads/2020/09/Fig-9.-Decrypted-shellcode-and-PE-File-300x183.png 300w" sizes="auto, (max-width: 480px) 100vw, 480px" /><figcaption id="caption-attachment-4529" class="wp-caption-text">Fig 9: Decrypted shellcode and PE File</figcaption></figure>
<p>The Shellcode deobfuscates several API calls at runtime, such as <em>LoadLibraryA, GetProcAddress, VirtualAlloc </em>and <em>VirtualProtect</em>, all of which will be used to resolve APIs and allocate memory to run the additional PE.</p>
<figure id="attachment_4530" aria-describedby="caption-attachment-4530" style="width: 480px" class="wp-caption aligncenter"><img loading="lazy" decoding="async" class="size-full wp-image-4530" src="https://www.seqrite.com/blog/wp-content/uploads/2020/09/Fig-10.-API-Resolved.png" alt="Fig 10: API Resolved" width="480" height="140" srcset="https://www.seqrite.com/blog/wp-content/uploads/2020/09/Fig-10.-API-Resolved.png 480w, https://www.seqrite.com/blog/wp-content/uploads/2020/09/Fig-10.-API-Resolved-300x88.png 300w" sizes="auto, (max-width: 480px) 100vw, 480px" /><figcaption id="caption-attachment-4530" class="wp-caption-text">Fig 10: API Resolved</figcaption></figure>
<p>After this, the malware allocates memory and copies the data of decrypted file and calls  <em>VirtualProtect </em>and<em> f</em>inally, the program jumps to the real entry point of the decrypted file.</p>
<p>Spreading mechanism of Emotet campaign remains almost the same that we had already discussed in our previous blog. Read it here in the link below.</p>
<p><a href="https://blogs.quickheal.com/evolution-4-year-old-threat-emotet-infamous-trojan-complex-threat-distributer/" data-wpel-link="internal" target="_self" rel="follow">The evolution of a 4-year-old-threat Emotet: From an infamous Trojan to a complex threat distributer</a></p>
<p>After executing the Emotet, it will exfiltrate the data to the CnC server. While sending, the data is encoded and sent with some random name of the file and random path to the server.</p>

<h2>Conclusion</h2>
<p>Emotet is a persistent <a href="https://www.seqrite.com/threat-intel/" data-wpel-link="internal" target="_self" rel="follow">threat actor</a> and highly successful in delivering email-based malware, with a major focus on email theft and sending additional malware. It has moderate obfuscated code to deliver and bypass the detection technique.</p>
<p>With the global impact of COVID-19, threat actors are likely to continue to use COVID-19-themed emails to deliver malware broadly in support of their objectives for all sectors.</p>
