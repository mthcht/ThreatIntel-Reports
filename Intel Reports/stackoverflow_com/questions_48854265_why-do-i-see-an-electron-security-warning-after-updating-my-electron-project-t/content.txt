<p>You're having this:</p>

<blockquote>
  <p>Electron Security Warning 
  This renderer process has Node.js integration enabled and 
  attempted to load remote content. This exposes users of this app to severe security risks.</p>
</blockquote>

<p>Because from the 2nd Security Recommendations from <a href="http://electronjs.org/docs/tutorial/security" rel="noreferrer">Electron Documentation</a></p>

<h3>2) Disable Node.js Integration for Remote Content</h3>

<p>It is paramount that you disable Node.js integration in any renderer (BrowserWindow, BrowserView, or WebView) that loads remote content. The goal is to limit the powers you grant to remote content, thus making it dramatically more difficult for an attacker to harm your users should they gain the ability to execute JavaScript on your website.</p>

<p>After this, you can grant additional permissions for specific hosts. For example, if you are opening a BrowserWindow pointed at "<a href="https://my-website.com/" rel="noreferrer">https://my-website.com/</a>", you can give that website exactly the abilities it needs, but no more.</p>

<h3>Why?</h3>

<p>A cross-site-scripting (XSS) attack is more dangerous if an attacker can jump out of the renderer process and execute code on the user's computer. Cross-site-scripting attacks are fairly common - and while an issue, their power is usually limited to messing with the website that they are executed on. Disabling Node.js integration helps prevent an XSS from being escalated into a so-called "Remote Code Execution" (RCE) attack.</p>

<h3>How?</h3>

<pre><code>// Bad
const mainWindow = new BrowserWindow()
mainWindow.loadURL('https://my-website.com')

// Good
const mainWindow = new BrowserWindow({
  webPreferences: {
    nodeIntegration: false,
    preload: './preload.js'
  }
})

mainWindow.loadURL('https://my-website.com')
</code></pre>

<hr>

<pre><code>&lt;!-- Bad --&gt;
&lt;webview nodeIntegration src="page.html"&gt;&lt;/webview&gt;

&lt;!-- Good --&gt;
&lt;webview src="page.html"&gt;&lt;/webview&gt;
</code></pre>

<p>When disabling Node.js integration, you can still expose APIs to your website that do consume Node.js modules or features. Preload scripts continue to have access to require and other Node.js features, allowing developers to expose a custom API to remotely loaded content.</p>

<p>In the following example preload script, the later loaded website will have access to a <code>window.readConfig()</code> method, but no Node.js features.</p>

<pre><code>const { readFileSync } = require('fs')

window.readConfig = function () {
  const data = readFileSync('./config.json')
  return data
}
</code></pre>

<p>Therefore you're been warned so that you can <strong>Disable Node.js Integration for Remote Content</strong>.</p>

<p>I hope this helps answer your question. </p>

    <div class="s-prose js-post-body" itemprop="text">
<p>The Electron <a href="https://electronjs.org/docs/tutorial/security" rel="nofollow noreferrer">security checklist</a> mentions how to deal with the security warning. In particular, when serving <code>index.html</code> from <code>file:</code> protocol (where you can't use HTTP CSP headers), it is possible to use the meta tag for the same purpose, as documented in the security checklist here: <a href="https://electronjs.org/docs/tutorial/security#csp-http-header" rel="nofollow noreferrer">CSP HTTP header</a>.</p>
<p>It recommends to use</p>
<pre class="lang-html prettyprint-override"><code>&lt;meta http-equiv=&quot;Content-Security-Policy&quot; content=&quot;default-src 'none'&quot; /&gt;
</code></pre>
<p>…but I have found (got help on GitHub <a href="https://github.com/electron/electron/issues/19775" rel="nofollow noreferrer">here</a>) this one to be more practical as it allows one to use <code>script src</code>:</p>
<pre class="lang-html prettyprint-override"><code>&lt;meta http-equiv=&quot;Content-Security-Policy&quot; content=&quot;script-src 'self';&quot; /&gt;
</code></pre>
<p>More on CSP on <a href="https://content-security-policy.com/" rel="nofollow noreferrer">content-security-policy.com</a>.</p>

</code></pre>

<p>From Electron 2.0 on, developers will see warnings and recommendations printed to the developer console. They only show up when the binary's name is Electron, indicating that a developer is currently looking at the console.  </p>

<p>I would suggest you to follow Electron official Security Recommendations checklist to avoid these warnings <a href="https://github.com/electron/electron/blob/master/docs/tutorial/security.md" rel="nofollow noreferrer">https://github.com/electron/electron/blob/master/docs/tutorial/security.md</a></p>

    <div class="s-prose js-post-body" itemprop="text">
<p>TLDR: Disable eval() in your BrowserWindow options.</p>

<p>I just went through this process on the latest electron, vue etc. and the solution is to disable <code>eval()</code> which can be a security risk due to it executing code which is not from you (or your app).</p>

<p>Add the <code>allowEval: false</code> to your <code>webPreferences</code> during window creation to prevent the warning cleanly:</p>

<pre><code>const win = new electron.BrowserWindow({
    webPreferences: {
        allowEval: false // This is the key!
    }
});
</code></pre>

<p>Some background info: electron actually tries to execute some javascript code (from a string using <code>require('electron').executeJavaScript</code>) and, if it succeeds, it considers your code unsafe.</p>
