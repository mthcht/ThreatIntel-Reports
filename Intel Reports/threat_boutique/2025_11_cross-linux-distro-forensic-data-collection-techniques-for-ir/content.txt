                            <h1 class="title-post" itemprop="name">Cross-Linux Distro Forensic Data Collection Techniques for IR</h1>
                    <div class="date">
            <span itemprop="datePublished"><a href="https://threat.boutique/archive/2025-11" title="Show all posts made on this month">01 November 2025</a></span>
            - Posted in            <span itemprop="articleSection"><a href="https://threat.boutique/category/incident-response">Incident Response</a></span> by            <span itemprop="author"><a href="https://threat.boutique/author/b3vSclAuunBMsdt">Jok3r</a></span> -
            <span><a href="https://threat.boutique/2025/11/cross-linux-distro-forensic-data-collection-techniques-for-ir" rel="permalink">Permalink</a></span>
        </div>
                    <div class="featured-image">
                <a href="https://threat.boutique/2025/11/cross-linux-distro-forensic-data-collection-techniques-for-ir"><img src="https://threat.boutique/content/images/20251101232228-u1527899822_linux_operation_system_component_which_is_able_to_f00796f2-2df8-487b-921a-8be5da48e732_1.png" alt="Cross-Linux Distro Forensic Data Collection Techniques for IR"/></a>
            </div>
                                        <div class="post-body post-1762024527" itemprop="articleBody">
            <p><strong><em>Background:</em></strong>
One of the IR stages is the "collection" stage, which occurs between containment and analysis. We sometimes need to collect evidence from Kubernetes pods or Docker containers, which can run different Linux distributions and create new challenges for incident responders. Likewise, on‑premises or VM environments that are not using containers — and environments without Kubernetes or Docker — can also present difficulties, especially when collecting logs or cloning disks.</p>

<p><strong><em>Challenge:</em></strong>
As we dive deeper into action items, one method for cloning a disk is to use specialized forensic kits for data acquisition, or to use the out-of-the-box Linux utility dd, which is included by default in many distributions.</p>

<p>Challenge for all distors related to DD:
All ubuntu distros support DD
<img src="https://threat.boutique/content/images/20251101235759-Screenshot%202025-10-18%20232241.png" alt="enter image description here" />
Alpine linux contains DD
<img src="https://threat.boutique/content/images/20251102000052-000008.png" alt="enter image description here" /></p>

<p>Sometimes, the <code>dd</code> command may not be available to resolve such issues. In these cases, you can use the <code>cp</code> command to create a backup and then archive it. However, this method has some disadvantages because certain directories, such as <code>/proc</code> and some folders under <code>/sys</code>, cannot be copied.</p>

<p><code>cp -r /  /mnt/backup/ 2&gt;/dev/null</code></p>

<p>To bypass these restrictions, another method is to use rsync and exclude those folders.</p>

<pre><code>sudo rsync -aAXv / /mnt/backup   --exclude="/sys/" --exclude="/proc/"
</code></pre>

<p><strong><em>Conclusion:</em></strong>
In this article, we have described only on-premises hosted Linux environments. The situation changes when we start to deal with Kubernetes clusters or cloud-hosted systems, which we will explore in the next chapters.</p>
