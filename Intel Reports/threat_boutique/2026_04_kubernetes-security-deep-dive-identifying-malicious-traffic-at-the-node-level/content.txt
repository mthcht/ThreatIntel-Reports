                            <h1 class="title-post" itemprop="name">Kubernetes Incident Response Hunting: Identifying Malicious Traffic at the Node Level</h1>
                    <div class="date">
            <span itemprop="datePublished"><a href="https://threat.boutique/archive/2026-04" title="Show all posts made on this month">12 April 2026</a></span>
            - Posted in            <span itemprop="articleSection"><a href="https://threat.boutique/category/incident-response">Incident Response</a></span> by            <span itemprop="author"><a href="https://threat.boutique/author/b3vSclAuunBMsdt">Jok3r</a></span> -
            <span><a href="https://threat.boutique/2026/04/kubernetes-security-deep-dive-identifying-malicious-traffic-at-the-node-level" rel="permalink">Permalink</a></span>
        </div>
                    <div class="featured-image">
                <a href="https://threat.boutique/2026/04/kubernetes-security-deep-dive-identifying-malicious-traffic-at-the-node-level"><img src="https://threat.boutique/content/images/20260412154929-1.jpg" alt="Kubernetes Incident Response Hunting: Identifying Malicious Traffic at the Node Level"/></a>
            </div>
                                        <div class="post-body post-1775994382" itemprop="articleBody">
            <p><strong>Background:</strong></p>

<p>Sometimes, you may encounter situations where no logs are being stored for your Kubernetes pods. In such cases, you still need to investigate potential malicious network activity using Indicators of Compromise (IOCs).
In this article, we’ll explore the available options and the practical steps you can take to analyze network traffic directly at the node level.
To hunt for network IOCs, follow these simple steps:</p>

<ul>
<li>Install tcpdump on the Kubernetes node</li>
<li>Identify the pod’s internal network interface</li>
</ul>

<p><strong>Steps:</strong>
Get Node IP</p>

<pre><code>kubectl get nodes -o wide
</code></pre>

<p><img src="https://threat.boutique/content/images/20260412162112-2temprem.png" alt="enter image description here" /></p>

<p>SSH into NODE</p>

<pre><code>ssh username@yourip
</code></pre>

<p>Get POD names</p>

<pre><code>kubectl get pod -A
</code></pre>

<p><img src="https://threat.boutique/content/images/20260412162327-3temprem.png" alt="enter image description here" /></p>

<p>Get POD running port</p>

<pre><code>kubectl get pod NameOfThePod -o wide
</code></pre>

<p>Now use tcpdump to look for the outgoing traffic and IOC</p>

<pre><code>tcpdump -i any host PODINTERNALIP -nn -s 0 -X   
</code></pre>

<p><img src="https://threat.boutique/content/images/20260412163121-4temprem.png" alt="enter image description here" /></p>

<p>This steps will help at least on incident active stage find  and correlate IOC .</p>

<p><strong>Background:</strong>
This is not the only way to reveal outgoing connections. However, different measurement approaches have shown that, in some scenarios within Kubernetes, it may not be possible to capture all outgoing connections from within pods—because different pods can be deployed with different types of containers and network configurations.</p>
