                            <h1 class="title-post" itemprop="name">Data Poisoning Attacks on LLM leveraged Product Support Bots: Attack, Risk, Prevention</h1>
                    <div class="date">
            <span itemprop="datePublished"><a href="https://threat.boutique/archive/2026-05" title="Show all posts made on this month">24 May 2026</a></span>
            - Posted in            <span itemprop="articleSection"><a href="https://threat.boutique/category/threat-analyze">Threat Analyze</a></span> by            <span itemprop="author"><a href="https://threat.boutique/author/b3vSclAuunBMsdt">Jok3r</a></span> -
            <span><a href="https://threat.boutique/2026/05/data-poisoning-attacks-on-llm-leveraged-on-product-support-bots" rel="permalink">Permalink</a></span>
        </div>
                    <div class="featured-image">
                <a href="https://threat.boutique/2026/05/data-poisoning-attacks-on-llm-leveraged-on-product-support-bots"><img src="https://threat.boutique/content/images/20260524104114-uPTm9.jpg" alt="Data Poisoning Attacks on LLM leveraged Product Support Bots: Attack, Risk, Prevention"/></a>
            </div>
                                        <div class="post-body post-1779604752" itemprop="articleBody">
            <p><strong>Background:</strong>
Because industry started leveraging AI capabilities for routine cases like general customer support, a new threat has emerged: data poisoning.</p>

<p><strong>Core attack category:</strong>
Based on MITRE ATLAS, it is categorized as AML.T0020 (Poison Training Data). This type of data poisoning can have a significant impact on the product side because models may perform inadequately as a result.</p>

<p><strong>Simple Attack Demo:</strong>
Let’s imagine that our company has an AI-powered chatbot for customer support. Based on data provided by customers, we train our model. 
<img src="https://threat.boutique/content/images/20260524105240-Screenshot_20260524_105125.png" alt="enter image description here" /></p>

<p>Where is the risk in this case? At minimum, an attacker could inject information claiming that product ratings or prices are lower than they really are, or provide other misleading product-related information.
<img src="https://threat.boutique/content/images/20260524105446-12.png" alt="enter image description here" /></p>

<p>What the attacker did was flood the chat with misleading information, which creates a chance that the model could learn from it. Since all user input can become a source of training data, this can corrupt the model’s behavior.</p>

<p><strong>Risk:</strong>
 1. Fake information spreading 
 2. Malicious link injection
 3. Reputation damage
 4. Compliance issues</p>

<p><strong>Prevention:</strong>
 1. Put Access Control on production model training scope
 2. Add rate limit on public exposed components
 3. Sanitize data to detect offensive language from beeing used .
 4. Filter data before train production model
 5. Always use version control for the LLM model , to be able to revert back to old one version .</p>

<p>Conclusion:
Data poisoning is a serious risk in AI-powered support systems because untrusted user input can corrupt training data and degrade model behavior. To reduce exposure, organizations should tightly control who can influence training, rate-limit public inputs, sanitize and filter data before training, and keep model versions under strict version control so they can quickly roll back if poisoning is detected.</p>
