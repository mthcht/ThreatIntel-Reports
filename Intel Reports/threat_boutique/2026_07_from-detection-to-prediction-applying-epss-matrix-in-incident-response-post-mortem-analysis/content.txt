                            <h1 class="title-post" itemprop="name">From Detection to Prediction: Applying EPSS matrix in Incident Response Post-Mortem Analysis</h1>
                    <div class="date">
            <span itemprop="datePublished"><a href="https://threat.boutique/archive/2026-07" title="Show all posts made on this month">25 July 2026</a></span>
            - Posted in            <span itemprop="articleSection"><a href="https://threat.boutique/category/incident-response">Incident Response</a></span> by            <span itemprop="author"><a href="https://threat.boutique/author/b3vSclAuunBMsdt">Jok3r</a></span> -
            <span><a href="https://threat.boutique/2026/07/from-detection-to-prediction-applying-epss-matrix-in-incident-response-post-mortem-analysis" rel="permalink">Permalink</a></span>
        </div>
                    <div class="featured-image">
                <a href="https://threat.boutique/2026/07/from-detection-to-prediction-applying-epss-matrix-in-incident-response-post-mortem-analysis"><img src="https://threat.boutique/content/images/20260725094056-Gemini_Generated_Image_bpzpfpbpzpfpbpzp.png" alt="From Detection to Prediction: Applying EPSS matrix in Incident Response Post-Mortem Analysis"/></a>
            </div>
                                        <div class="post-body post-1784957800" itemprop="articleBody">
            <p><strong><em>Background:</em></strong>
EPSS (Exploit Prediction Scoring System) is a specialized model and scoring framework that predicts the likelihood of real-world exploitation based on observed exploitation activity, including data from honeypots, threat intelligence sources, and real security incidents.</p>

<p>In the Incident Response (IR) post-mortem stage, EPSS can be leveraged to determine whether a vulnerable system was potentially impacted and whether a specific CVE could have been the root cause of the initial access vector.</p>

<p>However, it is important to keep in mind that the EPSS score alone is not working. It must be combined with additional input data collected from other security and infrastructure systems, such as vulnerability scanners, endpoint telemetry, SIEM logs, network monitoring, asset inventory, and threat intelligence platforms.</p>

<p>In real-world environments, not every CVE represents the same level of risk. For example, a medium-severity vulnerability cannot be prioritized based only on its CVSS score. Additional context is required to understand whether the vulnerability has an active exploit, a publicly available proof of concept (PoC), or observed exploitation activity in the wild.</p>

<p>This is where EPSS provides additional value by helping answer a critical question: Is this vulnerability being actively exploited, and should it be considered a likely attack vector during the investigation?</p>

<p>By combining EPSS with environmental telemetry and incident evidence, security teams can improve root cause analysis, validate initial access hypotheses, and make more accurate risk-based decisions during post-incident reviews.</p>

<p><strong><em>EPSS Leverage:</em></strong>
For our small demo, we will collect the existing inventory data from Kubernetes nodes and identify installed applications and their versions. Based on this information, we will map the detected versions to relevant CVEs.</p>

<p>After identifying the vulnerabilities, we will correlate them with the EPSS score to understand which applications and vulnerabilities should be prioritized based on their real-world exploitation likelihood.</p>

<p><img src="https://threat.boutique/content/images/20260725101601-yp2.png" alt="enter image description here" /></p>

<p>In the example above, you can see that even though we inventoried our asset components and found about 955 CVEs, only 1 SSL CVE needs to be prioritized. This is because EPSS metrics correlate directly with real-world exploitation."</p>

<p><strong><em>Conclusion:</em></strong>
During incident post-mortem analysis and patch management processes, always utilize a EPSS approach based on initial access vectors, such as exploiting a known CVE (Common Vulnerabilities and Exposures). This systematic method helps you effectively identify the root cause. Furthermore, this same structured approach should be applied to patch management, allowing you to effectively prioritize and address critical vulnerabilities before proceeding to routine patches.</p>
