                            <h1 class="title-post" itemprop="name">Generated with Intent: Weaponizing AI/SI Artifacts</h1>
                    <div class="date">
            <span itemprop="datePublished"><a href="https://threat.boutique/archive/2026-10" title="Show all posts made on this month">10 October 2026</a></span>
            - Posted in            <span itemprop="articleSection"><a href="https://threat.boutique/category/threat-analyze">Threat Analyze</a></span> by            <span itemprop="author"><a href="https://threat.boutique/author/b3vSclAuunBMsdt">Jok3r</a></span> -
            <span><a href="https://threat.boutique/2026/10/generated-with-intent-weaponizing-aisi-artifacts" rel="permalink">Permalink</a></span>
        </div>
                    <div class="featured-image">
                <a href="https://threat.boutique/2026/10/generated-with-intent-weaponizing-aisi-artifacts"><img src="https://threat.boutique/content/images/20261010122207-rX2EW.jpg" alt="Generated with Intent: Weaponizing AI/SI Artifacts"/></a>
            </div>
                                        <div class="post-body post-1791620417" itemprop="articleBody">
            <p><strong><em>Background:</em></strong></p>

<p>LLM artifacts are powerful components that extend a model’s capabilities. However, in the hands of an attacker, these same components can become attack vectors. This is where the user trust boundary intersects with AI and software supply-chain security: seemingly legitimate components, such as model checkpoints, tokenizer configurations, chat templates, and other artifacts required to load and operate a model, can be manipulated to introduce malicious behavior.</p>

<p><strong><em>Attack vector 1:</em></strong></p>

<p>By design, when a user loads a poisoned PyTorch (.pth) checkpoint into a model, the artifact may contain a specially crafted code payload. During deserialization, this payload can execute before the model is fully loaded, potentially giving an attacker the ability to perform malicious actions on the host.</p>

<p><img src="https://threat.boutique/content/images/20261010133509-qwc.png" alt="enter image description here" /></p>

<p><strong><em>Mitigation 1:</em></strong></p>

<p>Always load checkpoint only weight . Do not load any metadata
<img src="https://threat.boutique/content/images/20261010133924-qwc.png" alt="enter image description here" /></p>

<p><strong><em>Attack vector 2:</em></strong>
Pickle is a serialization mechanism used in Python-based LLM workflows to convert objects into a byte stream. The security issue lies in the special <strong>reduce</strong>() method, which can specify how an object is reconstructed during deserialization. This mechanism can invoke legitimate functions, but if abused by an attacker, it can also execute malicious code when the serialized object is loaded.</p>

<p><img src="https://threat.boutique/content/images/20261010142144-zxcvb.png" alt="enter image description here" /></p>

<p><strong><em>Mitigation 2:</em></strong>
Use Unpickler function not to call the hidden threat 
<img src="https://threat.boutique/content/images/20261010144056-000.png" alt="enter image description here" /></p>

<p><strong><em>Attack vector 3:</em></strong>
Tokenizer files, which are responsible for converting data into tokens, can be tampered with. As a result, the model’s instructions or intended behavior may be overridden.</p>

<p><strong><em>Conclusion:</em></strong></p>

<p>Technology continues to evolve, becoming more advanced and intelligent, but the human factor remains a constant in our threat landscape. This is a valuable reminder to invest time and effort in internal security awareness training for our team members.</p>
