		<div>
			<p>We recently published a research paper on <a href="https://www.trendmicro.com/vinfo/tmr/?/us/security/news/cyber-attacks/operation-earth-kitsune-tracking-slub-s-current-operations">Operation Earth Kitsune</a>, a watering hole campaign aiming to steal information by compromising websites. Besides its heavy use of SLUB malware, we also uncovered two new espionage backdoors associated with the campaign: agfSpy and dneSpy, dubbed as such following the attackers’ three-letter naming scheme.</p>
<p>Our previous research on the operation found that, while SLUB was primarily used to exfiltrate data, agfSpy and dneSpy were employed for the same purpose but also for seizing control of affected systems. This post provides more details about these malware types, including the relation between them and their command and control (C&amp;C) servers.</p>
<p>Figure 1 shows how agfSpy and dneSpy are used in the attacks. We were able to identify five C&amp;C servers communicating and providing instructions to the espionage backdoors. </p>

		</div>
	

</div>

<p>DneSpy used a dynamic C&amp;C discovery mechanism that first connects to whoami2[.]ddns[.]net then receives information about the master server whoamimaster[.]ddns[.]net.</p>
<p>As a part of its deployment, dneSpy also delivers agfSpy, as shown in Figure 2. </p>

	<figure class="image-figure">
		
			<img src="/content/dam/trendmicro/global/en/research/20/j/operation-earth-kitsune-a-dance-of-two-new-backdoors/Fig-2-How-dneSpy-delivers-agfSpy.jpg" alt="Figure 2. How dneSpy delivers agfSpy"/>

    <div class="richText">
	
    


	
		<div>
			<p>This scheme shows why dneSpy first checks, using the <a href="http://www.cs.rpi.edu/courses/fall01/os/CreateMutex" target="_blank">CreateMutex</a> technique, if agfSpy is already installed on the system. With this architecture, the attacker is looking to have a certain level of resiliency during deployment — even when agfSpy was already delivered as part of the initial vector, the attacker tries it again. For these two backdoors, the saying &quot;it takes two to tango&quot; applies, as the pair acts as partners in this &quot;dance.&quot;</p>
<h1><span class="body-subhead-title">DneSpy espionage backdoor</span></h1>
<p>DneSpy collects information, takes screenshots, and downloads and executes the latest version of other malicious components in the infected system. The malware is designed to receive a “policy” file in JSON format with all the commands to execute. The policy file sent by the C&amp;C server can be changed and updated over time, making dneSpy flexible and well-designed. The output of each executed command is zipped, encrypted, and exfiltrated to the C&amp;C server. These characteristics make dneSpy a fully functional espionage backdoor.</p>
<h2><span class="body-subhead-title">DneSpy C&amp;C communication</span></h2>
<p>Upon execution, dneSpy generates a unique ID for its victim based on the system parameters by executing the command shown in Figure 3.</p>

		</div>
	

</div>


    
    
    <div class="image">
	
    


	<figure class="image-figure">
		
			<img src="/content/dam/trendmicro/global/en/research/20/j/operation-earth-kitsune-a-dance-of-two-new-backdoors/Fig-3-Victim-ID-identification-parameters.png" alt="Figure 3. Victim ID identification parameters"/>
		
		<div class="caption-image-container ">
			<figcaption>Figure 3. Victim ID identification parameters</figcaption>
			
		</div>
	</figure>

</div>


    
    
    <div class="richText">
	
    


	
		<div>
			<p>From the full output of the command (full text) in Figure 3, a 4-byte hash is created and concatenated with the computer name to form an ‘id’ parameter in the communication requests with the C&amp;C server. The generated unique victim ID is then used to track unique first-time infections, and the C&amp;C server makes decisions based on that. Figure 4 shows a Python implementation of the algorithm generating the custom 4-byte hash.</p>

		</div>
	

</div>


    
    
    <div class="image">
	
    


	<figure class="image-figure">
		
			<img src="/content/dam/trendmicro/global/en/research/20/j/operation-earth-kitsune-a-dance-of-two-new-backdoors/Fig-4-Algorithm-for-comouting-a-custom-4-byte-hash.png" alt="Figure 4. Algorithm for computing a custom 4-byte hash"/>
		
		<div class="caption-image-container ">
			<figcaption>Figure 4. Algorithm for computing a custom 4-byte hash</figcaption>
			
		</div>
	</figure>

</div>


    
    
    <div class="richText">
	
    


	
		<div>
			<p>Before sending the request, C&amp;C server details are decoded first. DneSpy uses multiple obfuscation string mechanisms in the same binary, sometimes using either XOR encryption or ROT cipher. In the case of the C&amp;C URL path, it uses ROT, as seen in Figure 5.</p>

		</div>
	

</div>


    
    
    <div class="image">
	
    


	<figure class="image-figure">
		
			<img src="/content/dam/trendmicro/global/en/research/20/j/operation-earth-kitsune-a-dance-of-two-new-backdoors/Fig-5-Deobfuscation-of-C2-parameters-using-ROT.png" alt="Figure 5. Deobfuscation of C&amp;C parameters using ROT"/>
		
		<div class="caption-image-container ">
			<figcaption>Figure 5. Deobfuscation of C&amp;C parameters using ROT</figcaption>
			
		</div>
	</figure>

</div>


    
    
    <div class="richText">
	
    


	
		<div>
			<p>DneSpy then creates a directory or account on the C&amp;C server to register a new victim. The first request, shown in Figure 6, has the format of the victim ID: CC669737_WIN-RSG1AKRI2C4.</p>

		</div>
	

</div>


    
    
    <div class="image">
	
    


	<figure class="image-figure">
		
			<img src="/content/dam/trendmicro/global/en/research/20/j/operation-earth-kitsune-a-dance-of-two-new-backdoors/Fig-6-dneSpy-first-request.png" alt="Figure 6. dneSpy’s first request"/>
		
		<div class="caption-image-container ">
			<figcaption>Figure 6. dneSpy’s first request</figcaption>
			
		</div>
	</figure>

</div>


    
    
    <div class="richText">
	
    


	
		<div>
			<p>One interesting aspect of dneSpy’s design is its C&amp;C pivoting behavior. The central C&amp;C server's response is actually the next-stage C&amp;C server's domain/IP, which dneSpy has to communicate with to receive further instructions.</p>

		</div>
	

</div>


    
    
    <div class="image">
	
    


	<figure class="image-figure">
		
			<img src="/content/dam/trendmicro/global/en/research/20/j/operation-earth-kitsune-a-dance-of-two-new-backdoors/Fig-7-Dynamic-C2-server-selection.jpg" alt="Figure 7. Dynamic C&amp;C server selection"/>
		
		<div class="caption-image-container ">
			<figcaption>Figure 7. Dynamic C&amp;C server selection</figcaption>
			
		</div>
	</figure>

</div>


    
    
    <div class="richText">
	
    


	
		<div>
			<p>The pivoting design suggests that the malware can be used as a service where the actual samples are distributed to collect information for a selected C&amp;C server on demand.</p>
<p>The dneSpy C&amp;C server uses HTTP with the HTTP data body encrypted with AES CBC cipher. The dneSpy binary needs to receive a command-line parameter when it is launched. Figure 8 shows an example.</p>

		</div>
	

</div>


    
    
    <div class="image">
	
    


	<figure class="image-figure">
		
			<img src="/content/dam/trendmicro/global/en/research/20/j/operation-earth-kitsune-a-dance-of-two-new-backdoors/Fig-8-dneSpy-parameters.png" alt="Figure 8. dneSpy parameters"/>
		
		<div class="caption-image-container ">
			<figcaption>Figure 8. dneSpy parameters</figcaption>
			
		</div>
	</figure>

</div>


    
    
    <div class="richText">
	
    


	
		<div>
			<p>The parameter “helloworld” is used during the communication with the C&amp;C server to decrypt the received data. Using the command line parameter and the first 16 bytes of the response from the server, which is actually the initialization vector for AES, the payload data (from the 17th byte of the received blob) decrypts into a ZIP file. This ZIP archive contains an additional TXT file called “DNS_PROFILE,” which contains a new domain name. Figure 9 shows the full process, starting from decrypting the first response from the central C&amp;C server.</p>

		</div>
	

</div>


    
    
    <div class="image">
	
    


	<figure class="image-figure">
		
			<img src="/content/dam/trendmicro/global/en/research/20/j/operation-earth-kitsune-a-dance-of-two-new-backdoors/Fig-9-The-first-response-decryption-process.jpg" alt="Figure 9. The first response decryption process"/>
		
		<div class="caption-image-container ">
			<figcaption>Figure 9. The first response decryption process</figcaption>
			
		</div>
	</figure>

</div>


    
    
    <div class="richText">
	
    


	
		<div>
			<p>During the decryption and decompression process, multiple temporary files are created in the current user’s TEMP folder, as displayed in Figure 10.</p>

		</div>
	

</div>


    
    
    <div class="image">
	
    


	<figure class="image-figure">
		
			<img src="/content/dam/trendmicro/global/en/research/20/j/operation-earth-kitsune-a-dance-of-two-new-backdoors/Fig-10-Decrypting-the-first-request-and-getting-the-next-C2-server.png" alt="Figure 10. Decrypting the first request and getting the next C&amp;C server"/>
		
		<div class="caption-image-container ">
			<figcaption>Figure 10. Decrypting the first request and getting the next C&amp;C server</figcaption>
			
		</div>
	</figure>

</div>


    
    
    <div class="richText">
	
    


	
		<div>
			<p>Once the new C&amp;C URL name is received and decrypted, dneSpy constructs an HTTP POST request and sends it to the new C&amp;C server. The server then responds with an “Account Created!” message if everything is working properly. This is a way to authenticate the victim with the pivoted C&amp;C server and protect the C&amp;C channel.</p>

		</div>
	

</div>


    
    
    <div class="image">
	
    


	<figure class="image-figure">
		
			<img src="/content/dam/trendmicro/global/en/research/20/j/operation-earth-kitsune-a-dance-of-two-new-backdoors/Fig-11-Victim-account-created-on-the-dynamically-defined-C2-server.png" alt="Figure 11. Victim account created on the dynamically defined C&amp;C server"/>
		
		<div class="caption-image-container ">
			<figcaption>Figure 11. Victim account created on the dynamically defined C&amp;C server</figcaption>
			
		</div>
	</figure>

</div>


    
    
    <div class="richText">
	
    


	
		<div>
			<p>Once the account is created on the current C&amp;C server, dneSpy sends an HTTP GET request to receive the policy.txt file (with commands to be executed) and further malware payloads.</p>
<p>The following section will detail the exfiltration mechanism and the data capture method used by this specific version.</p>
<h3><span class="body-subhead-title">Exfiltration mechanism</span></h3>

<h2><span class="body-subhead-title">The agfSpy espionage backdoor</span></h2>
<p>The agfSpy backdoor retrieves configuration and commands from its C&amp;C server. These commands allow the backdoor to execute shell commands and send the execution results back to the server. It also enumerates directories and can list, upload, download, and execute files, among other functions. The capabilities of agfSpy are very similar to dneSpy, except each backdoor uses a different C&amp;C server and various formats in message exchanges.</p>
<h3><span class="body-subhead-title">AgfSpy C&amp;C server communication</span></h3>

			<h2><span class="body-subhead-title">Conclusion</span></h2>
<p>DneSpy and agfSpy are fully functional espionage backdoors, and while they use different C&amp;C server mechanisms, they have many things in common. Multiple tactics and procedures are implemented to give the infrastructure versatility and resiliency in its behavior.</p>
<p>Operation Earth Kitsune turned out to be complex and prolific, thanks to the variety of components it uses and the interactions between them. The campaign’s use of new samples to avoid detection by security products is also quite notable. From the Chrome exploit shellcode to the agfSpy, elements in the operation are custom coded, indicating that there is a group behind this operation. This group seems to be highly active this year, and we predict that they will continue going in this direction for some time.</p>
<p>We recommend using a multilayered security approach that can detect and block such complex threats from infiltrating the system through <a href="/en_us/business/products/user-protection/sps/endpoint.html" target="_self">endpoints</a>, <a href="/en_us/business/products/hybrid-cloud/deep-security.html" target="_self">servers</a>, <a href="/en_us/business/products/network/advanced-threat-protection/inspector.html" target="_self">networks</a>, and <a href="/en_us/business/products/user-protection/sps/email-and-collaboration/email-security.html" target="_self">emails</a>.</p>
