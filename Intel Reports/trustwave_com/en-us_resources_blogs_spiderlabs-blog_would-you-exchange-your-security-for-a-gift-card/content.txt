<h3>Overview</h3> 
<p>We often talk about attackers targeting companies with social engineering attacks. These usually take the form of phishing attacks that attempt to trick the recipient into opening a malicious attachment or clicking on a malicious link. Less discussed are targeted attacks using physical media. Penetration Testers that perform physical "pentests" are well versed in dropping "malicious" USB sticks in a target's parking lot or waiting room. More complex are so-called "Rubber Ducky" (https://github.com/hak5darren/USB-Rubber-Ducky/wiki) attacks, where what looks like a USB stick is actually, in effect, a malicious USB keyboard preloaded with keystrokes. Those types of attacks are typically so explicitly targeted that it's rare to find them coming from actual attackers in the wild. Rare, but still out there.</p> 
<h3>The Attack</h3> 
<p>This letter was supposedly from Best Buy giving out a $50 gift card to its loyal customers. Included in this letter is seemingly a USB drive that claims to contain a list of items to spend on. Very nice gesture!</p> 
<div id="photo-xid-6a0133f264aa62970b0240a5124870200b">
 <img loading="lazy" src="https://www.levelblue.com/hubfs/Imported_Blog_Media/6a0133f264aa62970b0240a5124870200b-800wi" border="0" alt="Gift Card Letter" title="Gift Card Letter"> 
 <div id="caption-xid-6a0133f264aa62970b0240a5124870200b" style="font-size: 14px;">
  Figure 1. Suspicious Best Buy gift card containing a malicious USB device
 </div> 
</div> 
<p>&nbsp;</p> 
<p>One of our digital forensics and incident response retainer clients brought this device to our attention. One of their business associates received this suspicious letter. Fortunately, our client and their associate did not plug the drive into any computer. Thank you, security training!</p> 
<h3>Analysis</h3> 
<p>To start the analysis, we inspected the drive for inscriptions such as serial numbers. At the head of the drive on the printed circuit board we saw “HW-374”. A quick Google search for this string found a “BadUSB Leonardo USB ATMEGA32U4” for sale on shopee.tw.</p> 
<p>&nbsp;</p> 
<div id="photo-xid-6a0133f264aa62970b0240a4edabdd200d">
 <img loading="lazy" src="https://www.levelblue.com/hubfs/Imported_Blog_Media/6a0133f264aa62970b0240a4edabdd200d-800wi" border="0" alt="BadUSB" title="BadUSB"> 
 <div id="caption-xid-6a0133f264aa62970b0240a4edabdd200d" style="font-size: 14px;">
  Figure 2: The website images matched the drive that the client received!
 </div> 
</div> 
<p>&nbsp;</p> 
<p>This USB device uses an Arduino microcontroller ATMEGA32U4 and was programmed to emulate a USB keyboard. Since PCs trust keyboard USB devices by default, once it is plugged in, the keyboard emulator can automatically inject malicious commands.</p> 
<p>To quickly get the payload off the USB drive we connected it to an air-gapped laptop that had Ubuntu installed while Wireshark captured traffic on the third USB bus and the active window was set Vim. We figured Vim could act as a rudimentary jail to capture traffic and that the intended target is the Windows OS. Sure enough, we were presented with the following payload.</p> 
<p>&nbsp;</p> 
<h3>Powershell Payload</h3> 
<p>&nbsp;</p> 
<div id="photo-xid-6a0133f264aa62970b0240a5124895200b">
 <img loading="lazy" src="https://www.levelblue.com/hubfs/Imported_Blog_Media/6a0133f264aa62970b0240a5124895200b-800wi" border="0" alt="Payload" title="Payload"> 
 <div id="caption-xid-6a0133f264aa62970b0240a5124895200b" style="font-size: 14px;">
  Figure 3. Payload was intercepted through VIM and reveals an obfuscated PowerShell script
 </div> 
</div> 
<p>&nbsp;</p> 
<p>De-obfuscating the PowerShell command is a simple mono substitution cipher by which the cipher text ASCII table is shifted 1 step to the left. For example, to decode the character ‘j’ can be done by shifting 1 step backward and is equal to ‘i’, for ‘f’ is substituted by ‘e’ then ‘y’ = ‘x’ so on and so forth.</p> 
<p>&nbsp;</p> 
<div id="photo-xid-6a0133f264aa62970b0240a51248e4200b">
 <img loading="lazy" src="https://www.levelblue.com/hubfs/Imported_Blog_Media/6a0133f264aa62970b0240a51248e4200b-800wi" border="0" alt="Decoding the payload" title="Decoding the payload"> 
 <div id="caption-xid-6a0133f264aa62970b0240a51248e4200b" style="font-size: 14px;">
  Figure 4. PowerShell command deobfuscated using CyberChef
 </div> 
</div> 
<p>&nbsp;</p> 
<p>The de-obfuscated string reveals a command that downloads the second stage PowerShell code from hxxps://milkmovemoney[.]com/st/mi.ini.</p> 
<p>&nbsp;</p> 
<p><img loading="lazy" src="https://www.levelblue.com/hubfs/Imported_Blog_Media/6a0133f264aa62970b0240a51a4ec2200b-800wi" border="0" alt="Deobfus" title="Deobfus"></p> 
<p style="font-size: 14px;">Figure 5. Downloaded 2nd Stage Powershell Code</p> 
<p>&nbsp;</p> 
<div id="photo-xid-6a0133f264aa62970b0240a51249c9200b">
 <img loading="lazy" src="https://www.levelblue.com/hubfs/Imported_Blog_Media/6a0133f264aa62970b0240a51249c9200b-800wi" border="0" alt="Downloaded script" title="Downloaded script"> 
 <div id="caption-xid-6a0133f264aa62970b0240a51249c9200b" style="font-size: 14px;">
  Figure 6
 </div> 
</div> 
<p>&nbsp;</p> 
<p>To summarize, this is the second stage PowerShell execution flow:</p> 
<ol> 
 <li>Copy wscript.exe to %AppData%\Microsoft\Windows\wipre.exe</li> 
 <li>Decode a JScript command and save it as prada.txt</li> 
 <li>Execute prada.txt with the command “cmd.exe /c wipre.exe /e:jscript prada.txt”</li> 
 <li>Show a fake message box warning</li> 
</ol> 
<div id="photo-xid-6a0133f264aa62970b0240a5124a2e200b">
 <img loading="lazy" src="https://www.levelblue.com/hubfs/Imported_Blog_Media/6a0133f264aa62970b0240a5124a2e200b-800wi" border="0" alt="Fake Message Box" title="Fake Message Box"> 
 <div id="caption-xid-6a0133f264aa62970b0240a5124a2e200b" style="font-size: 14px;">
  Figure 7. A convincing fake message box pops up
 </div> 
</div> 
<p>&nbsp;</p> 
<h3>Javascript Payload</h3> 
<p>The Jscript code saved to prada.txt is the third stage payload. This is executed using the Windows built-in script host engine - wscript.exe.</p> 
<p>&nbsp;</p> 
<div id="photo-xid-6a0133f264aa62970b025d9b381a95200c">
 <img loading="lazy" src="https://www.levelblue.com/hubfs/Imported_Blog_Media/6a0133f264aa62970b025d9b381a95200c-800wi" border="0" alt="Prada.txt" title="Prada.txt"> 
 <div id="caption-xid-6a0133f264aa62970b025d9b381a95200c">
  Figure 8. de-obfuscated JScript saved as Prada.txt
 </div> 
</div> 
<p>&nbsp;</p> 
<p>The Jscript is mildly obfuscated using a simple variable substitution. The main function of this script is to register the infected host to the command and control (C&amp;C) server with a unique ID, then in return, it receives an additional JScript code that is executed using eval() function.</p> 
<p>Below is the step by step execution flow of the Jscript code:</p> 
<ol> 
 <li>Generates a unique ID by getting the current UTC milliseconds</li> 
 <li>Check if the script is in the folder %AppData%\Microsoft\Windows and delete itself if it is not</li> 
 <li>Delay execution for 2 minutes</li> 
 <li>Generate a data containing the following information: 
  <ol> 
   <li>group : f1 (hardcoded)</li> 
   <li>rt : 2 (hardcoded)</li> 
   <li>secret : secret hash (hardcoded)</li> 
   <li>time : 120000</li> 
   <li>uniq_id : current UTC milliseconds</li> 
   <li>id : MAC address and hostname (using WMI query)</li> 
  </ol> </li> 
 <li>URL encode the data and XOR encode it using a random generated key.</li> 
 <li>Append the generated XOR key to the encoded data delimited with “&amp;_&amp;”</li> 
 <li>Form a HTTP POST body containing the parameter. 
  <ol> 
   <li>kbaxmaconhuc=
    <encoded data+generated xor key></encoded></li> 
  </ol> </li> 
 <li>Form a URL path: 
  <ol> 
   <li>https://<command and control domain>/
    <random path>
     /
     <random file>
      /?type=name
     </random>
    </random></li> 
  </ol> </li> 
 <li>Send the data to the command and control URL as a HTTP POST raw body and using the following HTTP request header: 
  <ol> 
   <li>User-Agent: Mozilla/5.0 (Windows NT 6.1; Win64; x64; rv:69.0) Gecko/20100101 Firefox/50.0'</li> 
   <li>Content-Type: %application/x-www-form-urlencoded'</li> 
  </ol> </li> 
 <li>Command and control responds an encoded JScript code</li> 
 <li>Decode and execute Jscript code using eval()</li> 
</ol> 
<p>In the event that the C&amp;C server is alive, it will respond with an encoded data as shown in figure 9. The encoded data includes a XOR key to decode it. Data and the key is delimited with<em><span>&nbsp;</span>“&amp;_&amp;”</em>&nbsp; or URL encoded “%26_%26”. The decoded data reveals an additional Jscript code that will be executed in the infected host.</p> 
<p>&nbsp;</p> 
<div id="photo-xid-6a0133f264aa62970b0240a4edae49200d">
 <img loading="lazy" src="https://www.levelblue.com/hubfs/Imported_Blog_Media/6a0133f264aa62970b0240a4edae49200d-800wi" border="0" alt="Encoded Data" title="Encoded Data"> 
 <div id="caption-xid-6a0133f264aa62970b0240a4edae49200d" style="font-size: 14px;">
  Figure 9: The C&amp;C server responded with this encoded data
 </div> 
</div> 
<p>&nbsp;</p> 
<p>The JScript code could be anything. But when we decoded it, it reveals a code that gathers system information from the infected host.</p> 
<p>&nbsp;</p> 
<div id="photo-xid-6a0133f264aa62970b0240a4edae85200d">
 <img loading="lazy" src="https://www.levelblue.com/hubfs/Imported_Blog_Media/6a0133f264aa62970b0240a4edae85200d-800wi" border="0" alt="Figure9" title="Figure9"> 
 <div id="caption-xid-6a0133f264aa62970b0240a4edae85200d" style="font-size: 14px;">
  Figure 10: The deobfuscated JScript code that was part of the code sent by the C&amp;C server
 </div> 
</div> 
<p>&nbsp;</p> 
<p>The following information is collected, encoded then sent back to the C&amp;C server:</p> 
<ul> 
 <li>Username</li> 
 <li>Hostname</li> 
 <li>User’s System Privilege</li> 
 <li>Uses WMI query to get the: 
  <ul> 
   <li>Process owner</li> 
   <li>Domain name</li> 
   <li>Computer model</li> 
   <li>Operating system information 
    <ul> 
     <li>OS name</li> 
     <li>OS build</li> 
     <li>OS version</li> 
     <li>Memory capacity</li> 
     <li>Free memory available</li> 
     <li>OS registered user</li> 
     <li>OS registered organization</li> 
     <li>OS serial number</li> 
     <li>Last boot up time</li> 
     <li>Install date</li> 
     <li>OS architecture</li> 
     <li>OS product type</li> 
     <li>Language code</li> 
     <li>Time zone</li> 
     <li>Number of users</li> 
     <li>Desktop monitor type</li> 
     <li>Desktop resolution</li> 
     <li>UAC level privilege</li> 
    </ul> </li> 
   <li>Office and Adobe acrobat installation</li> 
   <li>List of running Processes (including PID)</li> 
   <li>Whether the infected host is running in a virtualized environment</li> 
  </ul> </li> 
</ul> 
<p>After this gathered information is sent to C&amp;C server. The main Jscript code enters an infinite loop sleeping for 2 minutes in each loop iteration then getting a new command from the command and control. Here is the full attack flow:</p> 
<p>&nbsp;</p> 
<p><img loading="lazy" src="https://www.levelblue.com/hubfs/Imported_Blog_Media/6a0133f264aa62970b0240a51a4c0f200b-800wi" border="0" alt="Attack_flow" title="Attack_flow"><span style="font-size: 14px;">Figure 11: Attack Flow</span></p> 
<p>&nbsp;</p> 
<h3>Conclusion</h3> 
<p>In summary, once a USB controller chip is reprogrammed to unintended use (in this case as an emulated USB keyboard) these devices could be used to launch an attack and infect unsuspecting users’ computer without them realizing it.</p> 
<p>These types of USB devices are widely known and used by security professionals. The fact that they are also cheap and readily available to anyone meant that it was just a matter of time to see this technique used by criminals "in the wild." Since USB devices are ubiquitous, used, and seen everywhere, some consider them innocuous and safe. Others can be very curious about the contents of an unknown USB device. If this story teaches us anything, it's that one should never trust such a device.<br><br></p>

<h3>UPDATE 27.March.2020:</h3> 
<p>Since our initial publication, we've received confirmation from multiple sources that this campaign matches IOCs from similar campaigns from FIN7 (<a href="https://attack.mitre.org/groups/G0046/">https://attack.mitre.org/groups/G0046/</a>). FIN7 is a cybercriminal collective that has been targeting the hospitality and retail sectors since at least 2015.</p>
