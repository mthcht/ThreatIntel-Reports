                <h2><a id="post-188392-_4lt92rr5muov"></a>Executive Summary</h2>
<p>Unit 42 identified a campaign targeting government entities and state-affiliated infrastructure, with observed activity spanning from October 2025–April 2026. We track this activity as CL-UNK-1211.</p>
<p>In the operations we witnessed, the attackers relied on AI-generated payloads. Multiple artifacts deployed throughout the intrusion contained AI-made conversational annotations and developer reasoning comments, suggesting that the code was either generated using large language models (LLMs) or executed by an automated AI agent.</p>
<p>The attackers behind this cluster of activity focused on Linux environments to conduct extensive reconnaissance and maintain persistent network access to support intelligence-gathering. The attackers attempted to dump sensitive databases and exfiltrate government mailboxes to access social media accounts.</p>
<p>The campaign included a diverse toolkit that combined open-source tools, custom cross-platform backdoors and widespread web shell deployments. We observed various defense evasion techniques, including attempts to disable endpoint protections, erase system logs and plant deceptive red-team markers to disguise activity as a legitimate security assessment.</p>
<p>Our attribution of this activity to CL-UNK-1211 is in accordance with the <a href="https://unit42.paloaltonetworks.com/unit-42-attribution-framework/" target="_blank" rel="noopener">Unit 42 attribution framework</a>. We designate the term UNK to clusters of activity whose affiliation with either nation-state or cybercrime activity we have not yet determined.</p>
<p>This investigation uncovers the defining tools, techniques and attack patterns of this activity cluster.</p>

<h2><a id="post-188392-_d3nfzv15e61m"></a>Technical Analysis Overview</h2>
<p>Our analysis of the CL-UNK-1211 cluster of activity reveals a versatile operational playbook tailored to enterprise Linux and database environments. The attackers targeted government entities and state-affiliated infrastructure, maintaining persistent access by using a combination of custom cross-platform backdoors, open-source utilities and widespread web shell deployments.</p>
<p>The attackers enumerated mailboxes to identify and gain access to social media accounts tied to government email addresses. In addition, they dumped entire database contents before attempting to exfiltrate the data.</p>
<p>The attackers behind CL-UNK-1211 exhibited a methodical approach to defense evasion. This included attempting to disable endpoint protections on compromised systems, and to tamper with system logs that might contain evidence of the attack.</p>
<p>We provide a comprehensive analysis of the defining tools, techniques and procedures (TTPs) used throughout the operation, highlighting how the attackers leveraged AI to streamline payload creation across their execution workflow. Our analysis details key mechanisms across the attack chain. These include:</p>
<ul>
<li>Initial access via web shell deployment and credential harvesting</li>
<li>Custom RAT execution</li>
<li>Mailbox targeting</li>
<li>Anti-forensics measures</li>
</ul>
<h2><a id="post-188392-_wj4f289ens0c"></a>Using AI to Streamline Payload Creation</h2>
<p>Throughout the operation, the attackers relied on malicious PHP and shell scripts to maintain persistence, perform reconnaissance and exfiltrate data. These payloads revealed structural patterns and artifacts consistent with AI-assisted code generation.</p>
<p>Rather than standard developer documentation, multiple scripts contained conversational, step-by-step reasoning notes. These notes explained the code’s logic to the operator who provided the initial instructions. Their presence suggests that the code was either copied directly from an AI prompt output or deployed by an automated AI agent.</p>
<p>In addition, we identified several common characteristics that are consistent with AI-operated attacks, such as:</p>
<ul>
<li>Section headers in scripts and shell commands, which AI uses to analyze the output faster</li>
<li>Extensive use of Base64-encoded commands</li>
<li>Seamless switching between different technologies throughout the attack, including PHP, JavaScript, Bash and Python</li>
</ul>

<h2><a id="post-188392-_1qhq2lrfand4"></a>Dropping Multiple Web Shells for Initial Access</h2>

These were a combination of custom and open-source web shells found on GitHub. Figure 2 shows interactive web shell activity from the <span style="font-family: 'courier new', courier, monospace;">php-fpm</span> parent process.</p>

Any file that is specified in the modified <span style="font-family: 'courier new', courier, monospace;">auto_prepend_file</span> value will automatically load and execute before any other PHP script runs.</p>

They also modified the <span style="font-family: 'courier new', courier, monospace;">auto_prepend_file</span> to load the malicious web shell to ensure persistence. <h2><a id="post-188392-_beeu0df5yv82"></a>Credential Harvesting Techniques</h2>
<p>The attackers used multiple methods to gather credentials in the targeted environments, including:</p>
<ul>
<li>Editing the <span style="font-family: 'courier new', courier, monospace;">.bashrc</span> file</li>
<li>Inserting malicious lines of code into PHP scripts</li>
<li>Scanning the network for cleartext passwords</li>
</ul>
<h3><a id="post-188392-_sqq2evyvuk9c"></a>Hijacked .bashrc File</h3>
<p>The attackers replaced the <a href="https://www.digitalocean.com/community/tutorials/bashrc-file-in-linux" target="_blank" rel="noopener"><span style="font-family: 'courier new', courier, monospace;">.bashrc</span></a> file with a copy containing a malicious command that steals victims’ passwords. In one instance, they created an alias for the <span style="font-family: 'courier new', courier, monospace;">sudo</span> command that was designed to execute each time a user attempted to run it. The malicious command:</p>
<ul>
<li>Displays a prompt for the user to insert their password (mimicking the standard system authentication prompt)</li>
<li>Captures the inserted password</li>
<li>Writes it to the attackers’ log file</li>
</ul>
<p>The harvested password is then passed to the legitimate <span style="font-family: 'courier new', courier, monospace;">sudo</span> command for execution, leaving the victim unaware of the underlying interception. The attackers named the log file <span style="font-family: 'courier new', courier, monospace;">Solarwinds.StatusLog.txt</span>, to mimic legitimate SolarWinds activity in the environment. We have no evidence of SolarWinds systems and infrastructure being compromised during this operation; the attackers misused the organization’s name as an evasion method.</p>
<p>Figure 4 shows the command hijacking technique inside the <span style="font-family: 'courier new', courier, monospace;">.bashrc</span> file.</p>
<figure id="attachment_188426" aria-describedby="caption-attachment-188426" style="width: 1000px" class="wp-caption alignnone"><img  class="wp-image-188426 lozad"  data-src="https://unit42.paloaltonetworks.com/wp-content/uploads/2026/10/word-image-474057-188392-4.png" alt="Screenshot of a line of code in a text editor, written in a dark-themed interface. <h3><a id="post-188392-_o8l3h9epas75"></a>PHP Credential Logger</h3>
<p>The attackers inserted a line of code into a PHP login page — most likely targeting a database authentication routine — to harvest admin credentials. If an administrator logs in, the code forwards the username and password to the attackers’ log file. Figure 5 shows a snippet of a PHP script including the code added by the attackers.</p>

<h2><a id="post-188392-_yqpslhtvkzx4"></a>SysGoRAT Malware</h2>
<p>The attackers deployed a custom-developed, multi-platform remote access Trojan (RAT) written in Go, first observed under the benign file name <span style="font-family: 'courier new', courier, monospace;">sys-control-client</span>. We named this malware SysGoRAT. This malware supports cross-platform execution on Windows and Linux and employs multiple persistence methods to maintain long-term access.</p>
<p>The malware established a command and control (C2) connection over WebSocket to <span style="font-family: 'courier new', courier, monospace;">wss://&lt;addr&gt;/ws</span>. This WebSocket address defaults to a hardcoded IP address <span style="font-family: 'courier new', courier, monospace;">104.194.158[.]65:443</span>, which the malware operator can modify via a command-line parameter at execution. <p>We found indications that the attackers also intended to exfiltrate multiple databases and steal highly sensitive government data. The data exfiltration techniques the attackers used are detailed in <a href="#post-188392-_lco5s1bjycyb">Appendix B</a>.</p>
<h2><a id="post-188392-_bse55guoab3b"></a>Defense Evasion and Anti-Forensics Attempts</h2>
<p>A core component of the attackers’ playbook involved anti-forensics techniques, specifically:</p>
<ul>
<li>Attempting to disable endpoint protections</li>
<li>Tampering with logs</li>
<li><a href="https://attack.mitre.org/techniques/T1070/006/" target="_blank" rel="noopener">Timestomping</a></li>
<li>Disguising malicious activity</li>
<li>Deleting residual artifacts to hinder post-incident analysis</li>
</ul>
<p>This section details the specific evasion techniques and cleanup commands the attackers used to cover their tracks.</p>
<h3><a id="post-188392-_6jimbdlob744"></a>Disabling Endpoint Protection</h3>
<p>One of the techniques the attackers used for defense evasion was an attempt to disable security protection devices on the compromised hosts. As Figure 11 shows, the attackers executed bash scripts that use the Linux commands <span style="font-family: 'courier new', courier, monospace;">pgrep</span> and <span style="font-family: 'courier new', courier, monospace;">pkill</span> to attempt to terminate Cortex XDR-related processes on infected systems.</p>

Snippets of code from a script used in an attempt to terminate Cortex XDR.</figcaption></figure>
<p>These attempts were successfully detected and mitigated by Cortex XDR, with telemetry confirming that endpoint protections were not suppressed.</p>
<h3><a id="post-188392-_rk5119prxsdi"></a>Removing Scripts After Execution</h3>
<p>Throughout the campaign, the attackers ensured that single-use scripts were removed after execution by formulating a single command that:</p>
<ul>
<li>Wrote the script to disk</li>
<li>Executed the script</li>
<li>Removed the script using <span style="font-family: 'courier new', courier, monospace;">rm</span></li>
</ul>

<h3><a id="post-188392-_5ex6d8ywucl"></a>Timestomping</h3>
<p>For scripts that were meant for long-term use, the attackers used timestomping.</p>
<p>They used the command<span style="font-family: 'courier new', courier, monospace;"> touch -t</span> to change the access and modification time of malicious files, to make them appear as if they were created long before the attack started. The goal of this technique is to evade analysis by misleading analysts into believing the file is unrelated to malicious activity, due to its creation time predating the attack timeline.</p>
<h3><a id="post-188392-_1p8r52qausls"></a>Disguising Activity as Red Team Operations</h3>
<p>In several instances, we observed the attackers employing planted deception techniques to mislead post-incident analysis. They attempted to disguise their activity as a red team operation, by using operational indicators such as the key <span style="font-family: 'courier new', courier, monospace;">RedTeamOps2025</span> in one of the malicious scripts, and <span style="font-family: 'courier new', courier, monospace;">pentest123</span> as a password for a user the attackers created.</p>

<ul>
<li>Authentication</li>
<li>Command history</li>
<li>Email activity</li>
<li>Operating system (OS)</li>
<li>Web server</li>
<li>Active PHP user sessions</li>
</ul>

<h2><a id="post-188392-_2an8ryq91inv"></a>Conclusion</h2>
<p>This campaign demonstrates how attackers are combining traditional post-exploitation techniques with AI-accelerated workflows to target governmental Linux server infrastructure. By leveraging AI to rapidly generate, adapt and deploy operational scripts, the attackers behind CL-UNK-1211 maintained a fast pace of operation while minimizing manual developer overhead.</p>
<p>The attackers behind this activity exhibited a deep understanding of the Linux OS, employing techniques such as:</p>
<ul>
<li>Global PHP configuration hijacking for persistent access</li>
<li>Command-line credential harvesting and privilege escalation using different shells</li>
</ul>
<p>Alongside open-source utilities, their toolkit featured custom tools, including a multi-platform Go RAT and custom vulnerability scanners.</p>
<p>The attackers also maintained a thorough cleanup strategy to thwart forensic analysis, by erasing system logs and attempting to disable endpoint protections. Despite these evasion efforts, endpoint security controls effectively neutralized their activity. Cortex XDR detected and prevented the process termination attempts targeting the agent.</p>
<p>Attackers continue to adopt AI to streamline payload development and scale their campaigns.</p>
<p>Comprehensive visibility into Linux servers, databases and environments remains critical to countering attackers’ efforts and strengthening enterprise security.</p>

<h4><a id="post-188392-_dvm1ajiul7s3"></a>SSH-Based Persistency</h4>
<p>The attackers achieved SSH-based persistence by injecting an SSH public key into the compromised user’s <span style="font-family: 'courier new', courier, monospace;">authorized_keys</span> file. This establishes passwordless remote shell access. Following is the command sequence the attackers executed to install the SSH backdoor:</p>
<ol>
<li>Ensure the hidden <span style="font-family: 'courier new', courier, monospace;">.ssh</span> directory exists</li>
<li>Restrict directory access only to the owner (using <span style="font-family: 'courier new', courier, monospace;">chmod 700</span>)</li>
<li>Append the malicious public key to the<span style="font-family: 'courier new', courier, monospace;"> authorized_keys</span> file</li>
<li>Set strict permissions on the <span style="font-family: 'courier new', courier, monospace;">authorized_keys</span> file</li>
</ol>

<h3><a id="post-188392-_fkre8sero1if"></a>Additional Proxy Tools</h3>
<p>The attackers deployed a variety of tunneling and proxy tools, while employing multiple techniques to maintain persistence and evade detection:</p>
<ul>
<li><strong>revsocks</strong>: The attackers deployed the open-source tool <a href="https://github.com/kost/revsocks" target="_blank" rel="noopener">revsocks</a>, a reverse SOCKS5 tunneling tool with SSL/TLS and proxy support.</li>
<li><strong>pysoxy</strong>: The tool set also included <a href="https://github.com/MisterDaneel/pysoxy/" target="_blank" rel="noopener">pysoxy</a>, an open-source Python SOCKS proxy script used to route traffic.</li>
<li><strong>GSocket and gs-netcat:</strong> The attackers misused <a href="https://www.gsocket.io/" target="_blank" rel="noopener">Global Socket</a>, a framework designed to solve NAT and firewall traversal problems. They deployed the framework’s binary, <span style="font-family: 'courier new', courier, monospace;">gs-netcat</span>, which forces the internal host to establish an outbound connection to the public relay server (<span style="font-family: 'courier new', courier, monospace;">gsocket[.]io</span>).<br />
This binary was stored in <span style="font-family: 'courier new', courier, monospace;">/dev/shm/.gs-10085/</span> and executed under the disguised process name <span style="font-family: 'courier new', courier, monospace;">[kcached]</span> (mimicking a kernel cache thread), alongside the binary <span style="font-family: 'courier new', courier, monospace;">gs-dbus</span> (mimicking the D-Bus system). Execution parameters were passed via the environment variable (<span style="font-family: 'courier new', courier, monospace;">GSOCKET_ARGS</span>) to hide them from process monitoring, and the spawned sessions were configured with <span style="font-family: 'courier new', courier, monospace;">HISTFILE=/dev/null</span> to prevent shell command history from being logged to disk.</li>
</ul>
<h3><a id="post-188392-_42gryi969gs8"></a>Additional Data Exfiltration Attempts</h3>
<p>The attackers used a combination of methods to extract sensitive data. We observed how they dumped entire database contents into compressed local archives before attempting to exfiltrate them to their C2 infrastructure. They also misused legitimate file-hosting platforms to blend the outgoing data with standard web traffic.</p>
<p>Exfiltration attempts began with attackers using the <span style="font-family: 'courier new', courier, monospace;">echo</span> command to print small data samples directly to the terminal, using <span style="font-family: 'courier new', courier, monospace;">TOP</span> clauses to limit the output. They subsequently attempted a structured dump, writing four tables, each capped at 100 rows, to a local SQLite database named <span style="font-family: 'courier new', courier, monospace;">dump.sqlite</span>.
