    <p class="category text-uppercase">Prevention and Awareness</p>
    <h1 class="page-headline">The rise of TeleBots: Analyzing disruptive KillDisk attacks</h1>    <p class="sub-title">ESET's Anton Cherepanov analyzes the work of TeleBots, a malicious toolset that was used in focused cyberattacks against targets in Ukraine's financial sector.</p>

    <div class="article-authors d-flex flex-wrap">  <div class="article-author d-flex">  <a href="/blog/en/our-experts/anton-cherepanov/" title="Anton Cherepanov">   <picture>  <source srcset="https://web-assets.esetstatic.com/tn/-x45/blog/2020/03/Anton_Cherepanov.jpg" media="(max-width: 768px)" />   <img class="author-image me-3"  src="https://web-assets.esetstatic.com/tn/-x45/blog/2020/03/Anton_Cherepanov.jpg" alt="Anton Cherepanov"  /></picture>  </a>  <div class="author-text"><p><a href="/blog/en/our-experts/anton-cherepanov/" title="Anton Cherepanov"><b>Anton Cherepanov</b></a></p></div></div> </div>

    <p class="article-info mb-5">
        <span>13 Dec 2016</span>
        <span class="d-none d-lg-inline">&nbsp;&bull;&nbsp;</span>
        <span class="d-inline d-lg-none">, </span>
        <span>18 min. read</span>
    </p>


</div>

                    <div class="article-body">
    <p>In the second half of 2016, ESET researchers identified a unique malicious toolset that was used in targeted cyberattacks against high-value targets in the Ukrainian financial sector. We believe that the main goal of attackers using these tools is cybersabotage. This blog post outlines the details about the campaign that we discovered.</p>
<p>We will refer to the gang behind the malware as TeleBots. However it’s important to say that these attackers, and the toolset used, share a number of similarities with the BlackEnergy group, which conducted attacks against the energy industry in Ukraine in <a href="http://www.welivesecurity.com/2016/01/03/blackenergy-sshbeardoor-details-2015-attacks-ukrainian-news-media-electric-industry/" target="_blank" rel="noopener">December 2015</a> and <a href="http://www.welivesecurity.com/2016/01/20/new-wave-attacks-ukrainian-power-industry/" target="_blank" rel="noopener">January 2016</a>. In fact, we think that the BlackEnergy group has evolved into the TeleBots group.</p>
<h1>Infection vector</h1>
<p>As with campaigns attributed to BlackEnergy group the attackers used spearphishing emails with Microsoft Excel documents attached that contain malicious macros as an initial infection vector. This time malicious documents don’t have any content with social engineering directing potential victims to click an Enable Content button. It seems that the attackers are depending on the victims to decide entirely on their own whether to click it or not.</p>
<p><div class="caption center"><img class="size-full wp-image-86909" src="https://web-assets.esetstatic.com/blog/2016/12/01_Malicious_XLS.png" alt="Figure 1: One example of a malicious XLS document used in the spear phishing attack." width="935" height="610" /><p class="caption-text">Figure 1: One example of a malicious XLS document used in the spearphishing attack.</p></div></p>
<p>Usually, the malicious documents don’t contain meaningful information in the metadata, but this time the metadata of the document contains the nickname of the person who is responsible for its modification. Moreover, this nickname matches that of an individual who is actively communicating within a Russian-speaking community of cybercriminals. However, we should say that it is possible that this was intended deceptively as a false flag or a coincidence.</p>
<p><div class="caption center"><img class="size-full wp-image-86910" src="https://web-assets.esetstatic.com/blog/2016/12/02_DeSecurity.png" alt="Figure 2: Metadata reveals what might be the attacker's nickname." width="245" height="313" /><p class="caption-text">Figure 2: Metadata reveals what might be the attacker's nickname.</p></div></p>
<p>Once a victim clicks on the Enable Content button, Excel executes the malicious macro. Our analysis shows that the code of the macro used in TeleBots documents matches the macro code that was used by the BlackEnergy group in 2015. Figure 3 illustrates these similarities.</p>
<p>The main purpose of the macro is to drop a malicious binary using the <span style="font-family: 'courier new', courier, monospace;">explorer.exe</span> filename and then to execute it. The dropped binary belongs to a trojan downloader family, its main purpose being to download and execute another piece of malware. This trojan downloader is written in the <a href="https://en.wikipedia.org/wiki/Rust_(programming_language)" target="_blank" rel="noopener">Rust programming language</a>.</p>
<p>It should be noted that during the first stages of the attack, the TeleBots group abuse various legitimate servers in order to hide malicious activity in the network. For example, the trojan downloader fetches data from a hardcoded URL that points to a text file on the putdrive.com service (which allows anyone to upload and share files online). The text file that is hosted on the online service is a final payload, encoded using the Base64 algorithm.</p>
<p>The final payload is a backdoor written in Python and detected as the <a href="http://www.virusradar.com/en/Python_TeleBot.AA/description" target="_blank" rel="noopener">Python/TeleBot.AA trojan</a>. This backdoor is the main piece of malware used by these attackers, which is why we've named the TeleBots group as such.</p>
<p><div class="caption center"><img class="size-full wp-image-86911" src="https://web-assets.esetstatic.com/blog/2016/12/03_Macro.png" alt="Figure 3: Similarities between malicious macro code used by BlackEnergy and TeleBots." width="528" height="516" /><p class="caption-text">Figure 3: Similarities between malicious macro code used by BlackEnergy and TeleBots.</p></div></p>
<h1>Python/TeleBot.AA backdoor</h1>
<p>In January 2016 we published our <a href="http://www.welivesecurity.com/2016/01/20/new-wave-attacks-ukrainian-power-industry/" target="_blank" rel="noopener">analysis</a> of a spearphishing attack against energy companies in Ukraine. That attack probably has a connection to the infamous BlackEnergy attacks in 2015 because the attackers used exactly the same mail server to send spearphishing messages. However, the attacks in January 2016 were different. Instead of using the BlackEnergy malware family, the attackers used a relatively simple open-source backdoor, written in the Python programming language, called GCat. The Python code of the GCat backdoor was obfuscated, then converted into a stand-alone executable using the <a href="http://www.pyinstaller.org/" target="_blank" rel="noopener">PyInstaller program</a>.</p>
<p>The Python/TeleBot malware uses exactly the same approach; the Python backdoor code is obfuscated and packed into a standalone executable using PyInstaller. In addition, the Python code is ROT13 encoded, AES encrypted, compressed using <span style="font-family: 'courier new', courier, monospace;">zlib</span> library and then Base64 encoded.</p>
<p>But what really makes this backdoor interesting is the way in which it communicates with attackers in order to receive commands. Python/TeleBot abuses the <a href="https://core.telegram.org/bots/api" target="_blank" rel="noopener">Telegram Bot API</a> from <a href="https://telegram.org/" target="_blank" rel="noopener">Telegram Messenger</a> to communicate with the attackers. The Telegram Bot API is based on HTTP and to a network administrator within a compromised network, the communication between the infected computer and the attackers will look like HTTP(S) communication with a legitimate server, specifically <span style="font-family: 'courier new', courier, monospace;">api.telegram.org</span>. We have informed Telegram of this abuse of their communication platform.</p>
<p><div class="caption center"><img class="size-full wp-image-86912" src="https://web-assets.esetstatic.com/blog/2016/12/04_Telegram_API.png" alt="Figure 4: The Python/TeleBot.AA malware code that uses Telegram Bot API." width="602" height="334" /><p class="caption-text">Figure 4: The Python/TeleBot.AA malware code that uses Telegram Bot API.</p></div></p>
<p>Each of the samples we discovered has a unique token embedded in its code, which means that each sample uses its own Telegram Messenger account. Python/TeleBot uses private chats for communicating with the cybercriminals. This scheme allows the control of infected computers through any device with Telegram Messenger installed, even from a smartphone, just by issuing commands via chat.</p>

In addition, the malware automatically saves all incoming files from the attacker to its own folder. By this means, attackers can push additional malicious tools to an infected computer. During our research, we were able to find a Telegram account belonging to one of the attackers.</p>
<p><div class="caption center"><img class="size-full wp-image-86913" src="https://web-assets.esetstatic.com/blog/2016/12/05_Mark_Stolnberg_source.png" alt="Figure 5: Profile of one of the attackers in Telegram Messenger." width="320" height="145" /><p class="caption-text">Figure 5: Profile of one of the attackers in Telegram Messenger.</p></div></p>
<p>It should be noted that the Telegram Bot API was not the <em>only</em> legitimate protocol that was used by these attackers. We have seen at least one sample of this backdoor that uses an outlook.com mailbox as C&amp;C.</p>
<h1>Password stealing malicious tools</h1>
<p>After successful compromise of the network, attackers use various malicious tools in order to collect passwords, allowing them to subsequently perform a lateral movement within the compromised LAN.</p>
<p>A string, that contains a PDB-path to debug symbols, suggests one such tool was named <span style="font-family: 'courier new', courier, monospace;">CredRaptor</span> by the attackers. This tool collects saved passwords from various browsers such as Google Chrome, Internet Explorer, Mozilla Firefox, and Opera.</p>
<p><div class="caption center"><img class="size-full wp-image-86914" src="https://web-assets.esetstatic.com/blog/2016/12/06_CredRaptor.png" alt="Figure 6: PDB-Path reveals the name of the password stealer." width="804" height="96" /><p class="caption-text">Figure 6: PDB-Path reveals the name of the password stealer.</p></div></p>
<p>The attackers are using a tool with name <span style="font-family: 'courier new', courier, monospace;">plainpwd</span> in order to dump Windows credentials from memory. This tool is a slightly modified version of the open-source project <span style="font-family: 'courier new', courier, monospace;">mimikatz</span>.</p>
<p>In addition to <span style="font-family: 'courier new', courier, monospace;">plainpwd</span> and <span style="font-family: 'courier new', courier, monospace;">CredRaptor</span> the toolkit includes a keylogger. The keylogger uses a standard technique to capture keystrokes, specifically the <span style="font-family: 'courier new', courier, monospace;">SetWindowsHookEx</span> function.</p>
<p>In order to also sniff passwords in network traffic, the attackers use a console version of Interceptor-NG. Since it requires WinPcap drivers to be installed, the attackers made a custom tool to install them silently.</p>
<p><div class="caption center"><img class="size-full wp-image-86915" src="https://web-assets.esetstatic.com/blog/2016/12/07_Intercepter_NG.png" alt="Figure 7: Intercepter-NG password sniffing tool." width="678" height="318" /><p class="caption-text">Figure 7: Intercepter-NG password sniffing tool.</p></div></p>
<p>The combined use of all these tools allows attackers to gain a foothold in a compromised network, with the objective of gaining full control by obtaining domain administrator privileges.</p>
<h1>LDAP query tool</h1>
<p>Another interesting discovery was a tool that was used during attacks to make queries to Active Directory using LDAP. This tool is able to dump detailed information about computers and usernames listed in Active Directory, and is tailored for a specific victim’s domain.</p>
<p><div class="caption center"><img class="size-full wp-image-86916" src="https://web-assets.esetstatic.com/blog/2016/12/08_LDAP_Query.png" alt="Figure 8: Disassembled code of the tailored LDAP query tool." width="645" height="199" /><p class="caption-text">Figure 8: Disassembled code of the tailored LDAP query tool.</p></div></p>
<h1>Additional backdoor</h1>
<p>Further research revealed that the attackers deployed additional backdoors in order to regain access to the compromised network, should their main Python/TeleBot backdoor be discovered and removed. This additional backdoor is written in VBS and some samples we discovered were packaged using the <span style="font-family: 'courier new', courier, monospace;">script2exe</span> program.</p>
<p>&nbsp;</p>
<p><div class="caption center"><img class="size-full wp-image-86917" src="https://web-assets.esetstatic.com/blog/2016/12/09_VBS.png" alt="Figure 9: Source code of additional backdoor written in VBS." width="1138" height="333" /><p class="caption-text">Figure 9: Source code of additional backdoor written in VBS.</p></div></p>

The variable <span style="font-family: 'courier new', courier, monospace;">timeout</span> defines the period of time in minutes between calls to the server. <h1>BCS-server</h1>
<p>The attackers also used a malicious tool that they named BCS-server. This tool allows them to open a tunnel into an internal network and then this tunnel can be used to send and receive data between the C&amp;C server and even non-infected computers in the network. The main idea of this tool is based on the same principles as the <a href="https://web-assets.esetstatic.com/blog/2016/10/eset-sednit-part-2.pdf#36" target="_blank" rel="noopener">XTUNNEL malware used by the Sednit group</a>.</p>
<p>During our analysis we discovered that the attackers used a guide for this specific tool. Interestingly, the guide was written in Russian.</p>
<p><div class="caption center"><img class="size-full wp-image-86918" src="https://web-assets.esetstatic.com/blog/2016/12/10_BCS_guide.png" alt="Figure 10: Guide for BCS-server in Russian." width="552" height="270" /><p class="caption-text">Figure 10: Guide for BCS-server in Russian.</p></div></p>
<p>The guide in Russian can be roughly translated as:</p>
<p><em>Parameters<br />
</em><em>-saddr – address of BCS server<br />
</em><em>-hport – port of a host, which we did setup on the server, this how we bypass firewall<br />
</em><em>Examples:<br />
</em><em>phost_win.exe –saddr=10.10.10.10 –hport=80<br />
</em><em>Debug versions:<br />
</em><em>phost_cnv.exe – console version<br />
</em><em>phost_win_log.exe – version that logs to file</em></p>
<p>So attackers specify an external C&amp;C server in the command line and the tool connects to this server using HTTP. This remote server is used as a proxy by attackers: the connection that goes to this server is redirected to the internal network by the tool and any response that the tool gets from a computer in the internal network goes to the C&amp;C server. Thus, attackers can communicate with internal servers that are normally unreachable from the internet.</p>
<p>The communication traffic between the BCS-server tool and the C&amp;C server is base64 encoded and encapsulated in HTML tags.</p>
<p><div class="caption center"><img class="size-full wp-image-86919" src="https://web-assets.esetstatic.com/blog/2016/12/11_BCS_Traffic.png" alt="Figure 11: The captured handshake of BCS-server tool and C&amp;C server." width="447" height="350" /><p class="caption-text">Figure 11: The captured handshake of BCS-server tool and C&amp;C server.</p></div></p>
<h1>KillDisk</h1>
<p>The KillDisk is a destructive component that is used by these attackers as the final stage of an attack. Previous versions of this component were used in attacks against media companies in November 2015 and against power grid companies in Ukraine in <a href="http://www.welivesecurity.com/2016/01/03/blackenergy-sshbeardoor-details-2015-attacks-ukrainian-news-media-electric-industry/" target="_blank" rel="noopener">December 2015</a>.</p>
<p>KillDisk is designed to run with high privileges, this time it registers itself as a service under <span style="font-family: 'courier new', courier, monospace;">Plug-And-Play Support</span> name. Since at the final stage attackers have probably collected network administrator level credentials, that’s why they are using Microsoft PsExec in order to execute KillDisk with the highest possible privileges on servers and workstations.</p>
<p>The attackers may specify an activation date of KillDisk via the command line. However, one of the samples had a predefined activation time that is set to 9:30am, 6 December 2016.</p>
<p>There are improvements in the code, however the main idea of KillDisk hasn’t change so much - it deletes important system files and makes computer unbootable. Beside that it also overwrites files with specific file extensions – those defined by the malware authors in this version of KillDisk are:</p>
<ul>
<li>.kdbx .bak .back .dr .bkf .cfg .fdb .mdb .accdb .gdb .wdb .csv .sdf .myd .dbf .sql .edb .mdf .ib .db3 .db4 .accdc .mdbx .sl3 .sqlite3 .nsn .dbc .dbx .sdb .ibz .sqlite .pyc .dwg .3ds .ai .conf .my .ost .pst .mkv .mp3 .wav .oda .sh .py .ps .ps1 .php .aspx .asp .rb .js .git .mdf .pdf .djvu .doc .docx .xls .xlsx .jar .ppt .pptx .rtf .vsd .vsdx .jpeg .jpg .png .tiff .msi .zip .rar .7z .tar .gz .eml .mail .ml .ova .vmdk .vhd .vmem .vdi .vhdx .vmx .ovf .vmc .vmfx .vmxf .hdd .vbox .vcb .vmsd .vfd .pvi .hdd .bin .avhd .vsv .iso .nrg .disk .hdd .pmf .vmdk .xvd</li>
</ul>
<p>The KillDisk malware may create new, small files instead of deleted ones with the exact same filename and these new files will contain one of two strings <span style="font-family: 'courier new', courier, monospace;">mrR0b07</span> or <span style="font-family: 'courier new', courier, monospace;">fS0cie7y</span> instead of the original content. This is not the only reference to the <a href="http://www.welivesecurity.com/2016/07/23/researching-mr-robot-elliots-world-cybersecurity-comic-con/" target="_blank" rel="noopener">Mr. Robot TV show</a>, in addition this KillDisk variant displays the picture that is illustrated in Figure 12.</p>
<p><div class="caption center"><img class="size-full wp-image-86920" src="https://web-assets.esetstatic.com/blog/2016/12/12_JOIN_US.png" alt="Figure 12: Picture displayed by KillDisk component." width="1024" height="768" /><p class="caption-text">Figure 12: Picture displayed by KillDisk component.</p></div></p>
<p>Interestingly, the KillDisk malware does not store this picture anywhere: rather it has code that draws this picture in real-time using the Windows GDI. It looks like attackers put a lot of effort just to make the code that draws this picture.</p>
<h1>Conclusion</h1>
<p>The cybercriminals behind these targeted attacks demonstrate serious intention to conduct cybersabotage attacks. To be able to mount such attacks, they are constantly inventing new malware and techniques, such as the use of the Telegram Bot API instead of a more conventional C&amp;C server for example.</p>
