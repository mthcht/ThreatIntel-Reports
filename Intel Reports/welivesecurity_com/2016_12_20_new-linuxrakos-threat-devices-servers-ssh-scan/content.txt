    <h1 class="page-headline">New Linux/Rakos threat: devices and servers under SSH scan (again)</h1>    <p class="sub-title">ESET's Peter Kálnai and Michal Malik report on a new Linux/Rakos threat - devices and servers are under SSH scan again.</p>

    <div class="article-authors d-flex flex-wrap">  <div class="article-author d-flex">  <a href="/blog/en/our-experts/peter-kalnai/" title="Peter Kálnai">   <picture>  <source srcset="https://web-assets.esetstatic.com/tn/-x45/blog/2023/07/kalnai-peter-photo.jpeg" media="(max-width: 768px)" />   <img class="author-image me-3"  src="https://web-assets.esetstatic.com/tn/-x45/blog/2023/07/kalnai-peter-photo.jpeg" alt="Peter Kálnai"  /></picture>  </a>  <div class="author-text"><p><a href="/blog/en/our-experts/peter-kalnai/" title="Peter Kálnai"><b>Peter Kálnai</b></a></p></div></div>  <div class="article-author d-flex">  <a href="/blog/en/our-experts/michal-malik/" title="Michal Malik">   <picture>  <source srcset="https://web-assets.esetstatic.com/tn/-x45/blog/2016/03/Malik_Michal.jpg" media="(max-width: 768px)" />   <img class="author-image me-3"  src="https://web-assets.esetstatic.com/tn/-x45/blog/2016/03/Malik_Michal.jpg" alt="Michal Malik"  /></picture>  </a>  <div class="author-text"><p><a href="/blog/en/our-experts/michal-malik/" title="Michal Malik"><b>Michal Malik</b></a></p></div></div> </div>

                    <div class="article-body">
    <p>Apparently, frustrated users complain more often recently on various forums about their embedded devices being overloaded with computing and network tasks. What these particular posts have in common is the name of the process causing the problem. It is executed from a temporary directory and disguised as a part of the Java framework, namely “.<span style="font-family: 'courier new', courier, monospace;">javaxxx</span>”. Additional names like “.<span style="font-family: 'courier new', courier, monospace;">swap</span>” or “<span style="font-family: 'courier new', courier, monospace;">kworker</span>” are also used. A few weeks ago, we discussed the recent Mirai incidents and Mirai-connected IoT security problems in <a href="http://www.welivesecurity.com/2016/10/26/hive-mind-iot-devices-go-rogue/" target="_blank">The Hive Mind: When IoT devices go rogue</a> and all that was written then still holds true.</p>
<h2>Attack vector</h2>
<p>The attack is performed via brute force attempts at SSH logins, in a similar way to that in which many Linux worms operate, including <a href="https://web-assets.esetstatic.com/blog/2015/05/Dissecting-LinuxMoose.pdf" target="_blank">Linux/Moose</a> (which spread by attacking Telnet logins) – also referenced <a href="http://www.welivesecurity.com/2016/11/02/linuxmoose-still-breathing/" target="_blank">here</a> – as analyzed by ESET since last year. The targets include both embedded devices and servers with an open SSH port and where a very weak password has been set. The obvious aim of this trojan is to assemble a list of unsecured devices and to have an opportunity to create a botnet consisting of as many zombies as possible. The scan starts with not too extensive list of IPs and spreads incrementally to more targets. Only machines that represent low-hanging fruit from the security perspective are compromised. Note that victims reported cases when they had had a strong password but they forgot their device that had online service enabled and it was reverted to a default password after a factory reset. Just a couple of hours of online exposure was enough for such a reset machine to end up compromised!</p>
<h2>Analysis</h2>
<p>The malware is written in the Go language and the binary is usually compressed with the standard  UPX tool. The awkward thing was that the function names were stripped from the binary in the usual way, but they are still present in a special section anyway. With the help of a script by <a href="http://rednaga.io/2016/09/21/reversing_go_binaries_like_a_pro/" target="_blank">RedNaga Security</a> that maps symbols back to their respective function in the IDA Pro disassembling software, the whole analysis was simplified to reviewing the features that function names suggested, like <span style="font-family: 'courier new', courier, monospace;">main_loadConfig, main_startLocalHttp, main_Skaro_Upgrade, main_IPTarget_checkSSH</span> etc.  There are strings like “<span style="font-family: 'courier new', courier, monospace;">Skaro</span>” and “<span style="font-family: 'courier new', courier, monospace;">dalek</span>” in the binary. The author(s) possibly had in mind a connection to a fictional planet in the science fiction television series Doctor Who from whence the Daleks originated.</p>
<p>As a first step, [Linux/]Rakos loads its configuration via standard input (stdin) in <a href="http://yaml.org/" target="_blank">YAML</a> format. <p>The full plain text Linux/Rakos configuration is available on ESET’s Github: <a href="https://github.com/eset/malware-ioc/tree/master/rakos" target="_blank">https://github.com/eset/malware-ioc/tree/master/rakos</a>.</p>
<p>Following this, it starts a <strong>local</strong> HTTP service available at<span style="font-family: 'courier new', courier, monospace;"> http://127.0.0.1:61314</span>. There are two reasons why this is installed: the first is as a cunning method for the future versions of the bot to kill the running instances regardless of their name by requesting <span style="font-family: 'courier new', courier, monospace;">http://127.0.0.1:61314/et</span>; second, it tries to parse a URL query for parameters “ip”, “u”, “p” by requesting <span style="font-family: 'courier new', courier, monospace;">http://127.0.0.1:61314/ex.</span> The purpose of this /<span style="font-family: 'courier new', courier, monospace;">ex</span> HTTP resource is still unclear at the time of writing and it seems not to be referenced elsewhere in the code.</p>

<p>The main feature of this bot is its scanning of the SSH service on various IP addresses, which are obtained from the C&amp;C server by asking for the list located at <span style="font-family: 'courier new', courier, monospace;">https://{C&amp;C}/scan</span>. This list seems to be modified frequently. The previous versions of the trojan also scanned for the SMTP service, but the attackers have disabled  this feature in current build. We speculate that this feature might be under further development together with additional network scanning features.</p>
<p>The main attack is performed as follows: if one of the username:password pairs from the configuration file results in a successful login to one of the target devices connection to target is successful, two commands are run on that newly-accessed victim <span style="font-family: 'courier new', courier, monospace;">(id, uname -m</span>), and other checks are performed and their results reported. Finally the binary checks whether if it is possible to upload to the new victim and does so if the answer is affirmative. We simulated an attack locally with two targets picked, 127.0.0.1 and 127.0.0.100 (originally, the attackers try 200 simultaneous targets every 10 seconds). Suppose the bot fails to connect to the first one which it then marks as FORGET, while the latter one is successful with the <span style="font-family: 'courier new', courier, monospace;">INSTALL</span> notice (a SSH connection was established with the correct shipping:shipping login credentials; also note that the uploaded executable is deleted immediately after execution):</p>
<p><img class="aligncenter size-full wp-image-87055" src="https://web-assets.esetstatic.com/blog/2016/12/1_skaro_logs.png" alt="1_skaro_logs" width="954" height="491" /></p>
<p>Moreover, the backdoor is capable of:</p>
<ul>
<li>updating the configuration file (from <span style="font-family: 'courier new', courier, monospace;">https://{C&amp;C}/upgrade/vars.yaml</span>)</li>
<li>upgrading itself</li>
</ul>
<p>No unequivocally malicious activities that might be expected, like DDoS attacks or spam spreading (yet!), are implemented. However, sending back the IP address, username and password allows the attackers to do anything they want with the machine afterwards. Together with the foul language used in the code, we think it is unlikely that this is just an invasive but innocent experiment or an unfortunate exercise in academic research.</p>

<h2>Mitigation and cleanup</h2>
<p>The trojan isn’t able to maintain persistence after the system is rebooted. Instead, available devices may be compromised repeatedly.</p>
<p>The steps needed to clean up after a compromise are as follows:</p>
<ul>
<li>connect to your device using SSH/Telnet,</li>
<li>look for a process named .<span style="font-family: 'courier new', courier, monospace;">javaxxx</span>,</li>
<li>run commands like <span style="font-family: 'courier new', courier, monospace;">netstat</span> or <span style="font-family: 'courier new', courier, monospace;">lsof</span> with -n switch to confirm that it is responsible for unwanted connections,</li>
<li>(voluntarily) collect forensic evidence by dumping the memory space of the corresponding process (with gcore for example). One could also recover the deleted sample from /<span style="font-family: 'courier new', courier, monospace;">proc</span> with <span style="font-family: 'courier new', courier, monospace;">cp /proc/{pid}/exe {output_file}</span></li>
<li>the process with the <span style="font-family: 'courier new', courier, monospace;">-KILL</span></li>
</ul>
<p>Needless to say that victims have to secure their SSH credentials and have to do that after every factory reset.</p>
<p>We also prepared a plugin for Volatility Framework called <span style="font-family: 'courier new', courier, monospace;">vf_ioc_linux_rakos_a.py</span> that would detect indicators of compromise if a whole memory dump supported by this framework is acquired. Moreover, it extracts from the malicious process space data such as configuration or information sent to the C&amp;C. It is available here: <a href="https://github.com/eset/malware-ioc/tree/master/rakos" target="_blank">https://github.com/eset/malware-ioc/tree/master/rakos</a></p>
<h2>Conclusion</h2>
<p>We have presented here another example of a Linux backdoor spreading through a well-known channel. It seems worthwhile for attackers to write new pieces of malicious software to misuse loopholes in the current state of network security. Our advice is this: Don’t build walls around your devices from sticks and straws, but from bricks and stones. The internet is a windy place.</p>
