    <h1 class="page-headline">TeleBots are back: Supply-chain attacks against Ukraine</h1>    <p class="sub-title">This blogpost reveals many details about the Diskcoder.C (aka ExPetr or NotPetya) outbreak and related information about previously unpublished attacks.</p>

    <div class="article-authors d-flex flex-wrap">  <div class="article-author d-flex">  <a href="/blog/en/our-experts/anton-cherepanov/" title="Anton Cherepanov">   <picture>  <source srcset="https://web-assets.esetstatic.com/tn/-x45/blog/2020/03/Anton_Cherepanov.jpg" media="(max-width: 768px)" />   <img class="author-image me-3"  src="https://web-assets.esetstatic.com/tn/-x45/blog/2020/03/Anton_Cherepanov.jpg" alt="Anton Cherepanov"  /></picture>  </a>  <div class="author-text"><p><a href="/blog/en/our-experts/anton-cherepanov/" title="Anton Cherepanov"><b>Anton Cherepanov</b></a></p></div></div> </div>

        <span>30 Jun 2017</span>
        <span class="d-none d-lg-inline">&nbsp;&bull;&nbsp;</span>
        <span class="d-inline d-lg-none">, </span>
        <span>15 min. read</span>
    </p>


</div>

                    <div class="article-body">
    <p>The latest <a href="https://www.welivesecurity.com/2017/06/27/new-ransomware-attack-hits-ukraine/">Petya-like outbreak</a> has gathered a lot of attention from the media. However, it should be noted that this was not an isolated incident: this is the latest in a series of similar attacks in Ukraine. This blogpost reveals many details about the Diskcoder.C (aka ExPetr, PetrWrap, Petya, or NotPetya) outbreak and related information about previously unpublished attacks.</p>
<p><div class="caption center"><img class="wp-image-96329 " src="https://web-assets.esetstatic.com/blog/2017/06/1.png" alt="TeleBots" width="1088" height="489" /><p class="caption-text">Figure 1 - The timeline of supply-chain attacks in Ukraine.</p></div></p>
<h1>TeleBots</h1>
<p>In December 2016 we published two detailed blogposts about disruptive attacks conducted by the group ESET researchers call TeleBots, specifically about attacks against <a href="https://www.welivesecurity.com/2016/12/13/rise-telebots-analyzing-disruptive-killdisk-attacks/" target="_blank" rel="noopener noreferrer">financial institutions</a> and a <a href="https://www.welivesecurity.com/2017/01/05/killdisk-now-targeting-linux-demands-250k-ransom-cant-decrypt/" target="_blank" rel="noopener noreferrer">Linux version</a> of the KillDisk malware used by this group. The group mounted cyberattacks against various computer systems in Ukraine; systems that can be defined as <a href="https://en.wikipedia.org/wiki/Critical_infrastructure" target="_blank" rel="noopener noreferrer">critical infrastructure</a>. Moreover, this group has connections with the infamous BlackEnergy group that was responsible for the <a href="https://www.welivesecurity.com/2016/01/03/blackenergy-sshbeardoor-details-2015-attacks-ukrainian-news-media-electric-industry/" target="_blank" rel="noopener noreferrer">December 2015 power outages</a> in Ukraine.</p>
<p>In the final stage of its attacks, the TeleBots group always used the KillDisk malware to overwrite files with specific file extensions on the victims’ disks. Putting the cart before the horse: collecting ransom money was never the top priority for the TeleBots group. The KillDisk malware used in the first wave of December 2016 attacks, instead of encrypting, simply overwrites targeted files. Further, it did not provide contact information for communicating with the attacker; it just displayed an image from the Mr. Robot TV show.</p>
<p><div class="caption center"><img class="wp-image-96330" src="https://web-assets.esetstatic.com/blog/2017/06/2.png" alt="TeleBots" width="828" height="621" /><p class="caption-text">Figure 2 – The picture displayed by KillDisk malware in the first wave of December 2016 attacks.</p></div></p>
<p>In the second wave of attacks, the cybersaboteurs behind the KillDisk malware added contact information to the malware, so it would look like a typical ransomware attack. However, the attackers asked for an extraordinary number of bitcoins: 222 BTC (about $250,000 at that time). This might indicate that they were not interested in bitcoins, but their actual aim was to cause damage to attacked companies.</p>
<p><div class="caption center"><img class="size-full wp-image-96331" src="https://web-assets.esetstatic.com/blog/2017/06/3.png" alt="TeleBots" width="1024" height="232" /><p class="caption-text">Figure 3 - The ransom demand displayed by KillDisk in the second wave of December 2016 attacks.</p></div></p>
<p>In 2017, the TeleBots group didn’t stop their cyberattacks; in fact, they became more sophisticated. In the period between January and March 2017 the TeleBots attackers compromised a software company in Ukraine (not related to M.E. Doc), and, using VPN tunnels from there, gained access to the internal networks of several financial institutions.</p>
<p>During that attack, those behind TeleBots enhanced their arsenal with two pieces of ransomware and updated versions of tools mentioned in the previously-linked blogposts.</p>
<p>The first backdoor that the TeleBots group relied heavily on was Python/TeleBot.A, which was rewritten from Python in the Rust programming language. The functionality remains the same: it is a standard backdoor that uses the Telegram Bot API in order to receive commands from, and send responses to, the malware operator.</p>
<p><div class="caption center"><img class="size-full wp-image-96332" src="https://web-assets.esetstatic.com/blog/2017/06/4.png" alt="TeleBots" width="855" height="347" /><p class="caption-text">Figure 4 - Disassembled code of the Win32/TeleBot.AB trojan.</p></div></p>
<p>The second backdoor, which was written in VBS and packaged using the <span style="font-family: 'courier new', courier, monospace;">script2exe</span> program, was heavily obfuscated but the functionality remained the same as in previous attacks.</p>
<p><div class="caption center"><img class="size-full wp-image-96333" src="https://web-assets.esetstatic.com/blog/2017/06/5.png" alt="" width="1015" height="429" /><p class="caption-text">Figure 5 - The obfuscated version of the VBS backdoor.</p></div></p>
<p>This time the VBS backdoor used the C&amp;C server at 130.185.250[.]171. To make connections less suspicious for those who check firewall logs, the attackers registered the domain <strong>transfinance.com[.]ua</strong> and hosted it on that IP address. As is evident from Figure 6 this server was also running the Tor relay named <span style="font-family: 'courier new', courier, monospace;">severalwdadwajunior<span style="font-family: georgia, palatino, serif;">.</span></span></p>
<p><div class="caption center"><img class=" wp-image-96334" src="https://web-assets.esetstatic.com/blog/2017/06/6.png" alt="" width="861" height="623" /><p class="caption-text">Figure 6 - Information about Tor relay run by the TeleBots group.</p></div></p>
<p>In addition, the attacker used the following tools:</p>
<ul>
<li>CredRaptor (password stealer)</li>
<li>Plainpwd (modified Mimikatz used for recovering Windows credentials from memory)</li>
<li>SysInternals’ PsExec (used for lateral movement)</li>
</ul>
<p>As mentioned above, in the final stage of their attacks, the TeleBots attackers pushed ransomware using stolen Windows credentials and SysInternals’ PsExec. This new ransomware was detected by ESET products as Win32/Filecoder.NKH. Once executed, this ransomware encrypts all files (except files located in the C:\Windows directory) using AES-128 and RSA-1024 algorithms. The malware adds the <span style="font-family: 'courier new', courier, monospace;">.xcrypted</span> file extension to already-encrypted files.</p>
<p>When encryption is done, this filecoder malware creates a text file !readme.txt with the following content:</p>
<p><em>Please contact us: openy0urm1nd@protonmail.ch</em></p>
<p>In addition to Windows malware, the TeleBots group used Linux ransomware on non-Windows servers. This ransomware is detected by ESET products as Python/Filecoder.R and, predictably, it is written in the Python programming language. This time attackers execute third-party utilities such as <span style="font-family: 'courier new', courier, monospace;">openssl</span> in order to encrypt files. The encryption is done using the RSA-2048 and AES-256 algorithms.</p>
<p><div class="caption center"><img class=" wp-image-96335" src="https://web-assets.esetstatic.com/blog/2017/06/7.png" alt="" width="849" height="418" /><p class="caption-text">Figure 7 - Python code of Linux ransomware Python/Filecoder.R used by the TeleBots group.</p></div></p>
<p>In the code of Python script, attackers left their comment which had following text:</p>
<p><em>feedback: openy0urm1nd[@]protonmail.ch</em></p>
<h1>Win32/Filecoder.AESNI.C</h1>
<p>On 18 May 2017, we noticed <a href="https://www.welivesecurity.com/2017/05/23/xdata-ransomware-making-rounds-amid-global-wannacryptor-scare/" target="_blank" rel="noopener noreferrer">new activity</a> on the part of another ransomware family Win32/Filecoder.AESNI.C (also referred to as XData).</p>
<p>This ransomware was spread mostly in Ukraine, because of an interesting initial vector. According to our LiveGrid® telemetry, the malware was created right after execution of the M.E.Doc software that is widely used by accounting personnel in Ukraine.</p>
<p>The Win32/Filecoder.AESNI.C ransomware had a spreading mechanism that allowed it to perform lateral movement automatically, inside a compromised company LAN. Specifically, the malware had an embedded Mimikatz DLL that it used to extract Windows account credentials from the memory of a compromised PC. With these credentials, the malware started to spread inside its host network using SysInternals’ PsExec utility.</p>
<p>It seems that the attackers either did not reach their goal on that occasion, or it was the test before a more effective strike. The attackers posted master decryption keys on the <a href="https://www.bleepingcomputer.com/news/security/aes-ni-ransomware-dev-releases-decryption-keys-amid-fears-of-being-framed-for-xdata-outbreak/" target="_blank" rel="noopener noreferrer">BleepingComputer forum</a>, along with the assertion that this was done because the original author claimed that the source was stolen and used in the Ukraine incident.</p>
<p>ESET <a href="https://www.welivesecurity.com/2017/05/31/eset-releases-new-decryption-tool-aes-ni-ransomware/" target="_blank" rel="noopener noreferrer">published a decryption tool</a> for Win32/Filecoder.AESNI ransomware, and this event didn’t gain much media attention.</p>
<h1>Diskcoder.C (aka Petya-like) outbreak</h1>
<p>What did gain a lot of media attention, however, was the <a href="https://www.welivesecurity.com/2017/06/27/new-ransomware-attack-hits-ukraine/">Petya-like outbreak</a> of 27 June, 2017, because it successfully compromised a lot of systems in critical infrastructure and other businesses in Ukraine, and further afield.</p>
<p>The malware in this attack has the ability to replace the Master Boot Record (MBR) with its own malicious code. This code was borrowed from <a href="http://virusradar.com/en/Win32_Diskcoder.Petya.B/description" target="_blank" rel="noopener noreferrer">Win32/Diskcoder.Petya ransomware</a>. That’s why some other malware researchers have named this threat as ExPetr, PetrWrap, Petya, or NotPetya. However, unlike the original Petya ransomware, Diskcoder.C's authors modified the MBR code in such a way that recovery won’t be possible. Specifically, the attacker cannot provide a decryption key and the decryption key cannot be typed in the ransom screen, because the generated key contains non-acceptable characters.</p>
<p>Visually this MBR part of Diskcoder.C looks like a slightly modified version of Petya: at first it displays a message that impersonates CHKDSK, Microsoft's disk checking utility. During the faux CHKDISK scan Diskcoder.C actually encrypts the data.</p>
<p><div class="caption center"><img class="size-full wp-image-96336" src="https://web-assets.esetstatic.com/blog/2017/06/8.png" alt="" width="695" height="246" /><p class="caption-text">Figure 8 - Fake CHKDSK message displayed by Diskcoder.C.</p></div></p>
<p>When encryption is complete, the MBR code displays the next message with payment instructions, but as noted before this information is useless.</p>
<p><div class="caption center"><img class="size-full wp-image-96337" src="https://web-assets.esetstatic.com/blog/2017/06/9.png" alt="" width="741" height="456" /><p class="caption-text">Figure 9 - Diskcoder.C message with payment instructions.</p></div></p>
<p>The remainder of the code, other than the borrowed MBR, was implemented by the authors themselves. This includes file encryption that can be used as a complement to the disk-encrypting MBR. For file encryption, the malware uses the AES-128 and RSA-2048 algorithms. It should be noted that the authors made mistakes that make decryption of files less possible. Specifically, the malware encrypts only the first 1MB of data and it does not write any header or footer, only raw encrypted data and does not rename encrypted files, so it’s hard to say which files are encrypted and which are not. In addition to that, files that are larger than 1MB after encryption do not contain padding, so there is no way to verify the key.</p>
<p>Interestingly, the list of target file extensions is not identical but is very similar to the file extensions list from the KillDisk malware used in the <a href="https://www.welivesecurity.com/2016/12/13/rise-telebots-analyzing-disruptive-killdisk-attacks/" target="_blank" rel="noopener noreferrer">December 2016 attacks</a>.</p>
<p><div class="caption center"><img class="size-full wp-image-96338" src="https://web-assets.esetstatic.com/blog/2017/06/10.png" alt="" width="731" height="108" /><p class="caption-text">Figure 10 - List of target file extensions from Diskcoder.C.</p></div></p>
<p>Once the malware is executed it attempts to spread using the infamous EternalBlue exploit, leveraging the DoublePulsar kernel-mode backdoor. Exactly the same method was used in the WannaCryptor.D ransomware. Diskcoder.C also adopted the method from the Win32/Filecoder.AESNI.C (aka XData) ransomware: it uses a lightweight version of Mimikatz to obtain credentials and then executes the malware using SysInternals’ PsExec on other machines on the LAN. In addition to that, the attackers implemented a third method of spreading using a WMI mechanism.</p>
<p>All three of these methods have been used to spread malware inside LANs. Unlike the infamous <a href="https://www.welivesecurity.com/2017/05/15/wannacryptor-key-questions-answered/" target="_blank" rel="noopener noreferrer">WannaCryptor malware</a>, the EternalBlue exploit is used by Diskcoder.C only against computers within the local network address space.</p>
<p>Why are there infections in other countries than Ukraine? Our investigation revealed that affected companies in other countries had VPN connections to their branches, or to business partners, in Ukraine.</p>
<h1>Initial infection vector</h1>
<p>Both Diskcoder.C and Win32/Filecoder.AESNI.C used a supply-chain attack as the initial infection vector. These malware families were spread using Ukrainian accounting software called M.E.Doc.</p>
<p>There are several options for how this attack can be implemented. The M.E.Doc has an internal messaging and document exchange system so attackers could send spearphishing messages to victims. User interaction is required in order to execute something malicious in this way. Thus, social engineering techniques would be involved. Since Win32/Filecoder.AESNI.C didn’t spread so widely, we mistakenly assumed that these techniques were used in this case.</p>
<p>However, the subsequent Diskcoder.C outbreak suggests that the attackers had access to the update server of the legitimate software. Using access to this server, attackers pushed a malicious update that was applied automatically without user interaction. That’s why so many systems in Ukraine were affected by this attack. However, it seems like the malware authors underestimated the spreading capabilities of Diskcoder.C.</p>
<p>ESET researchers found evidence that supports this theory. Specifically, we identified a malicious PHP backdoor that was deployed under <span style="font-family: 'courier new', courier, monospace;">medoc_online.php</span> in one of the FTP directories on M.E.Doc's server. This backdoor was accessible from HTTP; however, it was encrypted, so the attacker would have to have the password in order to use it.</p>
<p><div class="caption center"><img class="size-full wp-image-96339" src="https://web-assets.esetstatic.com/blog/2017/06/11.png" alt="" width="865" height="247" /><p class="caption-text">Figure 11 - Listing of FTP directory containing the PHP backdoor.</p></div></p>
<p>We should say that there are signs that suggest that Diskcoder.C and Win32/Filecoder.AESNI.C were not the only malware families that were deployed using that infection vector. We can speculate that these malicious updates were deployed in a stealthy way to computer networks that belong to high-value targets.</p>
<p>One such malware that was deployed via this possible compromised M.E.Doc update server mechanism was the VBS backdoor used by the TeleBots group. This time the attacker again used a financially-themed domain name: <strong>bankstat.kiev[.]ua</strong>.</p>
<p>On the day of the Diskcoder.C outbreak, the A-record of this domain was changed to 10.0.0.1</p>
<h1>Conclusions</h1>
<p>The TeleBots group continues to evolve in order to conduct disruptive attacks against Ukraine. Instead of spearphishing emails with documents containing malicious macros, they used a more sophisticated scheme known as a supply-chain attack. Prior to the outbreak, the Telebots group targeted mainly the financial sector. The latest outbreak was directed against businesses in Ukraine, but they apparently underestimated the malware’ spreading capabilities. That’s why the malware went out of control.</p>
