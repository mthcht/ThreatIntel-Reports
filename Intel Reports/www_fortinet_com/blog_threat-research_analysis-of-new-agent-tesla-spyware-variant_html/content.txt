<div class="cmp cmp-title aem-GridColumn aem-GridColumn--default--12">
<h2>Analysis of filename.exe</h2>

    

</div>
<div class="cmp cmp-text aem-GridColumn aem-GridColumn--default--12">
  <p>When “filename.exe” starts, like most other malware it creates a suspended child process with the same name to protect itself. It then extracts a new PE file from its resource to overwrite the child process memory. Afterwards, it resumes the execution of the child process. This is when it executes the code of that new PE file, which is the main part of this malware.</p>


</div>
<div class="cmp cmp-image aem-GridColumn aem-GridColumn--default--12">

    
        <noscript data-cmp-image="{&#34;smartImages&#34;:[],&#34;smartSizes&#34;:[],&#34;lazyEnabled&#34;:true}">
            
            <img src="/blog/threat-research/analysis-of-new-agent-tesla-spyware-variant/_jcr_content/root/responsivegrid/image_992123924.img.png/1522869970446/analysis-of-new-agent-tesla-spyware-image6.png" class="custom"/>
        </noscript>
    
    
    <!--<div class="enlarge-btn" data-sly-test=""><div class="gg-maximize-alt"></div> <div>Click to Enlarge</div></div>-->
    <span class="cmp-image--title">Figure 6. Checking to see if the module mscorjit.dll is loaded</span>


    
</div>
<div class="cmp cmp-text aem-GridColumn aem-GridColumn--default--12">
  <p>Let’s go on to the analysis of the child process. It first checks to see if the environment value of &quot;Cor_Enable_Profiling&quot; is set to 1, and if the modules &quot;mscorjit.dll&quot; and &quot;clrjit.dll&quot; have been loaded (see figure 6). If one of these checks is true, it exits the process without doing anything.  So far, I have no idea what the purpose of doing that is, but it is likely anti-something.</p>
<p>If the process doesn’t exit, it loads a named resource. The resource name is &quot;__&quot;, which is a string decrypted from a local variable.  Afterwards, by calling the API functions “FindResource” and “LoadResource”, it can read the resource data to the process memory. Figure 7 shows the “__” resource in CFF Explorer. For sure, the data is encrypted.</p>


</div>
<div class="cmp cmp-image aem-GridColumn aem-GridColumn--default--12">

    
        <noscript data-cmp-image="{&#34;smartImages&#34;:[],&#34;smartSizes&#34;:[],&#34;lazyEnabled&#34;:true}">

        </noscript>
    
    
    <!--<div class="enlarge-btn" data-sly-test=""><div class="gg-maximize-alt"></div> <div>Click to Enlarge</div></div>-->
    <span class="cmp-image--title">Figure 7. Encrypted “__” resource</span>


    
</div>
<div class="cmp cmp-text aem-GridColumn aem-GridColumn--default--12">
  <p>By decrypting the “__” data, we obtain another PE file, which is a .Net framework program. This is to be loaded into the child process memory. It reads sections of the .Net program into memory according to the PE file headers, imports APIs defined in the import table for .Net programs, <a name="OLE_LINK52" id="OLE_LINK52"></a><a name="OLE_LINK51" id="OLE_LINK51"></a>relocates offset of the function “_CorExeMain”, as well as builds the .Net framework running environment by calling several APIs. Finally, it jumps to the entry point of the .Net program where it later jumps to “_CorExeMain” – which is the entry point of all .Net programs – to execute this .Net program. You can see in figure 8 how it jumps to the “_CorExeMain” function.</p>


</div>

  <p>In order to further analyze the .Net program, I dumped it from the child process memory into a local file. This allowed me to launch it independently rather than running it within the child process. This also allowed me to load it into the .Net program analysis tools to analyze it.</p>


</div>
<div class="cmp cmp-title aem-GridColumn aem-GridColumn--default--12">
<h2>Deep analysis of the .Net program</h2>

    

</div>
<div class="cmp cmp-text aem-GridColumn aem-GridColumn--default--12">
  <p>The dumped file has an incorrect PE header. I manually repaired it so that it can be executed, debugged, and parsed by .Net program analysis tools. Figure 8 shows the main function of the .Net program in an analysis tool.</p>


</div>
<div class="cmp cmp-image aem-GridColumn aem-GridColumn--default--12">

    
        <noscript data-cmp-image="{&#34;smartImages&#34;:[],&#34;smartSizes&#34;:[],&#34;lazyEnabled&#34;:true}">

        </noscript>

    <span class="cmp-image--title">Figure 9. The main function of the .Net program</span>


    
</div>
<div class="cmp cmp-text aem-GridColumn aem-GridColumn--default--12">
  <p>As you may have already noticed, it uses some kind of code <a name="OLE_LINK7" id="OLE_LINK7"></a><a name="OLE_LINK4" id="OLE_LINK4"></a>obfuscation technique to increase the difficulty of code analysis. In the following parts, you may see that some of the names of method, class, variable, etc. have been modified to make them <a name="OLE_LINK8" id="OLE_LINK8"></a>understandable.</p>
<p>All the constant strings in the .Net program are encoded and saved within a large buffer, and every string is assigned an index. Whenever it needs to use the string, it calls a function with its string index to get the string. If the string is encoded, it throws the encoded string into another function to get it decoded. In figure 10 we can see that it reads the huge string into the big buffer—“Pkky9noglfauhKN1Fjq.QOZ4uWBaWw”.</p>
<p>Here is an example: “<a name="OLE_LINK26" id="OLE_LINK26"></a><a name="OLE_LINK25" id="OLE_LINK25"></a><a name="OLE_LINK24" id="OLE_LINK24"></a>XtL6rF5GoidQVxdCxi.R6ybT342I(<a name="OLE_LINK23" id="OLE_LINK23"></a><a name="OLE_LINK22" id="OLE_LINK22"></a><a name="OLE_LINK21" id="OLE_LINK21"></a>Pkky9noglfauhKN1Fjq.Y3LpEpC6nY(3172));”</p>
<p>“3172” is the string index.</p>
<p>The “Pkky9noglfauhKN1Fjq.Y3LpEpC6nY” function picks up the string of index 3172 from that large buffer. In this case, it’s &quot;<a name="OLE_LINK55" id="OLE_LINK55"></a><a name="OLE_LINK30" id="OLE_LINK30"></a><a name="OLE_LINK29" id="OLE_LINK29"></a>hyNN5z+7qAsS695lDXLuHg==&quot;.</p>
<p>“XtL6rF5GoidQVxdCxi.R6ybT342I” is the decoding function. After decoding, we get the string “True\x00\x00\x00\x00\x00\x00\x00\x00”.  i.e. “True”.</p>


</div>
<div class="cmp cmp-image aem-GridColumn aem-GridColumn--default--12">

</div>
<div class="cmp cmp-text aem-GridColumn aem-GridColumn--default--12">
  <p>When the main function is called, it first pauses 15 seconds by calling “Thread::Sleep()” function. This allows it to potentially bypass sandbox detection.</p>
<p>As my analysis in the <a name="OLE_LINK69" id="OLE_LINK69"></a><a name="OLE_LINK68" id="OLE_LINK68"></a><a href="https://www.fortinet.com/blog/threat-research/in-depth-analysis-of-net-malware-javaupdtr.html">previous blog</a> showed, Agent Tesla is a spyware. It monitors and collects the victim’s keyboard inputs, system clipboard, screen shots of the victim’s screen, as well as collects credentials of a variety of installed software. To do that it creates many different threads and timer functions in the main function. So far, through my quick analysis, this version is similar to the older one. As I did not find much change, I won’t talk about it more here but simply refer you to the previous blog analysis.</p>
<p>However, the way of submitting data to the C&amp;C server has changed. It used to use HTTP POST to send the collected data. In this variant, it uses SMTPS <a name="OLE_LINK76" id="OLE_LINK76"></a><a name="OLE_LINK75" id="OLE_LINK75"></a><a name="OLE_LINK74" id="OLE_LINK74"></a>to send the collected data to the attacker’s email box.</p>
<p>Based on my analysis, the commands used in the SMTP method include “Passwords Recovered”, “Screen Capture”, and “Keystrokes”, etc.  The commands are identified within the email’s “Subject” field.  For example:</p>
<p><i>“System user name</i>/<i>computer name</i> Screen Capture From: <i>victim’s IP”</i></p>
<p>Here’s an example to show you how it sends the collected credential data to the attacker’s email address. Figure 10 shows the email content that will be sent out with my PC information along with the collected credentials. It enables an SSL function and uses TCP port 587. The “Body” field is the collected data in HTML format. The “Subject” field contains the command “Passwords Recovered&quot; which tells the recipient that this email contains credentials.</p>


</div>

<h2>Daemon program</h2>

    

</div>
<div class="cmp cmp-text aem-GridColumn aem-GridColumn--default--12">
  <p>It also drops a daemon program from the .Net program’s resource named “Player” into the “%temp%” folder and run it up to protect “filename.exe” from being killed. </p>


</div>

<div class="cmp cmp-text aem-GridColumn aem-GridColumn--default--12">
  <p>The daemon program’s name is made up of three random letters, as you can see in figure 15. It’s also a .Net program and its main purpose is very clear and simple. Figure 16 shows the daemon program’s entire code in an analysis tool. </p>
<p>You can see that the main function receives a command line argument (for this sample, it’s the full path to “filename.exe”.) and saves it to a string variable called “filePath”. It creates a thread, and in the thread function it checks to see if the file “filename.exe” is running in each 900 millisecond. It runs it again whenever the “filename.exe” is killed.</p>
