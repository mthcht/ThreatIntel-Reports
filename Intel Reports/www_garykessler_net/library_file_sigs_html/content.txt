</h4>
<blockquote>
<p>
This table of file signatures (aka "magic numbers") is a continuing work-in-progress. I had found little information on this in a single place, with the exception of the table in <i>Forensic Computing: A Practitioner's Guide</i> by T. Sammes & B. Jenkinson (Springer, 2000); that was my inspiration to start this list in 2002. See also Wikipedia's <a href="https://en.wikipedia.org/wiki/List_of_file_signatures" target="_blank"> List of file signatures</a>. Comments, additions, and queries can be sent to Gary Kessler at <a href="mailto:gck@garykessler.net"> gck@garykessler.net</a>.</p>
<p>
This list is not exhaustive although I add new files as I find them or someone contributes signatures. Interpret the table as a one-way function: the magic number generally indicates the file type whereas the file type does not always have the given magic number. If you want to know to what a particular file extension refers, check out <a href="https://file-extension.net/seeker/" target="_blank"> File Extension Seeker: Metasearch engine for file extensions</a>.</p>

<p>
Some other useful information:</p>
<ul>
<li><p>My <a href="../software/index.html#filesigs" target="_blank"> software utility</a> page contains a custom signature file based upon this list, for use with FTK, Scalpel, Simple Carver, Simple Carver Lite, and TrID. There is also a raw CSV file and JSON file of signatures.</p></li>
<li><p>Tim Coakley's <a href="https://www.filesig.co.uk/" target="_blank"> Filesig.co.uk</a> site, with Filesig Manager and Simple Carver. Also, see Tim's <a href="http://www.filesig.co.uk/sqlitedatabasecatalog/" target="_blank"> SQLite Database Catalog</a> page, "a repository of information used to identify specific SQLite databases and properties for research purposes."</p></li>
<li><p>Marco Pontello's <a href="http://mark0.net/soft-trid-e.html" target="_blank"> TrID - File Identifier</a> utility designed to identify file types from their binary signatures.</p></li>
<li><p>The National Archives' <a href="https://apps.nationalarchives.gov.uk/PRONOM/Default.aspx" target="_blank">PRONOM</a> site provides on-line information about data file formats and their supporting software products, as well as their multi-platform <a href="https://www.nationalarchives.gov.uk/information-management/manage-information/preserving-digital-records/droid/" target="_blank">DROID (Digital Record Object Identification)</a> software.</p></li>
<li><p>Additional details on graphics file formats can be found at <a href="https://www.dcs.ed.ac.uk/home/mxr/gfx/2d-hi.html" target="_blank"> The Graphics File Formats Page</a> and the <a href="https://www.digitalpreservation.gov/formats/fdd/still_fdd.shtml" target="_blank"> Sustainability of Digital Formats Planning for Library of Congress Collections</a> site.</p></li>
<li><p>Additional details on audio and video file formats can be found at the <a href="https://www.digitalpreservation.gov/formats/fdd/browse_list.shtml" target="_blank"> Sustainability of Digital Formats Planning for Library of Congress Collections</a> site.</p></li>
</ul>

<p>
If you are using a Linux/MacOS/Unix system, you can use the <font face=Courier><a href="https://en.wikipedia.org/wiki/File_%28command%29" target="_blank">file</a></font> command to determine the file type based upon the file signature, per the system's <i>magic</i> file.</p>
<p>
And, one last and final item &#151; if you are searching for network traffic in raw binary files (e.g., RAM or unallocated space), see <a href="netsig.html" target="_blank"> Hints About Looking for Network Packet Fragments</a>.</p>

<blockquote>
<b>NOTES on JPEG file headers:</b> The proper JPEG header is the two-byte sequence, 0xFF-D8, aka <i>Start of Image (SOI)</i> marker.<br>
JPEG files end with the two-byte sequence, 0xFF-D9, aka <i>End of Image (EOI)</i> marker.<br><br>
Between the SOI and EOI, JPEG files are composed of <i>segments</i>. Segments start with a two-byte <i>Segment Tag</i> followed by a<br>
two-byte <i>Segment Length</i> field and then a zero-terminated string identifier (i.e., a character string followed by a 0x00), as<br>
shown below with the JFIF, Exif, and SPIFF segments.<br><br>
Segment Tags of the form 0x-FF-Ex (where x = 0..F) are referred to as APP0-APP15, and contain application-specific information. The<br>
most commonly seen APP segments at the beginning of a JPEG file are APP0 and APP1 although others are also seen. Some additional<br>
tags are shown below:<br><br>

<ul>
<!--<li>0xFF-D8-FF-DB &#151; Samsung D807 JPEG file</a>.</li>-->
<li>0xFF-D8-FF-E0 &#151; <a href="http://www.faqs.org/faqs/jpeg-faq/part1/section-15.html" target="_blank"> Standard JPEG/JFIF file</a>, as shown below.</li>
<li>0xFF-D8-FF-E1 &#151; Standard JPEG file with Exif metadata, as shown below.</li>
<li>0xFF-D8-FF-E2 &#151; Canon Camera Image File Format (CIFF) JPEG file (formerly used by some EOS and Powershot cameras).</li>
<!--<li>0xFF-D8-FF-E3 &#151; Samsung D500 JPEG file</li>-->

<li>0xFF-D8-FF-E8 &#151; <a href="http://www.digitalpreservation.gov/formats/fdd/fdd000019.shtml" target="_blank"> Still Picture Interchange File Format (SPIFF)</a>, as shown below.</li>
</ul>
