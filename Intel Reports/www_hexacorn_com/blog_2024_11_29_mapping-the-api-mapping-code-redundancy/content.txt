		<h1 class="entry-title">Mapping the API mapping/code redundancy</h1>

				<div class="entry-meta">
			<span class="sep">Posted on </span><a href="https://www.hexacorn.com/blog/2024/11/29/mapping-the-api-mapping-code-redundancy/" title="7:23 pm" rel="bookmark"><time class="entry-date" datetime="2024-11-29T19:23:33+00:00">2024-11-29</time></a><span class="by-author"> <span class="sep"> by </span> <span class="author vcard"><a class="url fn n" href="https://www.hexacorn.com/blog/author/adam/" title="View all posts by adam" rel="author">adam</a></span></span>		</div><!-- .entry-meta -->
			</header><!-- .entry-header -->

	<div class="entry-content">
		
<p>In my <a href="https://www.hexacorn.com/blog/2024/11/28/windows-storage-lol/" data-type="post" data-id="9685">last post</a> I have shown that some of the <em>shell32.dll</em> functions are now mapped to <em>windows.storage.dll</em>. </p>



<p>This sort of API mapping, as well as blatant code redundancy present in many Windows binaries is not new, and we have seen many instances of it over the years:</p>



<ul>
<li>Windows API sets</li>



<li><em>gdi32.dll</em> and <em>gdi32full.dll</em></li>



<li><em>gdi32full.dll</em> and <em>win32u.dll</em></li>



<li><em>combase.dll</em> and <em>ole32.dll</em></li>



<li><em>kernel32.dll</em> and <em>KernelBase.dll</em></li>



<li><em>IEAdvpack.dll</em> and <em>advpack.dll</em></li>



<li><em>crtdll.dll</em>, <em>msvcirt.dll</em>, <em>ucrtbase.dll</em> and their many, many versions over the years</li>



<li><em>ntdll.dll</em> and <em>ntoskrnl.exe</em> (user mode vs. kernel mode mapping)</li>
</ul>



<p>and so on, and so forth.</p>



<p>It is probably not surprising that after that latest discovery it was only natural for me to build a list of APIs (API names) that are shared between many libraries to see if I can discover more interesting bits.</p>



<p>Looking at the list of API names that appear to be shared between at least 2 DLL libraries on the Windows 11 24 H2 build &#8211; <a href="https://hexacorn.com/d/win11_24H2_list_64_shared.txt">win11_24H2_list_64_shared.txt</a> &#8211; one can immediately see a lot of interesting findings:</p>



<ul>
<li>sqlite functions are exported by <em>SearchIndexerCore.dll</em>, <em>StateRepository.Core.dll</em>, <em>winsqlite3.dll</em></li>



<li>apart from <em>kernel32.dll</em> and <em>KernelBase.dll</em> there is now also <em>kernel.appcore.dll</em></li>



<li>code base of <em>tcblaunch.exe</em> and <em>winload.exe</em> seems to be overlapping a lot</li>



<li><em>edgehtml.dll</em> replaces <em>mshtml.dll</em></li>
</ul>



<p>Unfortunately, I have not seen anything similar to <em>ShellExec_RunDLL</em> &#8211; a discovery that kicked off this research 🙁</p>
