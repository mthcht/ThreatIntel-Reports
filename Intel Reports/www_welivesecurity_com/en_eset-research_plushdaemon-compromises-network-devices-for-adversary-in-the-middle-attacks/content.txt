                    <div class="article-body">
    <p>ESET researchers provide insights into how PlushDaemon performs adversary-in-the-middle attacks using a previously undocumented network implant that we have named EdgeStepper, which redirects all DNS queries to an external, malicious hijacking node, effectively rerouting the traffic from legitimate infrastructure used for software updates to attacker-controlled infrastructure.</p>
<blockquote>
<div><strong>Key points in this blogpost:</strong></div>
<ul>
<li>We analyzed the network implant EdgeStepper to understand how PlushDaemon attackers compromise their targets.</li>
<li>We provide an analysis of LittleDaemon and DaemonicLogistics, two downloaders that deploy the group&rsquo;s signature SlowStepper backdoor on Windows machines.</li>
</ul>
</blockquote>
<h2>PlushDaemon profile</h2>
<p>PlushDaemon is a China-aligned threat actor active since at least 2018 that engages in espionage operations against individuals and entities in China, Taiwan, Hong Kong, Cambodia, South Korea, the United States, and New Zealand. PlushDaemon uses a custom backdoor that we track as SlowStepper, and its main initial access technique is to hijack legitimate updates by redirecting traffic to attacker-controlled servers through a network implant that we call EdgeStepper. Additionally, we have observed the group gaining access via vulnerabilities in web servers, and in 2023 it performed a supply-chain attack.</p>
<h2>Overview</h2>
<p>In 2024, while researching PlushDaemon&rsquo;s clusters of activity (including the <a href="https://www.welivesecurity.com/en/eset-research/plushdaemon-compromises-supply-chain-korean-vpn-service/" target="_blank" rel="noopener">supply-chain compromise of a South Korean VPN service</a>), we noticed that an ELF file submitted to VirusTotal contained two subdomains from PlushDaemon&rsquo;s infrastructure. That file, called <span style="font-family: courier new, courier, monospace;">bioset</span>, was previously hosted on a server likely compromised by multiple threat actors. Note that on the same day of the submission to VirusTotal, a researcher (@James_inthe_box) <a href="https://x.com/James_inthe_box/status/1811143010777977010" target="_blank" rel="noopener">tweeted</a> about an open directory on the server where bioset was hosted, so the sample was probably uploaded to VirusTotal by a researcher who was investigating the contents of the directory.</p>
<p>Internally named <span style="font-family: courier new, courier, monospace;">dns_cheat_v2</span> by its developers &ndash; and codenamed EdgeStepper by us &ndash; <span style="font-family: courier new, courier, monospace;">bioset</span> is PlushDaemon&rsquo;s adversary-in-the-middle tool, which forwards DNS traffic from machines in a targeted network to a malicious DNS node. This allows the attackers to redirect the traffic from software updates to a hijacking node that serves instructions to the legitimate software to download a malicious update.</p>

<figure class="image"><img title="Figure 1. Geographical distribution of victims" src="https://web-assets.esetstatic.com/wls/2025/11-25/plushdaemon/figure-1.png" alt="Figure 1. Geographical distribution of victims" width="" height="" />

<ul>

<li>Cambodia (2025), including a company in the automotive sector and a branch of a Japanese company in the manufacturing sector</li>
</ul>
<h2>Adversary-in-the-middle attack overview</h2>
<p>First, PlushDaemon compromises a network device (for example, a router) to which their target might connect; the compromise is probably achieved by exploiting a vulnerability in the software running on the device or through weak and/or well-known default administrative credentials, enabling the attackers to deploy EdgeStepper (and possibly other tools).</p>
<p>EdgeStepper begins redirecting DNS queries to a malicious DNS node that verifies whether the domain (for example, <span style="font-family: courier new, courier, monospace;">info.pinyin.sogou.com</span> from Sogou Pinyin) in the DNS query message is related to software updates, and if so, it replies with the IP address of the hijacking node. Alternatively, we have also observed that some servers are both the DNS node and the hijacking node; in those cases, the DNS node replies to DNS queries with its own IP address.</p>
<p>Note that since we have closely studied updates for Sogou Pinyin software being hijacked, we will continue to use that as an example from here on out. Many other popular Chinese software titles also have their updates hijacked in similar ways by PlushDaemon via EdgeStepper.</p>
<p>Figure 2 illustrates the first stages of the deployment of PlushDaemon&rsquo;s capabilities.</p>
<figure class="image"><img title="Figure 2. Illustration of the first stages of the attack" src="https://web-assets.esetstatic.com/wls/2025/11-25/plushdaemon/figure-2.png" alt="Figure 2. Illustration of the first stages of the attack" width="" height="" />
<figcaption><em>Figure 2. Illustration of the first stages of the attack</em></figcaption>
</figure>
<p>The updating software communicates via HTTP with the hijacking node instead of Sogou&rsquo;s legitimate infrastructure; the hijacking node replies with instructions to, for example, download a DLL file from <span style="font-family: courier new, courier, monospace;">http://ime.sogou.com/popup_4.2.0.2246.dll</span>, as shown in Figure 3.</p>

<h2>EdgeStepper</h2>
<p>According to the symbols in the binary, EdgeStepper was originally called <span style="font-family: courier new, courier, monospace;">dns_cheat_v2</span>. It was developed in Go using the open-source <a href="https://github.com/gogf/gf" target="_blank" rel="noopener">GoFrame</a> framework, and compiled as an ELF file for MIPS32 processors. It is important to note that it is unlikely that EdgeStepper is the only component deployed on the compromised network device. Unfortunately, we don&rsquo;t have samples of other components in the compromise chain.</p>
<p>EdgeStepper begins by obtaining and decrypting configuration data from <span style="font-family: courier new, courier, monospace;">/etc/bioset.conf</span>. For decryption, it uses AES CBC with the key and IV being the string <span style="font-family: courier new, courier, monospace;">I Love Go Frame!</span>, which is used as the default IV in the implementation by the GoFrame <a href="https://github.com/gogf/gf/blob/master/crypto/gaes/gaes.go" target="_blank" rel="noopener">library</a>.</p>
<p>The decrypted configuration reveals the data shown in Figure&nbsp;6.</p>
<pre class="language-markup"><code>[cheat]
toPort = 1090
host = "ds20221202.dsc.wcsset[.]com"</code></pre>
<p style="text-align: center;"><em>Figure 6. Decrypted configuration</em></p>
<p>The meaning of the parameters is as follows:</p>
<ul>
<li><span style="font-family: courier new, courier, monospace;">toPort</span> specifies the port where EdgeStepper will listen, and</li>
<li><span style="font-family: courier new, courier, monospace;">host</span> specifies the domain that is resolved to obtain the IP address(es) of the DNS node to which the DNS query packets are forwarded.</li>
</ul>
<p>Additionally, there is a configuration block (Figure&nbsp;7) in the EdgeStepper binary, which appears to not be referenced anywhere in the code. The domain in the <span style="font-family: courier new, courier, monospace;">host</span> field is <span style="font-family: courier new, courier, monospace;">test.dsc.wcsset[.]com</span>, which resolved to <span style="font-family: courier new, courier, monospace;">47.242.198[.]250</span>. We observed that IP address from 2021 to 2022 as the source of the malicious update: the hijacking node. At the time of writing, the domain resolves to that IP address.</p>
<figure class="image"><img title="Figure 7. Unused configuration block in EdgeStepper" src="https://web-assets.esetstatic.com/wls/2025/11-25/plushdaemon/figure-7.png" alt="Figure 7. Unused configuration block in EdgeStepper" width="" height="" />
<figcaption><em>Figure 7. Unused configuration block in EdgeStepper</em></figcaption>
</figure>
<p>After loading its configuration, EdgeStepper initializes the <em><a href="#Distributor">Distributor</a> </em>system and the <em><a href="#Ruler">Ruler</a> </em>system.</p>
<h3>Distributor<a id="Distributor"></a></h3>
<p>The distributor resolves the IP address(es) associated with the domain value in the <span style="font-family: courier new, courier, monospace;">host</span> field of the configuration and invokes the Ruler system. The workflow of the distributor is illustrated in Figure&nbsp;8.</p>
<figure class="image"><img title="Figure 8. EdgeStepper workflow" src="https://web-assets.esetstatic.com/wls/2025/11-25/plushdaemon/figure-8.png" alt="Figure 8. EdgeStepper workflow" width="" height="" />
<figcaption><em>Figure 8. EdgeStepper workflow</em></figcaption>
</figure>
<ol>
<li>Via the Ruler system, the distributor redirects traffic on port <span style="font-family: courier new, courier, monospace;">53</span> to port <span style="font-family: courier new, courier, monospace;">1090</span>, establishing itself as a DNS proxy.</li>
<li>When a DNS message is received from a potential victim&rsquo;s device, it checks whether the message is RFC compliant (probably just to verify that the packet is really from the DNS protocol).</li>
<li>Then it forwards the packet to the malicious DNS node.</li>
<li>Finally, it forwards the reply from the DNS node to the device.</li>
</ol>
<h3>Ruler<a id="Ruler"></a></h3>
<p>The Ruler system uses the <a href="https://linux.die.net/man/8/iptables">iptables</a> command to issue new rules, and to remove them when concluding the attack. First, it issues a rule to redirect all UDP traffic on port <span style="font-family: courier new, courier, monospace;">53</span> of the device to the port specified by <span style="font-family: courier new, courier, monospace;">toPort</span> in the configuration:</p>
<p><span style="font-family: courier new, courier, monospace;">iptables -t nat -I PREROUTING -p udp --dport 53 -j REDIRECT --to-port &lt;value_from_toPort&gt;</span></p>
<p>Then it issues a command to accept the packets on that port:</p>
<p><span style="font-family: courier new, courier, monospace;">iptables -t filter -I INPUT -p udp --dport &lt;value_from_toPort&gt; -j ACCEPT</span></p>
<p>When terminating, it removes the previous rules it set up by issuing the commands:</p>
<p><span style="font-family: courier new, courier, monospace;">iptables -t nat -D PREROUTING *</span></p>
<p><span style="font-family: courier new, courier, monospace;">iptables -t filter -D INPUT -p udp &ndash;dport &lt;value_from_toPort&gt; -j ACCEPT</span></p>
<h2>LittleDaemon<a id="LittleDaemon"></a></h2>
<p>LittleDaemon is the first stage deployed on the victim&rsquo;s machine through hijacked updates. We have observed both DLL and executable versions, both of them 32-bit PEs. The main purpose of LittleDaemon is to communicate with the hijacking node to obtain the downloader that we call DaemonicLogistics. LittleDaemon does not establish persistence.</p>
<p>First, it verifies whether the SlowStepper backdoor is running on the system. If not, LittleDaemon downloads DaemonicLogistics by issuing an HTTP GET request to a server (typically, the hijacking node), decrypts it with a combination of XOR operations, and then executes it.</p>
<p>The request can be sent to two legitimate domains (<span style="font-family: courier new, courier, monospace;">ime.sogou.com</span> or <span style="font-family: courier new, courier, monospace;">mobads.baidu.com</span>) or the IP address <span style="font-family: courier new, courier, monospace;">119.136.153.0</span>. The resource path is <span style="font-family: courier new, courier, monospace;">/update/updateInfo.bzp</span> for all three. In the case of the legitimate domains, it&rsquo;s expected that the traffic will be redirected to the hijacking node by EdgeStepper.</p>
<h2>DaemonicLogistics</h2>
<p>DaemonicLogistics is position-independent code downloaded and executed in memory by LittleDaemon. Its main purpose is to download and deploy the SlowStepper implant.</p>
<p>When DaemonicLogistics sends a request to the server (typically, the hijacking node), it replies with an HTTP status code, which DaemonicLogistics interprets as a command, and performs the actions listed in Table 1.</p>

<p>The initial HTTP GET request is sent to:</p>
<p><span style="font-family: courier new, courier, monospace;">ime.sogou.com/update/latest/new_version?tp=2&amp;c=0&amp;s=&lt;OS_ID_number&gt;&amp;mac=&lt;identifier&gt;</span></p>
<p>The meaning of the parameters in the URL are as follows:</p>
<ul>
<li>The values <span style="font-family: courier new, courier, monospace;">tp</span> and <span style="font-family: courier new, courier, monospace;">c</span> are hardcoded by default to <span style="font-family: courier new, courier, monospace;">2</span> and <span style="font-family: courier new, courier, monospace;">0</span>, respectively.</li>
<li>The <span style="font-family: courier new, courier, monospace;">s</span> field is one byte and is a number that identifies the operating system version.</li>
<li>The <span style="font-family: courier new, courier, monospace;">mac</span> field is six bytes and is the MAC address value from the machine&rsquo;s ethernet or Wi-Fi adapter, or randomly generated if it fails to obtain any; the value is probably used as an identifier by the server.</li>
</ul>
<p>During our analysis we observed that the server replied with status code <span style="font-family: courier new, courier, monospace;">207</span>, to which DaemonicLogistics replied with another request to <span style="font-family: courier new, courier, monospace;">ime.sogou.com/update/latest/new_version?tp=1&amp;g=15&amp;c=0</span>. In this case, the part of the URL <span style="font-family: courier new, courier, monospace;">tp=1&amp;g=15&amp;c=0</span> is hardcoded.</p>
<p>The server replied with status code <span style="font-family: courier new, courier, monospace;">202</span>. DaemonicLogistics proceeded to do two requests to download the SlowStepper payload files, first to <span style="font-family: courier new, courier, monospace;">ime.sogou.com/update/file6.bdat</span>, and then to <span style="font-family: courier new, courier, monospace;">ime.sogou.com/update/file2.bdat</span>.</p>
<p>The payload data in the first and second responses from the server began with a magic value:</p>
<ul>
<li>In response to the first request, the magic value in hex was <span style="font-family: courier new, courier, monospace;">50 4B 03 04 0A 1B 2C 3D</span> (<span style="font-family: courier new, courier, monospace;">PK\3\4\A\1B\2C\3C</span>):
<p style="margin-top: 1em; display: flex; align-items: flex-start; gap: 0.3em;"><span style="color: #00a0a0; font-size: 1em; line-height: 1.4em; flex-shrink: 0;">○</span> <span style="margin: 0;"> DaemonicLogistics actively checks that the first eight bytes of data received from the server match this magic value. If true, it writes the data to <span style="font-family: courier new, courier, monospace;">%PROGRAMDATA%\Tencent\QQUpdateMgr\UpdateFiles\logo.gif</span>. </span></p>
</li>
<li>In response to the second request, the magic value in hex was <span style="font-family: courier new, courier, monospace;">47 49 46 38 39 61 10 10</span> (<span style="font-family: courier new, courier, monospace;">GIF89a\10\10</span>)
<p style="margin-top: 1em; display: flex; align-items: flex-start; gap: 0.3em;"><span style="color: #00a0a0; font-size: 1em; line-height: 1.4em; flex-shrink: 0;">○</span> <span style="margin: 0;">DaemonicLogistics does not check this magic value specifically: when the check for the previous magic value does not match, it processes the data and decrypts it using a combination of XOR operations. The data contains files that are written to disk on paths specified in the decrypted data.</span>.</p>
</li>
</ul>
<h2>Conclusion</h2>
<p>We analyzed the EdgeStepper network implant that enables PlushDaemon&rsquo;s adversary-in-the-middle capabilities to hijack updates from machines in a targeted network. We also analyzed LittleDaemon and DaemonicLogistics tools that together deploy the SlowStepper implant on Windows machines. These implants give PlushDaemon the capability to compromise targets anywhere in the world.</p>
